# Decisions — Demo

## ADR-001：C++ 优先
核心玩法使用 C++；蓝图只做配置与表现，以降低 AI 蓝图调试成本。

## ADR-002：三层 AI 上下文
AGENTS 为短入口；任务卡/交接为工作层；稳定事实、决策和日报进入 Memory MCP。

## ADR-003：文件级并行认领
非简单任务声明 Owner 和修改范围；重叠范围不得并行。

## ADR-004：三周交付优先
优先玩法闭环、新内容和高回报改进；低价值重构延后。

## ADR-005：夜间只读安全模式
无人值守时禁止修改/删除项目代码、资产、配置和规范，只允许记忆、报告与 Git 快照。

## ADR-006：运行时 PCG 与难度不变量
PCG 必须“实时、非工具”：最终打包游戏在每局开始时根据 Seed 和设置中选择的难度现场生成完整关卡，不以 Editor 预烘焙或固定地图随机摆放替代。难度在一局内固定；困难不明显延长目标单局时间；所有难度都限制长距离回头路。当前空间核心为 Grid-WFC 与显式全局约束；旧 Socket/A*/Progression Graph 方案已淘汰，不再视为现行架构。

## ADR-007：项目关卡统一归档到 Levels
可运行关卡与 PIE 测试关卡统一放在 `/Game/Levels`。功能目录只保存生成器、DataAsset、表现和可复用资产。

## ADR-008：单项素材兼容设置可先做后报
对于已确认是当前功能必要、只修改一项且可回退的同类素材兼容设置，AI 可直接处理并在完成后通知。该授权不扩大到改变外观、几何、碰撞语义或批量修改第三方素材。

## ADR-009：PCG 空间、批量放置与单局流程分层
WFC/Generator 是空间结果的唯一 Owner；Population 只消费只读空间查询，放置可重复陷阱/奖励；GameFlow 消费 Start/Exit 和空间候选，负责唯一玩家、追猎者及胜负状态。新增玩法对象先判断属于“可重复放置”还是“唯一局状态”，不得默认扩张 Generator。

## ADR-010：楼梯宏模块使用单一平滑 Pawn/Recast 行走面
HydroLab 楼梯的可见踏步只负责外观与非 Pawn 碰撞，并忽略 Pawn、关闭导航影响；每一跑随宏模块生成一块不可见坡面，独占 Pawn 阻挡与 Recast 采样，同时忽略 Visibility/Camera。转向平台保持真实水平地板。玩家在当前约 34.90° 配方中关闭 Character Movement 的 Maintain Horizontal Ground Velocity，避免沿坡速度突增。该配方属于项目模块合同，不是 UE 官方 WFC 概念；最终仍需玩家手感验收。

## ADR-011：多层 PCG 先放完整跨层结构，再逐层复用二维 WFC
首版多层关卡不改成统一三维 WFC。生成器先按 Seed 和难度完整放置双层楼梯、贯通三层的楼梯间与高天花板房间，冻结各层可走格、实体占用、净空和开放口，再把每层约束交给现有二维 WFC，最后合并楼梯内部跨层连接并一次验收整栋可达。每对相邻楼层至少一座双层楼梯；贯通三层的楼梯间只能额外生成。玩家与追猎者位于一楼，Exit 位于最高层。GridSize 是 DataAsset 可调值，不得写成固定生产合同。旧 Room 链删除；RegionKind 必须先迁移 GameMode/Population 消费者再删除。Level0 已验证的隐藏坡面是正式楼梯内部构件，不再创建一次性导航实验源码。

## ADR-012：HeavyImpact 起身使用提前物理快照到动画的单一混合

真实 Chaos 接触继续决定击飞、环境碰撞与最终倒地点。正常空间在身体满足最短物理时间、低速且有可行走支撑约 0.10 秒后，保存当前物理姿势、验证站立 Capsule、同步启动正/反面起身 Montage，再用约 0.22 秒的唯一混合权重从 Snapshot 过渡到现有 DefaultSlot。禁止恢复落地后唤醒全身刚体、用 Physics Control 可见地拧向起身首帧的蠕动路线。空间受阻时保持 Downed 睡眠并重试；可在 60 cm 内沿不穿阻挡物的骨盆通道小范围退让，但最终位置必须容纳完整站立 Capsule，完全封闭时不得强制穿墙起身。

## ADR-013：Population 机关与资源分层、有限候选最小图距采样

Population 保持一个 `AZeroEscapeGameplayPopulator` Owner，先规划机关、后规划资源；两层分别拥有密度目标、整栋通行图最小间距、确定性随机域和欠填统计。每个合法 1x2 高厅必放摆锤并计入机关目标；普通机关先按难度权重抽类型，再抽合法锚点和无冲突朝向，所有实际占用/操作格参与机关互斥和资源避让。资源在机关阶段后独立选择锚点，并在扣除真实占地的格内安全区域随机 X/Y。难度主要通过机关类型构成变化，总量只小幅变化；具体密度、间距和权重属于 DataAsset 可调验收基线，不写死为架构常量。旧 `OneEveryNCells + MaxCount` 规则链已删除，不保留兼容双轨、额外 Manager、每层硬上限或每类保底。

## 2026-08-13 — PCG 公开 Seed 与质量建模

- 玩家可见 Seed 是地图身份：运行时失败不得替换公开 Seed，也不得通过重载关卡偷偷换图。
- 只有结构合法、接口一致、必需端点/全图连通和最低可玩内容属于硬约束；密度、数量、覆盖、长直线、分散和距离属于软目标，必须从搜索开始引导，但不得成为最终拒绝。
- 固定工作量内先保存第一张硬合法结果，再择优；搜索预算耗尽时在同 Seed/同层做确定性合法兜底。禁止以 wall-clock、外部求解器或备用关卡扩张本方案。
- 当前正式产品合同为每栋至少两个高厅且至少一个非顶层；楼梯开口与机关资源另行讨论。

## ADR-014：实现写入单会话，纯文档任务可并行

本决策取代 ADR-003 的“所有修改范围不重叠才可并行”口径。同一时刻只允许一个会话持有实现文件写入权；这里的实现文件是项目内部并行分类，指会改变构建、运行或编辑器行为的代码、Blueprint、资产、配置、构建/测试文件等。纯文档任务不占用实现写入权，可与实现任务并行；其已知 Owner、路径明确且不重叠的未提交改动不阻塞实现范围 Git 基线，实现 Owner 不得修改、暂存或提交这些文档。来源不明的改动或其他会话持有的实现改动仍会阻塞。实现会话暂停、完成技术验证后等待用户验收或交接时必须释放写入权。

## PCG 发射器与机关相位边界

- 发射器的逻辑占用只有挂载锚点一格；炮口正前方由既有方向合法性和运行时弹体净空负责，不以整格硬封锁替代。
- 发射器组合是软评分：紧邻不奖励，2～3 格逐步奖励；缺少搭档永远不导致候选拒绝或地图重试。
- 周期机关相位在摆位完成后确定性派生并有限择优；相位差没有最低硬阈值，不参与 WFC、生成失败或公开 Seed 变化。
