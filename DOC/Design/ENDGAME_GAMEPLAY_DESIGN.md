# 《零号逃亡》终局玩法策划案：光球资源与守场

> 状态：正式策划案，2026-08-13 立案。本案是 `GAME_DESIGN.md` 的终局玩法专题展开；全局设定仍以 `GAME_DESIGN.md` 为准。
>
> 本案分两个可独立交付的阶段。阶段一为当前授权推进方向，阶段二为游戏性优化候选，是否实施按剩余工期决定。
>
> 本文只记录设计目标、玩家可感知规则、参数化要求与工期评估。类结构、组件接口、碰撞方案、计算公式、文件清单和验证步骤在方案确认后写入对应 `DOC/DailyPlan/`。
>
> 命名说明：「光球」「爆裂投掷」「守场」均为本项目内部命名，不是 UE 官方概念、标准算法或行业通用术语。

---

## 1. 立案背景

### 1.1 当前规则下的结构性问题

现行胜利条件是「玩家进入出口体积」，出口自开局即可通过。由此产生的最优策略是从起点直线冲向出口。

后果是三项已完成的重投入无法被玩家使用：

- 2026-08-12 验收的机关分层 Population（Normal 每百格 28 处机关，代表 Seed 实生成 1 摆锤 + 7 组地刺 + 16 冲锤 + 12 发射器）——玩家有动机全部绕开；
- 磁力吸取、持有、投掷、破碎全链——不需要对抗追猎者即可获胜；
- HeavyImpact 真实 Chaos 击飞、倒地、起身——把追猎者打倒没有战术收益。

同时 WFC 生成的死胡同（`FZeroEscapeGeneratedStats::DeadEndCount` 已在统计）当前是纯负面体验：进入、发现无路、退出，只损失时间。

### 1.2 设计目标

1. 让玩家有必须离开主路线的理由，使 PCG 生成的支路与死胡同产生价值；
2. 让玩家有必须对抗追猎者的场合，使磁力与物理受击系统成为必需品；
3. 把死胡同从负面体验转为风险回报选择；
4. 为一局提供明确的终局，替代「走进一个球体即获胜」。

### 1.3 前置依赖（不属本案，但本案效果依赖它们）

| 依赖 | 现状 | 说明 |
|---|---|---|
| 追猎者速度 > 玩家速度 | **未成立**：玩家 500（`ZeroEscapeCharacter.cpp:50`），追猎者 450（`PursuerConfig.h:35`） | 追猎者追不上时，玩家无需任何资源即可获胜，本案全部设计失效 |
| 持有物体时玩家减速 | 未实现 | `GAME_DESIGN.md` 2.6 已写「重物控制慢且拖累移动」 |
| 运行时导航可用 | **未证明**：最新 PIE 仍报 `Unable to find RecastNavMesh` | NavMesh 建不起来则追猎者不移动，本案无法验证 |
| 追猎者攻击造成伤害 | 代码已落盘待收口 | 追猎者无真实威胁时，爆裂投掷与守场都失去意义 |

**上述四项优先于本案实施。**

## 2. 阶段一：死胡同光球与爆裂投掷

### 2.1 玩家可感知规则

**光球**

- 生成在迷宫的死胡同末端，是一种可拾取资源；
- 拾取方式为即时计入，玩家进入其范围即获得，不需要搬运或按键读条；
- 光球有两种互斥用途，由玩家自行分配。

**光球的两种用途**

| 用途 | 玩家操作 | 效果 |
|---|---|---|
| 开启出口 | 自动计入 | 累计达到本局要求数量后，出口解除封锁 |
| 爆裂投掷 | 持有磁力物时消耗 | 该物体在正式投掷后的首次碰撞时小范围爆炸，并对范围内追猎者施加 HeavyImpact |

**出口**

- 开局处于封锁状态，玩家可以看到但不能通过；
- 光球数量不足时给出明确的锁定视觉与提示；
- 集满所需数量后解除封锁，玩家进入即获胜。

### 2.2 核心张力

玩家全程面对同一个决策：

> 手上这枚光球，留着开门，还是现在花掉保命？

该结构等同于经典生存类作品的弹药经济。它自动产生难度曲线：玩家越接近开门条件，可用于保命的余量越少，终局压力自然升高，不需要人为编排。

死胡同的风险结构由其几何形状自动成立：死胡同只有一个出口，玩家在其中被追猎者堵住时没有绕行路线，必须使用物理手段脱身。这一点不需要额外设计。

### 2.3 爆裂投掷的行为边界

- 只有正式投掷（`ThrowHeldObject()` 之后）的首次合格碰撞触发爆炸；拉取、持有、普通放下、命中前重新抓取均不触发；
- 爆炸为小范围球形，对范围内追猎者施加 HeavyImpact；对玩家自身的影响需在实施方案中明确定义并默认从严（首版建议不伤害玩家，避免自杀式误操作）；
- 爆炸与现有破碎不冲突：两者都是同一次投掷碰撞事件的消费者，需明确定义同时满足条件时的先后与叠加规则；
- 未命中的爆裂物需有明确的失效时限，不允许长时间后随机爆炸。

### 2.4 必须参数化的调参项（用户明确要求）

由于**本项目没有小地图**，玩家不一定会经过所有死胡同。因此全图光球总数与出口所需数量的关系必须可调，并作为后续调参重点。

| 参数 | 建议初值 | 调参含义 |
|---|---|---|
| 全图光球总数（按难度） | Normal 5~6 | 过少则玩家可能找不齐而卡关；过多则失去稀缺性 |
| 出口所需光球数 | 3 | 与总数的差值即为可用于爆裂的余量 |
| **可用余量**（总数 − 所需） | 2~3 | **这是两难的空间**：为 0 则玩家不敢花，过大则没有压力 |
| 单次爆裂消耗光球数 | 1 | 设为 2 会让玩家永不敢用 |
| 爆炸半径 | 待定 | 过大则不需要瞄准，过小则难以命中 |
| 爆炸对追猎者的 HeavyImpact 强度 | 复用现有 | 不新增强度体系 |
| 光球在死胡同的放置密度与最小间距 | 待定 | 复用现有 Population 拒绝采样机制 |

**容错要求**：必须保证任何 Seed 下全图光球总数不低于出口所需数量，否则该 Seed 无解。此项需纳入现有生成验证。

### 2.5 与现有系统的关系

| 现有系统 | 本阶段如何使用 |
|---|---|
| Population 分层放置（2026-08-12 验收） | 增加光球放置规则；按格子形状筛选与现有 `bStraightCorridorOnly` 同构 |
| WFC DeadEnd 类型 | DeadEnd 已是 Tile 一等公民（`FZeroEscapeWfcShapeWeights::DeadEndWeight`），不需要新写图分析 |
| `UMagneticObjectComponent::OnThrownBlockingHit()` | 多播委托，已处理正式投掷判定、投掷者过滤、冲量门槛、监听时限。爆裂作为新订阅者接入 |
| `UMagneticThrowBreakComponent` | 同一委托的现有订阅者，是爆裂实现的参照范式（含 next-tick 收尾） |
| HeavyImpact 提交接口 | 机关已在使用，爆裂复用同一入口，不改其状态机 |
| `AZeroEscapeExitVolume` / `GameState` | 出口增加解锁条件；胜负判定结构不变 |

**本阶段不新增玩法系统，不修改 HeavyImpact 内部，不修改磁力抓取事务与碰撞通道。**

### 2.6 阶段一工期评估

| 项 | 估时 |
|---|---|
| 光球 Actor + 死胡同放置规则 + 生成验证 | 0.5 天 |
| 爆裂投掷（订阅委托、范围查询、提交 HeavyImpact） | 0.5 天 |
| 出口锁 + 光球计数 + HUD 显示 | 0.25 天 |
| **小计** | **1.25 天** |

特效与音效不含在内，见第 4 节。

### 2.7 阶段一验收标准

1. 任意 Seed 下光球总数满足出口需求，无无解局；
2. 玩家能在死胡同拾取光球，HUD 正确显示已有数量与所需数量；
3. 出口在数量不足时不可通过且有明确视觉反馈，集满后可通过并判胜；
4. 爆裂投掷只在正式投掷首次碰撞时触发，能对追猎者产生 HeavyImpact 击飞倒地；
5. 爆裂与现有破碎同时满足条件时行为确定，不出现二者竞态或重复消耗；
6. 未命中的爆裂物在时限后安全失效；
7. 玩家在一局内实际做出「留着开门 vs 现在花掉」的决策，且两种选择都可行。

## 3. 阶段二：终点守场（游戏性优化候选）

### 3.1 设计意图

阶段一解决了「玩家为什么离开主路线」，但终局仍是「走进出口即获胜」。阶段二把终局改为一场有明确高潮的遭遇战。

### 3.2 玩家可感知规则

- 终点房间面积扩大，作为最终遭遇空间；
- 玩家集满光球进入终点房间并启动装置后，**房门关闭，玩家与追猎者都不能离开**；
- 装置启动为瞬时操作（按一下即生效），不使用持续读条；
- 启动后进入守场倒计时，时长按难度不同；
- 倒计时期间房间定期刷新磁力资源，保证玩家始终有物理手段可用；
- 房间偶尔刷新光球，允许玩家在战斗中获得爆裂能力；
- **玩家被攻击只损失生命，不中断倒计时**；
- 倒计时结束即获胜；生命归零即失败。

### 3.3 为什么关门优于区域约束

关门是一条物理上不可违反的硬约束，因此不需要「离开区域则暂停、返回则继续」的状态机与进度保留逻辑，玩家也不需要被教导规则边界。它同时提供明确的戏剧节点（门落下 = 退路消失）。

### 3.4 为什么被攻击不中断倒计时

若被攻击即中断，玩家最优策略会退化为远离追猎者躲避，物理系统依然不被使用。允许玩家硬抗，才会产生「我还有多少血、还剩几秒、这一下要不要吃」的实时权衡，使守场成为战斗而非躲避。

### 3.5 建议参数

| 参数 | 建议初值 |
|---|---|
| 守场时长（Easy / Normal / Hard） | 20 / 30 / 45 秒 |
| 房间资源刷新间隔 | 6~8 秒补一个 |
| 房间内资源同时存在上限 | 3~4 个 |
| 光球刷新概率 | 低频，保证一场守场内约出现 1 次 |

时长低于 15 秒难以形成遭遇战体感；高于 60 秒会从紧张转为消耗。

难度差异复用现有 `FZeroEscapeDifficultyDefinition` 结构，为纯数据配置。

### 3.6 与现有资产的协同

2026-08-12 验收的 Population 规则包含「合法 1x2 高厅必放摆锤」。若终点房间采用高厅结构，则守场空间天然自带一台摆锤，玩家可将追猎者引入其中换取安全时间，不需要额外的空间约束设计。

### 3.7 阶段二工期评估

| 项 | 估时 |
|---|---|
| 终点房间扩大与关门机制 | 0.25 天 |
| 守场倒计时、难度参数、胜负接线 | 0.25 天 |
| 房间资源与光球定期刷新 | 0.25 天 |
| **小计（不含特效音效）** | **0.75 天** |
| 关门特效、装置启动特效、倒计时 UI | 0.5 天（计入第 4 节） |

### 3.8 阶段二取舍原则

- 本阶段是游戏性优化，不是交付前提。阶段一已构成完整可玩闭环；
- 只有在阶段一完成并验收、且特效音效 UI 与打包时间已确保的前提下才启动；
- 若中途发现工期不足，可整体放弃而不影响阶段一；
- 不允许为本阶段挤占第 4 节的表现层时间或打包时间。

## 4. 表现层要求（跨两个阶段）

用户明确要求保留一到两天用于特效、音效与 UI。本节列出本案产生的新增需求，音效具体素材要求并入既有 `DOC/Design/GAME_AUDIO_REQUIREMENTS.md`，不在本案重复。

### 4.1 阶段一新增

| 项 | 用途 | 优先级 |
|---|---|---|
| 光球待拾取表现（自发光、缓慢浮动） | 在昏暗走廊尽头可被远距离识别 | 高 |
| 光球拾取反馈（音效 + 短特效） | 确认获得 | 高 |
| 爆炸特效 | 爆裂投掷的核心表现 | **最高**（无此则玩法不可读） |
| 爆炸音效 | 同上 | **最高** |
| 磁力物已附魔状态表现 | 让玩家知道当前手上是爆裂物 | 高 |
| 出口锁定 / 解锁视觉与音效 | 让玩家理解胜利条件 | 高 |
| HUD：已有光球数 / 所需数 | 玩家的基本信息权 | 高 |

### 4.2 阶段二新增

| 项 | 优先级 |
|---|---|
| 关门特效与音效 | 高（戏剧节点） |
| 装置启动特效 | 中 |
| 守场倒计时 UI | 高 |
| 资源刷新出现表现 | 中 |

### 4.3 不属本案但为本案前提的表现项

以下项目虽不由本案产生，但缺失会使本案玩法不可玩，需在同一批表现层工作中完成：

- **追猎者脚步声与距离衰减** —— 第三人称视角下追猎者从背后或墙后接近时玩家当前零信息来源。玩家无法判断威胁位置则无法做本案要求的任何决策；
- **玩家血量显示** —— 阶段一的「花不花光球」与阶段二的「吃不吃这一下」都需要玩家知道自己血量；
- **撞击音效与命中镜头反馈** —— 物理对抗的基础可读性。

## 5. 总工期与排期建议

### 5.1 总账

| 项 | 估时 | 性质 |
|---|---|---|
| 前置四项（速度、Recast、跳跃攻击收口、持物减速） | 0.5~1 天 | **前提** |
| 阶段一 | 1.25 天 | **本次授权方向** |
| 表现层（含前提项） | 1~1.5 天 | **不可压缩** |
| 打包与独立包实测 | 0.5 天 | **不可替代** |
| 整局回归与修复 | 0.5 天 | 必要 |
| 阶段二 | 0.75 天 + 0.5 天特效 | **候选** |

在 08-17 冻结的前提下，阶段一 + 表现层 + 打包 + 回归已占满可用工期。**阶段二只能在其他项提前完成时插入。**

### 5.2 硬约束

1. **运行时导航验证必须最先完成**：NavMesh 建不起来则追猎者不移动，本案两个阶段都无法验证。这是全项目唯一的单点故障；
2. **玩法先于表现**：阶段一功能未成形时不投入特效音效，否则可能为被改动的机制制作素材；
3. **打包不得晚于 08-16**：项目至今从未执行 Development 或 Shipping 独立构建，首次打包通常暴露 Editor-only 依赖、软引用未 Cook、第三方素材路径问题，必须留出修复时间。

### 5.3 止损顺序

工期不足时按以下顺序放弃，不得逆序：

1. 阶段二守场（整体）；
2. 爆裂投掷 —— 放弃后光球退化为纯钥匙资源，阶段一闭环仍成立，但核心张力大幅下降，应尽量保留；
3. **不得放弃**：出口锁（放弃则阶段一失去意义）、表现层前提三项、打包。

### 5.4 关于物理轻受击

局部物理轻受击已落盘但未验收。`claude/reviews/2026-08-12-轻受击动画与局部物理融合拟实现代码.md` 指出两个阻塞项与一条静默失效路径，修复后仍需调参与画面验收，且该方向历史上已被否决一次、方案推翻两轮。

在剩余工期内，建议**保留已提交代码但关闭启用开关，不再投入调参与验收时间**，将该时间转入本案与表现层。此建议需用户确认。

## 6. 未确定事项

- 光球的美术形态、世界观解释（能量核心 / 电磁电容 / 其他）与叙事关系；
- 爆炸是否对玩家自身造成伤害或位移（首版建议不造成，待试玩确认）；
- 爆裂与破碎同时满足条件时的最终叠加规则；
- 全图光球总数与出口所需数量的最终难度曲线，需多 Seed 实测后确定；
- 阶段二终点房间是否强制采用高厅结构；
- 阶段二守场失败后是否允许在同一局重试。

以上在实施方案或试玩后收敛，不阻塞阶段一立案。
