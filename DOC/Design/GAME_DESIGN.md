# 《零号逃亡》游戏策划案

> 状态：唯一现行策划案，2026-07-21 综合整理。当前仍处于方案讨论阶段；未完成“确定方案—展示拟实现代码—用户明确允许”前，不进入实现。

## 1. 命题与方案结论

**主题：程序化内容生成 + 物理**

**题目描述：核心玩法使用 PCG 的物理玩法 3D 游戏。**

**PCG 要求：实时，非工具。**

本项目将该要求落实为：玩家在最终打包游戏中开始一局后，程序根据本局固定的难度与 Seed，在 Runtime 现场生成最终关卡的流程、空间拓扑、模块布局和内容描述；不依赖 Unreal Editor、Editor-only 模块、预烘焙关卡抽取或只在固定地图中随机摆放内容。允许提前制作模块素材、连接器数据和配置，但这些只是运行时算法的输入，不是最终生成结果。

要求：

1. 编码设计能体现技术能力；
2. 游戏完整可玩，无明显崩溃、Bug；
3. 使用 UE 引擎；
4. 严禁抄袭剽窃；
5. PPT 中需要阐述 AI 使用情况。

本项目制作一款第三人称 3D 物理追逐动作游戏：玩家在运行时生成的工业迷宫中逃离持续追击的追猎者，以磁力吸取、控制和投掷 Chaos 刚体，使追猎者偏转、踉跄或倒地，并利用物体通过危险区。PCG 必须生成整局的空间结构、追逐路线与物理资源，而非只随机摆放内容；核心生成算法计划由独立 C++ 模块承载，不把 UE 官方 PCG 节点系统作为主要技术点。

最小剧情前提：主角拥有电磁能力，正遭受未知追猎者猎杀，必须逃离设施。具体身份、追猎原因和世界背景后续补充，不阻塞核心玩法开发。

三周内先完成稳定、可反复游玩的基本游戏。肉鸽成长、复杂破坏和高级物理求解属于候选扩展，不作为基本闭环成立的前提。

当前中期开发优先级为：先完成 PCG 整关生成、Seed 复现与验证，再完成一种追猎者的基础追踪、攻击和受击交互；磁力系统只收口阻塞基础闭环的问题，蓄力投掷等进阶玩法不抢占这两项工作。

## 2. 核心玩法

### 2.1 一句话体验

> 在追猎者逼近时抓起铁板，将它撞退或砸倒，趁硬直穿过陷阱并冲向撤离点；下一局的路线、危险和可利用物体由 PCG 重新组合。

### 2.2 玩家核心能力

| 能力 | 当前用途 | 玩家感受 |
|---|---|---|
| 磁力选择 | 在准星周围的屏幕区域内筛选无遮挡目标，不要求像素级对准 | 快速追逐中仍容易选中 |
| 吸取与持有 | 按住右键，物体沿物理路径来到玩家手前方的控制区域并保持安全距离 | 有重量、有过程 |
| 投掷 | 物体稳定吸附到身前后，持续按住右键并点击左键，沿准星方向发射 | 主动确认攻击，不会因松手误投 |
| 自由释放 | 松开右键即关闭控制，物体保留受安全上限保护的少量惯性并自由下落 | 直觉清晰、可以布置物体，又不能用甩镜头替代投掷 |
| 基础移动 | WASD、视角；是否加入闪避由试玩决定 | 操作负担保持低 |

目标选择按屏幕距离、世界距离、遮挡和候选优先级综合评分，右键按下后锁定本次目标。投掷后必须先松开并重新按下右键才能抓取下一个目标，避免自动连抓。持有控制可以按质量和物体类型定制位置、响应速度和投掷参数。首版只保证铁板自动目标姿态；通用不规则物体旋转后续单独设计，不进入当前抓取闭环。表现层后续增加从玩家手部连接到物体的电弧特效。

中期只要求稳定、可控的基础投掷：吸取途中或刚到身前但尚未稳定的物体不能投掷，普通释放也不能通过快速甩动视角获得超过正式投掷的动能。蓄力、逐级摇晃和体力消耗属于中期后的进阶候选。

### 2.3 物理对抗与追猎者反馈

追猎者难以被直接消灭。玩家攻击的主要收益是控制其行动、制造距离并争取通过危险区或开启出口的时间。

| 撞击级别 | 主要判定 | 追猎者反馈 | 战术价值 |
|---|---|---|---|
| 轻微 | 低质量或低相对速度 | 身体偏转、当前攻击被打断 | 紧急自救 |
| 中等 | 有效铁板命中 | 后退、短暂踉跄 | 拉开数米距离 |
| 强力 | 重物、高速或有利接触方向 | 倒地并经历起身 | 穿越危险或操作目标 |
| 环境重击 | 撞墙、机关或特殊危险 | 长硬直、护甲受损或行为变化 | 高风险高收益 |

- 冲击效果由物体质量、相对速度、形状、接触方向和追猎者状态共同决定。
- 伤害可以累积失衡或破甲，但首版胜利条件不是击杀追猎者。
- 起身后给予短暂抗硬直，避免玩家利用单件物体无限压制。
- 投掷首先保证可控，不使用会让准星失去意义的全房间随机磁场偏转。
- 后续不同物体通过重量、姿态、易碎性、弹性、导电性等属性产生不同反馈。

### 2.4 环境交互

- 大型铁板可覆盖一段地刺、阻挡弹道或成为移动掩体。
- 玩家也可以绕行、快速穿过，或把追猎者引入危险区。
- 关卡提供多种可理解的解法，不要求 PCG 精确摆出唯一谜题答案。

### 2.5 基本游戏闭环

1. 输入或随机获得 Seed，运行时生成工业迷宫、资源和撤离点。
2. 玩家取得首个目标或离开安全区后，追猎者开始持续追击。
3. 玩家观察路线、磁性物体、掩体和危险区，决定直接逃跑或绕路获取资源。
4. 吸取—持有—投掷，通过偏转、踉跄、倒地和环境重击迟滞追猎者。
5. 完成少量沿途目标解除撤离封锁，在追猎者恢复前抵达并开启出口。
6. 成功撤离则胜利；被追猎者击倒或生命耗尽则失败。
7. 立即重开新 Seed，获得不同路线和物理机会。

沿途目标必须轻量，例如激活一个供电节点或取得一枚撤离钥匙；它的作用是迫使玩家进入迷宫并使用物理能力，不发展成精密解谜。基本版本不依赖升级系统。PCG 带来的重玩差异来自空间拓扑、追逐节奏、危险与资源关系，而不是只更换数值。

### 2.6 物理资源策略

- 轻物体：吸取快、投掷快，用于打断攻击，但硬直短。
- 铁板：首版核心资源，可防御、稳定击退，也可覆盖部分地刺。
- 重物：控制慢且拖累移动，但能造成倒地；放置点必须允许玩家承担风险后获得收益。
- 易碎物：一次性高反馈，破碎后失去重复使用价值。
- 特殊属性物体作为扩展：高弹性、导电、易爆、旋转或可产生大碎块。

玩家不能随身无限保存物体。选择“立刻投掷”“带到下一个危险点”或“放下后绕行取重物”构成资源决策。

## 3. PCG 整关生成

### 3.1 生成范围

运行时一次生成：

- 起点、终点、主路线、可选支路和房间连接关系；
- 模块化地面、墙体、门洞和走廊；
- 追逐房间、环路、追猎者出生点、磁性物体、危险、沿途目标和撤离点；
- Seed、难度参数、验证结果和修复记录。

这构成完整场景关卡，不是固定地图中的随机刷怪或随机摆物。

### 3.2 算法边界

具体算法另行评估，可考虑随机房间图、BSP、图语法或其他适合模块化小房间的算法。正式玩法代码只依赖统一生成接口：

**输入：** Seed、房间数量、主路/环路/支路目标、模块集合、追猎压力、物理资源预算和难度参数。

**输出：** 抽象房间图、空间与连接口、玩法对象生成描述、验证与修复报告。

这样可替换或比较算法，也能明确展示自研 C++ 的数据结构、确定性生成、约束验证和调试能力。中期必须确定一种可工作的算法，不能因继续选型而阻塞整关生成。

### 3.3 生成流程

1. 根据 Seed 生成抽象房间图。
2. 为节点选择空间模块并对齐连接口。
3. 实例化地面、墙体、门和走廊。
4. 按空间标签生成追猎者出生点、铁板、危险、沿途目标和撤离点。
5. 检查连通、出生安全、资源下限、重叠和性能预算。
6. 定向修复；仍失败时有限重试并记录失败 Seed。

### 3.4 必须验证

- Start 到 Exit 可达，主路长度符合预算。
- 玩家出生安全，生成对象无严重重叠。
- 每个追逐区至少提供规定数量和强度的磁性物体。
- 携带铁板时仍能通过关键通路。
- 关键路线存在可绕行环路，连续死胡同数量受限。
- 追猎者出生距离安全，且玩家与追猎者导航均有效。
- 危险不封死唯一道路，重物附近有足够操作空间。
- 物理刚体、追猎者和生成尝试次数不超预算。
- 相同 Seed 能复现布局和问题。

### 3.5 PCG 与物理的耦合

首版耦合采用可验证的宽约束与追逐资源预算，而非昂贵的精确物理模拟：

- 房间按面积、可见距离、环路、死角和危险比例划分追逐类型。
- 资源配置保证每段关键路线有可投掷物，但轻重比例不同。
- 以路线长度、资源控制时长、危险收益和追猎者接近时间估算“逃生资源预算”。
- 危险区附近为玩家保留绕路、覆盖或击退追猎者的多种可能。
- 验证器检查“有物可用、双方能导航、不会被必然堵死”。

后续若基本玩法证明好玩，再加入轨迹预测和物理机会评分。

## 4. 内容规模与三周范围

### 4.1 中期必须完成（07-27 功能锁定）

实施顺序以 PCG 完整关卡和验证为第一优先，以一种追猎者的基础交互为第二优先；磁力系统只保留基础选择、吸取、稳定投掷和安全释放，不要求蓄力投掷或体力机制。

- 一种铁板：选择、吸取、定制姿态、放下和投掷。
- 一种追猎者：追踪、攻击、偏转、踉跄、倒地、恢复与防止无限硬直。
- 一份可替换的 MVP Flow Profile：当前验收内容可暂用 Start、至少 2 个追逐区段、一个轻量目标和 Exit，但 Chase/Objective 不作为生成算法的固定空间节点类型。
- 持续追逐、一个轻量沿途目标、撤离开启、胜利、失败、重开和 Seed 复现。
- 连通、出生、资源和重叠验证。
- 地刺属于加分项，不得阻塞上述闭环。

### 4.2 三周完整游戏目标（08-10 功能锁定）

- 一局约 8～12 分钟，3～4 个追逐区、一个沿途目标和撤离终点。
- 维持 1 种高完成度追猎者；优先增加物体属性和受击反馈，再考虑第二种追猎者。
- 至少 2 种不同布局/遭遇节奏。
- 基础教学、HUD、音效、命中反馈和结算。
- 多 Seed 回归、独立构建和备用演示视频。

### 4.3 资源策略

- 使用统一的模块化科幻工业/废料设施风格。
- 优先使用免费授权、已购买或 AI 辅助生成的资源，不手搓大量独占素材。
- C++ 负责玩法和生成；蓝图负责资源装配、UI、关卡配置与表现连接。
- 保存第三方资产名称、来源、许可和修改记录。

## 6. UE、Chaos 与自研边界

### 6.1 使用 Chaos 的部分

- 刚体质量、惯性、积分、碰撞、摩擦、弹性、睡眠和唤醒。
- Force、Impulse、Torque 的执行，物理子步、CCD 与碰撞事件。
- Physical Material；后续按需使用 Constraint、Ragdoll、Geometry Collection。

### 6.2 项目实现的部分

- 磁性目标筛选与吸取/持有/投掷状态机。
- 按质量与形状配置的目标姿态、响应和安全失效处理。
- 撞击强度、追猎者偏转/踉跄/倒地/抗硬直，以及危险交互规则。
- 运行时关卡算法、确定性 Seed、数据化生成契约。
- 连通、资源、物理可用性、重叠与预算验证及定向修复。

中期如实表述为“基于 Chaos 的定制物理玩法系统”，不把调用引擎 API 包装成自研物理引擎。中期后只从实际问题中选择一个高价值技术深入，并用对照数据证明效果。

### 6.3 建议代码职责

- Character/Pawn：移动、相机、输入转发。
- MagneticInteractionComponent：选择、吸取、姿态、释放和投掷。
- MagneticObject Component/Interface：物体能力和数据配置。
- Pursuer：追踪、攻击、受击层级、恢复、脱困和追逐压力。
- RuntimeLevelGenerator：组织生成并实例化关卡。
- GenerationAlgorithm Interface：Seed 到抽象关卡描述。
- GeneratedLevelValidator：验证、修复和报告。
- GameMode/GameState：开始、推进、胜败与重开。
- DataAsset/DataTable：物体、房间、追猎者和难度参数。

## 7. 可扩展玩法与技术库

以下内容保留此前 V3 及讨论中有价值的创意，但不进入当前必做范围。

### 7.1 玩家与战斗

- 增加不同追猎者，形成对轻物、重物、陷阱和路线的不同反应。
- 追猎者护甲产生少量可再次吸取的大碎块，并改变受击反馈。
- 钢梁重击、锯片旋转伤害、炮弹反射等差异化物体。
- 多物抓取、环绕盾、排斥脉冲、投掷反冲移动。
- 远程或拉拽型追猎者使“持板防御—寻找窗口—反击”形成更强节奏。

#### 蓄力投掷（中期后候选）

- 前置条件：普通释放具有线速度和角速度安全上限；物体只有稳定吸附到身前后才进入可投掷状态。
- 稳定后立即按左键执行基础投掷，距离和动能较低，只造成少量伤害、轻度打断或击退。
- 继续按住右键则自动蓄力；蓄力期间随时可以按左键，以当前蓄力比例投出。
- 蓄力越高，物体摇晃幅度越大；摇晃采用有界表现，不能通过持续随机冲量积累超过正式投掷上限的隐藏动能。
- 最大蓄力提供该物体允许的最大动能、距离、伤害和击退。投掷结果与物体质量相关，但速度、冲量和伤害的具体映射需在实际敌人交互完成后再确定。
- 体力属于进一步扩展：蓄力持续消耗体力，体力耗尽时自动安全放下物体并进入恢复；当前不确定体力数值、UI 和恢复规则。
- 启动条件：PCG 中期关卡和一种追猎者交互已经稳定，且剩余工期足够；否则保留基础投掷，不进入实现。

### 7.2 环境系统

- 电场使金属物带电，火焰引燃或引爆容器。
- 粉碎机把大物变成碎片，输送带和旋转机械改变运动。
- 铁板搭桥、覆盖地刺或形成移动掩体。
- 磁核运输、护送或限时撤离作为独立任务模式。

### 7.3 可选肉鸽层

- 单局分支路线、风险房与奖励房。
- 3～6 个改变操作规则的升级，例如盾反、动量回收、重物强化和碎片控制。
- 根据玩家流派调整 PCG 的资源、路线与追猎压力。

肉鸽层只有在基本战斗、完整关卡和重开本身已有乐趣时才加入，不用升级数值掩盖核心手感问题。

### 7.4 高级技术候选

- 质量/惯性自适应的六自由度力—力矩持有控制器。
- 面向 PCG 的降阶刚体轨迹预测与机会评分。
- 预测结果与 Chaos 实际结果的误差统计。
- Active Ragdoll 与追猎者分层物理反应。
