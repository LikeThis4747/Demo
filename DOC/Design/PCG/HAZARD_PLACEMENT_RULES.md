# PCG 机关放置规则方案

> 状态：正式方案，2026-08-14 立案。本案是 `CHALLENGE_DESIGN.md` 第 5 节的实施级展开，取代 2026-08-12 已验收的「全局最小间距 + 均匀密度」放置规则。
>
> 本文只定义放置规则的目标、权重结构、参数与验收方式。类结构、采样实现、数据资产字段和验证代码在实施方案中确定。
>
> 命名说明：「机关组」「组压力」「通过余量」「类型上下文回写」均为本项目内部命名，不是 UE 官方概念、标准算法或行业通用术语。本文的“图距离”指最终通行图上两格之间的最短边数；“log2 评分”指先相加评分、再用 `2^Score` 映射为抽样权重。

---

## 1. 立案背景

### 1.1 要解决的问题

**当前机关均匀分布，既简单又无聊，玩家可以完全忽略机关与资源，一路冲向终点。**

具体表现：

- 机关之间存在全局最小间距，因此每个机关都是孤立的；
- 孤立机关只产生单一决策（绕开或等待周期），玩家两秒内解决，不构成挑战；
- 机关之间不形成配合，没有真实压力；
- 玩家没有使用资源的场合，因为吃伤害硬闯的代价低于停下处理的代价。

### 1.2 上一版规则的根本缺陷

2026-08-12 验收的规则使用全局最小间距（间距 2）来保证「玩家有喘息机会」。

**问题在于：排斥力的数学结果必然是均匀分布。** 这不是参数没调好，而是几何决定的——最小间距同时排除了「机关成组」和「大段空白」两种情况，只留下等距分布，也就是节奏最平的分布。

**因此本案的核心改动是：质量目标不再依赖全局排斥，而由图距离机关组、变化目标压力、组合奖励和位置偏好共同产生节奏。**

### 1.3 设计方法论（必须遵守）

**关卡质量目标一律采用有限且非零的软权重，鼓励算法自行产生多样组合；只有技术上不能生成、会造成占用冲突或使关卡失效的情况才作为硬约束。**

上一版的教训是把“通常不理想”误写成“不允许”。本案因此严格区分第 5 节的技术合法性与第 6 节的质量权重：开局宽松、组合偏好、组间留白、类型多样性和近乎无解诊断都不能把合法候选直接归零。

**推论：难度档给出机关期望量，评分决定“放什么、放在哪里、与谁相邻”；达到期望量后若仍存在真实长空白段，允许继续补位。期望量不是截断全图内容的硬上限。**

## 2. 机关定性（设计输入）

以下定性由制作人给出，是全部权重设计的基础。

| 机关 | 定位 | 通过难度 | 受击惩罚 | 放置特性 |
|---|---|---|---|---|
| 冲锤 | 重型 | 容易 | **大** | 无特殊限制 |
| 摆锤 | 特殊 | — | **大** | 依赖高厅结构 |
| 地刺 | 中型 | **需要等待** | 中 | 无特殊限制 |
| 刺轮 | 辅助型 | 容易 | 中 | **适合与其他机关连格出现，提高其他机关难度** |
| 投掷物发射器 | 轻型 | — | 轻 | **位置敏感**：宜转角，不宜直走廊侧面；后续可放地面 |

### 2.1 两个独立维度

上表包含一个关键区分：**「通过难度」与「受击惩罚」是两个独立维度**。

| | 惩罚小 | 惩罚大 |
|---|---|---|
| **容易通过** | 意义低 | **紧张但公平**（冲锤、摆锤） |
| **难通过** | **消耗型**（地刺） | **劝退区**，应罕见 |

「容易通过 + 大惩罚」可以多放：它制造紧张感，但玩家真正被命中的次数不多，失败时会归因于自己而非规则不公。

「难通过 + 大惩罚」应当降权：那是劝退，不是挑战。

**注意**：两个维度保留独立可调输入，但在每次候选评估中只共同形成一次基础压力。由基础压力再派生组压力与通过余量诊断，不能把“通过难度、受击惩罚、通过余量”作为三个常规权重重复放大同一危险。

### 2.2 刺轮是组合放大器

刺轮自身容易观察和通过，基础压力较低；价值主要来自压缩相邻机关的走位空间与等待位置。首版不采用难以解释的额外连乘，而用两条可独立诊断的路径表达：

- 刺轮自身只增加少量组压力；
- 刺轮与前后相邻机关形成组合时，候选评分和组合压力分别获得明确增量。

首版组合优先级固定为；表中数值由 512 Seed 夹具首轮收敛，仍需 PIE 手感复核：

| 情况 | log2 组合贡献初值 | 含义 |
|---|---:|---|
| 刺轮 + 冲锤 | `+3.0` | 强奖励，候选权重约乘 8 |
| 刺轮 + 地刺 | `+2.25` | 中奖励，候选权重约乘 4.76 |
| 刺轮没有上述搭档 | `-2.0` | 候选权重乘 `0.25`，明显降权但保持非零，允许单独出现 |

组合判断与放置顺序无关：先放刺轮或先放冲锤/地刺，都应得到同一配对奖励。

### 2.3 300cm 机关站与占用边界

- WFC 与通行图仍使用 `600 × 600cm` 逻辑格，不改地图生成骨架；
- Population 沿每个开放通行方向，在格中心前后 `150cm` 处建立机关站；直走廊因此有两个相距 `300cm` 的站；
- 同一机关站只允许一个机关，属于防止物理重叠的硬约束；直走廊格内前后相反的两个站可以分别放机关，转角/T 路口中操作包络重叠的垂直半站必须互斥；
- 一次地刺放置仍生成横跨 `600cm` 走廊的两个地刺 Actor，中心相距 `300cm` 且中间无可绕空隙；它整体只占一个机关站；
- Population 刺轮只占一个机关站，并从 DataAsset 中现有的一格路线确定性选择轨迹、镜像、方向和相位；连续刺轮按多个独立 Actor 放置；
- 冲锤只使用机关站左右两侧的真实封闭墙面；发射器保留后墙安装和沿走廊发射语义；
- 首版仍不在同一机关站做跨类型复合，也不在机关所在逻辑格内部再划资源安全子区域。资源仍避开整个机关格；未来若需同格资源，再设计机关自述安全区合同。

## 3. 通过余量（难度估算）

### 3.1 定义与用途边界

**通过余量指玩家在一段路径上「所有机关同时安全」的可用时间宽度。**

它是由基础压力、空间关系和可控相位信息派生的诊断结果，**不是第二份危险度乘数，也不是绝对权威**。

**明确不做的事：**

- 不精确求解交集到 0.0X 秒；
- 不反推机关周期以命中某个目标余量值（该做法会写死玩家的通过方式，且破坏可学习性，见 3.3）；
- 不用它作为硬性过滤条件。

### 3.2 估算方式

只需粗略分档，不需精算：

```
输入：邻域内机关数量、各机关危险期占周期的比例、玩家通过该邻域所需时间
输出：四档之一 —— 宽松 / 合适 / 偏窄 / 几乎无解
```

四档是完整方案的目标诊断。首版实现会在 Population 开始时由正式玩家的实际 Class 取得 UE 类默认对象（Class Default Object，CDO）上的名义地面速度 `CharacterMovement.MaxWalkSpeed`，并只传递给纯值 Policy：

```text
RepresentativeTraversalSeconds = (LogicalTileSizeCm * 0.5) / PlayerMaxWalkSpeedCmPerSecond
BasePressure = TraversalPressurePerSecond * RepresentativeTraversalSeconds
             + HitConsequencePressure
```

`MaxWalkSpeed` 是本局使用的名义输入，不读取会被临时 Stop/Slow 改写的实例值或瞬时 `Velocity`，不把 `400` 写死在 Policy。通行时间只缩放“通行压力”，受击后果不随玩家速度缩放。

首版仍用“实际组压力 / 变化目标压力”的相对值近似风险：严重过载时给候选有限降权，并把目标压力、实际压力与资源支持优先级写入机关组记录。半格机关站的代表性时长不等于所有机关的精确共同安全窗；精确四档要等地刺、冲锤相位接入后再做。

### 3.3 周期与相位合同

**同类机关的速度、周期和运动规律继续由各自 DataAsset 统一管理，Population 不为单个实例修改速度。** 若每处同类机关周期不同，玩家无法积累可复用知识；保持规律一致、只改变起始相位，才能同时获得可学习性与变化。

首版范围必须说清：

- Population 只给刺轮写入由 `Seed + 锚点 + 朝向` 派生的归一化相位；
- 闭环路线的 `Phase01` 覆盖一整圈，开放路线覆盖完整“去程 + 回程”；
- 地刺与冲锤保持当前固定启动流程，尚不能由 Population 主动控制组内相位关系；
- 因此首版通过余量是近似诊断，不能宣称精确求出了所有周期机关的共同安全窗口。地刺/冲锤相位接入属于第二步候选。

### 3.4 确定性要求

路线随机和相位随机必须使用稳定散列与独立盐值：同一公开 Seed、同一难度/Profile 与同一名义玩家速度得到相同结果；玩家速度不混入随机 Seed，但作为明示的本局评分输入记录。增加候选或调整资源参数不能洗牌已经规划的刺轮路线与相位。首版不加入“10% 人工引导相位”等额外模式，先验证最小闭环。

## 4. 放置邻域与配合类型

### 4.1 组合邻接与机关组是两种尺度

- **组合邻接**：相邻逻辑格的图距离为 `1`；同一直走廊逻辑格内可共存的前后两个 300cm 机关站也按相邻组合处理。刺轮 + 冲锤、刺轮 + 地刺奖励只在这一近距尺度触发。
- **机关组**：双方所有占用格之间的最短图距离不超过可调组半径；首版初值为 `3`。机关组可跨转角、楼梯和多层连接，用于压力累计与资源诊断。

机关组距离仍按 `600cm` 通行图的边数计算：同格为 `0`，前后相邻格为 `1`，转角与楼梯都按实际最短路径累计。机关站只细化同格占用与近距组合，不复制一套新的地图图结构。

### 4.2 四种配合类型

| 配合类型 | 机制 | 典型 |
|---|---|---|
| **时间配合** | 周期叠加，可用窗口变窄 | 连续格地刺 + 冲锤 |
| **信息配合** | 玩家看不见，靠反应 | **转角后的投掷物** |
| **空间配合** | 走位空间被压缩 | 刺轮 + 周期机关 |
| **资源配合** | 高压组附近有可利用资源，形成使用决策 | 安全进入侧邻格的资源 |

**首版权重设计必须支持位置、时间近似、空间与资源四类信息。** 刺轮配对按相邻格判断；转角对投掷物的加成来自位置评分；更宽的图距离机关组负责整体压力，而不是把所有关系混成一个距离阈值。

### 4.3 允许的所有形态

以下形态**全部允许**，由权重决定出现频率，不得预先排除任何一种：

- 连续多格都放机关；
- 每隔一格放一个；
- 单独放置一个机关；
- 同类型机关连续出现（如左右左三个冲锤、地刺空格地刺）；
- 跨转角配合；
- 同一 `600cm` 格的不同机关站分别放置机关；同一机关站的不同方向或轨迹变体最终只选一个。

**制作人明确要求不排斥单独放置，也不排斥同类型重复。** 同类型重复有其自身难度特征，实测前不预设优劣。

### 4.4 候选与方向去偏

普通机关的锚点现在指一个 300cm 机关站；同一站可能因为左右墙面或刺轮路线朝向产生多个合法变体。类型选择阶段每个站只贡献其最佳变体，不能把多个方向的分数累加；否则“方向多”会被误当成“类型更合适”。抽中类型与站后，再在该站的合法变体间做加权选择。

首版不增加天花板地刺、地面发射器或跨类型同格形态；以后增加时仍应作为候选变体进入同一评分流程，而不是另建硬编码模板。

## 5. 硬约束只负责技术合法性

候选只有在以下情况才被排除：

1. 超出地图或不属于允许安装该机关的空间；
2. 同一 300cm 机关站已被占用，或运行操作范围与已接收机关发生物理冲突；
3. 会占用生成流程保留的玩家、追猎者、出口或必要结构格；
4. 机关 Class、Transform 或刺轮生成前配置无效；
5. 首版跨类型同格复合，因尚无安全占用合同而不进入候选。

这些是“无法正确生成或运行”的技术条件，不是质量判断。以下情况必须保留非零概率：

- 起点附近出现机关；
- 机关位于开阔区或非理想位置；
- 单独刺轮、同类型连续或高压组后继续出现机关；
- 通过余量诊断为“几乎无解”；
- 高压组附近没有抽到资源。

若实测证明某种合法结果体验差，应先调整已有位置、组合、组目标或超载曲线；不能立即增加新的硬过滤或第七个评分通道。

## 6. 权重结构

### 6.1 设计参照

以下概念来自公开关卡设计文献（The Level Design Book, Pacing），属通用设计词汇，用于说明本案的节奏目标：

- **强度曲线**：以时间为横轴、玩家投入强度为纵轴的曲线。文献明确指出强度分级「不是硬科学」，来自实测直觉，每个项目须自定义指标。
- **高低交替**：玩家会适应长时间高强度并变得麻木；停顿作为对比，使高强度段落重新有效。**不应试图让玩家全程紧绷。**
- **开局宜缓**：以低强度内容开场，让玩家熟悉操作与空间。
- **pulse / accent / rest / variation**：建立规律、强调、休止、变奏——用于避免同一密度贯穿全程。

这些原则支持本案的核心判断：**均匀密度是最差的分布，节奏必须有峰谷。**

### 6.2 候选位置权重

放置采用逐个加权随机选择。每项原始数据先映射为有正有负、`0` 表示中性的评分贡献，再在 log2 空间相加：

```
TotalLog2Score = Clamp(
      Position
    + Progress
    + GroupPressure
    + Combination
    + Diversity
    + Diagnostic,
    -K, K)

Weight = 2 ^ TotalLog2Score
```

首版 `K` 初值为 `5`，使合法候选权重有界且永不因某一质量贡献为零而被硬删除。所有 Strength、曲线和组合值放在 Population DataAsset；每次选择保留六项拆分，便于定位“为什么选中”。

### 6.3 类型选择读取位置上下文

仍保留“先选类型、再选位置”的候选数量无关结构，但类型选择不能对地图上下文失明：

1. 先计算每种类型全部合法的“锚点 × 变体”分数；
2. 每个锚点只保留最佳变体，避免方向数量增加类型概率；
3. 每种类型取评分最高的三个**不同锚点**求平均；
4. 该平均分按首版强度 `0.5` 回写类型基础权重；
5. 抽中类型后，再按完整候选分数抽锚点和变体。

```text
TypeWeight = BaseTypeWeight × 2 ^ (Top3AnchorMean × 0.5)
```

不得对所有候选求和；否则某类仅因合法位置多就会被动提高概率。`0.5` 是首轮重点调参项，必须同时观察刺轮组合的绝对出现次数，而不只验证相对排序。

### 6.4 图距离机关组与变化目标压力

每次假设接收候选后，以第 4.1 节的图距离动态计算它会加入或连接哪些机关组，再评估放入后的实际压力。压力低于目标时逐渐鼓励补足，接近目标时权重最高，超过目标后快速下降；这是有界的钟形软倾向，不是容量上限。

目标压力不能是全图常数，否则只会把“机关均匀”换成“组压力均匀”。每个组的目标由以下稳定分量组成：

```text
TargetPressure =
    DifficultyBase
  + ProgressCurve
  + StableRegionVariation(Seed, ProgressBand)
  + StableAnchorVariation(Seed, GroupAnchor)
```

因此同一进度也会出现弱组、中组和强组，并由组外候选的相对权重自然产生空白段。组压力只累计一次“每秒通行压力 × 半格机关站代表时长 + 受击后果”和明确的组合压力增量，不能再次乘入通过难度与通过余量。

### 6.5 组合、多样性与诊断

组合贡献由对称表给出，与放置顺序无关。首版只明确实现刺轮 + 冲锤强奖励、刺轮 + 地刺中奖励和 solo 刺轮轻微降权；其他同类型或异类型相邻在组合通道保持中性，只受组压力、多样性等已有通道影响。是否增加通用相邻贡献必须等试玩后再决定，不能在首版暗中扩项。

- `Diversity` 只观察最近有限个普通机关，防止单一类型长期占据结果，但不禁止连放；
- `Diagnostic` 只处理接近无解等异常风险，允许大幅负贡献但不归零；
- 高压组合最终还会受到组压力超载曲线抑制，因此强组合奖励不等于无限堆叠。

若 Seed Sweep 仍接近均匀或刺轮组合太少，优先调整现有组合奖励、类型回写强度、变化目标压力和超载曲线，不增加新的评分通道。

### 6.6 期望量与覆盖补位

难度档计算出的机关量是期望值，不再是循环立即结束的硬预算：

1. 未达到期望量时，在全部技术合法候选中按完整权重抽样；
2. 达到期望量后，只让仍有正向路线覆盖贡献的候选继续参与抽样；
3. 当所有可放站都已覆盖到参考距离内、没有合法站，或触及 Actor 技术安全上限时停止。

补位阶段仍按类型、位置、组合、组压力和多样性权重选择，不指定某格必放某机关。资源层采用相同思想并保留独立随机域：先满足期望量，再只补仍远离全部机关与资源的空白区。显式配置期望量为 `0` 仍表示关闭对应普通放置层，不自动补位。

这里的“只补覆盖缺口”不是把普通合法位置升级成非法位置：所有位置在期望量阶段仍保持非零权重；覆盖不足只是达到期望量后继续超额放置的唯一理由。

---

## 7. 资源放置

机关阶段完成后输出机关组记录，至少包含成员、组锚点、目标压力、实际压力、资源支持优先级和安全进入侧候选格。资源阶段读取这份诊断，但继续使用独立随机域。

| 输入 | 资源倾向 |
|---|---|
| 实际压力高于目标 | 提高支持优先级 |
| 首版组压力明显高于变化目标 | 提高支持优先级；精确「几乎无解」诊断留到相位接入后 |
| 安全进入侧邻格 | 加权，帮助玩家在进入组合前看到并使用资源 |
| 机关占用/运行格 | 首版排除，不实现格内安全子区域 |

**关键效果：**「机关越难的地方越容易获得资源支持」是奖励权重，不保证每个高压组必有资源。只有未来某个机关组被证明“没有资源就绝对无法通过”，才需要升级为可行性硬检查。

**随机域独立是硬性工程合同：**资源可以读取已经冻结的机关组诊断，但不能消费或改变机关随机流。只修改资源密度、间距或支持权重时，机关类型、位置、组合、路线和相位必须完全不变。

---

## 8. 参数清单

首版的 Population 策划参数全部进入 Population DataAsset；玩家速度不复制成 Population 参数，而是由有 World 权限的 Populator 从正式玩家实际 Class 的默认对象读取后传给纯值 Policy。只有密度、类型基础权重和起点/终点目标压力按 Easy / Normal / Hard 分档；评分强度、风险输入与组合值跨难度共享。

### 8.1 机关属性（每类机关）

| 参数 | 说明 |
|---|---|
| 类型基础权重 | 各难度档的无上下文概率 |
| 每秒通行压力 | 与实际单格通行时间相乘，再与受击惩罚合成一次基础压力 |
| 受击惩罚输入 | 同上，不作为第二条重复乘数 |
| 位置偏好 | 走廊、转角、高厅等贡献 |
| 统一速度/周期 | 由机关自身 DataAsset 管理，不按实例改变 |
| 候选变体 | 方向、墙面和刺轮一格路线；锚点阶段只取最佳变体 |

### 8.2 全局参数与难度分档

| 参数 | 说明 |
|---|---|
| 期望机关量（每百格） | 按难度分档的基础内容量；达到后仍可为真实长空白段补位 |
| `MaxAbsLog2Score` | 总评分边界；首版初值 5 |
| 类型上下文锚点数与回写强度 | 首版 3 个不同锚点、强度 0.5 |
| 机关组图半径 | 首版初值 3 条通行边 |
| 玩家名义地面速度 | 从正式玩家实际 Class 的默认 `MaxWalkSpeed` 读取；非 Population DataAsset 副本 |
| 起点/终点目标压力 | 按难度分档的整体强度曲线 |
| 区域起伏与锚点抖动 | 避免组压力趋同，必须由 Seed 稳定派生 |
| 压力不足/超载曲线 | 控制补足、成组与留白 |
| 组合偏好各贡献 | 首版仅含刺轮+冲锤、刺轮+地刺与 solo 刺轮 |
| 多样性窗口与强度 | 反重复但不禁止连续 |
| 过载诊断贡献 | 首版以组压力相对目标作近似；精确通过余量四档属于第二步 |
| 资源支持权重 | 读取组诊断，使用独立随机域 |

### 8.3 首版调参顺序

1. 先确认技术合法性、Seed 确定性与候选数量无关；
2. 再调整刺轮组合奖励和类型上下文回写，使 Normal 多 Seed 下刺轮组合达到可感知的绝对频率；
3. 再调变化目标压力与超载曲线，形成强弱组和空白；
4. 最后调多样性与资源支持，不新增评分通道。

单独刺轮偏多时优先降低 solo 刺轮贡献，不提高刺轮基础压力；后者会同时改变组合的组预算语义。

## 9. 调试输出（建议实施）

由于本案结论是「参数靠实测收敛」，**迭代速度比初始参数是否准确更重要**。

建议生成后输出一份放置报告，至少包含：

- 每个已选机关的类型、锚点、变体和六项 log2 评分拆分；
- 每次类型抽样的基础权重、最佳三个不同锚点均分与回写结果；
- 每个机关组的成员、目标压力、实际压力和安全进入侧；
- 刺轮路线 Seed、归一化相位及强/中/无搭档统计；
- 资源支持优先级与最终资源分布。

有此输出，玩一局后即可定位「刚才那段为什么这么难」，一天可完成多轮调参；没有则只能靠感觉，轮次显著减少。

**在两天工期下，这项的收益可能高于任何单个参数的初值。**

---

## 10. 验收标准

1. 生成结果**不再呈现均匀等距分布**，可观察到机关簇与空白段交替；
2. 允许出现连续多格机关、隔格机关、单独机关、同类型连续和跨转角机关组，且合法情况均保留非零概率；
3. Population 刺轮只占一格，从现有一格路线选择；固定速度且同 Seed 的路线和相位可复现；
4. 资源调参不会改变任何机关放置、组合、路线或相位；高压组的安全进入侧获得更高资源概率；
5. 玩家在一局中至少出现数次「必须处理机关」而非「可以直接冲过」的场合；
6. 无卡关（通路被堵死）与物理重叠；
7. 相同 Seed 可复现；
8. 首版对外调参项可在不重新编译的前提下调整；仅用于保护异常状态的内部固定诊断值不冒充策划参数。
9. Normal 固定测试夹具的多 Seed 统计同时检查绝对频率：目标机关数足够时，每局平均至少出现一次刺轮组合，并保持“刺轮+冲锤高于刺轮+地刺、二者均高于完全单独刺轮”的方向；小地图或合法候选不足时不套用该门槛。
10. 机关或资源达到期望量后，若路线仍超过各自覆盖参考距离，允许追加补位；只有技术合法位置耗尽或 Actor 安全上限才停止。

**第 5 条是本案的根本目的，其余条目均服务于它。**

---

## 11. 未确定事项

以下必须实测后确定，不在本案预设：

- 类型上下文回写强度、组半径和超载曲线的最终取值；
- 通过难度与受击惩罚两个输入的相对强度；
- 同类型相邻与不同类型相邻的偏好差异；
- 通过余量四档的分界标准；
- 「几乎无解」路段每局的合理出现次数；
- 跨类型同格机关是否值得在后续单独建立安全占用合同；
- 投掷物发射器地面形态的实现成本与实际手感；
- 地刺与冲锤是否在第二步接入 Population 相位；
- `400 cm/s` 已确认为当前正式玩家 Class 的默认 `MaxWalkSpeed`；它需继续经 PIE 验证手感，但放置算法只读该真实配置值，不保存 `400` 常量。
