## 实施结果补充

- UE5.8 运行源码复核纠正了早期假设：AnimBP 的编辑目标骨架不等于运行时 Montage 骨架。运行时 AnimInstance 使用当前 Skeletal Mesh 的骨架，动态 Montage 使用 Sequence 骨架；玩家 Mesh 与两条起身 Sequence 同属 `CH_SciFiTrooper_Man_03_Skeleton`，因此无需另做 AnimBP 重定向或更换玩家骨架。
- 玩家项目副本保持 `SK_Mannequin` Target Skeleton，以保留官方 locomotion 图；C++ 只要求起身 Sequence 与运行时 Mesh Skeleton 相同。
- 实现保留真实 Chaos 位移，不在角色侧调用 `AddImpulse` 或 `LaunchCharacter`；恢复位置以最终物理骨盆为锚，最大水平调整 60 cm。

## A Pose 回归修复补充

- 现场证据：玩家和追猎者运行时均创建了正确的项目 AnimInstance，动画未暂停，倒地快照分支为 false；A Pose 不是 AnimBP 丢失或接错。
- 根因：UE5.8 Physics Control 在创建 BodyModifier 时会先把 Skeletal Mesh 的全身物理混合权重设为 1，并依赖后续 PrePhysics Tick 把各 BodyModifier 的 `Inactive` 权重写回 0。当前实现调用 `Inactive` Profile 后立刻关闭 Physics Control Tick，正常动画因此被物理参考姿势覆盖。
- 最小修复：仅修改 `Source/Demo/Private/Components/Physics/HeavyImpactResponseComponent.cpp`。初始化后临时保持 Physics Control 与 HeavyImpact Tick 开启；下一次 Physics Control PrePhysics 已应用 `Inactive` 后，由 HeavyImpact PostPhysics 检测 `Inactive` 状态并一次性关闭两个 Tick。
- 验证：Demo 模块构建、`Demo.Physics.HeavyImpact.*` 自动化、正常 PIE 玩家/AI Idle/移动、运行时物理混合状态，以及一次真实重冲击进入 Prepared/Simulating 的回归。
