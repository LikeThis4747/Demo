# 2026-07-27 PCG 玩法对象放置层最小实现

## 目标与范围

- 在自研空间生成器（`AZeroEscapeRuntimeLevelGenerator`）完成后，按数据驱动规则把玩法对象 Actor（首个为地刺 `BP_SpikeTrap`）**确定性**撒入生成结果。
- 采用方案 C「独立放置层消费空间结果」：生成器只补只读查询，不生成玩法对象；放置逻辑独立成层。
- 数据驱动：新增一类对象 = 在放置 Profile 里加一条规则，**零代码改动**（后续铁板/奖励/出生点同一套）。
- 本步只新增 4 个 C++ 文件、给生成器加 2 个只读 getter；不动 WFC、事务/回滚、第三方素材、Level0 结构、测试 Harness、小地图、地刺与生命组件。

## 设计依据（业界参考）

- UE `ProceduralDungeonPlugin`（GitHub draquel，UE5.7）：语义空间结果 + 确定性 Seed + 独立 populate 步骤。
- 以撒式 Roguelike 框架复盘：数据驱动（DataAsset）+ 规则表避免「每加一种就写 if-else」。
- UE 官方 `SpawnActor` + DataAsset 驱动：Actor 类与放置参数入数据，逻辑仅一个通用生成循环。
- 与本项目既有 `GenerationProfile` / `PresentationProfile` 两个 DataAsset 范式一致，延续为第三个「放置 Profile」。

## 架构（三块，各自最小）

1. **生成器只读查询（唯一改现有文件）**：与现成 `GetGeneratedRoomWorldTransforms` 同构，遍历 `LastPlan.Cells` 按 `RegionKind` 过滤、用现有 `ConvertLocalToWorld` 转世界 Transform，Z 取地板高度 `PresentationProfile->FloorTopZCm`；可排除 Start/Exit 及相邻格。另加 `GetGeneratedSeed()` 供下游复现随机。不动算法与事务。
2. **放置 Profile（DataAsset）**：`UZeroEscapePopulationProfile` 持有 `TArray<FZeroEscapePlacementRule>`；每条规则 = 放什么（软类引用）+ 放哪类格（RegionKind）+ 稀疏度（每 N 格 1 个）+ 数量上限 + 是否避开起点终点邻格。可扩展性全在这张表。
3. **通用放置器（唯一新逻辑）**：独立 `AZeroEscapeGameplayPopulator`，编辑器指向 Generator + 一个 Profile；订阅 `OnGenerationFinished` → 用本局 Seed 建 `FRandomStream` → 逐规则读候选、确定性洗牌、按稀疏度截断、`SpawnActor`。只做「读候选→抽取→Spawn」，不做权重/约束求解/堵路校验（留给策划案 6.3 Validator）。

## 最小 vs 可扩展权衡

| 取舍 | 更省做法 | 采用 | 理由 |
|---|---|---|---|
| 规则数据驱动 | C++ 写死放地刺 | **数据驱动 Profile** | 「还要放别的」是已知需求非猜测；项目本就 DataAsset 化，抽象成本仅一 struct+一数组 |
| 放置器载体 | 挂生成器 Actor | **独立 Actor** | 生成器边界明确「不生成玩法对象」，独立才不破坏 |
| 规则复杂度 | 权重/优先级/冲突消解 | **每 N 格 1 个 + 上限 + 避开起点终点** | 最小可玩规则；权重与堵路校验以后再加 |

## 规模审计

- 新增 C++ ≈ 245 行；修改现有 ≈ 58 行。
- 新增类型：1 USTRUCT（`FZeroEscapePlacementRule`，5 字段）、1 DataAsset（`UZeroEscapePopulationProfile`，1 数组）、1 AActor（`AZeroEscapeGameplayPopulator`，5 函数 / 3 成员）。
- 新增 public API：生成器 +2 个 const `BlueprintPure` getter；无新增模块依赖、不改 `Build.cs`。
- 侵入性：生成器仅追加 2 个只读查询，与顶灯放置同构，不触碰 WFC/事务/回滚/EndPlay 清理路径。
- 圈复杂度：集中在 `HandleGenerationFinished`（2 层循环 + 判空），每层短、无深嵌套。

## 风险与缓解

1. **时序**：若生成器改为 BeginPlay 自动生成，放置器绑定可能晚于生成完成 → 绑定后立即检查 `State==Ready`，是则补放一次。当前默认 ExplicitOnly，显式触发在 BeginPlay 之后，天然安全。
2. **软类同步加载**：`LoadSynchronous` 首次可能有轻微卡顿；单机少量对象可接受。
3. **Spawn 重叠**：`AlwaysSpawn` + 走廊格中心 + 地刺 pivot 贴地，重叠风险低；不做堵路校验，已用「避开 Start/Exit 邻格」降低最坏情况。
4. **重生成清理**：`HandleGenerationFinished` 先销毁上一批、`EndPlay` 再清一次，避免残留。

## 实施步骤

1. 落盘 4 个新增文件 + 修改生成器 2 文件（用户确认拟实现代码后）。
2. 用户关闭 UE 后完整构建 `DemoEditor`。
3. 重开后新建 `DA_Population_Default`，加一条地刺规则；Level0 放 Populator 并连 Generator + Profile。
4. 显式触发一次生成，PIE 观察：走廊出现地刺、避开出生点/出口邻格、同 Seed 分布一致、重生成无残留。

## 验证与回退

- 不跑自动化测试；用户在主视口 PIE 用 Seed 12345 + 至少一个不同 Seed 检查放置分布与确定性。
- 检查：地刺只落走廊、数量约 = 走廊候选/N 且不超过上限、避开 Start/Exit 邻格、重新生成旧地刺被清、无堵死唯一通路的明显情况。
- 回退：Profile 清空规则即不放任何对象；移除 Populator Actor 即彻底停用，生成器与地刺均不受影响。
- 构建与资产装配完成后仍标「待用户验收」，不提前宣称完成。

## 遗留事项（2026-07-27 验收后确认，暂未实现）

- **同一格并排摆多个占满路宽**：走廊逻辑格 600cm 宽，`SM_SpikeTrap` 仅 300×300，单格放一个在格中心只占半条路，玩家可绕行。需在同一格沿走廊横向并排摆放（约 ±150cm 偏移）。横向方向应由该格 `OpeningMask` 推断走廊走向后取垂直方向，不能硬编码横纵轴。当前 Populator 每格只放一个实例，需扩展为支持"每格横向多实例 + 偏移"。
- **地刺尺寸微调**：网格缩放或摆放间距调整，确保并排后真正挡住整条路、且不留可跳过的缝隙。与上一条一起做。
- 验收记录：2026-07-27 用户在 PCG 关卡 PIE 中确认走廊成功生成地刺、避开出生点/出口，主体功能验收通过。
