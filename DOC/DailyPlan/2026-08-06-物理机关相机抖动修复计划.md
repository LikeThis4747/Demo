# 2026-08-06 物理机关相机抖动修复计划

## 目标与当前结论

- 解决玩家靠近摆锤/冲锤或被其击中时出现的相机快速跳动，同时保留地牢场景所需的墙体防穿透。
- 当前证据支持两条来源：
  1. 受击时，HeavyImpact 在 `TG_PostPhysics` 让玩家 Actor/Capsule 跟随物理骨盆，而直接挂在根节点上的 `CameraBoom` 也在同组更新；项目没有显式声明同帧先后关系。
  2. 只靠近机关时，锤体忽略 `ECC_Camera`，但狭窄测试房间墙体阻挡相机。原生 SpringArm 遇墙会立即缩到命中点，离开命中后也立即恢复，边界反复切换时可能表现为忽远忽近。
- 第一版优先消除确认度最高、成本最低的更新顺序问题，并用原生位置延迟过滤根节点的高频位移；不提前实现自定义相机系统。

## 术语说明

- `AddTickPrerequisiteComponent` 是 UE 原生的组件更新依赖：当两个组件都需要在一帧内更新时，指定后者等待前者完成。这里用于保证 HeavyImpact 先更新角色根节点，弹簧臂再读取它。
- `Camera Lag` 是 UE `USpringArmComponent` 自带的“相机位置延迟”，只平滑位置目标，不等于输入延迟。本计划不启用旋转延迟。
- “碰撞回缩”是 SpringArm 为防止相机进入墙体而把相机移到碰撞命中点的原生行为。

## 第一版文件与资产范围

- 修改 `Source/Demo/Private/Characters/ZeroEscapeCharacter.cpp`：为 `CameraBoom` 增加对 `HeavyImpactResponse` 的原生 Tick 依赖。
- 修改 `Content/ZeroEscape/Characters/BP_ZeroEscapeCharacter.uasset`：只调整现有 `CameraBoom` 的 SpringArm 参数。
- 不新增 C++ 文件，不修改头文件，不修改 HeavyImpact、机关、关卡、AnimBP、起身动画、PCG 或引擎源码。

## 第一版参数

| 属性 | 当前值 | 第一版值 | 目的 |
|---|---:|---:|---|
| `bEnableCameraLag` | `false` | `true` | 平滑角色根节点的高频位置变化 |
| `CameraLagSpeed` | `10.0`（未启用） | `12.0` | 提供较轻的位置平滑，避免明显拖尾 |
| `CameraLagMaxDistance` | `0 cm` | 首测 `60 cm` | 角色高速移动时限制相机最多落后距离；同场景对照 `40/60/100 cm` |
| `bClampToMaxPhysicsDeltaTime` | `false` | `true` | 仅作为低于约 `30 FPS` 时的时间步防过冲保险，不是正常帧率消抖主力 |
| `bUseCameraLagSubstepping` | `true` | 保持 | 降低波动帧率下的位置延迟差异 |
| `CameraLagMaxTimeStep` | 约 `1/60 s` | 保持 | 不增加额外调参维度 |
| `bEnableCameraRotationLag` | `false` | 保持 | 不改变玩家视角输入响应 |
| `bDoCollisionTest` | `true` | 保持 | 防止地牢墙体穿帮 |
| `ProbeSize` | `12 cm` | 保持 | 不用缩小探头掩盖碰撞边界问题 |

## 实施顺序

1. 用户 Review 本计划与拟实现代码；本轮文档不等于功能落盘授权。
2. 实现前检查完整工作区，按项目 Git 门禁把所有已确认改动形成一次成功推送的基线；并行任务文件归属不清时暂停。
3. 在玩家构造函数中增加一条更新依赖，不改变 HeavyImpact 状态机或 Tick 组。
4. 正式构建 DemoEditor。
5. 用 UE5.8 官方 MCP 修改并保存玩家 Blueprint 的四个 SpringArm 参数，编译 Blueprint 后回读真实值。
6. 在同一房间中央受击场景对照 `CameraLagMaxDistance = 40/60/100 cm`；以 `60 cm` 为起点，只保留“能消抖且击飞跟随不拖拽”的最小合适值。
7. 在 Level0 做其余 A/B 和边界验证，结束后正常退出 PIE。

## PIE 验证矩阵

1. 普通空旷区域：跑动、急停、跳跃、快速旋转镜头，确认位置延迟没有明显拖沓，旋转手感不变。
2. 房间中央受击：相机后方没有墙，分别承受摆锤与冲锤命中，隔离验证“根节点跟随 + 更新顺序”；固定场景比较最大落后距离 `40/60/100 cm`。
3. 贴墙受击：角色与相机后方接近墙体，验证防穿透仍生效，并记录是否仍出现连续回缩/伸回。
4. 只靠近机关、不发生受击：观察锤头从相机附近经过以及玩家靠近墙体时，区分“镜头距离跳变”和“模型铺满屏幕”。
5. 波动帧率：正常帧率通过后再用短时间低帧率采样，确认子步与物理时间步限制没有引入更大的拖尾。

## 验收口径

- 房间中央受击时，不再出现明显逐帧来回跳动；一次连续物理位移可以被平滑跟随。
- 普通移动和相机旋转仍清晰可控；相机落后距离不会超过配置上限。
- 最终 `CameraLagMaxDistance` 不能只按“越稳越好”选择；若击飞时角色明显先走、相机随后拖拽追赶，应改用更小的对照值。
- 墙体碰撞保持开启，相机不能穿出地牢墙面。
- 贴墙时允许一次合理缩臂，但不能把“原生碰撞瞬时回缩仍存在”误报为第一版已彻底解决。
- 如果只靠近墙体仍发生连续抽动，留下复现位置和视频后进入第二阶段；如果只是锤头遮满画面，转为近距离淡出方案。

## 代码规模与后续方向

- 第一版：约 `2` 行 C++ 增量，`1` 个现有 Blueprint 的 `4` 项参数修改；不新增类和文件。
- 可选的“只在 HeavyImpact 期间启用位置延迟”：需要监听现有 `OnStateChanged`、保存并恢复 Blueprint 初始值，约增加 `20~40` 行，不放入第一版。
- 可选的“平滑离墙恢复”：需要自定义 SpringArm 并覆盖 UE 原生 `BlendLocations`，预计 `80~140` 行、`2` 个镜像 C++ 文件，不放入第一版。
- 可选的“锤体近距离淡出”：属于机关表现，不与相机位置修复混写。
