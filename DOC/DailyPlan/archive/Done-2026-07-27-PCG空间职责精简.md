## 1. 本轮目标

把当前 PCG 从“空间生成兼玩法流程”收敛为可独立复用的空间生成核心：

- PCG 只负责生成可行走 Grid、Start、Exit、中立房间和结构实例。
- 未来 GameFlow 再根据一局玩法规则向中立房间分配通关材料、奖励、陷阱和敌人。
- 不在玩法尚未确定时预埋 K-of-N、CollectAll、多 Flow 或 Objective 绕行逻辑。
- 保留已经验证的完整 WFC、全局约束与回溯，不退回固定路线或第二套生成器。
- 以删除旧职责和重复数据为主，不新建抽象框架、兼容壳或备用算法。

## 2. 本轮明确不做

- 不实现室内光源。
- 不实现小地图。
- 不实现正式 GameFlow、材料收集、奖励、陷阱或敌人分配。
- 不实现追猎者导航。
- 不修改第三方 HydroLab 素材或 Presentation Profile。
- 不修改 `Level0`、追猎者、Physics、`Demo.Build.cs`。
- 不删除 Runtime Test Harness；正式 GameFlow 尚未接管生成与出生流程前，它仍是必要的独立 PIE 验收边界。

光源和小地图必须等本轮删改完成、构建与 PCG 回归通过后再分别讨论，不借本轮顺手扩展。

## 3. 保留的空间 PCG 核心

以下能力原样保留或只做接口收窄：

1. 16 种 `OpeningMask` 的 Simple-Tiled WFC。
2. 局部邻接传播与带权 Shannon 熵观察。
3. `Count`、`MaxConsecutive`、`Connected` 三项全局约束。
4. 有界 chronological backtracking、确定性有限重试和总预算。
5. Start、Exit 和固定数量的中立 2×2 房间占格。
6. 房间内部必开边；房间外部入口、转弯、T 字、十字和环路继续由 WFC 决定。
7. 同一 Seed、Difficulty、算法版本和 Profile 版本的确定性复现。
8. Start 到 Exit 的逻辑最短距离上限。
9. 纯数据 Plan 到五类结构 HISM 的事务式提交和失败回滚。
10. Start、Exit 和中立房间的稳定世界 Transform 查询。

## 4. 删除的玩法职责和重复数据

### 4.1 公共契约

删除：

- `EZeroEscapeCompletionRule` 的 `EscapeOnly / CollectAll / CollectKOfN` 玩法分支。
- `EZeroEscapeGameplayAnchorType`、Objective/Gameplay/Landmark 三套重复 Binding。
- `ObjectiveCandidateCount`、`RequiredObjectiveCount` 和相关 K/N 错误码。
- `CanonicalProgressionHash`、`FlowVersion` 及 Plan 中的玩法完成字段。
- 只服务旧玩法链的细碎 Metrics 和日志字段。

替换为一套中立输出：

- `FZeroEscapeGenerationRequest` 只包含 `Seed` 和 `Difficulty`。
- `FZeroEscapeGeneratedRoom` 只包含 `RegionId`、`AnchorCoordinate`、`LocalTransform`。
- `FZeroEscapeGeneratedLevelPlan` 只包含 Signature、单一 Layout Hash、Cells、Start/Exit、Rooms 和 Junction Metrics。

### 4.2 配置与解析

删除：

- `FlowProfileId`、Flow 配置数组与 Flow 解析。
- 难度中的 N/K 和 Objective 数量。
- `ObjectiveProgressBandCount` 的玩法命名。
- `MaxRequiredRouteExtraTiles`。
- Snapshot → Progression Settings → Progression Intent 的多段复制链。
- Objective Selection 随机域与 Progression Hash。

替换为：

- Profile 共享 `RoomCount=3`，不随难度增加房间数，避免困难模式显著延长单局。
- Difficulty 当前只选择 WFC 形态权重。
- 一次 `ResolveGenerationInput` 产生 Signature、共享空间规则和该难度的 WFC 权重。
- `AlgorithmVersion` 与 `ProfileVersion` 从 4 更新为 5，明确标记确定性契约改变。

### 4.3 Grid 与最终验收

删除：

- `FGridLayoutRequest` 与重复的 `FGridLayoutSettings`。
- Progression Landmark/Intent 解析和 Stable Objective Id 链。
- K-of-N bitmask DP。
- CollectAll/K-of-N 的目标绕行与额外折返验收。
- Count、MaxConsecutive、开口对称和第二套 Connected 的重复生产复核。

保留一遍最终 BFS：

- 验证所有非空 Cell 均可从 Start 到达。
- 验证 Exit 可达。
- 验证 Start→Exit 逻辑最短距离不超过 `MaxRequiredRouteLengthTiles`。
- 验证生成的中立房间数等于 Profile 的 `RoomCount`。

Count、MaxConsecutive、OpeningMask 对称和 Connected 继续由 WFC 约束负责，并由专项 Automation 防回归，不在生产管线重复实现第二遍算法。

## 6. 目标接口

### 6.1 当前 Seed 调整

生成器 Details 直接展开 `DefaultRequest.Seed` 和 `DefaultRequest.Difficulty`，用于当前 PIE 快速换 Seed；不增加第二个 Seed 状态。

Blueprint 或未来菜单 UI 使用同一入口：

```text
Make ZeroEscapeGenerationRequest(Seed, Difficulty)
    -> GenerateFromRequest(Request)
```

独立测试关卡继续使用：

```text
Make ZeroEscapeGenerationRequest(Seed, Difficulty)
    -> TestHarness.RegenerateFromRequest(Request)
```

### 6.2 内容层入口

Runtime Generator 只公开：

- `GetGeneratedStartWorldTransform`
- `GetGeneratedExitWorldTransform`
- `GetGeneratedRoomWorldTransforms`

未来玩法层从 `Rooms` 选择内容落点，但不反向修改 WFC 拓扑。
