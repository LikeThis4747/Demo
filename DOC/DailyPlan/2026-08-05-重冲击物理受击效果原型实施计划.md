> 状态：2026-08-05 用户已明确授权完整实现与构建；官方 UE5.8 MCP 已在线，B 稿已按 `2026-08-05c` 审阅修订为 v1.1。当前正在执行首次功能落盘前的完整 Git 基线 commit、内部工蜂 push 与远端核验门禁；门禁通过前不修改功能代码或资产。

## 1. 结论与完成边界

本轮实现“短时全身受控物理接管”：Chaos 决定角色整体位移、空中运动和环境二次碰撞；Physics Control 只用有最大扭矩上限的父级空间角驱动维持人体张力，不使用把身体钉回 Capsule 的世界空间位置驱动，也不让大幅受击蒙太奇主导画面。

追猎者是第一个外部观察和调参对象，但不是原型完成边界。**同一轮原型必须紧接着接入玩家**，并验证骨盆—胶囊—相机跟随、输入锁定、磁力释放和完整状态恢复；只有 AI 和玩家都通过，才可称为共享重冲击原型。

本轮完成条件：

1. 追猎者在空地和靠墙场景中出现清楚可辨的全身击飞与不同二次碰撞结果。
2. 玩家使用同一共享组件和输入合同完成击飞，身体不离开镜头，Camera 不继承 ragdoll 翻滚，磁力与输入状态能正确恢复。
3. 两个角色的普通移动、玩家磁力和追猎者追逐/攻击不发生非重击回归；现有追猎者局部受击源码、调参资产、蒙太奇字段和回调完整保留，原型期只暂停三处运行时装配，不让两套系统同时写同一个 Physics Control。
4. 每个代码增量独立形成受限 diff、构建/自动化、UE 资产回读和 PIE 证据包；随后暂停实施，交由另一位 AI 做代码增量审计。
5. 身体必须保留真实击飞后的倒地位置，禁止返回受击前位置。起身资产未接入前可以停在 Downed 供效果验收；用户提供起身动画后，在同一最终落点完成 Capsule/动画恢复。

## 3. 范围与非目标

### 3.1 本轮范围

- 一个玩家/AI 共用的重冲击输入结构与状态组件。
- 每套 Physics Asset 独立的 `UPhysicsControlAsset` 和重冲击调参 DataAsset；两边使用相同 Profile/Set 语义。
- 追猎者完整的预接管、真实物理接触、AI 停止、环境碰撞和最终落点 Downed/Recovery。
- 玩家完整的预接管、真实物理接触、骨盆跟随、相机稳定、输入/磁力中断和最终落点恢复。
- 为摆锤、冲锤和其他重物保留同一调用入口；本计划不接管另一会话的摆锤 Actor 或 PCG 放置代码。

### 3.2 本轮非目标

- 物理击飞标定阶段不制作、搜索或购买新受击动画；用户可另行提供起身动画。恢复增量是否需要 Pose Snapshot 或最小 AnimBP 接线，须在资产到位后单独展示代码/资产预览，不在物理核心中暗改。
- 不实现死亡、生命值结算、完整翻身系统、远距离导航传送或长期主动布娃娃；起身只围绕真实倒地点做最小恢复桥。
- 不修改第三方 Skeleton、Skeletal Mesh 或原始 Physics Asset。
- 不修改 `Content/Assets/**`、`Content/SciFITrooper_Man_03/**`、`Content/Sci_Fi_Character_08/**`。
- 不实现摆锤/冲锤 Actor，不修改 PCG/WFC/Population；只冻结接口和净空要求。
- 不新增永久 Tick、GAS、联机预测、全局物理设置或通用物理框架。

## 4. 共享运行时设计

以下类型与 Profile 名称均为项目拟命名，不是 UE 官方概念。

### 4.1 唯一状态管理者

`UHeavyImpactResponseComponent` 是重冲击和该 Character 上 Physics Control 的唯一权威，状态建议为：

`Inactive → Prepared → Simulating → Settling → Downed → Recovering → Inactive`

- `Prepared` 表示机关已预测即将接触：角色全身已经 Simulated，但尚未收到锤头真实接触；短超时未命中则原地无副作用恢复。
- `Simulating/Settling` 由 Chaos 真实动量、环境碰撞和稳定判断驱动；`Downed` 保留实际落点，不自动回传。
- Character、AI Controller、磁力组件和机关只读取状态或响应 Delegate，不写 Physics Control 内部状态。
- 组件平时关闭 Tick；只在 `Prepared/Simulating/Settling` 启用 PostPhysics Tick，用于预接管超时、骨盆跟随、速度/落地采样和恢复判断。`Downed` 睡眠后共享组件与 PhysicsControl 都关闭 Tick；新的真实 Mesh Hit 由 Chaos 先传递动量，再唤回 `Simulating`，不补人工冲量。
- 旧 `UPhysicsControlHitResponseComponent` 首版不再创建另一套 Control/Modifier；只暂停角色侧三处运行时接线，其源码、DataAsset、成员和回调全部原样保留，后续轻冲击再决定是否重构进本权威模块。
- `EndPlay`、Owner 销毁、配置失败、PIE 停止和安全超时都必须走幂等清理；只有未发生接触的 `Prepared` 可以回到预接管位置/姿态，真实受击后不得回到受击前位置。

### 4.2 共享输入

B 路线不再把“碰撞后补一次冲量”作为 V1。拟冻结的输入改为 `FHeavyImpactPreparationRequest`（项目拟命名，不是 UE 官方类型），至少包含：

- 一次摆动/冲撞的非零 `ImpactId`；同一摆多次 Overlap/Hit 共用同一 ID。
- 预期真正接触角色的 Source Actor 与 Source Primitive Component。
- 来源当前世界速度、预测接触点/方向和预计接触时间；只用于筛选预接管与调试，不由角色重新计算一份替代冲量。
- 很短的准备超时；未发生期望接触时由接收端原地取消 Prepared。

摆锤/冲锤的近距离前置体积只调用项目接口 `IHeavyImpactReceiver::PrepareForHeavyImpact`。接收端在 Prepared 期间监听自己 Mesh 的真实 `OnComponentHit`：只有命中来源与请求中的 Source Component/Actor 匹配时，才把本次 ImpactId 从 Prepared 提交为 Simulating。这样机关不需要第二次操作角色内部状态，实际冲量也只来自 Chaos 接触求解。

- 玩家和追猎者实现同一接口，只转交给权威 `UHeavyImpactResponseComponent`。
- 接口返回 `Accepted / Duplicate / Busy / Invalid`；Busy 时机关继续自身运动，不得隐藏回退到 A、`LaunchCharacter` 或直接操作 Mesh。
- 预测接触失败是可见的集成错误：Prepared 超时并恢复，不在 OnHit 后再补人工冲量掩盖时序问题。
- Light/普通局部受击不塞进首版 B 合同；重击成立后再把它作为同一权威组件的轻冲击 Profile/局部区域能力重构。
- 该准备合同在正式 B 代码预览、官方 MCP 复核和双方 review 后才冻结；当前旧 `FHeavyImpactRequest` 代码稿不再是 V1。

### 4.3 物理接管

1. 前置体积预测即将命中后，接收端快照 Mesh 附着/Transform、动画、碰撞、CCD、CharacterMovement、Capsule 和输入相关状态。
2. 进入 Prepared：停止 CharacterMovement/AI；Capsule 改为 QueryOnly，Mesh 保持世界姿势脱离 Capsule、临时切为 `PhysicsBody + QueryAndPhysics` 并冻结当前动画目标。玩家只在指定锤体真实 Hit、状态提交为 Simulating 时释放磁力，预测误报不应导致丢物。
3. 通过角色专属官方 PCA 创建/启用全身 Body Modifier 与 `Prepared` Profile，在锤头真实接触前把 Physics Asset 中的全身刚体切为 Simulated。Prepared 只允许极短窗口，不能靠长期世界位置控制把身体钉住。
4. 锤头与已经 Simulated 的人体刚体由 Chaos 直接碰撞；锤的减速/偏转与人的线速度、角速度来自同一次求解，接收端不调用 `AddImpulse` 补第二份力量。
5. 权威组件从 Mesh Hit 匹配期望 Source，切换到 `Flight` Profile 与 Simulating；空中初版可使用恒定有限 Parent-space 角驱动，所有驱动都有最大扭矩上限且无世界位置拉回。
6. 环境碰撞继续改变轨迹和姿势。手部是否关闭环境碰撞只在官方 MCP 回读和真实 A/B 后决定，不先写死。
7. 目标误差、角速度或控制能量超过安全阈值时切换 `FreeFallback`，关闭姿势驱动而不是用更大力矩硬拉。
8. pelvis 线速度、角速度和地面接触连续满足稳定窗口后进入 Settling/Downed；Actor/Capsule 的最终 XY 来自真实骨盆，Z 使用地面命中高度 + Capsule 半高，并对墙、坡面、台阶和角落做安全放置/扫掠验证，绝不使用受击前 Transform。
9. PCA/Profile 从首版预留 `Prepared / Flight / Landing-Recovery` 三段；首轮可以让 Flight 保持一组常量，后续只增加 Profile 切换或强度包络，不改变 B 输入合同。

### 4.4 玩家/AI 共同与差异

- 共同：预接管、官方 PCA Profile、真实 Chaos 接触、环境碰撞、稳定检测、最终落点和调试记录。
- 追猎者：AI Controller 读取重击状态后停止移动/攻击；Downed 后只有在最终落点完成 Capsule/起身恢复才重新追逐。落点若不适合站立，只允许附近小范围安全修正。
- 玩家：物理期间 Capsule 保持直立且不阻挡模拟身体；其位置以经过滤波的 pelvis 为目标，Actor 不继承 pelvis 的 Pitch/Roll。Spring Arm/Camera 继续跟随直立 Actor，因此不随身体翻滚。
- 玩家输入：Move/Jump/Grab/Throw 在重击期间无副作用；当前 `JumpAction Started` 必须从直接绑定 `ACharacter::Jump` 改为项目入口 `AZeroEscapeCharacter::TryJump`，Completed/Canceled 仍保留 `StopJumping`。已有持有物必须通过磁力组件的明确“外部中断释放”入口释放，结束后只有原输入状态允许时才恢复。
- 起身动画未到位时，AI 与玩家可以停留在真实 Downed 位置供物理效果验收；用户提供动画后，再选择 Pose Snapshot/物理到动画混合方案。无论采用哪种恢复，均不得回到受击前位置。

## 5. 增量实施顺序

### Increment 0：共享类型、配置与无表现基础

- 新增 B 路线准备请求、只面向 Actor 的预接管接口、`Prepared/Simulating/Downed/Recovering` 状态、配置校验和共享组件骨架。
- 以每套角色独立的官方 `UPhysicsControlAsset` 为控制配置来源；少量项目 DataAsset 只保存预接管、稳定、相机和恢复阈值。
- 建立自动化测试：非法准备请求拒绝、重复 ImpactId 去重、拒绝日志限频但不阻止同一 ID 稍后重试、非预期 Source Hit 不提交、Prepared 超时原地恢复、幂等清理和硬安全超时。
- 门槛：完整构建和测试通过；未接入任何角色时，PIE 行为与基线一致。

### Increment 1：追猎者可视标定

- 追猎者装配共享组件并复用唯一 `UPhysicsControlComponent`。
- 首版只成组暂停旧局部受击的三处运行时装配：默认子对象构造、`Configure`、`OnPhysicsHit.AddDynamic`。旧组件源码、Tuning Data/资产、指针、三方向蒙太奇字段、回调和 `bIsReacting` 全部保留；精确代码与恢复顺序以 B 稿第 13 节为 Git 之外的第二份保险。
- 与摆锤任务在冻结的预接管接口上做一次串行集成：前置体积先 Prepare，锤头随后直接撞已 Simulated 身体。官方 MCP 用于配置、回读、PIE 控制和证据采集，不用“直接提交冲量”替代真实接触。
- 场景：空地侧撞、靠墙侧撞、斜向上撞；每组对比自由 ragdoll、官方 PCA 受控物理和旧局部受击的基线录像/独立运行，不让两套组件同时写身体。
- 门槛：整体位移和环境差异清楚；受控版明显减少尸体感；无颈部爆转、穿透、持续抖动或手部挂墙。

### Increment 2：玩家必须接入

- 玩家装配同一共享组件和独立角色 Profile。
- 完成 pelvis—Capsule—Camera 桥、输入锁定、磁力强制释放、UnPossessed/关卡退出恢复。
- 使用与追猎者相同的物理锤头速度、质量和场景，不因玩家身份改用人工冲量、动画或 Character Launch 伪造结果。
- 门槛：玩家始终处于可观察镜头范围；Camera 不继承翻滚；空地/靠墙结果不同；Downed 保留最终落点。起身资产接入后，移动、跳跃、磁力和相机必须在该落点恢复。
- **Increment 2 未通过时，本原型不得标记为完成，也不得先转去扩展摆锤或 PCG。**

### Increment 3：玩家/AI 最终落点恢复与机关合同收口

- 与摆锤任务只对接 `IHeavyImpactReceiver` 和 B 路线准备请求；不得让机关直接操作 Mesh、Capsule、AI 或玩家输入。
- 验证同一预接管接口能分别作用于 AI 和玩家，并通过 ImpactId 去除前置体积/多刚体重复回调；角色 Mesh 自己确认期望 Source 的真实 Hit。
- 任何真实接触发生时角色若仍为 Kinematic，都判为预接管集成失败；不得在碰撞后补人工冲量掩盖。
- 用户提供起身动画后，在真实倒地点完成朝上/朝下判断、附近安全 Capsule 放置和物理到动画恢复；无动画时明确停在 Downed，不回原点。
- PCG 后续投放必须保留飞行/落地区域净空、机关扫掠空间与恢复安全区；本增量不修改 PCG 代码或 DataAsset。

### 7.2 并行执行方式

- **同一工作树并行**：只允许编辑完全不重叠的文件。每次落盘前后都记录 HEAD、`git status --short` 和本任务白名单；发现白名单外文件在操作期间变化，立即停在当前增量，不覆盖、不自动合并。
- **独立 Git worktree/分支**：若多个机关确实同时写 C++，这是更安全的方式，但创建分支、提交或集成必须另行获得用户授权并遵守内部 Git 规范。本 Plan 不擅自创建 worktree、分支或提交。
- 独立 worktree 只隔离文本和构建目录，**不能让同一个 UE Editor 进程安全地并行写两套资产**。Blueprint、DataAsset、Physics Control Asset 和关卡写入仍要串行分配“Editor 资产写入窗口”。
- 同一工程内的完整构建、Live Coding、自动化、PIE 和资产保存全部串行执行；不让两个会话同时驱动 Editor、覆盖日志或争用编译产物。
- UE 资产只保存本任务明确拥有的 Package，不使用 Save All。若 Editor 因引用链把白名单外 Package 标脏，先取消该 Package 的保存并报告，不把它纳入本任务改动。

### 7.3 合同冻结与集成门禁

1. Increment 0 先完成 V1 请求、结果和接收接口的代码预览、授权、构建与审计；在此之前，其他机关只能按文档做适配预留，不能复制临时接口。
2. 合同冻结后，摆锤/冲锤只需在近距离前置体积构造准备请求并处理返回结果；锤头真实碰撞保持纯物理。机关可以在角色效果尚未完成时用 `Busy/Invalid` 路径独立验证运动、碰撞和 PCG 放置。
3. 两边各自在自己的文件白名单内通过后，再进入单独的集成窗口；集成者只连接已有接口，不同时重构机关和受击内部实现。
4. 优先做向后兼容的字段新增，并给出明确默认值；改预测时间、坐标空间、Source Collider 或 ImpactId 生命周期属于破坏性变更，必须重新审计两个模块。
5. 集成 PIE 必须证明锤头接触前角色 Body 已为 Simulated，且同一次接触只有 Chaos 一份动量；代码中不得存在 OnHit 后补 `AddImpulse` 的隐藏兼容路径。

### 7.4 主要并行风险

| 风险 | 可能后果 | 预防/处理 |
|---|---|---|
| V1 合同频繁变化 | 所有机关反复改代码，测试结论失效 | 先冻结最小字段；破坏性变更统一停工和复审 |
| 两个任务同时改 Character 或局部受击组件 | 文本冲突、恢复路径互相覆盖 | 这些文件只归重冲击任务，机关只调接口 |

## 8. 分增量回退策略

### 8.1 回退基线

每个 Increment 开始前保存一份只读清单：当前 HEAD、`git status --short`、本增量文件白名单、文本 diff，以及所有待写 `.uasset` 的 Package 路径、引用、关键语义属性、编译状态和文件哈希。开始后新增的文件与资产单独列为 `CreatedByThisIncrement`。

这份清单既是给另一位审计 AI 的证据，也是回退边界；它不等于创建审计报告，也不授权提交 Git。

本 Plan 当前不创建提交或推送。用户明确授权实现后、Increment 0 首次功能落盘前，必须按项目工作规范把当前全部已确认改动形成一次完整基线 commit，确认工作区干净，将该提交成功 push 到内部工蜂并核验远端分支已包含该哈希；这是强制实现门禁。若用户另外授权后续 Git 检查点，建议每个 Increment 在审计通过后只暂存自己的白名单文件并形成一个窄提交；集成分支可回退该增量提交，但遇到同一文件/资产已有后续修改时仍须先检查冲突，不能把 `revert` 当作无条件安全。

### 8.2 先停用，再做文本代码回退

- 共享接口必须支持安全拒绝：组件未激活、配置无效或效果被临时停用时，角色适配返回 `Ignored`，机关自身继续运行。这是出现回归时的第一道止血措施，不等于最终回退。
- 已有机关依赖 V1 合同时，优先保留稳定接口并停用接收端，不立即删除公共 Header；这样其他机关仍可编译和独立验收。
- 追猎者旧受击回退不依赖从 Git 猜代码：B 稿第 13 节逐字保存被暂停的构造、`Configure` 与 Delegate 绑定，并列出保留文件、资产、成员和恢复顺序；恢复时必须先撤掉 HeavyImpact 运行装配，再整体恢复旧三处接线。

- 不使用 `git reset --hard`、整工作树 `stash`、目录级 checkout 或任何覆盖另一会话改动的命令。
- 修改现有文件时，只反向应用由本 Increment 产生的精确 hunk。若同一段代码在本增量后又被别的任务修改，停止自动回退，保留双方 diff，由用户指定集成者人工处理。
- 新增 C++ 文件只有在确认路径属于 `CreatedByThisIncrement`、没有其他模块引用且移除后可构建时，才作为整体回退；目标路径必须逐个核对，不使用通配删除。
- 接口已被其他机关采用后，不直接删除或改回旧签名；先提供兼容层或先回退依赖方，再回退合同，保持依赖顺序与构建可用。

### 8.3 UE 二进制资产回退

- `.uasset` 不尝试三方文本合并。写入前必须确认唯一 Owner；若同一资产在本窗口外被修改，停止整包恢复。
- 本任务新建的 PCA/DA 可作为独立回退单元，但删除前先做引用审计并取得用户对资产删除的明确许可；通过 UE 资产操作删除，不直接在文件系统中移除。
- 对既有 `BP_ZeroEscapeCharacter` / `BP_Pursuer`，优先按写入前的官方 MCP 语义快照逐项撤销本任务新增组件和属性。只有能证明自基线后没有其他模块写入时，才考虑恢复整个 Package。
- Level0 和机关 Blueprint 不属于本任务，因此本任务回退绝不恢复或删除它们；反过来，机关任务也不得用整包恢复角色 Blueprint。

### 8.4 各 Increment 的回退顺序

| Increment | 回退顺序 | 不得连带回退 |
|---|---|---|
| 0 共享合同/骨架 | 无下游依赖时按“测试 → 组件 → 配置 → 接口/类型”逆序移除；已有机关依赖时保留 V1 Header，仅让接收端返回 `Ignored` | 摆锤/冲锤自身代码、PCG |

### 8.5 回退后的最低验证

每次回退仍需重新执行白名单检查、完整构建、相关自动化、资产回读和最小 PIE 冒烟，证明项目回到了“可编译、可打开、原功能可用”的状态；不能以 diff 变小代替回退成功。若回退失败或出现交织修改，保留现场并立即报告，不继续扩大修改范围。

## 9. 代码增量审计交付边界

### 9.1 职责边界

- 审计 AI 的报告路径、格式、结论和是否允许继续由该 AI 与用户决定；收到意见后，本任务只处理用户确认需要修正的项。

### 9.2 每个增量提交给审计 AI 的材料

1. 当前 HEAD、增量开始前的 `git status --short` 和本 Increment 文件白名单。

4. 已知风险、未验证项和明确回退边界；不得把实现 AI 的自检写成独立审计结论。

### 9.3 每个增量开始前

1. 记录 `git status --short`、`git diff --name-status` 和当前 HEAD。
2. 确认 `Source/**`、`Content/**` 中不存在其他会话的重叠修改；发现重叠立即报告。
3. 为涉及的 Blueprint/DataAsset/Physics Control Asset 通过官方 MCP 保存父类、组件、关键属性、引用和编译状态的只读基线。
4. 对照本 Plan 的当前 Increment 文件白名单；不允许“顺手”修改后续增量或无关文件。

### 9.4 建议审计 AI 重点检查的代码问题

- 状态是否只有 `UHeavyImpactResponseComponent` 写入，Character/AI 是否只是适配。
- 所有失败、超时、EndPlay、UnPossessed 路径是否恢复 Mesh 附着、碰撞、动画、CCD、Capsule、Movement、Controller 与磁力状态。

### 9.6 PIE 验收矩阵

追猎者和玩家分别覆盖：

- 空地左/右侧重击、正面斜向上重击。
- 距墙约一个身位的相同重击，验证墙面改变旋转/落地结果。
- 连续两次不同碰撞 ID、同一碰撞 ID 重复回调、恢复过程中再次命中。

玩家额外覆盖：

- 持有磁性物、吸取途中和空手三种状态。

- 在真实倒地点完成起身后，移动、跳跃、相机、磁力、暂停/退出和重新开始均恢复。
