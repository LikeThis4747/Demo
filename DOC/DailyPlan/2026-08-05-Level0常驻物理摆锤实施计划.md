# 2026-08-05 Level0 常驻物理摆锤实施计划

> 状态：2026-08-05 已完成 C++、资产、Level0 独立高厅装配与 PIE 验证，V1 已获用户验收。后续策划方向调整为“初始静止、玩家磁力蓄能并释放”，尚未改造；暂不接入 PCG，玩家/追猎者受击由另一任务负责。

## 目标与完成边界

本计划记录已经完成的 V1：读取 `/Game/Levels/Level0` 的既有高厅配方后，在关卡空白区重搭一间独立测试高厅，并实现一个始终运行的物理摆锤。Chaos 负责重力、约束、碰撞和动量交换；机关只在穿过最低点且速度不足时施加有限补能。模拟刚体无须标签、质量或速度门槛即可改变摆锤的摆幅、相位和有限侧摆。

V1 验收后确定的 V2 方向不追溯修改本计划的历史实施步骤：摆锤初始静止，玩家以磁力牵引并在松开后启动自由摆动，玩家与追猎者都可能受击。V2 需另行讨论衰减/补能、复位、重复使用和磁力接口，再经代码预览与授权落盘。

本轮完成边界：

1. C++、DataAsset、Blueprint 和一个 Level0 实例形成最小可玩闭环；
2. 显式关闭 UE 5.8 Twist/Cone 默认 Soft Constraint，使用 23° 主轴硬角限位；
3. 先以补能 0 测量 3 分钟自由摆损失，再填写只覆盖被动损失的最小补速；
4. 完成构建、蓝图编译/保存、资产回读、PIE 和用户手感验收；
5. 不接入 PCG，不在摆锤内复制角色受击逻辑，不修改第三方素材。

## 验证与停止条件

- C++ 完整构建成功，新增蓝图为 UpToDate，DataAsset 数值和父类字段经官方 MCP 回读一致。
- 无干扰时补能后运行 3 分钟不逐步耗停、不过度增能；反向碰撞的减速至少保留到下一次完整摆动。
- 高能撞击下允许有限求解误差，但锤头不得接触墙面或地面；若 24.5 cm 净距不足，先报告并调整几何/摆幅，不增加隐藏纠偏力。
- 若同帧 `TeleportPhysics` 未形成 18° 初始释放，只在实测失败后改为下一物理帧释放。
- 若构建被 Live Coding 占用，直接请用户关闭 Live Coding 或编辑器，不写绕行脚本。
- 若官方 UE MCP 连接失败，立即停止 Blueprint/DataAsset/Level0 写入，由用户决定重连或允许本地 MCP 兜底。

- `DemoEditor Win64 Development` 完整构建成功；四个新增 C++ 文件合计 683 个物理行，拟实现代码的 451 行非空非纯注释规模未增加额外绕行框架。

- 摆锤位于 `(52000,30300,0)`、Yaw `90°`；18° 目标摆幅下侧墙余量约 69 cm，23° 硬限位下约 25 cm。
- 补能 0 时中线速度从 `213.57` 逐次衰减到 `151.37 cm/s`；按每半摆约 `13–18.5 cm/s` 的被动损失，将 Level0 DataAsset 单次补能上限标定为 `20 cm/s`。
- 补能版本稳定样本主要为当前 `203–209 cm/s`、单次补 `13–19 cm/s`；接近目标时自动降到 `4.8–9.1 cm/s`，没有角度伺服或超目标刹车。
- 20 kg 现有磁性箱在最低点碰撞后位移约 76 cm、旋转约 8°；摆锤首个中线速度降到 `164.81 cm/s`，本次只补 `20 cm/s`，证明真实碰撞可改变轨迹且不会一次恢复。测试箱最终放回南侧入口供人工投掷。
- 2026-08-05 用户确认当前摆锤方案验收通过；该结论只覆盖 V1 技术原型，不代表 V2 磁力玩法、双方受击或 PCG 投放已经完成。
