## 已确认玩法规则

1. 玩家持有磁力物时只有“普通”和“爆裂”两种可操作状态；新抓取默认普通。
2. 普通状态按 `E`：剩余次数大于 0 时切换为爆裂状态，但不扣次数。
3. 爆裂状态激活满 1 秒后再次按 `E`：恢复普通状态，不扣次数；不足 1 秒的重复输入忽略。该 1 秒只限制取消，不限制立即投掷。
4. 普通状态正式投掷完全沿用现有行为，不扣次数，也不改变现有 Light、破碎阈值和普通碎片速度。
5. 爆裂状态正式投掷成功建立投掷事务后扣 1 次；普通放下、强制释放或 Heavy 打断均取消爆裂状态且不扣次数。
6. 已投出的爆裂物在有效时间内第一次合格 Blocking Hit 爆炸；未命中、超时或命中前被重新抓取均不爆炸，已扣次数不返还。
7. 爆炸对范围内玩家与追猎者使用相同距离衰减：提交径向 Heavy Impact 并结算一次伤害。Heavy 已处于任意阶段时仍接受新的爆炸冲量，但不得重建或覆盖当前唯一恢复基线。
8. 爆裂碰撞不再向直接命中角色叠加普通 Light；同一次命中仍可触发现有破碎替换。
9. 爆裂破碎绕过普通 `MinimumBreakNormalImpulse`，碎片分离速度使用 DA 倍率；普通投掷路径保持原值。
10. 首版不制作红光、Niagara、音效、HUD、光球、死亡流程、墙体遮挡衰减、碎片二次伤害或连锁爆炸；只预留爆裂状态变化事件供后续红光表现绑定。

## 径向 Heavy 对现有状态的处理

`IsBusy()` 只表示角色当前正被 Heavy 状态机接管，不表示爆炸免疫。径向入口不使用统一 Busy 拒绝，而按当前状态复用同一份 `RecoveryBaseline`：

| 当前状态 | 径向爆炸处理 |
|---|---|
| `Inactive` | 同步释放 Light 的局部身体写入，捕获唯一恢复基线，进入径向 Prepared；至少跨过一个完整帧后切到 Flight 并施加速度改变量 |
| `Prepared` | 不再次捕获身体、不覆盖 `ActiveRequest` 或预期真实接触源；只排队爆炸速度改变量。跨帧后把现有 Prepared 推进到物理飞行，原来源稍后发生的真实接触仍可按原 `ImpactId` 提交一次 |
| `Simulating` | 保持现有恢复基线，唤醒刚体、重置判稳累计并追加速度改变量 |
| `Settling` | 切回 Flight/`Simulating`，重置判稳累计并追加速度改变量，避免刚被炸起又立即判定倒地 |
| `Downed` | 取消睡眠/起身重试，唤醒刚体，切回 Flight/`Simulating` 后追加速度改变量 |
| `Recovering` | 复用现有安全恢复收尾并停止 Montage，再在同一次调用中从当前可玩身体建立新的径向 Heavy；内部同步经过 `Inactive -> Prepared`，中间没有渲染帧 |

- 不创建第二套 Heavy 状态机，也不保存第二份恢复快照；多次爆炸只是给当前物理身体追加新的速度改变量。
- 每个目标仍按爆炸 `ImpactId` 去重；同一爆炸不能因多组件 Overlap/Hit 重复加速，不同爆炸可以连续作用。
- 现有机关/追猎者使用的 `PrepareForImpact` 仍在非 `Inactive` 时返回 `Busy`，其预测、真实 Chaos 接触与 `OnImpactCommitted` 语义保持不变。
- 伤害与物理请求分别收口：只要目标属于本次范围查询，伤害结算一次；径向物理请求失败不得重复扣血或转交 Light。

## 实际采用的径向入口形状

为减少类型和校验层，径向入口不再新增请求结构体，只接收爆炸方已经算好的三个必要值：

```cpp
EHeavyImpactPrepareResult UHeavyImpactResponseComponent::RequestRadialImpact(
    const FGuid& ImpactId,
    AActor* SourceActor,
    const FVector& VelocityChange)
{
    if (HasSeenImpactId(ImpactId))
    {
        return EHeavyImpactPrepareResult::Duplicate;
    }

    if (!bInitialized || !ImpactId.IsValid() || !IsValid(SourceActor) ||
        !IsFinite(VelocityChange) || VelocityChange.IsNearlyZero())
    {
        return EHeavyImpactPrepareResult::Invalid;
    }

    switch (State)
    {
    case EHeavyImpactState::Inactive:
        if (!CaptureAndEnterPreparedForRadialImpact())
        {
            return EHeavyImpactPrepareResult::Invalid;
        }
        break;

    case EHeavyImpactState::Prepared:
    case EHeavyImpactState::Simulating:
        // 保留当前请求与 RecoveryBaseline；只追加待处理速度。
        break;

    case EHeavyImpactState::Settling:
    case EHeavyImpactState::Downed:
        ResumeExistingPhysicalResponse(SourceActor);
        break;

    case EHeavyImpactState::Recovering:
        CompleteRecoveryAndEnterNewRadialPrepared(SourceActor);
        break;
    }

    PendingRadialVelocityChange += VelocityChange;
    PendingRadialSourceActor = SourceActor;
    RecordRecentImpactId(ImpactId);
    SetComponentTickEnabled(true);
    return EHeavyImpactPrepareResult::Accepted;
}
```

```cpp
void UHeavyImpactResponseComponent::ApplyPendingRadialImpact()
{
    if (PendingRadialVelocityChange.IsNearlyZero())
    {
        return;
    }

    // Inactive 发起的径向 Prepared，以及正在等待原接触的 Prepared，
    // 都必须先跨过完整帧；原接触请求和恢复基线不被替换。
    if (State == EHeavyImpactState::Prepared)
    {
        if (GFrameCounter <= PreparedEntryFrame)
        {
            return;
        }
        PromotePreparedToFlightForRadialImpact();
    }

    if (State != EHeavyImpactState::Simulating ||
        !Mesh->IsSimulatingPhysics(Tuning->PelvisBone))
    {
        return;
    }

    Mesh->WakeAllRigidBodies();
    Mesh->AddImpulse(PendingRadialVelocityChange, Tuning->PelvisBone, true);
    PendingRadialVelocityChange = FVector::ZeroVector;
    TotalCommittedSeconds = 0.0f;
    StableElapsedSeconds = 0.0f;
}
```

实际代码只抽出接触式和径向入口共用的 `EnterPreparedPhysicalState`，并抽出 Downed 共用的唤醒函数；不增加 Actor、Component、Interface、新状态枚举或新的 Heavy 请求类型。

## 运行顺序

1. `E` 只把意图转发给 `UElectromagneticGrabComponent::ToggleExplosionMode()`。
2. 爆裂状态正式投掷时，组件先保留物体表现状态并走现有 `ReleaseHeldObject`，再调用扩展后的 `ArmThrownImpact`。
3. 只有 `ArmThrownImpact` 成功后才减少 `AvailableExplosionCharges`；失败则物体仍按普通物理速度飞出，但不扣次数、不爆炸。
4. 爆裂物第一次合格 Hit 生成一个 `ImpactId`，按 `ECC_Pawn` 做一次半径查询并按 Actor 去重。
5. 每个目标先计算距离衰减与有限随机速度改变量，再调用 `RequestRadialImpact`；随后通过 `UGameplayStatics::ApplyDamage` 结算一次同源伤害。
6. 径向 Heavy 请求按上表处理：Inactive 才捕获恢复基线；Prepared 保留原请求后排队；Simulating/Settling/Downed/Recovering 在同一基线上继续物理响应。所有待处理速度改变量只在全身物理以及 Flight 或明确物理 fallback 已有效时以 `bVelChange=true` 施加。
7. 同一次 Hit 广播给破碎组件；爆裂命中强制排队破碎并把 DA 倍率传给 `AMagneticFractureActor`。
8. 爆炸事务立即收口并清除武装与表现状态，后续 Hit 不再重复爆炸或提交 Light。
