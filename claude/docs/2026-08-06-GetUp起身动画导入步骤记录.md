### [教训] 不能因为"服务器清单里没列出"就断言 MCP 不可用
- 本会话 AI 两次向用户报告"官方 MCP 不可用"，理由是系统提供的 MCP 服务器清单里只有 `ue-editor-mcp` 和 `ue-editor-mcp-logs`，没有 `ue58-official-mcp`。
- 用户要求实际检查后发现：**端口 8000 正常监听（`Test-NetConnection` TcpTestSucceeded=True），`ue58-official-mcp` 配置存在且 `disabled:false`，`list_toolsets` 正常返回 20+ 工具集。官方 MCP 一直是可用的。**
- 根因：AI 只看清单没实际调用，违反了 `MCP/capability-notes/README.md` 里"实际调用验证（搜到不等于能用，必须实际调用一次）"的规则——这次是反向错误："清单里没看到就说不能用"。
- **规则补充：判断某个 MCP 是否可用，必须实际发起一次调用，不能只依据工具清单是否列出。清单可能不完整。**

### 官方 MCP 调用要点（本次实测）
- 必须走统一入口 `call_tool`，参数 `{toolset_name, tool_name, arguments}`。直接用全限定名（如 `editor_toolset.toolsets.skeletal_mesh.SkeletalMeshTools.get_skeleton`）当工具名调用会报 `Tool not found`。
- 资产引用 `refPath` **必须是完整对象路径** `/Game/Path/Asset.Asset`，只给包路径 `/Game/Path/Asset` 会报 `is not a valid object path`。
- `ObjectTools.get_properties` 的参数名是 `instance` + `properties`（不是 `object` + `property_names`）。
