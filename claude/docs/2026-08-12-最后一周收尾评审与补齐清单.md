## 0. 一句话结论

**项目现在是「一组高完成度的技术演示」，还不是「一个能玩的游戏」。**

PCG 整关生成、Chaos 重受击、物理机关这三块的深度已经超过一个三周 Demo 的要求；但把它们串起来实际游玩时会发现：

- 追猎者**打不疼玩家**（攻击零伤害）；
- 出口**开局就是开着的**（沿途目标/撤离封锁零实现）；
- 全程**没有一点声音、没有一个撞击特效、没有一次镜头抖动**；
- HUD **只有一个准星**，玩家不知道血量、不知道目标、不知道怎么操作；
- 花一周做的三套机关**一个都没进正式一局**。

答辩评委最直接感知的恰恰是上面这五条，而不是 WFC 求解器的回溯策略。所以最后一周的正确方向是**停止深挖物理，补齐游戏性最小闭环 + 表现层**。

## 2. P0 致命缺失（不补，游戏就不成立）

### P0-1 追猎者攻击完全不造成伤害 —— 追逐没有惩罚

**这是整个项目最大的空洞。** 玩家永远不会因为被追猎者打到而失败，追猎者实质上只是「会跟着你走的移动障碍」。策划案 2.5「被追猎者击倒则失败」这条失败条件根本不成立。

证据链：
- `Source/Demo/Private/AI/PursuerAIController.cpp:122-136`：进入 `AttackRange` 后只调用 `Pursuer->PlayAttackMontage()`；
- `Source/Demo/Private/Characters/PursuerCharacter.cpp:160`：`PlayAttackMontage()` 只同步加载并播放蒙太奇；
- 全项目 grep `AnimNotify` / `AttackHit` / `SphereOverlapActors`：**0 处攻击命中判定**；
- 官方 MCP 回读 `DA_Pursuer`：字段只有 `maxWalkSpeed / senseRadius / loseSightRadius / attackRange / attackCooldown / attackMontage / hitReact*`，**没有任何伤害或击退字段**；
- `TASK-20260811-001` 自己也记录了：「C++ 没有攻击命中 Sweep、伤害或冲击提交，`BP_Pursuer` 的 EventGraph/ConstructionScript 也为空，因此现状是攻击表现，不是真实攻击结算」。

当前玩家唯一会掉血的来源是地刺（`SpikeTrapHazard.cpp:250` 的 `UGameplayStatics::ApplyDamage`）。

> 顺带修正一处过期注释：`SpikeTrapHazard.cpp:252` 写「生命/结算系统尚未接入，ApplyDamage 暂无接收方」，但 `ZeroEscapeCharacter.cpp:63` 已创建 `HealthComponent` 并在 `BeginPlay` 绑定 `OnTakeAnyDamage`，地刺伤害实际是生效的。注释误导后续判断。

### P0-2 沿途目标 → 解除撤离封锁：零实现 —— PCG 生成的迷宫失去意义

出口一开局就可通过，玩家可以从 Start 直线跑到 Exit 结束一局。这直接摧毁三件事：
1. PCG 辛苦生成的支路、环路、资源分布**没有任何被使用的理由**；
2. 策划案要求的「一局 8~12 分钟」不成立，实测可能 1 分钟；
3. 「迫使玩家进入迷宫并使用物理能力」的设计意图为 0。

证据链：
- 全项目 grep `Objective` / `Collected` / `Lockdown` / `Unlock`：**0 命中**；
- `AZeroEscapeExitVolume` 只有 `Activate(WorldTransform)` 和 `bool bReached`，**没有 Locked/Unlocked 状态**；
- `EZeroEscapeRoundState` 只有 `InProgress / Won / Lost` 三态，GameState **无目标计数字段**；
- 胜利条件唯一来源：`AZeroEscapeGameMode::HandleExitReached()` ← ExitVolume Overlap。

这是策划案 2.5 第 5 步、4.1、4.2 三处都明确要求的内容，也是中期就该有的。

### P0-3 玩家投掷打不出「倒地」—— 物理对抗的收益层级缺失

策划案 2.3 的四级反馈表里，「中等→后退踉跄」「强力→倒地」目前都不存在。磁力投掷命中追猎者的实际效果只有 **Stop 0.60 秒 + 箱子破碎**。能触发 HeavyImpact（击飞+倒地+起身）的只有机关（摆锤等），**玩家自己怎么投都打不倒追猎者**。

也就是说，玩家的核心能力对核心敌人的最大收益是「让它停半秒」。这让「用物理对抗追猎者」这个卖点在实机演示里几乎看不出来。

### P0-4 零音效 / 零特效 / 零镜头反馈 —— 物理游戏最致命的表现缺口

- `Source/Demo` 全量 grep `USoundBase|UAudioComponent|PlaySoundAtLocation|UMetaSound`：**0 命中**
- `Source/Demo` 全量 grep `UNiagaraSystem|SpawnSystemAtLocation|UParticleSystem|CameraShake`：**0 命中**
- `Content` 下自制音效资产：**0 个**（唯一的 `*Cue*` 来自第三方 SciFiHydroLab 的水泡声）

一个以「物理力量感」为卖点的游戏，撞击没有声音、没有火花、没有镜头抖动。这项的**投入产出比是全项目最高的**：一天工作量能让整个 Demo 的观感提升一个档次。ENEMY_DESIGN 第 7 节自己也写了「声音应帮助玩家在遮挡和转角后判断距离与状态」。

### P0-5 HUD 只有准星 —— 玩家不知道血量、目标、操作

`AZeroEscapeHUD` 全类只做一件事：画一个四段圆弧准星（`DrawArc` + `DrawCenterDot`）。

缺失：血条、目标进度、追猎者威胁提示、抓取/投掷状态、操作教学。

而且有一个结构性障碍：`UHealthComponent` **只暴露 `OnHealthDepleted`（归零广播），没有 `OnHealthChanged` 也没有 `GetHealthPercent()`**，`CurrentHealth` 是 private。所以 HUD 现在**技术上拿不到血量**，补血条必须先给组件加委托/getter。

### P0-6 三套物理机关一个都没进正式一局 —— 一周投入零展示

官方 MCP 回读 `DA_Population_Default` 的 `Rules`，正式一局只会生成两类东西：

| ActorClass | oneEveryNCells | maxCount | 说明 |
|---|---|---|---|
| `BP_SpikeTrap` | 4 | 8 | 地刺 |
| `BP_MagneticProp` | 4 | 8 | 磁力箱 |

摆锤、周期冲锤、壁挂预判抛射**全部只存在于 Level0 测试关**。08-05 到 08-11 将近一周的机关工作，在正式游戏里玩家一个都看不到。

好消息：`AZeroEscapeGameplayPopulator` 是纯规则驱动的（`FZeroEscapePlacementRule{ActorClass, OneEveryNCells, MaxCount, LateralCount, LateralSpacing, bAvoidStartExitNeighbors, bStraightCorridorOnly, SpawnZOffsetCm}`），**加机关只需在 DataAsset 里加 Rule，不用改 C++**。这是全清单里性价比最高的一项。

### P0-7 正式一局的真实追猎者追逐从未被证明 —— 最高风险项

`activeContext.md` 与 `current-task.md` 连续多天记录：Level0 静态存在 `NavMeshBoundsVolume` / `RecastNavMesh`，但**最新 PIE 日志仍报 `Unable to find RecastNavMesh`**；正式一局（PCG 运行时生成 + 动态导航）里的真实跨层追逐**至今没有证据**。

如果 PCG 生成后 NavMesh 建不起来，追猎者就不会动，那么上面所有玩法补齐都是空的。**这一项必须最先验证，它是其他所有工作的前提。**

## 7. 需要用户裁决的三件事

1. 是否接受**砍掉冲撞重构与局部物理轻受击**，把 5 天全部投给「攻击伤害 + 目标链 + 音效特效 + HUD + 机关进局 + 打包」？
2. P0-3（投掷打出倒地）要做**完整 HeavyImpact 升级**，还是降级为**加长 Stop + 受击动画**？前者约半天且有与 Light 争抢身体控制权的风险，后者一小时且零风险。
3. 沿途目标的形式：**走过去 Overlap 自动激活**（最省，推荐）还是**按键交互 + 读条**（更有玩法感，多半天）？
