## 0. 本稿回答什么

这不是“用动画播一个受击”，也不是“撞到以后补一次 AddImpulse”的方案。

本稿采用已经确认的 B 路线：

1. 机关在真实接触前，用预测体积通知角色进入 `Prepared`。
2. 角色在 `Prepared` 阶段已经把 Skeletal Mesh 切成可模拟刚体，并由官方
   Physics Control Asset（以下简称 PCA，UE 官方资产类型）提供有限的姿态约束。
3. 摆锤/冲锤随后与角色刚体发生真实 Chaos 接触；动量来自这次接触本身。
4. 接触后的飞行、落地、翻滚由物理继续决定；系统只限制明显难看的姿态，
   不把角色钉回动画轨迹。
5. 角色和 Capsule 跟随落地后的骨盆位置，最终倒在真实落点；绝不回到受击前位置。

本文中的 `HeavyImpact`、`Prepared`、`Flight` 等名称都是**本项目拟定名称**，
不是 UE 官方术语。UE 官方能力是 Chaos 刚体、Physics Asset、Physics Control
Component 和 Physics Control Asset。

## 1. 官方 MCP 恢复后的实证结论

以下结论来自 2026-08-05 对当前资产的官方 UE5.8 MCP 读取，不是仅凭 C++ 推断：

| 项目 | 玩家 | 追猎者 | 对设计的影响 |
|---|---|---|---|
| 角色蓝图 | `BP_ZeroEscapeCharacter` | `BP_Pursuer` | 都是 Data Only，真实父类分别是项目 C++ 角色 |
| AnimBP | 官方 `ABP_Unarmed` | `ABP_Pursuer_Locomotion` | 第一版可以不改 AnimGraph |
| AnimGraph 尾部 | `DefaultSlot -> ControlRig IK -> Output` | `DefaultSlot -> Output` | 进入物理前暂停动画目标；玩家必须确保 IK 不继续拉扯物理姿态 |
| Mesh 默认碰撞 | `QueryOnly / CharacterMesh / Pawn` | 同左 | 当前不能直接承受摆锤的物理碰撞，必须由 Prepared 临时接管 |
| Mesh 刚体 Hit 通知 | 关闭 | 关闭 | Prepared 中打开，离开时按快照恢复 |
| Capsule | `QueryAndPhysics / Pawn` | 同左 | Prepared 后改成 QueryOnly，避免胶囊先挡住摆锤 |
| Physics Asset | 17 个主要身体 | 17 个主要身体 | 足以做首版全身原型，但约束质量仍需 PIE 验证 |
| PCA | 当前 `/Game` 没有项目 PCA | 当前没有 | 需要新建玩家、AI 各一个 PCA；不修改原 Physics Asset |
| 旧追猎者局部受击 | 无 | 存在 | 旧组件会手工补冲量且会清空全部控制，不能与新权威模块并存 |

玩家 Physics Asset 的 `neck_01 -> spine_03` 约束有自由扭转；追猎者头/上胸约束较硬。
它们都是首轮画面验收风险，但首版先不修改原 Physics Asset，以便把问题明确归因于
PCA 控制还是原始约束。

## 2. 关键碰撞桥接：为什么当前摆锤能真正撞飞 Mesh

当前并行摆锤草稿中的锤体碰撞意图是：

- Object Type：`PhysicsBody`
- `PhysicsBody = Block`
- `Pawn = Overlap`
- 开启 CCD

这恰好允许我们做一个很小、也容易回退的桥接：

```text
平时：
  Capsule(Pawn)       <- 摆锤 Overlap，用来提前预测
  CharacterMesh(Pawn) <- QueryOnly，不参与刚体接触

Prepared 后：
  Capsule(Pawn)              <- QueryOnly，不拦截锤体
  CharacterMesh(PhysicsBody) <- QueryAndPhysics，摆锤对 PhysicsBody=Block

真实接触：
  PendulumBob(PhysicsBody) <Block> CharacterMesh(PhysicsBody)
```

因此首版不需要新增自定义碰撞通道，也不需要把摆锤的 `Pawn` 响应改成 Block。

硬性契约：发起者传入的 `SourceComponent` 必须开启物理碰撞，并且对
`ECC_PhysicsBody` 是 `Block`；否则角色拒绝进入 Prepared，避免“看似准备好了，
实际锤体穿过人”的假成功。

## 3. 状态机及不可破坏的行为约束

```text
Inactive
   | 预测请求被接受
   v
Prepared --真实指定锤体命中--> Simulating --> Settling --> Downed
   |                               ^             |
   | 未发生指定接触（短超时）       +--再次失稳----+
   v
恢复进入 Prepared 前快照

Downed --以后接入起身动画--> Recovering --> Inactive
```

规则：

- 只有 `Prepared` 超时且**没有发生真实指定接触**时，才允许恢复进入 Prepared 前的位置。
- 一旦命中提交到 `Simulating`，禁止使用受击前 Transform。
- `OnComponentHit` 只负责确认“指定锤体已真实接触”；不调用 `AddImpulse`、
  `AddImpulseAtLocation` 或 `LaunchCharacter`。
- 飞行状态不依赖受击动画。PCA 只给有限角向控制，线性方向不拉回动画。
- 首版允许在 `Downed` 停住，等用户补起身动画后再实现 `Recovering`。
- PCA 调用失败时进入明确错误/自由物理兜底，不暗中退回旧 A 路线。

### `HeavyImpactTypes.cpp`

`IsStructurallyValid` 的拟实现：

```cpp
bool FHeavyImpactPreparationRequest::IsStructurallyValid(
    const AActor* Receiver,
    FString& OutReason) const
{
    if (!ImpactId.IsValid())
    {
        OutReason = TEXT("ImpactId is invalid.");
        return false;
    }

    if (!IsValid(SourceActor) || !IsValid(SourceComponent))
    {
        OutReason = TEXT("Source actor or component is invalid.");
        return false;
    }

    if (SourceComponent->GetOwner() != SourceActor)
    {
        OutReason = TEXT("SourceComponent does not belong to SourceActor.");
        return false;
    }

    if (SourceActor == Receiver)
    {
        OutReason = TEXT("Receiver cannot prepare for its own component.");
        return false;
    }

    return true;
}
```

### `HeavyImpactTuningData.cpp` 的关键校验

```cpp
bool UHeavyImpactTuningData::Validate(
    const USkeletalMeshComponent* Mesh,
    FText& OutError) const
{
    if (!IsValid(Mesh) || !IsValid(PhysicsControlAsset))
    {
        OutError = FText::FromString(TEXT("Mesh or PhysicsControlAsset is missing."));
        return false;
    }

    if (Mesh->GetBoneIndex(PelvisBone) == INDEX_NONE)
    {
        OutError = FText::Format(
            NSLOCTEXT("HeavyImpact", "MissingPelvis", "Missing pelvis bone: {0}"),
            FText::FromName(PelvisBone));
        return false;
    }

    const TArray<FName> RequiredProfiles = {
        Demo::HeavyImpact::ProfileInactive,
        Demo::HeavyImpact::ProfilePrepared,
        Demo::HeavyImpact::ProfileFlight,
        Demo::HeavyImpact::ProfileLandingRecovery,
        Demo::HeavyImpact::ProfileFreeFallback
    };

    for (const FName ProfileName : RequiredProfiles)
    {
        if (!PhysicsControlAsset->Profiles.Contains(ProfileName))
        {
            OutError = FText::Format(
                NSLOCTEXT("HeavyImpact", "MissingProfile", "PCA missing compiled profile: {0}"),
                FText::FromName(ProfileName));
            return false;
        }
    }

    if (PhysicsControlAsset->CharacterSetupData.LimbSetupData.IsEmpty())
    {
        OutError = NSLOCTEXT(
            "HeavyImpact", "EmptyCompiledPCA",
            "PCA has no compiled CharacterSetupData. Save/compile the asset first.");
        return false;
    }

    return true;
}
```

`Profiles` 和 `CharacterSetupData` 是 PCA 的编译后运行时数据。检查它们可以避免
“编辑器里填了 MyProfiles，但资产未编译，运行时 InvokeControlProfile 全部失败”。

### 9.4 请求校验：必须证明随后能发生真实刚体接触

```cpp
bool UHeavyImpactResponseComponent::ValidatePreparationRequest(
    const FHeavyImpactPreparationRequest& Request,
    FString& OutReason) const
{
    if (!bInitialized)
    {
        OutReason = TEXT("HeavyImpact component is not initialized.");
        return false;
    }

    if (!Request.IsStructurallyValid(GetOwner(), OutReason))
    {
        return false;
    }

    const ECollisionEnabled::Type SourceCollision =
        Request.SourceComponent->GetCollisionEnabled();
    if (SourceCollision != ECollisionEnabled::PhysicsOnly
        && SourceCollision != ECollisionEnabled::QueryAndPhysics)
    {
        OutReason = TEXT("SourceComponent has no physics collision.");
        return false;
    }

    if (Request.SourceComponent->GetCollisionResponseToChannel(ECC_PhysicsBody)
        != ECR_Block)
    {
        OutReason = TEXT("SourceComponent does not block ECC_PhysicsBody.");
        return false;
    }

    if (Request.EstimatedTimeToContactSeconds > Tuning->MaximumPreparationSeconds)
    {
        OutReason = TEXT("Prediction arrived too early for the configured preparation window.");
        return false;
    }

    return true;
}
```

### 9.5 Prepare：快照、停止角色驱动、在接触前同步切到物理

```cpp
EHeavyImpactPrepareResult UHeavyImpactResponseComponent::PrepareForImpact(
    const FHeavyImpactPreparationRequest& Request)
{
    if (HasSeenImpactId(Request.ImpactId))
    {
        return EHeavyImpactPrepareResult::Duplicate;
    }

    if (State != EHeavyImpactState::Inactive)
    {
        return EHeavyImpactPrepareResult::Busy;
    }

    FString FailureReason;
    if (!ValidatePreparationRequest(Request, FailureReason))
    {
        UE_LOG(LogTemp, Warning, TEXT("HeavyImpact request rejected on %s: %s"),
            *GetNameSafe(GetOwner()), *FailureReason);
        return EHeavyImpactPrepareResult::Invalid;
    }

    // 接受后立刻记 ID；相同 Overlap 即使后续准备失败也不能在同一摆次无限重试。
    RecordRecentImpactId(Request.ImpactId);

    if (!CapturePreContactSnapshot(FailureReason)
        || !EnterPrepared(Request, FailureReason))
    {
        UE_LOG(LogTemp, Error, TEXT("HeavyImpact prepare failed on %s: %s"),
            *GetNameSafe(GetOwner()), *FailureReason);
        RestoreSnapshotAfterFalsePositive();
        return EHeavyImpactPrepareResult::Invalid;
    }

    return EHeavyImpactPrepareResult::Accepted;
}
```

`EnterPrepared` 的顺序不能随意调整：

```cpp
bool UHeavyImpactResponseComponent::EnterPrepared(
    const FHeavyImpactPreparationRequest& Request,
    FString& OutReason)
{
    ActiveRequest = Request;
    ExpectedSourceActor = Request.SourceActor;
    ExpectedSourceComponent = Request.SourceComponent;

    // 1. 立即停掉 CharacterMovement，避免 Capsule 继续推进 Mesh。
    Movement->StopMovementImmediately();
    Movement->DisableMovement();

    // 2. 冻结现有动画目标。玩家的 ControlRig IK 不应继续产生新目标姿态。
    Mesh->SetPauseAnims(true);

    // 3. Mesh 保持世界姿态脱离 Capsule；之后 Capsule 反向跟随骨盆。
    ActorToPelvisZ = Character->GetActorLocation().Z
        - Mesh->GetBoneLocation(Tuning->PelvisBone).Z;
    Mesh->DetachFromComponent(FDetachmentTransformRules::KeepWorldTransform);

    // 4. Capsule 不再提供物理阻挡，但保留查询，供相机/游戏逻辑识别角色。
    Capsule->SetCollisionEnabled(ECollisionEnabled::QueryOnly);

    // 5. Mesh 临时成为 PhysicsBody，匹配当前摆锤 Bob 的 Block PhysicsBody 配置。
    Mesh->SetCollisionObjectType(ECC_PhysicsBody);
    Mesh->SetCollisionEnabled(ECollisionEnabled::QueryAndPhysics);
    Mesh->SetCollisionResponseToChannel(ECC_WorldStatic, ECR_Block);
    Mesh->SetCollisionResponseToChannel(ECC_WorldDynamic, ECR_Block);
    Mesh->SetCollisionResponseToChannel(ECC_PhysicsBody, ECR_Block);
    Mesh->SetAllBodiesNotifyRigidBodyCollision(true);

    // 6. Physics Control 在 PrePhysics 更新；本组件自身在 PostPhysics 跟随/判稳。
    PhysicsControl->SetComponentTickEnabled(true);
    if (!InvokeRequiredProfile(Demo::HeavyImpact::ProfilePrepared))
    {
        OutReason = TEXT("Prepared PCA profile failed.");
        return false;
    }

    // 7. 同一调用栈内完成刚体切换，不能把真正启用物理推迟到下一帧。
    Mesh->SetAllBodiesSimulatePhysics(true);
    Mesh->SetAllBodiesPhysicsBlendWeight(1.0f, false);
    Mesh->WakeAllRigidBodies();

    if (!Mesh->IsSimulatingPhysics(Tuning->PelvisBone))
    {
        OutReason = TEXT("Pelvis was not simulating after Prepared transition.");
        return false;
    }

    bFreeFallbackInvoked = false;
    TotalCommittedSeconds = 0.0f;
    StableElapsedSeconds = 0.0f;
    SetState(EHeavyImpactState::Prepared);
    SetComponentTickEnabled(true);
    return true;
}
```

这里的 `SetAllBodiesSimulatePhysics(true)` 是“在接触前武装刚体”，不是手工制造
冲击。角色最终速度仍由锤体质量、速度、接触法线、摩擦和身体落点决定。

#### 9.5.1 快照必须覆盖每个 Physics Asset Body

```cpp
bool UHeavyImpactResponseComponent::CapturePreContactSnapshot(FString& OutReason)
{
    Snapshot.Reset();

    const UPhysicsAsset* PhysicsAsset = Mesh->GetPhysicsAsset();
    if (!IsValid(PhysicsAsset) || !IsValid(Mesh->GetAttachParent()))
    {
        OutReason = TEXT("Mesh has no PhysicsAsset or attach parent.");
        return false;
    }

    Snapshot.ActorTransform = Character->GetActorTransform();
    Snapshot.CharacterVelocity = Movement->Velocity;
    Snapshot.MovementMode = Movement->MovementMode;
    Snapshot.CustomMovementMode = Movement->CustomMovementMode;

    Snapshot.MeshAttachParent = Mesh->GetAttachParent();
    Snapshot.MeshAttachSocket = Mesh->GetAttachSocketName();
    Snapshot.MeshRelativeTransform = Mesh->GetRelativeTransform();
    Snapshot.bMeshPauseAnims = Mesh->bPauseAnims;
    Snapshot.MeshCollisionEnabled = Mesh->GetCollisionEnabled();
    Snapshot.MeshObjectType = Mesh->GetCollisionObjectType();
    Snapshot.MeshResponses = Mesh->GetCollisionResponseToChannels();
    Snapshot.bMeshBodyInstanceNotify =
        Mesh->BodyInstance.bNotifyRigidBodyCollision;
    Snapshot.bMeshBodyInstanceCCD = Mesh->BodyInstance.bUseCCD;

    Snapshot.CapsuleCollisionEnabled = Capsule->GetCollisionEnabled();
    Snapshot.CapsuleResponses = Capsule->GetCollisionResponseToChannels();

    Snapshot.Bodies.Reserve(PhysicsAsset->SkeletalBodySetups.Num());
    for (const USkeletalBodySetup* BodySetup : PhysicsAsset->SkeletalBodySetups)
    {
        if (!IsValid(BodySetup))
        {
            continue;
        }

        FBodyInstance* Body = Mesh->GetBodyInstance(BodySetup->BoneName);
        if (!Body)
        {
            OutReason = FString::Printf(
                TEXT("Missing runtime body for bone %s."),
                *BodySetup->BoneName.ToString());
            Snapshot.Reset();
            return false;
        }

        FHeavyImpactBodySnapshot& BodySnapshot = Snapshot.Bodies.AddDefaulted_GetRef();
        BodySnapshot.BoneName = BodySetup->BoneName;
        BodySnapshot.bWasSimulating = Body->IsInstanceSimulatingPhysics();
        BodySnapshot.bNotifyRigidBodyCollision = Body->bNotifyRigidBodyCollision;
        BodySnapshot.bUseCCD = Body->bUseCCD;
        BodySnapshot.PhysicsBlendWeight = Body->PhysicsBlendWeight;
        // false = 读取 Body 自己的值；组件级 QueryOnly 由上方单独保存。
        BodySnapshot.CollisionEnabled = Body->GetCollisionEnabled(false);
    }

    Snapshot.bValid = true;
    return true;
}

void UHeavyImpactResponseComponent::RestoreBodySnapshot()
{
    Mesh->BodyInstance.SetInstanceNotifyRBCollision(
        Snapshot.bMeshBodyInstanceNotify);
    Mesh->BodyInstance.SetUseCCD(Snapshot.bMeshBodyInstanceCCD);

    for (const FHeavyImpactBodySnapshot& BodySnapshot : Snapshot.Bodies)
    {
        FBodyInstance* Body = Mesh->GetBodyInstance(BodySnapshot.BoneName);
        if (!Body)
        {
            UE_LOG(LogTemp, Error,
                TEXT("Cannot restore missing body %s on %s."),
                *BodySnapshot.BoneName.ToString(),
                *GetNameSafe(GetOwner()));
            continue;
        }

        Body->SetCollisionEnabled(BodySnapshot.CollisionEnabled, true);
        Body->SetUseCCD(BodySnapshot.bUseCCD);
        Body->SetInstanceNotifyRBCollision(
            BodySnapshot.bNotifyRigidBodyCollision);
        Body->PhysicsBlendWeight = BodySnapshot.PhysicsBlendWeight;
        Body->SetInstanceSimulatePhysics(
            BodySnapshot.bWasSimulating,
            false,
            true);
    }
}
```

拟实现的 `.cpp` 需要显式包含 `PhysicsEngine/PhysicsAsset.h`、
`PhysicsEngine/SkeletalBodySetup.h` 和 `PhysicsEngine/BodyInstance.h`。快照不是为了让已被
撞飞的角色回原位，而是让“预测到了、实际没撞上”的极短 Prepared 事务能够完整回滚。

### 9.7 PostPhysics：Capsule/Actor 跟随真实骨盆

```cpp
void UHeavyImpactResponseComponent::TickComponent(
    float DeltaTime,
    ELevelTick TickType,
    FActorComponentTickFunction* ThisTickFunction)
{
    Super::TickComponent(DeltaTime, TickType, ThisTickFunction);

    StateElapsedSeconds += DeltaTime;

    if (State == EHeavyImpactState::Prepared)
    {
        UpdatePhysicalFollow(DeltaTime);

        if (StateElapsedSeconds >= Tuning->MaximumPreparationSeconds)
        {
            CancelUncommittedPreparation(TEXT("Expected source did not make contact."));
        }
        return;
    }

    if (State == EHeavyImpactState::Simulating
        || State == EHeavyImpactState::Settling)
    {
        TotalCommittedSeconds += DeltaTime;
        UpdatePhysicalFollow(DeltaTime);
        UpdateStability(DeltaTime);
        return;
    }

    if (State == EHeavyImpactState::Downed
        && Mesh->IsAnySimulatingPhysics())
    {
        // 首版尚无起身桥。睡眠身体若被环境再次唤醒，Capsule 仍跟随真实骨盆，
        // 避免 Mesh 被推走而角色/相机留在旧落点。
        UpdatePhysicalFollow(DeltaTime);
    }
}

void UHeavyImpactResponseComponent::UpdatePhysicalFollow(
    float DeltaTime,
    bool bSnap)
{
    if (!IsValid(Character) || !IsValid(Mesh))
    {
        return;
    }

    const FVector PelvisLocation = Mesh->GetBoneLocation(Tuning->PelvisBone);
    FVector DesiredActorLocation = PelvisLocation;
    DesiredActorLocation.Z += ActorToPelvisZ;

    const FVector NewLocation = bSnap
        ? DesiredActorLocation
        : FMath::VInterpTo(
            Character->GetActorLocation(),
            DesiredActorLocation,
            DeltaTime,
            Tuning->CapsuleFollowInterpSpeed);

    // Actor/Capsule 保持直立，只跟随水平朝向；绝不复制骨盆的 Pitch/Roll。
    const FVector PelvisForward = Mesh->GetBoneQuaternion(Tuning->PelvisBone)
        .GetForwardVector();
    const float DesiredYaw = PelvisForward.Rotation().Yaw;
    const FRotator NewRotation(0.0f, DesiredYaw, 0.0f);

    Character->SetActorLocationAndRotation(
        NewLocation,
        NewRotation,
        false,
        nullptr,
        ETeleportType::TeleportPhysics);
}
```

`TeleportPhysics` 在这里只移动不参与模拟的 Actor/Capsule 外壳，不移动已经脱离并模拟的
Skeletal Mesh，也不把角色送回旧位置。首轮 PIE 必须确认该调用不会反向影响已脱离 Mesh。

### 9.8 判稳：速度 + 地面支撑 + 持续时间

```cpp
void UHeavyImpactResponseComponent::UpdateStability(float DeltaTime)
{
    const FVector LinearVelocity =
        Mesh->GetPhysicsLinearVelocity(Tuning->PelvisBone);
    const FVector AngularVelocityDeg =
        Mesh->GetPhysicsAngularVelocityInDegrees(Tuning->PelvisBone);

    const bool bSlowEnough =
        LinearVelocity.Size() <= Tuning->StableLinearSpeedCmPerSecond
        && AngularVelocityDeg.Size() <= Tuning->StableAngularSpeedDegPerSecond;
    const bool bSupported = HasGroundSupport();

    if (State == EHeavyImpactState::Simulating
        && TotalCommittedSeconds >= Tuning->MinimumSimulationSeconds
        && bSlowEnough
        && bSupported)
    {
        if (InvokeRequiredProfile(Demo::HeavyImpact::ProfileLandingRecovery))
        {
            SetState(EHeavyImpactState::Settling);
        }
    }

    if (bSlowEnough && bSupported)
    {
        StableElapsedSeconds += DeltaTime;
        if (StableElapsedSeconds >= Tuning->RequiredStableSeconds)
        {
            EnterDowned(TEXT("Body remained slow and supported."));
            return;
        }
    }
    else
    {
        StableElapsedSeconds = 0.0f;
        if (State == EHeavyImpactState::Settling)
        {
            InvokeRequiredProfile(Demo::HeavyImpact::ProfileFlight);
            SetState(EHeavyImpactState::Simulating);
        }
    }

    if (!bFreeFallbackInvoked
        && TotalCommittedSeconds >= Tuning->FreeFallbackAfterSeconds)
    {
        EnterFreeFallback(TEXT("Physical response exceeded normal duration."));
    }

    if (TotalCommittedSeconds >= Tuning->ForceDownedAfterSeconds)
    {
        // 仅作为坏物理的最终保险，不参与正常受击表现。
        Mesh->SetAllPhysicsLinearVelocity(FVector::ZeroVector, false);
        Mesh->SetAllPhysicsAngularVelocityInDegrees(FVector::ZeroVector, false);
        EnterDowned(TEXT("Hard safety timeout."));
    }
}

bool UHeavyImpactResponseComponent::HasGroundSupport() const
{
    const FVector Start = Mesh->GetBoneLocation(Tuning->PelvisBone);
    const FVector End = Start - FVector::UpVector * Tuning->GroundProbeDistance;

    FCollisionObjectQueryParams Objects;
    Objects.AddObjectTypesToQuery(ECC_WorldStatic);
    Objects.AddObjectTypesToQuery(ECC_WorldDynamic);

    FCollisionQueryParams Params(SCENE_QUERY_STAT(HeavyImpactGround), false);
    Params.AddIgnoredActor(GetOwner());
    Params.AddIgnoredActor(ExpectedSourceActor);

    FHitResult GroundHit;
    return GetWorld()->LineTraceSingleByObjectType(
        GroundHit, Start, End, Objects, Params);
}
```

首轮可以用骨盆速度判稳；如果实际出现“骨盆停了但手脚仍狂抖”，再将采样扩展为
骨盆、头、双手、双脚的最大速度。这个扩展不改变状态机或机关接口。

#### 9.8.1 自由物理兜底仍然不补冲量

```cpp

    StableElapsedSeconds = 0.0f;

    {
        // Profile 异常时只做明确、可审计的安全状态设置：关闭本组件拥有的控制，
        // 保证身体继续 Simulated + Gravity + Collision。这里仍不产生线性冲量。
        const bool bControlsDisabled = PhysicsControl->SetControlsEnabled(
            OwnedControlNames,
            false,
            true,
            false);
        const bool bMovementSet = PhysicsControl->SetBodyModifiersMovementType(
            OwnedBodyModifierNames,
            EPhysicsMovementType::Simulated,
            true,
            false);
        const bool bCollisionSet = PhysicsControl->SetBodyModifiersCollisionType(
            OwnedBodyModifierNames,
            ECollisionEnabled::QueryAndPhysics,
            true,
            false);
        const bool bGravitySet = PhysicsControl->SetBodyModifiersGravityMultiplier(
            OwnedBodyModifierNames,
            1.0f,
            true,
            false);
        const bool bBlendSet = PhysicsControl->SetBodyModifiersPhysicsBlendWeight(
            OwnedBodyModifierNames,
            1.0f,
            true,
            false);

        UE_LOG(LogTemp, Error,
            TEXT("HeavyImpact direct FreeFallback on %s: controls=%d movement=%d "
                 "collision=%d gravity=%d blend=%d"),
            *GetNameSafe(GetOwner()),
            bControlsDisabled,
            bMovementSet,
            bCollisionSet,
            bGravitySet,
            bBlendSet);
    }

    Mesh->SetAllBodiesSimulatePhysics(true);
    Mesh->SetAllBodiesPhysicsBlendWeight(1.0f, false);
    Mesh->WakeAllRigidBodies();
    PhysicsControl->SetComponentTickEnabled(true);

    if (State == EHeavyImpactState::Settling)
    {
        SetState(EHeavyImpactState::Simulating);
    }

    UE_LOG(LogTemp, Warning, TEXT("HeavyImpact entered FreeFallback on %s: %s"),
        *GetNameSafe(GetOwner()), Reason);
}
```

这段直接 API 只存在于 PCA Profile 无法调用的错误路径，设置的也只是模拟、碰撞、重力和
Blend，不设置控制强度，更不制造冲击。正常效果仍由 PCA Profile 完整定义。

### 9.9 Downed：停在真实落点，不做伪起身

```cpp
void UHeavyImpactResponseComponent::EnterDowned(const TCHAR* Reason)
{
    UpdatePhysicalFollow(0.0f, true);

    // 关闭姿态驱动，保留真实模拟姿态与碰撞，然后尝试睡眠。
    InvokeRequiredProfile(Demo::HeavyImpact::ProfileFreeFallback);
    Mesh->PutAllRigidBodiesToSleep();
    PhysicsControl->SetComponentTickEnabled(false);

    ExpectedSourceActor = nullptr;
    ExpectedSourceComponent = nullptr;
    SetState(EHeavyImpactState::Downed);
    // 首版保留状态驱动 Tick，以覆盖睡眠身体被环境再次唤醒的情况。
    // 接入 Recovering 或明确冻结 Downed 身体后再关闭。
    SetComponentTickEnabled(true);

    UE_LOG(LogTemp, Verbose, TEXT("HeavyImpact downed on %s: %s"),
        *GetNameSafe(GetOwner()), Reason);
}
```

首版在这里结束。以后接入起身时，应当：

1. 从**当前骨盆附近**寻找可容纳 Capsule 的安全位置。
2. 根据骨盆 Up/Forward 判断面朝上还是面朝下。
3. 把当前物理姿态桥接到相应起身 Montage。
4. 只在安全位置把 Mesh 重新附着 Capsule 并恢复 CharacterMovement。
5. 找不到安全位置就继续 Downed，不能回受击前位置。

这里有一个需要效果原型后再定的取舍：当前稿让 Downed 身体保持 Simulated、先睡眠，
被环境再次撞到时仍可移动，因此共享组件继续用状态驱动 Tick 跟随骨盆。若后续同屏倒地 AI
数量较多，或设计要求倒地后不再被推动，可以新增 `DownedKinematic` Profile 在当前姿态冻结，
再关闭 Tick；不能在未看效果前把这个取舍伪装成已经确定。

### 9.10 Prepared 误判恢复：唯一允许使用旧 Transform 的路径

```cpp

{
    check(State == EHeavyImpactState::Prepared);
    RestoreSnapshotAfterFalsePositive();
    UE_LOG(LogTemp, Verbose, TEXT("HeavyImpact preparation cancelled on %s: %s"),

void UHeavyImpactResponseComponent::RestoreSnapshotAfterFalsePositive()
{
    if (!Snapshot.bValid)
    {
        SetComponentTickEnabled(false);
        SetState(EHeavyImpactState::Inactive);
        return;
    }

    InvokeRequiredProfile(Demo::HeavyImpact::ProfileInactive);
    Mesh->SetAllBodiesSimulatePhysics(false);
    RestoreBodySnapshot();

    Mesh->AttachToComponent(
        Snapshot.MeshAttachParent,
        FAttachmentTransformRules::KeepWorldTransform,
        Snapshot.MeshAttachSocket);
    Mesh->SetRelativeTransform(Snapshot.MeshRelativeTransform);
    Mesh->SetCollisionObjectType(Snapshot.MeshObjectType);
    Mesh->SetCollisionEnabled(Snapshot.MeshCollisionEnabled);
    Mesh->SetCollisionResponseToChannels(Snapshot.MeshResponses);
    Mesh->SetPauseAnims(Snapshot.bMeshPauseAnims);

    Capsule->SetCollisionEnabled(Snapshot.CapsuleCollisionEnabled);
    Capsule->SetCollisionResponseToChannels(Snapshot.CapsuleResponses);

    Character->SetActorTransform(
        Snapshot.ActorTransform,
        false,
        nullptr,
        ETeleportType::TeleportPhysics);
    Movement->SetMovementMode(
        Snapshot.MovementMode,
        Snapshot.CustomMovementMode);
    Movement->Velocity = Snapshot.CharacterVelocity;

    PhysicsControl->SetComponentTickEnabled(false);
    ActiveRequest = FHeavyImpactPreparationRequest();
    ExpectedSourceActor = nullptr;
    ExpectedSourceComponent = nullptr;
    Snapshot.Reset();
    SetComponentTickEnabled(false);
    SetState(EHeavyImpactState::Inactive);
}
```

注意：这不是“被撞飞后回原位”。只有指定锤体根本没有命中、状态仍是 Prepared 时才走
此路径。一旦进入 Simulating，Snapshot.ActorTransform 不再用于任何恢复逻辑。

## 10. PCA 的拟配置：让身体“受控”，但不阻止击飞

### 10.1 Limb 顺序

PCA 的 Limb Setup 按“叶子先、躯干最后”建立，避免身体先被 Spine 抢占后四肢无法
进入各自集合：

| 顺序 | Limb 名（项目名） | Start Bone | 备注 |
|---:|---|---|---|
| 1 | Head | `head` | 只负责头颈区域 |
| 2 | ArmLeft | `upperarm_l` | 左臂 |
| 3 | ArmRight | `upperarm_r` | 右臂 |
| 4 | LegLeft | `thigh_l` | 左腿 |
| 5 | LegRight | `thigh_r` | 右腿 |
| 6 | Spine | `spine_01` | 最后创建，并把 `pelvis` 作为父级纳入 |

玩家和追猎者骨架名称当前都支持这些入口骨骼；各自 PCA 引用各自原 Physics Asset。

### 10.2 首版 Profile 语义

下面是**项目 Profile 名与目标行为**，不是 UE 官方预设：

| Profile | Parent Controls | Linear Drive | Angular Drive | Body Movement | Gravity | Collision | CCD |
|---|---|---:|---|---|---:|---|---:|
| Inactive | Disabled | 0 | 0 | Kinematic | 1 | QueryOnly（当前两角色默认） | Off |
| Prepared | Enabled | **0** | 有限强度/有限最大力矩 | Simulated | **0** | QueryAndPhysics | On |
| Flight | Enabled | **0** | 有限强度/有限最大力矩 | Simulated | 1 | QueryAndPhysics | On |
| LandingRecovery | 首版可等于 Flight | **0** | 预留后续渐强 | Simulated | 1 | QueryAndPhysics | On |
| FreeFallback | Disabled | 0 | 0 | Simulated | 1 | QueryAndPhysics | On |

为什么“脚仍受控”不等于“不会被击飞”：

- 不创建把脚钉在世界上的 World Space Control。
- Parent Control 只约束相邻身体之间的相对姿态。
- Linear Strength 和 Maximum Force 明确为 0，不把身体位置拉回动画。
- Angular Control 只尝试让关节不要折成尸体般的极端姿态。
- 整个身体质心仍可以被锤体带走，脚也会随身体一起离地。

首版不先承诺控制强度具体数值。Physics Control 的 Strength/Damping/MaxTorque
需要在真实玩家和 AI Physics Asset 上用三档 PCA 变体做 PIE 对比；尤其必须避免把
`MaxTorque = 0` 误当成“没有力矩”，因为在这套 API 中它可能表示“不限最大值”。

最低要求：

- 任何 Profile 都不创建世界锚点。
- Prepared 和 Flight 的 `LinearStrength` 与 `LinearExtraDamping` 都为 0，避免位置拉回或额外平移阻尼。
- Parent Control 使用冻结的 Skeletal Animation 姿态作为角向目标；Prepared 前先 `SetPauseAnims(true)`。
- Angular MaxTorque 使用显式有限正值。
- Flight 第一版可以固定强度；以后只改 PCA Profile，不改 C++ 状态机。

## 12. 摆锤/冲锤侧必须提供的适配（由机关并行任务实现）

本受击模块不修改并行机关代码，但摆锤必须增加一个在 Bob 前方的预测体积。

拟逻辑：

```cpp
void APendulumHazard::OnPreparationVolumeBeginOverlap(AActor* OtherActor)
{
    if (!OtherActor
        || !OtherActor->GetClass()->ImplementsInterface(UHeavyImpactReceiver::StaticClass()))
    {
        return;
    }

    const FVector BobVelocity = BobBody->GetPhysicsLinearVelocity();
    const float ClosingSpeed = CalculateClosingSpeed(OtherActor, BobVelocity);
    if (ClosingSpeed < MinimumHeavyImpactClosingSpeed)
    {
        return;
    }

    FHeavyImpactPreparationRequest Request;
    Request.ImpactId = CurrentSwingImpactId;
    Request.SourceActor = this;
    Request.SourceComponent = BobBody;
    Request.PredictedImpactPoint = PredictContactPoint(OtherActor);
    Request.SourceLinearVelocity = BobVelocity;
    Request.EstimatedTimeToContactSeconds = PredictTimeToContact(OtherActor);

    IHeavyImpactReceiver::Execute_PrepareForHeavyImpact(OtherActor, Request);
}
```

机关侧约束：

- `CurrentSwingImpactId` 每次有效摆次更新一次；同一摆次多个 Overlap 使用同一 ID。
- 预测体积只负责提前通知，不负责碰撞或施加冲量。
- `SourceComponent` 必须就是最终接触角色的 Bob/冲锤头，而不是预测 Trigger。
- Bob 必须 `QueryAndPhysics` 或 `PhysicsOnly`，并 `Block ECC_PhysicsBody`。
- Bob 的速度、质量、惯量、阻尼和碰撞形状决定击飞量；受击模块不覆盖这些值。
- PCG 只需要生成完整机关 Actor，不持有玩家/AI 硬引用。
- 预测提前量必须在高速下仍至少覆盖“角色切物理所需的一个可靠时间窗口”。

冲锤复用相同接口，只替换预测体积形状和自身运动方式。

## 13. 旧局部 Physics Control 代码的处理边界

旧追猎者组件目前存在三处与 B 路线直接冲突：

1. 它只接受带 `AttackProjectile` Tag 的 Actor，不是共享重冲击契约。
2. 它在 Hit 后手工 `AddImpulseAtLocation`，会把真实锤体碰撞与二次冲量叠加。
3. 它清理时销毁 PhysicsControl 中全部控制/修改器，破坏新模块的所有权。

因此首版不做“双系统协调”，直接让旧组件不再挂到追猎者实例上。旧源文件暂留，后续如果
还需要枪击/小型投射物局部反应，应重新设计为“轻受击层”：

- 与 HeavyImpact 共享输入语义或互斥策略。
- HeavyImpact Busy 时轻受击拒绝执行。
- 不拥有/清空 HeavyImpact 的 PCA 记录。
- 不把局部旧效果当成重冲击的隐式兜底。

## 14. 第一轮效果原型必须看到什么

### 14.1 成功画面

可以直接想象为：

1. 玩家/追猎者仍在跑动，摆锤高速靠近。
2. 接触前极短一瞬，角色停止主动迈步，但画面上没有明显“先倒下”等待锤子。
3. 锤头撞在胸、肩或髋部的哪个位置，身体就围绕哪个接触点产生不同旋转。
4. 整个人被带离原位置；脚会离地，因为没有世界锚点。
5. 四肢不是完全僵直，也不会毫无约束地打结；上身保留一点自我保护感。
6. 身体撞墙、擦地、滚落台阶会继续改变结果。
7. 稳定后 Capsule 和角色逻辑停在骨盆附近的真实落点，角色倒地等待后续起身。

### 14.2 以下任一出现就不能称为成功

- 角色位移主要来自代码补冲量，而不是锤体接触。
- 锤子撞上前角色已经明显软倒，像提前死亡。
- 脚或骨盆像被无形绳子固定在世界上，身体无法整体飞走。
- 角色被击飞后回到原地，或 Capsule 与 Mesh 分离到两个区域。
- PCA 开关前后肉眼几乎没有差异。
- 只是手臂晃动一点，对摆锤这种重物没有完整全身状态变化。
- 玩家镜头跟着骨盆翻滚到眩晕，或相机停在原地看不见角色。
- 追猎者 AI 继续寻路/攻击，和模拟身体争夺位置。

## 15. 实施顺序与每步止损条件

### Slice 0：实现前门禁

- 用户明确授权实施。
- 完整提交当时工作区全部已确认改动。
- `git status --short` 为空。
- 核对 origin 精确为 `git@git.woa.com:shiqiqiwang/Demo.git`。
- commit 成功 push 到内部工蜂，并核对远端分支包含该哈希。

任一失败即暂停，不能带脏工作区开始写功能代码。

### Slice 1：只做共享组件 + 追猎者单角色

- 新增类型、接口、Tuning Data 和组件。
- 新建追猎者 PCA/DA。
- 停用旧局部组件实例。
- 用受控测试锤体验证真实接触。

止损：如果 Mesh 切为 PhysicsBody 后仍无法产生稳定 Hit，或 PCA 编译数据无法由官方
资产工作流可靠建立，先解决根因，不补 AddImpulse 假装完成。

### Slice 2：角色飞行、跟随与判稳

- 验证 Capsule 不拦锤。
- 验证 Actor/Capsule PostPhysics 跟随骨盆。
- 验证墙/地面/斜坡参与结果。
- 验证最终 Downed 在真实落点。

止损：若 PCA 开/关对姿态没有可见差别，立即检查 Profile 是否真正 Invoke、Body Modifier
是否覆盖所有刚体、动画目标是否暂停，而不是继续叠参数。

### Slice 3：接入玩家

- 为玩家创建独立 PCA/DA。
- 接入输入门和磁力释放。
- 验证相机保持直立跟随。
- 验证官方 `ABP_Unarmed` 的 ControlRig IK 在物理期间不争夺姿态。

## 16. 建议其他 AI 重点审阅的问题

### P0：不通过就不能实施

1. `Prepared` 是否能保证锤体真正接触前完成所有刚体切换？

5. 角色 Mesh 脱离 Capsule 后，`SetActorLocationAndRotation` 是否完全不反推模拟 Mesh？
6. `OnComponentHit` 能否可靠收到指定 Bob、骨骼名和接触点？

### P1：首轮 PIE 必须观察

1. 玩家 `ABP_Unarmed` 尾部 ControlRig IK 在 PauseAnims 后是否仍有残余写入。

- 起身桥接采用 Pose Snapshot、Montage 混合还是独立恢复节点。

## 17. 复杂度与风险估算

| 部分 | 代码复杂度 | 资产/调参复杂度 | 主要风险 |
|---|---:|---:|---|
| 共享请求接口与去重 | 低 | 无 | 多次 Overlap/多机关并发 |
| Prepared 碰撞切换与回滚 | 高 | 低 | 切换晚一帧、碰撞矩阵遗漏、误报恢复不完整 |
| PCA 创建/Profile 驱动 | 中 | 高 | 资产未编译、强度单位误判、控制覆盖不完整 |
| 真实 Chaos 接触击飞 | 代码低 | 物理调参高 | 锤体质量/速度/形状才是最终效果主因 |
| Capsule/相机跟随 | 中高 | 中 | 穿墙、抖动、相机延迟、Mesh 与 Actor 分离 |
| 稳定/落地判断 | 中 | 中 | 斜坡、台阶、持续翻滚、四肢残余抖动 |
| 玩家接入 | 中 | 中 | 输入、抓取、相机、官方 ControlRig IK |
| AI 接入 | 低中 | 中 | 行为树/移动争抢；现有 IsReacting 可复用 |
| 起身 | 高 | 高 | 本轮明确延后，等待合适动画 |

最大的不确定性不在接口代码，而在“当前两套 Physics Asset + 新 PCA + 正式锤体参数”
组合出来的画面。为避免再次出现“说得很大、效果只有一点点”，首轮验收必须使用：

- 同一个真实摆锤速度和质量；
- 同一个接触位置；
- PCA 关闭、弱约束、强约束三次录屏对比；
- 同时记录角色落点距离、最大骨盆速度、稳定耗时；
- 画面不成立就回到碰撞/PCA/Physics Asset 根因，不扩功能。
