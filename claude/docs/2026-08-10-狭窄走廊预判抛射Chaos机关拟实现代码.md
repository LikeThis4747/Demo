# 狭窄走廊预判抛射 Chaos 机关——重新设计与拟实现代码

> 状态：2026-08-10 重新设计稿，尚未按本稿重新修改 Source、Blueprint、DataAsset 或 Level0；工作区中的慢速 DA 是上一轮观察基线，不是本稿参数。
>
> 本稿取代“短时推进并持续制导”和“用最短可见飞行时间/最高速度作为发射门槛”的两版思路。后者不是本机关的实现条件；正常玩法中不会因为弹道不够慢、预测不够精确或会撞到环境而取消发射。
>
> 项目内部暂称“预判抛射 Chaos 机关”：这里的“预判抛射”是项目描述，不是 UE 官方类型；`Chaos` 是 UE 的物理系统。

## 1. 最终结论

机关改成下列单一模型：

```text
角色进入触发区
    -> 发射器锁定首个角色并进行约 0.55 s 的可见预警
    -> 预警期间只在发射器端预测角色位置、机械转动炮管
    -> 发射瞬间冻结一次初速度
    -> 对动态刚体质心施加一次冲量
    -> 从第一帧开始由 Chaos 计算重力、碰撞、反弹和滚动
    -> 发射后不再读取目标，不再转向，不再推进
```

这不是“先脚本飞行、碰撞前切物理”，也不是“带推进器的导弹”。它更接近会预判移动目标的投射器/防空炮：瞄准是发射器的计算，弹体离膛后就是普通物理物体。

### 本稿明确删除的错误规则

- 不设置“玩家至少要看见 X 秒”作为运行时发射条件。
- 不设置“超过某个速度就取消这一发”。
- 不因精确弹道无解、路径可能碰到天花板或目标在预警中失效而恢复 `Armed`。
- 不用 `ThrustStrength`、推进时间、飞行中转矩或追踪 Tick 修补命中率。
- 不用一套参数同时迁就“正面迎击”和“从背后追逐远离目标”这两种完全不同的摆位。

## 2. 成熟方案依据

### 2.1 GDC 2017《Predictable Projectiles》

Robot Entertainment 在《Orcs Must Die!》系列使用的方向与本机关高度一致：设计先确定弹体速度/射程和抛射角，代码预测移动目标的交点并求低弧弹道；无解时也要给出可信的偏差弹，而不是让武器没有反应。演讲还把低天花板作为关卡美术和武器有效范围共同约束的问题，而不是每一发临时做“可见时间验收”。

- [GDC Vault 页面](https://www.gdcvault.com/play/1024368/Math-for-Game-Programmers-Predictable)
- [官方讲稿 PDF](https://media.gdcvault.com/gdc2017/Presentations/Stark_Chris_Predictable_Projectiles.pdf)
- [公开视频](https://www.youtube.com/watch?v=6OkhjWUIUf0)

本项目吸收的具体规则：

1. 设计侧暴露“参考射程 + 理想低抛角”，由代码推导统一初速。
2. 优先低弧，而不是为了数学命中自动切成高抛。
3. 预判只假设角色短时间保持当前速度；发射后变向就是玩家的有效躲避。
4. 无精确解时仍发射，偏差必须看起来来自角色走位、机械瞄准范围或环境碰撞。
5. 公平性主要由预警、炮口动作、弹体轮廓、尾迹和撞击反馈提供，不由运行时代码强行保证飞行秒数。

### 2.2 UE5.8 采用的官方能力

- [`UGameplayStatics::SuggestProjectileVelocity`](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UGameplayStatics/SuggestProjectileVelocity?lang=en-US)：给定起点、终点和固定初速，求受重力影响的低/高弧初速度。
- [`Accept Closest on No Solutions`](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI/Game/SuggestProjectileVelocity)：无精确解时返回在该固定速度下尽量接近目标的速度。本项目只把它当回退候选，不把 `true` 误写成“保证命中”。
- [`AddImpulse`](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI/Physics/AddImpulse)：给物理刚体一次瞬时冲量。弹体使用 `Impulse = Mass * LaunchVelocity`，不持续施力。
- [`PredictProjectilePath`](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UGameplayStatics/PredictProjectilePath)：仅用于开发期画出/检查预期抛物线，不作为正常发射许可。

`SuggestProjectileVelocity_MovingTarget` 要求先指定 `TimeToTarget`。这适合“策划直接规定几秒后命中”的武器，但本机关不采用它：飞行时间应是距离、目标速度、世界重力和固定初速计算出的结果，而不是可见性硬门槛。

## 3. 当前 Level0 暴露出的摆位问题

当前两个测试实例并不等价：

- 直段实例位于玩家行进方向正面，目标向发射器靠近。
- 转角实例目前位于转角入口一侧并朝走廊深处发射，玩家转弯后与弹体同向远离；它实际是“从背后追击”。

按当前约 5 m/s 的角色行走速度和约 0.9 s 预警估算，若两者共用固定速度，为追上转角实例的远离目标，需要约 26~27 m/s；同一速度打直段近目标时只有约 0.17 s 飞行，弹体本体必然接近瞬闪。这就是当前“看不清”和“打不中”不能只靠调 `ThrustStrength` 同时解决的结构性原因。

### 本稿的默认布局修正

把转角发射器移到玩家转弯后正面看见的走廊尽头墙上，朝转角方向发射：

```text
转角入口 ----玩家行进---->        [旧：背后发射器]
转角入口 ----玩家行进---->  <---- [新：正面发射器]
```

玩家完成转角后先取得炮口视线；TriggerAnchor 再放到距 Muzzle 约 900~1100 cm 的位置，而不是紧贴转角入口。这样两个测试实例在触发时都接近 10 m 正面交战距离，可以共用一套低速、低弧参数；玩家横移、折返、急停或拿物理资源阻挡都能改变结果。

如果必须保留“背后追击”摆位，它应使用单独的远程高速 DataAsset 和更强的尾迹表现，不能再和正面版本共用默认参数。本稿不把这两种武器偷偷混为一套。

## 4. 策划参数不是发射门槛

### 4.1 初速的推导

同高参考条件下：

```text
LaunchSpeed = sqrt(abs(GravityZ) * ReferenceRange / sin(2 * PreferredLaunchAngle))
```

第一轮建议值：

| 参数 | 初值 | 用途 |
|---|---:|---|
| `ReferenceRange` | 1000 cm | 定义这件机关最典型的交战距离，不是最大射程，也不是许可门槛 |
| `PreferredLaunchAngleDegrees` | 18° | 塑造低弧视觉；代码由它和参考射程推导速度 |
| 世界重力 | 约 980 cm/s² | 读取当前 World，不覆写 |
| 推导初速 | 约 1290 cm/s | 约 12.9 m/s，不单独暴露第二个互相矛盾的速度参数 |
| `WarningSeconds` | 0.55 s | 给玩家看见锁定、炮管转动和发射前摇 |
| `AimUpdateIntervalSeconds` | 0.05 s | 预警期 20 Hz 更新机械瞄准；Actor Tick 仍关闭 |
| `MaximumInitialAimAngleDegrees` | 30° | 炮管机械覆盖范围；超出后会限角发射而不是取消 |
| `FallbackElevationDegrees` | 8° | 所有弹道回退都失败时仍执行的稳定低仰角抛射 |

在 1000 cm、18°、同高目标下，理论飞行约 0.81 s，最高点约比炮口高 81 cm。实际迎面移动目标会缩短飞行时间；可读性由 0.55 s 预警、发射闪光和连续尾迹共同承担，不在代码中验证“必须飞满多少秒”。

### 4.2 弹体第一轮尺寸

```text
ProjectileRadius      = 22 cm
ProjectileHalfHeight  = 45 cm
ProjectileMass        = 60 kg（先保留现有量级，不用提高速度换重受击）
BallisticLinearDamping = 0
BallisticAngularDamping = 0.05
PostImpactLinearDamping = 0.08
PostImpactAngularDamping = 0.15
```

短胶囊比现有 25/60 胶囊更适合 300 cm 低顶走廊，也比细长气罐更不容易因端部扫到顶/墙而产生夸张翻滚。它仍是完整 Chaos 刚体，并不改成无碰撞的视觉导弹。

## 5. 发射前移动目标预测

### 5.1 求解顺序

每次预警采样使用固定的 `LaunchSpeed`：

1. 读取目标胶囊中心和当前速度。
2. 用水平距离 / 参考水平速度估计第一次飞行时间。
3. 计算 `PredictedTarget = TargetLocation + TargetVelocity * EstimatedTime`。
4. 调用 UE5.8 `SuggestProjectileVelocity`，`bFavorHighArc=false`，求该预测点的低弧速度。
5. 用返回速度的水平分量重新计算飞行时间，再迭代 2 次。
6. 所有精确解和回退候选都相对 BeginPlay 缓存的“中性炮管轴”限制到固定机械覆盖锥；不能以已经转动的 Muzzle Forward 作为下一次锥体中心。
7. 把最终结果保存为 `LastAimSolution`，并让 `AimPivot` 机械转向。
8. 发射时冻结该速度；弹体不保存目标引用。

三次迭代是内部数值实现，不做成策划调参。目标发射后变速或转向会自然造成未命中，这正是可躲避性。

### 5.2 无精确解也必须发射

回退层级固定为：

```text
预测移动交点的低弧精确解
    -> 目标当前/最后已知位置的低弧精确解
    -> AcceptClosestOnNoSolutions 给出的固定速度候选
    -> 炮管覆盖角内、固定速度、8° 仰角的直向抛射
```

任何一级失败都继续下一级。最后一级不依赖目标，因此正常进入过预警的机关一定会发射。

以下情况也不取消：

- 目标在预警末尾被销毁：使用最后一次解；从未有有效解则用最终直向回退。
- 预测弹道会打到天花板/转角：照常发射，由 Chaos 产生真实碰撞。
- 目标跑出炮管覆盖角：把发射方向限制到机械极限，产生可读的偏差弹。

BeginPlay 已存在的 Launcher 自身或 WorldStatic 重叠属于资产/PCG 装配错误；它会在玩家触发前明确禁用实例，避免再次制造出生穿透和乱飞。

运行时若玩家用可移动物理资源堵住炮口，不走上述禁用路径：机关仍消费并播放完整发射反馈，以本次发射冲量和接触点作用于堵塞刚体，记录 `BlockedDischarge`。这样“拿资源挡住机关”是有效物理应对，而不是一次无声取消；正常路径中的资源则仍由真正弹体撞击。

## 6. 为什么不使用 `UProjectileMovementComponent`

`UProjectileMovementComponent` 是 UE 官方的投射物移动组件：它按速度、重力、Sweep 和弹跳参数更新一个 `UpdatedComponent`，适合火球、榴弹、子弹等可预测投射物。官方文档也说明：若更新组件本身已经启用物理模拟，Projectile Movement 主要只提供初始发射参数，之后由物理模拟接管。

本机关不需要“检测到即将碰撞再从 Projectile Movement 切到 SimulatePhysics”，原因是：

1. 用户要的是从发射开始就参与 Chaos 交互；切换会形成两个模拟器和额外状态交接。
2. 当前穿墙问题可用完整出生净空、简单胶囊碰撞、World/Pawn Block 和 CCD 直接解决。
3. 一次 `AddImpulse` 已能得到与弹道公式一致的初速度，同时保留真实质量和碰撞。
4. 首碰后无需复制/恢复速度，Chaos 一直拥有同一个刚体状态，反弹连续。

因此本稿既不使用推进器，也不使用 `UProjectileMovementComponent`；它们都不是实现成熟抛射机关的必需条件。

## 7. 状态机

### 7.1 Launcher

```text
Armed
  -> Warning/Aiming
  -> Fired/Spent

任意配置或出生装配错误 -> Disabled
```

删除 `ReturnToArmedAfterCancelledWarning()` 的正常弹道用途。一次性机关一旦锁定并开始完整预警，就会消耗这一发。

### 7.2 Projectile

```text
Uninitialized
  -> Ballistic       // 已施加一次冲量，尚无首次阻挡碰撞
  -> FreePhysics     // 首碰后仍由同一个 Chaos 刚体继续反弹/滚动
  -> Sleeping

非法初始化 -> Disabled
```

`Ballistic` 和 `FreePhysics` 都是纯 Chaos；状态差异只用于日志、首碰后阻尼切换和表现事件，不代表切换模拟方式。

```cpp
FVector AThrustGuidedHazardLauncher::ClampDirectionToMechanicalCone(
	const FVector& DesiredDirection) const
{
	const FVector Center = NeutralAimDirection.GetSafeNormal();
	const FVector Desired = DesiredDirection.GetSafeNormal();
	const float MaxAngle = FMath::DegreesToRadians(
		TuningData->MaximumInitialAimAngleDegrees);
	const float Angle = FMath::Acos(FMath::Clamp(
		FVector::DotProduct(Center, Desired), -1.0f, 1.0f));
	if (Angle <= MaxAngle)
	{
		return Desired;
	}

	const FVector Axis = FVector::CrossProduct(Center, Desired).GetSafeNormal();
	return Axis.IsNearlyZero()
		? Center
		: FQuat(Axis, MaxAngle).RotateVector(Center).GetSafeNormal();
}
```

若方向被限制，`bWasMechanicalLimited=true`；日志不能再把这一发称为“预测命中解”，而应明确是覆盖角受限后的偏差弹。

关键求解预览：

```cpp
float AThrustGuidedHazardLauncher::CalculateDerivedLaunchSpeed() const
{
	const float Gravity = FMath::Abs(GetWorld()->GetGravityZ());
	const float Angle = FMath::DegreesToRadians(
		TuningData->PreferredLaunchAngleDegrees);
	return FMath::Sqrt(
		Gravity * TuningData->ReferenceRange / FMath::Sin(2.0f * Angle));
}

bool AThrustGuidedHazardLauncher::TrySolveLowArcToPoint(
	const FVector& TargetPoint,
	FVector& OutVelocity) const
{
	UGameplayStatics::FSuggestProjectileVelocityParameters Params(
		this,
		Muzzle->GetComponentLocation(),
		TargetPoint,
		CalculateDerivedLaunchSpeed());

	Params.bFavorHighArc = false;
	Params.TraceOption = ESuggestProjVelocityTraceOption::DoNotTrace;
	Params.OverrideGravityZ = 0.0f;
	Params.bAcceptClosestOnNoSolutions = false;
	return UGameplayStatics::SuggestProjectileVelocity(Params, OutVelocity);
}
```

移动预测预览：

```cpp
bool AThrustGuidedHazardLauncher::TrySolvePredictedIntercept(
	FBallisticAimSolution& OutSolution) const
{
	if (!LockedTargetComponent.IsValid())
	{
		return false;
	}

	const FVector Start = Muzzle->GetComponentLocation();
	const FVector TargetLocation = LockedTargetComponent->GetComponentLocation();
	const FVector TargetVelocity = LockedTargetActor.IsValid()
		? LockedTargetActor->GetVelocity()
		: FVector::ZeroVector;
	const float Speed = CalculateDerivedLaunchSpeed();
	const float ReferenceHorizontalSpeed = Speed * FMath::Cos(
		FMath::DegreesToRadians(TuningData->PreferredLaunchAngleDegrees));

	float Time = FVector::Dist2D(Start, TargetLocation) /
		FMath::Max(ReferenceHorizontalSpeed, 1.0f);
	FVector SolvedVelocity = FVector::ZeroVector;
	FVector PredictedPoint = TargetLocation;

	for (int32 Iteration = 0; Iteration < 3; ++Iteration)
	{
		PredictedPoint = TargetLocation + TargetVelocity * Time;
		if (!TrySolveLowArcToPoint(PredictedPoint, SolvedVelocity))
		{
			return false;
		}

		const float HorizontalSpeed = SolvedVelocity.Size2D();
		Time = FVector::Dist2D(Start, PredictedPoint) /
			FMath::Max(HorizontalSpeed, 1.0f);
	}

	OutSolution.LaunchVelocity = SolvedVelocity;
	OutSolution.AimPoint = PredictedPoint;
	OutSolution.EstimatedFlightTime = Time;
	OutSolution.Source = EBallisticAimFallback::PredictedIntercept;
	return true;
}
```

```cpp
	FBallisticAimSolution Result;
	const float Speed = CalculateDerivedLaunchSpeed();

	// 正式函数会先尝试最近一次有效解/当前点低弧，再尝试 Closest。
	const FVector FlatForward = FVector::VectorPlaneProject(
		NeutralAimDirection, FVector::UpVector).GetSafeNormal();
	const float Elevation = FMath::DegreesToRadians(
		TuningData->FallbackElevationDegrees);
	const FVector Direction =
		FlatForward * FMath::Cos(Elevation) + FVector::UpVector * FMath::Sin(Elevation);

	Result.LaunchVelocity = Direction.GetSafeNormal() * Speed;
	Result.AimPoint = Muzzle->GetComponentLocation() + Direction * TuningData->ReferenceRange;
	Result.Source = EBallisticAimFallback::MechanicalForward;
	return Result;
}
```

`UpdateWarningAim()` 每 0.05 s 更新 `LastAimSolution` 并从固定中性轴旋转 `AimPivot`。所有 exact/current/closest/direct 结果在保存前都经过同一个固定机械锥限制。`FireLockedTarget()` 不再因目标失效或弹道无解恢复 Armed，而是确保存在最终回退后生成一次弹体。

## 9. Blueprint、表现和 Level0

### 9.1 Launcher Blueprint

- C++ 新增 `AimPivot`，把 `Muzzle` 放到其下。
- 将现有 `BarrelMesh` 重挂到 `AimPivot`；外壳不转。
- 预警时点亮 `WarningLight`，炮管逐步跟随最近一次预测解。
- 增加约 0.55 s 蓄能/机械声；发射瞬间有闪光和清晰瞬态声音。

### 9.2 Projectile Blueprint

- 移除继承的 Thruster 后重新编译，确认没有残留组件引用。
- 第一轮使用紧凑、高对比的测试体，不再强调“高压气罐”造型。
- `BodyVisualRoot` 的网格碰撞关闭，唯一碰撞仍是 C++ 胶囊。
- `ExhaustVisualRoot` 改为连续短尾迹/烟迹挂点；这是速度阅读辅助，不表示仍有推进力。
- 增加掠过声和撞击火花/声音，使 0.3~0.7 s 的飞行也能读出方向和落点。

### 9.3 Level0

- 直段发射器保留正面墙摆位。
- 转角发射器移到转弯后正面走廊尽头，反向朝转角发射。
- 玩家刚完成转角时先看见炮口；TriggerAnchor 放在继续前进后、距 Muzzle 约 900~1100 cm 的位置，不改成压力板。
- 不通过缩小房间、加隐形墙或运行时取消发射来伪造稳定性。

### 9.4 未来 PCG 房间合同

首版不接入 PCG 生成，但后续房间只需满足：

- 发射器位于玩家预期行进方向的正面或明确侧前方，不把默认短程版本摆成背后追逐。
- Muzzle 完整胶囊出生范围为 `QueryAndPhysics` 可查询且无阻挡重叠。
- 触发区到炮口的典型距离围绕 `ReferenceRange` 布置；低顶默认房按约 900~1100 cm 验收。超出仍会发射，只是不承诺命中，也允许弹体真实撞顶。
- 300 cm 低顶房使用低抛角和紧凑弹体；天花板被击中是物理结果，不是代码故障。

## 10. 验证矩阵

### 10.1 静态/构建

- 六个 C++ 文件不再引用 Thruster、飞行中目标或 Actor Tick。
- Demo 模块 `-NoLink` 编译通过。
- 正常关闭 Editor 后仅完整链接 Demo 模块，不编译引擎。
- Launcher/Projectile Blueprint 编译保存，组件树回读正确。
- DataAsset 逐字段回读，旧推进/制导字段不再存在。

### 10.2 PIE 画面验收（由用户执行）

1. 正面直段：正常行走，能先读到炮口，再看到弹体迎面飞来并发生真实接触/掠过。
2. 转角正面：转弯后看见预警，继续前进会被预测；急停或横移能躲过。
3. 静止目标：低弧指向当前胶囊中心，不再“根本打不中人”。
4. 变向目标：发射后变向能躲，弹体不拐弯追踪。
5. 环境交互：弹体撞墙/顶/可移动物体后保持同一 Chaos 状态，多次反弹，不穿墙。
6. 无精确解：日志标记 fallback 层级，机关仍发射。
7. 静态出生装配错误：在触发前明确报错并禁用，不生成已经嵌墙的刚体。
8. 动态堵炮口：机关消费并产生 `BlockedDischarge` 声光/冲量反馈，不静默取消或生成重叠刚体。

### 10.3 验收边界

- 不以一次命中证明所有目标速度都可靠。
- 不以 HeavyImpact 是否触发反推必须提高初速；轻/重受击由受击系统合同决定。
- 第一轮只验收“看得清、正常路径有较高命中可能、可走位躲避、碰撞后是真实 Chaos”。

## 11. 实施前唯一需要确认的设计选择

本稿推荐直接采用：**把转角 Launcher 移到玩家转弯后正面墙上**。

若用户要求保留现有“从背后追逐远离玩家”的转角摆位，则必须改为两套 DataAsset；背后版本会是速度更高、主要依靠预警和尾迹阅读的另一种武器，不应再承诺与正面版本拥有相同飞行观感。

除这个摆位选择外，第一轮不需要再决定“气罐还是导弹”的命名。先用紧凑高对比测试体把弹道、可读性和 Chaos 碰撞验收，再决定最终美术身份。
