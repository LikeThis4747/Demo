# 狭窄走廊预判抛射 Chaos 机关——审查修订版拟实现代码

> 状态：2026-08-10 审查修订版；尚未按本稿修改 Source、Blueprint、DataAsset 或 Level0。
>
> 本稿取代同名文档上一版的 `ReferenceRange=1000 cm / PreferredLaunchAngle=18° / ProjectileMass=60 kg` 参数组合，也取代“短时推进并持续制导”和“以最短可见飞行时间决定是否发射”的旧思路。
>
> “预判抛射”是本项目对玩法的直白描述，不是 UE 官方类型；`Chaos` 是 UE 的物理系统。

## 1. 审查后的结论

核心模型保留，但上一版不能直接实现。最终模型收敛为：

```text
角色首次进入触发区
    -> 一次性锁定并进入可见预警
    -> 发射器按目标当前位置和速度反复计算低弧交点
    -> 炮管在独立水平/俯仰机械范围内真实转动
    -> 发射瞬间以炮管实际方向冻结一次初速度
    -> 在弹体真实质心出生点生成同一个 Chaos 刚体
    -> 对质心施加一次冲量
    -> 重力、碰撞、反弹、滚动和休眠始终由 Chaos 负责
```

发射后不再读取目标、不再追踪、不再推进，也不在第一次碰撞时切换模拟器。

### 保留

- 发射前预测移动目标。
- 固定设计初速、优先低弧。
- 一次质心冲量。
- 从出生起全程 Chaos。
- 无数学精确解时按回退层级照常发射。
- 紧凑简单胶囊、`QueryAndPhysics`、CCD。
- 转角实例改为玩家转弯后正面迎击。

### 撤回并重写

- 不再把 `1000 cm / 18°` 描述成当前走廊真实飞行画面；它只会得到约 12.9 m/s，且当前触发几何下实际仰角和飞行时间与文案不一致。
- 不再使用单一 30° 三维圆锥；低顶房必须分别限制水平转角与向上仰角。
- 不再从 Muzzle 出口平面求弹道、再把刚体质心前移后发射。
- 不再只做固定三次、没有收敛判据的移动目标迭代。
- 不再对堵在出生区的刚体直接调用 `AddImpulseAtLocation` 伪造“弹体命中”。
- 不再把 60 kg 当作无风险继承值，也不靠速度或质量强行触发重受击。
- 不再把 CCD 写成“保证不穿墙”；它只能降低穿透风险，仍需薄墙 PIE 专项验证。

## 2. 成熟方案依据与本项目采用边界

### 2.1 可预测投射物

Robot Entertainment 在 GDC 2017《Math for Game Programmers: Predictable Projectiles》中讲解的方向适合本机关：武器先有明确的速度/射程设计，再预测移动目标的交点并求低弧；发射后目标改变运动即可躲避。低顶和关卡几何属于武器与房间共同设计的问题，不需要把“可见飞行时间”写成每一发的运行许可。

- [GDC Vault](https://www.gdcvault.com/play/1024368/Math-for-Game-Programmers-Predictable)
- [讲稿 PDF](https://media.gdcvault.com/gdc2017/Presentations/Stark_Chris_Predictable_Projectiles.pdf)
- [公开视频](https://www.youtube.com/watch?v=6OkhjWUIUf0)

### 2.2 UE5.8 官方能力

- [`UGameplayStatics::SuggestProjectileVelocity`](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UGameplayStatics/SuggestProjectileVelocity?lang=en-US)：给定起点、终点、固定初速和重力，求低弧/高弧初速度。
- [`Accept Closest on No Solutions`](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI/Game/SuggestProjectileVelocity)：无精确解时给出“尽量接近”的候选；它不是命中保证，也不能绕过低顶机械仰角限制。
- [`AddImpulse`](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI/Physics/AddImpulse)：一次性改变刚体动量。本稿使用 `Impulse = ActualMass * LaunchVelocity`、`bVelChange=false`。
- [`PredictProjectilePath`](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UGameplayStatics/PredictProjectilePath)：仅用于开发期画线和布局检查，不作为是否发射的门槛。

本项目没有必要使用 `UProjectileMovementComponent`：官方组件适合由组件更新位置、Sweep、重力和弹跳的普通投射物；当 UpdatedComponent 已经模拟物理时，它主要提供初始发射参数，之后仍由物理接管。本机关直接对同一个模拟刚体施加一次冲量，状态更少，也更符合“从发射开始即可和 Chaos 物体互动”的目标。

## 3. Level0 几何结论

官方 MCP 已回读当前两个实例：

- 直段 Launcher：`(50500, 30900, 150)`，Yaw `-90°`；Muzzle 局部 `(100,0,0)`；TriggerAnchor 局部 `(600,0,0)`。
- 转角 Launcher：`(50800, 30600, 150)`，Yaw `180°`；Muzzle 局部 `(100,0,0)`；TriggerAnchor 局部 `(1100,0,0)`。
- 两者 TriggerVolume 半尺寸均为 `(500,260,140)`。
- 房间最低天花板约 300 cm。

`TriggerAnchor` 到 Muzzle 的距离不等于玩家触发时到 Muzzle 的距离。触发点是玩家路径与 1000 cm 长触发盒的第一次交点：

- 直段玩家从盒体远端迎面进入，现有 Anchor `600 cm` 大致形成约 10 m 的首次触发距离。
- 当前转角玩家与炮口同向移动，从盒体近端进入；Anchor `1100 cm` 并没有形成 11 m 迎击，而是形成背后追逐。

### 修订后的摆位

转角 Launcher 移到玩家转弯后正面的尽头墙，朝转角方向发射。触发盒放在玩家取得炮口视线之后；最终按“玩家路径第一次进入 TriggerVolume 的位置到 ProjectileSpawnPoint 的距离”回读，目标约为 900～1100 cm。

这里的 900～1100 cm 是关卡作者的首轮布局目标，不是运行时代码门槛。超出该范围仍会发射；只是默认参数不承诺同样的命中和观感。

在当前 `TriggerHalfExtent.X=500 cm` 且玩家从盒体远端迎面进入的布置中，TriggerAnchor 局部 X 初值可先用约 `600 cm`，再依据实际路径交点回读修正；不能再把 Anchor 本身盲填成 900～1100。

## 4. 第一轮参数基线

### 4.1 设计初速

仍用“参考射程 + 参考低抛角”推导唯一初速：

```text
LaunchSpeed =
    sqrt(abs(WorldGravityZ) * ReferenceRange
         / sin(2 * PreferredLaunchAngle))
```

修订后的第一轮初值：

| 参数 | 初值 | 含义 |
|---|---:|---|
| `ReferenceRange` | 600 cm | 只用于推导约 10 m/s 的设计初速，不代表 Trigger 距离或最大射程 |
| `PreferredLaunchAngleDegrees` | 18° | 同高参考条件；不是每一发的实际仰角 |
| 世界重力 | 约 980 cm/s² | 读取当前 World |
| 推导初速 | 约 1000 cm/s | 狭窄走廊的首轮观察速度 |
| `TargetAimHeightOffset` | +50 cm | 从角色胶囊中心抬到胸腹区域，避免一直瞄角色根部 |
| `WarningSeconds` | 0.55 s | 首轮预警；手感范围预留 0.55～0.80 s |
| `AimUpdateIntervalSeconds` | 0.05 s | 预警期间 20 Hz Timer 更新，不开 Actor Tick |
| `MaximumAimYawDegrees` | 30° | 相对初始炮轴的水平范围 |
| `MaximumAimPitchUpDegrees` | 18° | 300 cm 低顶房的向上机械上限 |
| `MaximumAimPitchDownDegrees` | 15° | 向下机械上限 |
| `AimTurnSpeedDegreesPerSecond` | 90°/s | 炮管有可读转动，不在发射帧瞬间跳转 |
| `FallbackElevationDegrees` | 8° | 全部数学候选失败时的固定低角度方向 |

在“玩家首次触发时距出生质心 900～1100 cm、随后以约 5 m/s 继续迎面前进、预警 0.55 s”的默认场景中，估算飞行约 0.42～0.56 s，实际仰角约 8～14°；精确值受 AimPivot 真实枢轴位置影响，必须以 Blueprint 组件回读和 PIE 为准。这只是调参预期，不写成运行时判断。

这套慢速参数不同时保证命中“刚触发便停在 900～1100 cm 处”的目标：10 m/s、向上最多 18° 时，静止目标有效距离约 600～700 cm。**预警期间急停、后退或横移被明确视为有效躲避**，不是需要用更高速度修补的命中失败；静止命中专项应把测试目标放在约 600～700 cm 内。

### 4.2 弹体

| 参数 | 初值 |
|---|---:|
| `ProjectileRadius` | 22 cm |
| `ProjectileHalfHeight` | 45 cm |
| `SpawnClearanceMargin` | 10 cm |
| `ProjectileMass` | 25 kg |
| 离膛阶段线性阻尼 | 固定 0；不进入 DA，保持 `SuggestProjectileVelocity` 的无阻力弹道合同 |
| `BallisticAngularDamping` | 0.05 |
| `PostImpactLinearDamping` | 0.08 |
| `PostImpactAngularDamping` | 0.15 |

25 kg、10 m/s 的动量约 250 kg·m/s、动能约 1.25 kJ，足以成为明显的物理物体，但不会像上一版 60 kg、12.9 m/s 那样把弹道调参与受击强度绑死。

紧凑胶囊保持局部 `+Z` 为长轴/飞行轴；可视网格和尾迹不拥有碰撞。

## 5. 必须统一的三个空间事实

### 5.1 Muzzle 只表示出口平面

`Muzzle` 用于炮口闪光、音效和机械外观，不再作为弹道起点。

新增 `ProjectileSpawnPoint`，表示弹体胶囊质心的真实出生点。它位于 Muzzle 沿炮管前方：

```text
CenterOffset = ProjectileHalfHeight + SpawnClearanceMargin
             = 45 + 10
             = 55 cm
```

`ProjectileSpawnPoint` 随 `AimPivot` 一起转动。弹道求解 Start、出生净空形状、SpawnTransform 和 Chaos 冲量都使用同一个质心位置，消除“公式从炮口算、刚体却从前方 55 cm 起飞”的系统性偏差。

### 5.2 固定机械基准

BeginPlay 缓存 `NeutralAimRotation`、Muzzle 和 ProjectileSpawnPoint 相对 AimPivot 的装配变换。所有目标方向都先转换到该固定局部空间，分别限制 Yaw、Pitch，再转换回世界空间。禁止把上一帧已经转过的 Muzzle Forward 当成下一帧的限制中心。

方向限制预览：

```cpp
FVector ClampToMechanicalLimits(const FVector& DesiredWorldDirection) const
{
    const FVector LocalDirection =
        NeutralAimRotation.UnrotateVector(DesiredWorldDirection.GetSafeNormal());

    float YawDegrees = FMath::RadiansToDegrees(
        FMath::Atan2(LocalDirection.Y, LocalDirection.X));
    float PitchDegrees = FMath::RadiansToDegrees(
        FMath::Atan2(
            LocalDirection.Z,
            FVector2D(LocalDirection.X, LocalDirection.Y).Size()));

    YawDegrees = FMath::Clamp(
        YawDegrees,
        -TuningData->MaximumAimYawDegrees,
        TuningData->MaximumAimYawDegrees);
    PitchDegrees = FMath::Clamp(
        PitchDegrees,
        -TuningData->MaximumAimPitchDownDegrees,
        TuningData->MaximumAimPitchUpDegrees);

    return NeutralAimRotation
        .RotateVector(FRotator(PitchDegrees, YawDegrees, 0.0f).Vector())
        .GetSafeNormal();
}
```

### 5.3 炮管实际朝向就是冲量方向

求解器产生 `DesiredDirection`，机械限制和转速产生 `ActualBarrelDirection`。发射时：

```text
PendingLaunchVelocity =
    ActualBarrelDirection * DerivedLaunchSpeed
```

弹体出生旋转把胶囊局部 `+Z` 对齐 `ActualBarrelDirection`。不能让炮管显示一个方向、SpawnTransform 用另一个方向、冲量再用第三个方向。

如果预警结束时炮管尚未追上理想解，机关仍沿实际炮管方向发射，并在日志标记 `SlewLimited`；这是可解释的机械偏差，不是偷偷瞬时校正。

## 6. 移动目标弹道求解

### 6.1 目标点

每次采样使用：

```text
TargetPoint =
    LockedTargetCapsuleCenter
    + TargetVelocity * EstimatedFlightTime
    + WorldUp * TargetAimHeightOffset
```

发射后目标变速、横移、急停会造成自然未命中，这是玩家躲避窗口。

### 6.2 质心起点与收敛

`TrySolveLowArcToPoint` 必须显式接收 `StartPoint`，不再内部硬读 Muzzle。

预测使用最多 8 次内部迭代：

1. 用当前质心起点和目标当前位置估计飞行时间。
2. 按时间外推目标点。
3. 调用 `SuggestProjectileVelocity` 求固定速度低弧。
4. 用候选方向组合缓存的装配变换，得到该方向下的假想 ProjectileSpawnPoint。
5. 从新的质心起点重新求解并更新时间。
6. 当相邻时间差不超过 0.01 s、预测目标点差不超过 15 cm、质心出生点差不超过 1 cm，且候选方向差不超过 0.1° 时才视为数值收敛。
7. 只有数值收敛且 Yaw/Pitch 都未被机械限制，才能标记 `PredictedIntercept`；任何限角候选都标记 `MechanicallyLimited`，仍然发射但不再声称是精确解。
8. 达到 8 次仍未收敛，不能伪称精确解，进入下一回退层。

8 次和容差是内部算法常量，不做成 DataAsset 手感参数。

`TrySolveLowArcToPoint()` 还必须拒绝近零水平距离、NaN/Inf，以及返回速度模长偏离固定设计初速超过容差的结果。

函数边界预览：

```cpp
bool TrySolveLowArcToPoint(
    const FVector& StartPoint,
    const FVector& TargetPoint,
    bool bAcceptClosest,
    FVector& OutLaunchVelocity) const;

bool TrySolvePredictedIntercept(
    const FVector& TargetLocation,
    const FVector& TargetVelocity,
    FBallisticAimSolution& OutSolution) const;

FTransform BuildHypotheticalSpawnTransform(
    const FVector& LimitedDirection) const;
```

### 6.3 回退层级

```text
已收敛的移动交点低弧
    -> 目标当前/最后有效位置的低弧
    -> AcceptClosestOnNoSolutions 候选
    -> 固定中性前向 + 8° 仰角
```

每一级都必须经过同一套水平/俯仰限制。`AcceptClosest` 可能返回接近高射程角的候选，不能绕过 18° 向上上限。

数学无解、目标在预警末尾失效、目标跑出机械范围、预览轨迹可能撞顶，都不会阻止进入发射流程。配置非法、真实出生阻挡或 Spawn 失败分别记录明确结果；不能把这些异常伪装成“弹道无解所以不发射”。

## 7. 预警与发射同步

Launcher 仍关闭 Tick，使用 Timer：

```text
OnTrigger
    -> 缓存首个目标与最后有效目标状态
    -> State = Warning
    -> 立即 UpdateWarningAim()
    -> 每 0.05 s 更新一次理想解和机械目标
    -> AimPivot 按真实经过时间、最大 90°/s 转向
    -> 0.55 s 到时 FireLockedTarget()
```

`FireLockedTarget()` 必须先同步执行最后一次采样，再读取实际 AimPivot/ProjectileSpawnPoint 变换；不能依赖 Timer 恰好在同一帧先运行。

`EndPlay`、`DisableHazard` 和进入 `Spent` 时统一清理 Warning Timer、Aim Timer、目标弱引用和预警表现。

## 8. 出生净空与堵膛

数学回退和物理堵膛是两件事：

- “算不出精确命中”仍然发射。
- “真实胶囊质心位置已经被实体占据”不能生成重叠刚体，否则会再次出现乱飞和穿透。

### 8.1 结构化结果

```cpp
enum class EProjectileSpawnCheck : uint8
{
    Clear,
    StaticAssemblyFault,
    RuntimeObstruction,
    InvalidQuery
};

struct FProjectileSpawnCheckResult
{
    EProjectileSpawnCheck Result = EProjectileSpawnCheck::InvalidQuery;
    TWeakObjectPtr<UPrimitiveComponent> BlockingComponent;
    FVector ApproximateContactPoint = FVector::ZeroVector;
    FString Reason;
};
```

### 8.2 两个阶段

1. **BeginPlay 装配预检**
   - 在中性炮轴下检查最终质心位置的完整胶囊 Overlap，并按第 2 阶段相同规则可选检查短 Margin；不从 Muzzle 中心 Sweep 完整胶囊。
   - Launcher 自身或 WorldStatic 结构阻挡视为 Blueprint/PCG 装配错误。
   - 在玩家触发前进入 `Disabled` 并明确日志。

2. **Fire 最终姿态检查**
   - 权威检查是在最终 ProjectileSpawnPoint 位置用实际半径/半高做完整胶囊 Overlap；刚体从未以“质心位于 Muzzle 平面”的姿态存在，因此禁止从 Muzzle 中心开始 Sweep 一个完整胶囊。
   - 若还需检查 10 cm 出生 Margin，只从 `Muzzle + ProjectileHalfHeight * Direction` 到最终 ProjectileSpawnPoint 做短距离保守 Sweep；该辅助 Sweep 明确忽略 Launcher Owner，最终位置的完整 Overlap 仍不忽略 Launcher。
   - 镜像 ProjectileBody 对另一组件 ObjectType 的响应，同时要求对方对 `ECC_PhysicsBody` 为 Block。
   - 只把 `QueryAndPhysics` 且双方真实 Block 的组件当作可查询物理阻挡，避免 QueryOnly 假阻塞。
   - 运行时动态物体堵在不可出生区域时，本次进入 `Spent`，播放明显的卡膛/撞膛声光和机械反冲，记录 `BlockedDischarge`；不禁用整个 Blueprint，也不向阻挡物伪造一次 `AddImpulseAtLocation`。

Launcher 外壳/炮管必须用碰撞阻止普通资源进入质心出生保护区。玩家把资源放在炮口前方正常弹道上时，弹体会真实生成并由 Chaos 撞上它；只有传送或极端堆叠把物体塞进出生体积时才走 `BlockedDischarge`。

UE Scene Query 无法可靠发现 `PhysicsOnly` 或 `NoCollision` 外壳，因此 Blueprint/PCG 装配合同必须是 `QueryAndPhysics + Block PhysicsBody`；代码不能把查询结果宣称为无条件覆盖一切炮管碰撞。

## 9. Projectile 物理实现

### 9.1 状态

```text
Uninitialized
    -> Ballistic      // 已施加一次冲量，尚未发生首个有效阻挡接触
    -> FreePhysics    // 首碰后，仅切阻尼/表现标签
    -> Sleeping

非法初始化 -> Disabled
```

`Ballistic` 与 `FreePhysics` 使用同一个 `UCapsuleComponent`、同一个 Chaos 刚体，不切换 SimulatePhysics，不复制速度。

### 9.2 初始化顺序

```cpp
ProjectileBody->SetCapsuleSize(Radius, HalfHeight);
ProjectileBody->SetMassOverrideInKg(NAME_None, ProjectileMass, true);
ProjectileBody->SetCollisionEnabled(ECollisionEnabled::QueryAndPhysics);
ProjectileBody->SetSimulatePhysics(true);
ProjectileBody->SetEnableGravity(true);
ProjectileBody->SetLinearDamping(0.0f);
ProjectileBody->SetAngularDamping(BallisticAngularDamping);
ProjectileBody->SetUseCCD(true);

const float ActualMass = ProjectileBody->GetMass();
ProjectileBody->AddImpulse(
    PendingLaunchVelocity * ActualMass,
    NAME_None,
    false);
```

在施加冲量前校验质量、速度和 SpawnTransform 均为有限值；`PendingLaunchVelocity.Size()` 必须与推导初速在容差内一致。

### 9.3 首碰

首个真实 Blocking Hit 只做：

- 记录接触点、法线、NormalImpulse、线/角速度和是否 `StartPenetrating`。
- `Phase = FreePhysics`。
- 切换为首碰后阻尼。
- 触发撞击表现。

不停止物理、不重设速度、不关闭 CCD、不增加反弹次数脚本。后续路线变化完全来自 Chaos 接触。

## 10. HeavyImpact 边界

第一轮弹道/画面验收默认把新增 `bEnableHeavyImpactPreparation` 设为 `false`。原因是当前最重要的问题是“看不清、打不中、穿墙”，不能再用重受击是否触发反向逼迫速度和质量。

开关为 `false` 时，PreparationVolume 始终保持 `NoCollision`，不绑定 Overlap、不启动 Timer，也不读取 LookAhead/Lead 等 HeavyImpact 字段；只有开关为 `true` 时才校验和使用整套准备配置。

现有 HeavyImpact 准备代码保留在 Projectile 中，待弹道画面通过后可由同一 DataAsset 开启，不抽公共层。开启时必须把当前匀速预测修正为带重力：

```text
沿接近方向：
Gap = ClosingSpeed * t + 0.5 * GravityAlongApproach * t^2

弹体预测中心：
P(t) = P0 + V0 * t + 0.5 * Gravity * t^2
```

真实接触仍是唯一提交依据。是否最终把该机关定义为轻受击或重受击，是弹道手感验收后的独立策划选择。

## 14. 验证矩阵

### 14.1 静态与构建

- 六文件中不再引用 Thruster、Projectile Tick、飞行中目标或动力阶段字段。
- `IsConfigured()` 覆盖全部新字段和关系，没有已删除字段。
- Demo 模块先 `-NoLink`，再正常关闭 Editor 后仅完整链接 Demo 模块；不编译 UE 引擎。
- Blueprint 以警告视为错误编译、保存并回读组件树/父类。
- DataAsset 逐字段回读；Level0 两个实例和实际触发交点回读。

### 14.2 开发期诊断

仅在调试开关启用时画出：

- 目标当前点与预测点。
- 理想弹道方向、机械限制后方向、发射时实际炮管方向。
- Muzzle 出口与 ProjectileSpawnPoint 质心。
- 预测抛物线；只用于观察，不决定发射。
- 解类型、迭代次数、时间/位置残差、是否 Yaw/Pitch/Slew Limited。

### 14.3 PIE 画面与物理验收

1. **近距静止目标**：把测试目标放在距质心出生点约 600～700 cm 内，记录命中/偏差；不应再存在固定约 55 cm 的弹道起点系统偏移。
2. **正面继续行走**：从约 900～1100 cm 真实 BeginOverlap 位置触发并保持约 5 m/s 前进，先读到 0.55 s 预警和炮管，再观察约 0.42～0.56 s 的预期飞行。实测不满足时调整参数/布局，但不阻止该发进入发射流程。
3. **预警期急停/后退/横移**：属于有效躲避；弹体不在离膛后拐弯补救。
4. **转角正面**：转弯取得视线后才触发，观感与直段属于同一类武器。
5. **物理资源阻挡**：放在出生保护区之外时由真实弹体撞击并改变双方 Chaos 状态。
6. **墙/顶/地面**：第一次和后续接触均由同一刚体连续反弹。
7. **薄墙专项**：至少连续多发观察 CCD；若仍稳定穿透，再依据碰撞厚度、速度、Chaos 设置处理，不能提前宣称解决。
8. **无精确解**：日志显示回退层级且仍发射。
9. **机械限角/转速不足**：炮管外观与实际弹道一致，偏差有日志。
10. **出生装配错误**：触发前 Disabled；运行时极端堵膛有明显 BlockedDischarge，不产生重叠弹体。

### 14.4 第一轮验收目标

只验收：

- 玩家能看清“有一个实体被发射过来”。
- 默认直行路线有较高命中可能。
- 发射后走位能够躲避。
- 弹体从出生起就是真实 Chaos，并能和环境/资源连续互动。
- 不再稳定复现出生乱飞和薄墙穿透。

不以重受击是否触发判断弹道成功，也不要求一次调参覆盖所有 PCG 摆位。

## 15. 本稿采用的默认设计决定

为了让下一步可直接进入实现门禁，本稿不再悬置三个核心选择：
