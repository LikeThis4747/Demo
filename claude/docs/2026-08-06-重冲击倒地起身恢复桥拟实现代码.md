## 1. 这版要做成什么画面

角色被摆锤或冲锤真实撞飞后，身体仍由当前 Chaos + Physics Control 方案决定飞行、翻滚和最终倒地位置。身体稳定后：

1. 在最终物理倒地点停留约 0.5 秒；
2. 判断角色现在是正面朝上还是朝下；
3. 检查当前位置是否放得下直立 Capsule；
4. 原位置放不下时，只在身体附近最多 60 cm 内寻找最近安全点；
5. 先冻结当前物理姿势，关闭物理模拟后不出现突然“立正”；
6. 在现有 AnimBP 的 `DefaultSlot` 中播放对应起身动画；
7. 动画结尾用 Montage Blend Out 混回 Idle，而不是硬切最后一帧；
8. 动画结束后才恢复玩家移动或 AI 追逐。

空间始终不足时，角色继续保持倒地并定时重试。不会回到受击前位置，不会挪到远处，不会穿墙，也不会因为超时突然站起来。

## 3. ABP 和 Montage 选型

结论：**确定使用 ABP + Montage。** 推荐首版使用 UE 官方 API 生成“动态 Montage”，不是切到 `AnimationSingleNode`，也不是绕开 AnimBP。

### 3.1 两种做法对比

| 方案 | 怎么播放 | 新资产 | 适合点 | 代价/问题 |
|---|---|---:|---|---|
| A. 四个保存的 Montage 资产 | 四条 AnimationSequence 各做一个 Montage，再由 ABP Slot 播放 | 4 | 可视化编辑 Section、Notify、复杂 Root Motion | 当前只需完整播放一次，没有 Section/Notify 需求；多四份资产和装配工作 |
| **B. 动态 Montage（推荐）** | `PlaySlotAnimationAsDynamicMontage()` 把现有 Sequence 临时包装成 Montage，经 `DefaultSlot` 播放 | 0 | 仍有 Blend In/Out、结束回调；最少动画资产工作 | 以后若需要复杂 Section/Notify，要切换成保存的 Montage |

推荐 B 的原因不是“不要 Montage”，而是四条 AnimationSequence 已经齐全，UE 可以在运行时为它们生成临时 Montage。我们仍然保留完整的 AnimBP、Slot、Montage 混合和结束回调。

这层选择封装在 `PlayRecoveryAnimation()` 内。以后若效果需要保存的 Montage，状态机、安全落点、Pose Snapshot 和 ABP 结构都不改，只替换 DataAsset 字段类型与这一处播放函数。

### 3.2 为什么动画最后一帧不会硬切 Idle

`DefaultSlot` 的底层输入一直是原 locomotion/Idle。起身动态 Montage 设置约 0.30 秒 Blend Out；临近结束时，Slot 自动把起身姿势逐步混回底层 Idle。因此首版不额外找“起身结束过渡动画”。

如果 PIE 仍能看出脚或髋在结尾滑一下，再基于真实画面选择：

- 调整 Blend Out 时间；
- 调整动画 PlayRate；
- 最后才考虑在 Slot 后加 UE 的 Inertialization 节点。

首版不同时堆三种修饰，避免又做出“代码很多、画面只变一点”的结果。

## 4. 权威与职责边界

### 4.1 `UHeavyImpactResponseComponent` 继续是唯一状态 Owner

它唯一写入 `EHeavyImpactState`，并负责：

- 倒地等待和重试 Timer；
- 正躺/趴倒判断；
- 附近安全 Capsule 位置；
- 物理 Mesh 到动画 Mesh 的交接；
- 动态 Montage 播放和结束；
- 最后恢复 CharacterMovement。

玩家 Character、追猎者 Character、机关和 AnimBP 都不能各自再维护一套起身状态。

### 4.2 新增 `UHeavyImpactAnimInstance` 只做表现桥

它只保存/释放 Pose Snapshot，向 AnimGraph 暴露一个布尔量；不判断空间、不决定起身时机、不写 HeavyImpact 状态。

### 4.3 DataAsset 只保存角色差异

玩家和追猎者各自保存自己的两条动画、骨骼名、朝向修正和时序参数。共享算法不按 Actor 名、关卡名或骨架资产名分支。

```cpp
#include "Animation/PoseSnapshot.h"

    TEXT("HeavyImpactDownedPose"));

bool UHeavyImpactAnimInstance::CaptureHeavyImpactDownedPose()
{
    SavePoseSnapshot(DownedPoseSnapshotName);
    const FPoseSnapshot* Pose = GetPoseSnapshot(DownedPoseSnapshotName);
    bUseHeavyImpactPoseSnapshot = Pose && Pose->bIsValid;
    return bUseHeavyImpactPoseSnapshot;
}

{
    // 让 AnimGraph 从冻结物理姿势混向正在播放的 Slot。
    bUseHeavyImpactPoseSnapshot = false;
}

void UHeavyImpactAnimInstance::ClearHeavyImpactDownedPose()
{
    bUseHeavyImpactPoseSnapshot = false;
    RemovePoseSnapshot(DownedPoseSnapshotName);
}
```

## 7. 拟修改 C++：快照寿命

### 7.1 当前问题

当前 `FHeavyImpactPreContactSnapshot` 的注释和寿命都只覆盖“预测误判回滚”。但真实撞击后起身仍需其中这些数据：

- Mesh 原附着父级、Socket 和相对 Transform；
- Mesh/Capsule 原碰撞配置；
- 每个 Physics Body 原模拟、碰撞、CCD 和 Hit 设置；
- 原 `bPauseAnims`。

如果 `CommitRealImpact()` 继续立即 `Snapshot.Reset()`，恢复时只能猜这些设置。

### 7.2 拟修改

- 把结构改名为 `FHeavyImpactCharacterSnapshot`，注释改为“整个重冲击事务的恢复基线”。
- `CommitRealImpact()` 只清空 `ActiveRequest`、预测源和准备计时，不再清空 Snapshot。
- `ActorTransform`、原速度和原 MovementMode **只允许** `CancelUncommittedPreparation()` 使用。
- 真实命中后的起身绝不读取受击前 `ActorTransform` 或速度。
- 成功完成起身或组件结束时才清空 Snapshot。

这条是“角色必须在倒下的位置起身”的代码保证，不是文字约定。

## 9. 正躺/趴倒与最终朝向

不用骨骼本地轴硬编码，直接使用世界空间骨骼位置：

```cpp
const FVector AcrossShoulders =
    (RightShoulderWorld - LeftShoulderWorld).GetSafeNormal();
const FVector TowardHead =
    (HeadWorld - PelvisWorld).GetSafeNormal();
FVector BodyFront = FVector::CrossProduct(AcrossShoulders, TowardHead).GetSafeNormal();
```

角色第一次初始化时，拿直立状态下的 `BodyFront` 与 Actor Forward 比较；若方向相反就记录一个 `-1` 校准符号。以后：

```cpp
const bool bFaceUp = FVector::DotProduct(BodyFront, FVector::UpVector) >= 0.0f;
```

最终站立朝向取身体头脚方向在地面的投影：

- 正躺：通常站起后面向脚的方向，使用 `-TowardHeadXY`；
- 趴倒：通常站起后面向头的方向，使用 `TowardHeadXY`；
- 再叠加 DataAsset 的 FaceUp/FaceDown YawOffset，修正具体动画资源方向。

如果肩线或头骨盆向量退化，使用角色当前水平 Yaw，并只记录一次 Warning；不让数学异常阻塞状态机。

## 10. 附近安全位置算法

### 10.1 搜索锚点

锚点始终是最终物理 `pelvis` 的 XY，不是受击前 Transform。Z 由向下地面 Trace 得到，再加 Capsule Half Height。

### 10.2 搜索顺序

1. 原地 `(0, 0)`；
2. 半径 20 cm 的 8 个固定方向；
3. 半径 40 cm 的 8 个固定方向；
4. 半径 60 cm 的 8 个固定方向。

每个候选点都执行：

- 向下 Trace，必须找到 `CharacterMovement::IsWalkable()` 的地面；
- 用当前 Capsule 尺寸和原碰撞响应检查直立空间；
- 调用 `UWorld::FindTeleportSpot()` 允许引擎做很小的穿插修正；
- 修正后水平距离仍必须不大于 60 cm；
- 从锚点到候选点的 Capsule Sweep 不得穿过阻挡体，防止隔着薄墙“找到”另一侧空地。

候选按距离优先，第一个成功即采用。UE5.8 运行时的 `FindTeleportSpot()` 对 XY 只尝试求解器给出的首个调整方向，因此这里保留确定性的环形候选，不能只调用一次 `FindTeleportSpot()` 就认为搜过附近空间。

### 10.3 一直找不到怎么办

- 保持 `Downed`，Mesh 仍是睡眠的物理姿势；
- 每 0.5 秒重试；
- 连续 5 秒失败只打一次 Warning，随后可把重试降为每 1 秒一次；
- 没有最终强制起身超时；
- 新的真实动态刚体撞击仍调用 `ResumeFromDownedHit()`，取消旧 Timer 后重新进入物理飞行。

这意味着一个角色真的被夹死在狭缝里时会一直倒着。死亡/传送/重生属于更上层玩法规则，首版不在底层受击组件里擅自处理。

## 11. 物理姿势到起身动画的交接

只把物理关掉再播动画会出现明显跳变。Pose Snapshot 的作用是把“关物理前的最后姿势”留在 AnimGraph 里，给 Montage 一小段时间混进来。

### 11.1 成功找到安全点后的顺序

```cpp
void UHeavyImpactResponseComponent::TryBeginRecovery()
{
    if (State != EHeavyImpactState::Downed || bPendingDownedSleep)
    {
        return;
    }

    // 在关闭物理前先完成所有可能失败的校验。
    FHeavyImpactRecoveryPlan Plan;
    FString Reason;
    if (!BuildRecoveryPlan(Plan, Reason))
    {
        ScheduleRecoveryAttempt(Tuning->RecoveryRetrySeconds);
        return;
    }

    if (!HeavyImpactAnimInstance->CaptureHeavyImpactDownedPose())
    {
        // 仍保持 Downed，不先关物理再想办法。
        ScheduleRecoveryAttempt(Tuning->RecoveryRetrySeconds);
        return;
    }

    SetState(EHeavyImpactState::Recovering);
    RecoveryPhase = EHeavyImpactRecoveryPhase::AligningFrozenPose;
    ActiveRecoverySequence = Plan.Animation;

    // Capsule 小范围放到已验证位置；Mesh 此时仍脱离，所以画面不会跟着瞬移。
    Character->SetActorTransform(
        Plan.CapsuleWorldTransform,
        false,
        nullptr,
        ETeleportType::TeleportPhysics);

    InvokeRequiredProfile(Demo::HeavyImpact::ProfileInactive);
    Mesh->SetAllBodiesSimulatePhysics(false);
    RestoreBodySnapshot();

    // KeepWorld 保持物理落地画面；随后把 Mesh 相对位置短时混到正常 Capsule 装配位置。
    Mesh->AttachToComponent(
        Snapshot.MeshAttachParent.Get(),
        FAttachmentTransformRules::KeepWorldTransform,
        Snapshot.MeshAttachSocket);

    RecoveryMeshStartRelative = Mesh->GetRelativeTransform();
    Mesh->bPauseAnims = false;
    RestoreCharacterCollisionWithoutMovement();

    RecoveryAlignmentElapsedSeconds = 0.0f;
    SetComponentTickEnabled(true);
}
```

### 11.2 为什么还要 0.15 秒 Mesh 对齐

Pose Snapshot 保存的是骨骼姿势，不会自动解决 Mesh Component 与直立 Capsule 的相对位置。直接把 Mesh 相对 Transform 设回站立默认值，整个倒地身体可能瞬间平移或转向。

所以在 Snapshot 仍显示时，短暂把 Mesh 的相对 Transform 从 `KeepWorld` 结果插值到原装配 Transform：

```cpp
const float Alpha = RecoveryAlignmentSeconds <= 0.0f
    ? 1.0f
    : FMath::Clamp(
        RecoveryAlignmentElapsedSeconds / RecoveryAlignmentSeconds,
        0.0f,
        1.0f);

Mesh->SetRelativeTransform(
    UKismetMathLibrary::TLerp(
        RecoveryMeshStartRelative,
        Snapshot.MeshRelativeTransform,
        Alpha));
```

正式代码不依赖 `UKismetMathLibrary`；会用 C++ Transform 平移/缩放插值与四元数 Slerp。上面只展示意图。

这一步不是把角色挪回受击前位置：Capsule 只在最终骨盆附近最多移动 60 cm，Mesh 从最终物理世界姿势对齐到该 Capsule。若原地空间足够，通常只有旋转和 Mesh 装配偏移。

### 11.3 播放动态 Montage

```cpp
void UHeavyImpactResponseComponent::PlayRecoveryAnimation()
{
    ActiveRecoveryMontage = HeavyImpactAnimInstance->PlaySlotAnimationAsDynamicMontage(
        ActiveRecoverySequence,
        TEXT("DefaultSlot"),
        Tuning->RecoveryMontageBlendInSeconds,
        Tuning->RecoveryMontageBlendOutSeconds,
        Tuning->RecoveryPlayRate,
        1,
        -1.0f,
        0.0f);

    if (!ActiveRecoveryMontage)
    {
        // 已经位于验证过的地面位置；安全回 Idle，不能永远锁输入。
        CompleteRecovery(TEXT("Dynamic Montage failed after physical handoff."));
        return;
    }

    FOnMontageEnded EndDelegate;
    EndDelegate.BindUObject(
        this,
        &UHeavyImpactResponseComponent::HandleRecoveryMontageEnded);
    HeavyImpactAnimInstance->Montage_SetEndDelegate(
        EndDelegate,
        ActiveRecoveryMontage);

    RecoveryPhase = EHeavyImpactRecoveryPhase::PlayingMontage;
    SetComponentTickEnabled(false);

    // 至少让 Snapshot 经过一帧 AnimGraph 求值，再开始向 Slot 混合。
    GetWorld()->GetTimerManager().SetTimerForNextTick(
        FTimerDelegate::CreateUObject(
            this,
            &UHeavyImpactResponseComponent::ReleaseRecoveryPoseSnapshot));
}
```

说明：正式实现只把本阶段必需的 `ActiveRecoverySequence` 等字段保存为组件成员，并使用项目当前 UE5.8 可编译的 Timer Delegate 重载；Review 不应把上面片段当作已经编译通过的最终文本。

### 11.4 动画结束

```cpp
void UHeavyImpactResponseComponent::HandleRecoveryMontageEnded(
    UAnimMontage* Montage,
    bool bInterrupted)
{
    if (Montage != ActiveRecoveryMontage
        || State != EHeavyImpactState::Recovering)
    {
        return;
    }

    CompleteRecovery(
        bInterrupted
            ? TEXT("Recovery Montage was interrupted; completed safely.")
            : TEXT("Recovery Montage completed."));
}

void UHeavyImpactResponseComponent::CompleteRecovery(const TCHAR* Reason)
{
    HeavyImpactAnimInstance->ClearHeavyImpactDownedPose();
    ActiveRecoveryMontage = nullptr;
    ActiveRecoverySequence = nullptr;
    RecoveryPhase = EHeavyImpactRecoveryPhase::None;

    Movement->StopMovementImmediately();
    Movement->SetMovementMode(MOVE_Walking);
    Snapshot.Reset();

    PhysicsControl->SetComponentTickEnabled(false);
    SetComponentTickEnabled(false);
    SetState(EHeavyImpactState::Inactive);
}
```

Montage 被其他系统意外打断时也完成恢复并记录 Warning，避免角色永远卡在 `Recovering`。首版 `Recovering` 期间忽略新的重冲击准备请求，相当于约两秒的起身保护；不在起身中途重新开 ragdoll。

```text
Main States
    ↓

    ↓

    ↓
```

## 13. 完整状态流程

| 当前状态 | 事件 | 结果 |
|---|---|---|
| `Downed` | 刚体睡眠完成 | 0.5 秒后尝试起身 |
| `Downed` | 空间不足 | 保持倒地，0.5 秒后重试 |
| `Downed` | 60 cm 内有安全点 | 捕获 Snapshot，进入 `Recovering` |
| `Downed` | 被真实动态刚体再次撞击 | 取消起身 Timer，回 `Simulating` |
| `Recovering` | 冻结姿势对齐完成 | 播放正躺/趴倒动态 Montage |
| `Recovering` | Montage 正常结束 | 恢复 Walking，进入 `Inactive` |
| `Recovering` | Montage 被打断/播放失败 | 记录错误，在安全地面位置恢复 Idle，进入 `Inactive` |
| `Recovering` | 新的预测请求 | 返回 Busy，不中断起身 |

## 14. PCG 关卡与 AI

- 算法只依赖碰撞、地面法线、Capsule 尺寸和角色当前骨骼位置，不依赖 `Level0`、房间 Actor 名或手摆 Actor。
- 20/40/60 cm 的附近搜索能用于 PCG 生成的墙角、窄走廊和障碍旁。
- 共享层首版只保证“物理可站立”；不把玩家恢复强行依赖 NavMesh。
- 追猎者现有 `IsReacting()` 已把 HeavyImpact Busy 视为反应中；状态回到 `Inactive` 后，AI Controller 下一轮 Think 应恢复追逐。
- PIE 必须额外验证追猎者起身点仍能继续寻路。若真实案例出现“能站但不在 NavMesh”，再在 AI 适配层增加导航投影；不提前把导航依赖塞进玩家共享恢复算法。
