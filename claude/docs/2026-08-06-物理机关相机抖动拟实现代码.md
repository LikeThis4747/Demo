## 2. 拟修改 C++

文件：`Source/Demo/Private/Characters/ZeroEscapeCharacter.cpp`

位置：`AZeroEscapeCharacter::AZeroEscapeCharacter()` 构造函数末尾，两个默认子对象都创建完成之后。

```cpp
	PhysicsControl = CreateDefaultSubobject<UPhysicsControlComponent>(TEXT("PhysicsControl"));
	PhysicsControl->SetupAttachment(GetRootComponent());
	PhysicsControl->SetAutoActivate(false);
	HeavyImpactResponse = CreateDefaultSubobject<UHeavyImpactResponseComponent>(TEXT("HeavyImpactResponse"));

	// HeavyImpact 先在 PostPhysics 更新角色根节点，弹簧臂再读取同帧的最终位置。
	CameraBoom->AddTickPrerequisiteComponent(HeavyImpactResponse);
```

### 为什么不写额外判空

`CameraBoom` 和 `HeavyImpactResponse` 都是同一构造函数中由 `CreateDefaultSubobject` 创建的必备默认子对象。这里不是运行时查找或可选资源装配；若默认子对象创建失败，角色本身已经不满足可运行前提。增加静默判空只会掩盖构造错误。

### 为什么不需要清理依赖

更新依赖只存在于两个同属玩家 Actor 的组件 TickFunction 之间，组件销毁时由 UE 生命周期一并清理。本方案不注册全局 Delegate、Timer 或异步回调。

## 4. 更新顺序

```text
Chaos 完成本帧物理解算
        ↓
HeavyImpactResponse（仅事务期间 Tick）
        ↓  跟随骨盆，更新 Actor/Capsule 根节点
CameraBoom（AddTickPrerequisiteComponent 保证随后运行）
        ↓  对根节点位置做轻量 Camera Lag
SpringArm 执行 ECC_Camera 墙体 Sweep
        ↓
FollowCamera 得到最终位置
```

## 5. UE5.8 原生边界

UE5.8 的 `USpringArmComponent::UpdateDesiredArmLocation` 先对弹簧臂起点应用 Camera Lag，再执行墙体 Sweep；默认 `BlendLocations` 在命中墙体时直接选择命中位置。因此：

- 本代码能够过滤 HeavyImpact 根节点的逐帧位置变化。
- 本代码能够固定 HeavyImpact 与 CameraBoom 的同帧读取顺序。
- 本代码保留墙体防穿透。
- 本代码不能把墙体命中位置本身变成平滑插值，也不能处理锤头网格进入相机近裁剪面。

`bClampToMaxPhysicsDeltaTime` 会无条件把 Camera Lag 使用的 `DeltaTime` 限制为物理最大时间步，但按常见 `1/30 s` 上限，它只在帧率低于约 `30 FPS` 时明显介入。因此它是卡顿时的保险；正常帧率下的主要效果来自更新依赖、`CameraLagSpeed` 与 `CameraLagMaxDistance`。

## 6. 不采用的第一版代码

以下代码方向本轮不写：

```cpp
// 不关闭地牢墙体碰撞。
CameraBoom->bDoCollisionTest = false;

// 不用缩小探头掩盖碰撞边界；这会增加穿墙概率。
CameraBoom->ProbeSize = 2.0f;

// 不启用旋转延迟；相机输入手感与位置抖动是两件事。
CameraBoom->bEnableCameraRotationLag = true;

// 不在 Character Tick 中重复插值，也不创建第二套相机状态机。
PrimaryActorTick.bCanEverTick = true;
```

也不在第一版监听 `HeavyImpactResponse->OnStateChanged` 动态开关位置延迟。全局轻量配置验证通过后，只有用户认为正常跑动明显拖沓，才考虑状态化开关并保存/恢复 Blueprint 初始值。
