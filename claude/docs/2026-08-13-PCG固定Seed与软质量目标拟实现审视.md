# PCG 固定 Seed、软质量目标与无终局失败：拟实现代码及自审

- 日期：2026-08-13
- 状态：讨论稿 / 代码预览，尚未授权修改功能代码
- Owner：Codex（当前会话）
- 适用范围：多层布局规划、单层 Grid-WFC、公开 Seed 流程、高厅结构保证与导航诊断
- 明确排除：楼梯多开口组合、三层楼梯表现调整、机关与资源投放规则、高厅灯光、Loading UI

## 1. 结论

这轮不需要换求解器，也不需要新增一套通用“质量系统”。建议继续使用现有二维 Grid-WFC，只做五类收敛修改：

1. **公开 Seed 从玩家确认后到本局结束永不改变。** 删除 GameMode/GameInstance 的自动换 Seed 重载；同一 Seed 内部允许固定次数、固定顺序的候选搜索，但最终结果必须确定。
2. **真正的合法性继续是硬约束，审美和数量指标改为软目标。** 普通格数量、整栋总格数、路线覆盖、端点分散、最长直线不再否决一张合法地图，而是从搜索开始影响权重，并用于最多三张合法候选之间择优。
3. **保留同一 Public Seed 内的确定性结构候选尝试，但只允许硬结构失败触发。** 现有 `WholeAttempt=0..3` 还负责改变楼梯开口组合与同分候选顺序，今晚不重写整棵结构搜索；质量不足和 WFC 预算耗尽不再触发整栋重做。
4. **WFC 没在固定预算内找到合法结果时，同一层做确定性收敛。** 它复用现有 Required/Open/Closed 约束和 16 种 OpeningMask，不生成第二套地图、不更换 Seed，也不新增生产文件。
5. **高厅改为构造阶段直接保证。** 每栋至少两个，且至少一个不在顶层；高厅先于可选楼梯占位，距离只参与候选排序，不再因“不够分散”而拒绝。

核心改动集中在 `ZeroEscapeWfcSolver`、`ZeroEscapeGridLayoutSolver` 和 `ZeroEscapeMultiFloorLayoutPlanner`。随机版本字段删除与 Seed 重试清理会机械性扩散到数据合同、GameFlow、Population 调用点和测试。

**不新增生产 C++ 文件，不删除生产文件，不引入 OR-Tools、MaxSAT、MIP、GAN 或三维 WFC。**

## 2. 当前实现证据与问题来源

正式配置 `/Game/ZeroEscape/Generation/Data/DA_LevelGenerationProfile` 当前关键值如下：

| 项目 | 当前值 | 当前后果 |
|---|---:|---|
| Grid | 20 × 12 | 每层 240 个逻辑格 |
| Empty 权重 | 12000 | 无约束推动时，空格占绝对优势 |
| 全部非空形态总权重 | 1025 | 初始非空倾向约为 7.87% |
| 最长连续直线 | 4 | 当前由 WFC 全局约束硬 Ban / 硬回溯 |
| WFC 每层 Solve 上限 | 10 | 质量拒绝会反复消耗整棵搜索树 |
| 路线覆盖率 | 0.75 | 当前完整叶子不足时直接 RejectBranch |
| 高厅最少数量 | 0 | 当前配置允许整栋没有高厅 |
| 高厅目标分布 | 0 个权重最高 | 玩家很难遇到高厅不是单纯“脸黑” |
| 同 Seed 内部完整布局尝试 | 4 | 当前结构、WFC 和质量失败都可能进入下一次；本方案仅保留给必要结构硬冲突 |
| 外层可恢复失败重试 | 最多 3 次 | GameMode/GameInstance 会换 Seed 后重载，造成 Seed 漂移与明显等待 |

`AlgorithmVersion=7` 不是纯记录字段：它参与随机流混合；`ProfileVersion` 主要参与签名、Hash 与配置校验。直接删除前者而不处理固定扰动，会顺便洗牌本轮不准备修改的机关与资源随机子流。

现有 `FWfcSolver` 已经具备：

- 带权 Shannon 熵选择待折叠格；
- 按权重生成无放回候选顺序；
- 边界、相邻开口、Count、MaxConsecutive、Connected 传播；
- 有界候选尝试与回溯；
- 完整候选回调验收。

因此问题不是“当前 WFC 完全不会优化”，而是**过多质量指标被接进了矛盾和拒绝路径，同时 Empty 权重没有根据每层期望密度调整**。

## 3. 参考资料如何映射到本项目

这里的“硬约束 / 软目标”是约束求解领域的通用建模分类，不是 UE 官方类型名。

- 原始 WFC 区分局部图案合法性和图案分布：前者必须成立，后者只要求近似；观察阶段就按权重选择，不是先生成再在末尾全盘拒绝。[WaveFunctionCollapse 原始实现](https://github.com/mxgmn/WaveFunctionCollapse/)
- Sturgeon 的公开资料将目标表述为满足全部硬规则、尽量满足更多软规则；数量分布可以作为软规则，可达性是否为硬规则取决于玩法是否必须使用。[GDC 2023 幻灯片](https://media.gdcvault.com/gdc2023/Slides/BeyondWaveFunctionCollapse_Cooper_Seth.pdf)、[AIIDE 论文页](https://ojs.aaai.org/index.php/AIIDE/article/view/21944)
- 通用求解器区分“已找到可行结果”和“已证明最优结果”：达到计算上限时可以交付可行结果，不必把“还没找到最好”解释成失败。[Google OR-Tools CP Solver](https://developers.google.com/optimization/cp/cp_solver)
- 确定性应使用固定节点、候选和回溯工作量，而不是 wall-clock 时间；机器负载不同会让按时间截止的结果漂移。[Gurobi Determinism](https://support.gurobi.com/hc/en-us/articles/360031636051-Is-Gurobi-deterministic)
- 关卡修复研究通常保留可玩性为硬条件，并以尽量少的局部编辑修复候选，而不是整张图和 Seed 全部推倒重来。[Repairing Mario Levels](https://arxiv.org/abs/2010.06627)

本方案只借用这些原则，不把项目迁移到外部优化库。

## 4. 最终规则分类

| 规则 | 分类 | 生成时行为 | 理由 |
|---|---|---|---|
| 玩家看到的 Public Seed 永不改变 | 产品硬规则 | 外层禁止自增、换 Seed、因失败重载 | Seed 是玩家对地图身份的理解 |
| 同 Public Seed + Difficulty 必须得到同地图 | 确定性硬规则 | 固定随机域、稳定遍历、固定工作量预算 | 不能由机器速度或线程完成顺序决定 |
| 同 Seed 内部结构 Attempt 最多 4 个 | 固定工作量机制 | 仅必要楼梯、高厅或 Required 潜在图硬冲突可进入下一 Attempt | 保留现有开口组合覆盖，但不向玩家暴露为换地图 |
| Outside、边界、RequiredOpen/RequiredClosed 合法 | 结构硬约束 | 非法候选被传播排除 | 否则会产生墙体和接口错误 |
| 公共边开口双向一致 | 结构硬约束 | WFC 传播或收敛构造直接保证 | 相邻模块必须能拼接 |
| 所有非空格连通 | 玩法硬约束 | Connected 保留；收敛结果也验证 | 避免孤岛房间 |
| Enter、Leave、楼梯、高厅等 Required 端点存在并连通 | 玩法硬约束 | 构造与 BFS 验证 | 主路线必须可走 |
| 一层至少 2 个普通格，其他层至少 1 个普通格 | 最小可用硬约束 | 只保留很低的硬下限 | 不能把 26～30 当作合法性下限 |
| 每栋至少 2 个高厅，至少 1 个非顶层 | 产品硬规则 | 结构阶段构造保证 | 用户已明确要求，且现有递归可直接实现 |
| 每层普通格当前最低值 26～30 | 软目标 | 参与 Empty 权重和候选评分 | 少一两个不应让整图失败 |
| 整栋总可走格范围 | 软目标 | 以范围中点分配目标，偏离只扣分 | 密度质量不是合法性 |
| 最长连续直线 4 | 软目标 | 搜索过程中降权，完成图超出再扣分，永不置零 | 偶尔长直线可接受，但不能主动偏爱 |
| Required 路线覆盖率 0.75 | 软目标 | 只记录和评分，不 RejectBranch | 低于 0.75 仍可能是合法地图 |
| 楼梯/Exit 端点分散 0.65 | 软目标 | 保留从远到近排序，删除阈值拒绝 | 主动追求分散，不因空间不足失败 |
| 玩家与追猎者起点 1200 cm | 软目标 | 优先满足；否则选最远合法普通格 | 不足不应废掉整张图 |
| 玩家到 Exit 最大路线 | 删除 | 删除字段、校验和拒绝逻辑 | 当前没有明确玩法价值 |
| 可选楼梯数量与分散 | 软目标 | 高厅之后再放；无候选/可选预算不足跳过；造成硬断连则恢复必需结构快照一次 | “可选”不能拖垮整栋 |
| Recast 导航完成与路径可查询 | 运行系统门槛 | 保留异步等待；失败不得换 Seed | 不能用换地图掩盖碰撞或导航配置问题 |

DataAsset 中部分字段名仍叫 `Min...`。本轮若直接重命名嵌套 UPROPERTY，会产生资产迁移和 Core Redirect 风险。建议先保留这些序列化字段名，只改注释及运行语义为“软目标”；明确不再需要的 `MaxPlayerToExit...` 与 Version 字段则删除。

## 5. 拟实现总流程

```text
玩家确认 Public Seed + Difficulty
        │
        ▼
同一 Public Seed 内选择结构候选顺序（最多 4 个稳定 Attempt Salt）
        │
        ▼
放置必要楼梯链
        │
        ▼
构造保证 2 个高厅（第 1 个禁止顶层）
        │
        ├─ 必要结构硬失败 → 同 Seed 下一个结构 Attempt
        │
        ▼
尝试可选楼梯（无合法候选或可选预算不足就跳过）
        │
        ▼
逐层 WFC：最多 3 棵确定性树
  ├─ 第一张硬合法图立即保存
  ├─ 后续候选只用于软质量择优
  └─ 质量不足绝不 Reject
        │
        ├─ 有硬合法候选 → 提交最佳候选
        │
        └─ 无硬合法候选 → 同层确定性收敛
                                  │
        │
        ▼
同 Seed 实例化 → 等待 Recast 完成 → 记录导航结果
```

内部最多 4 个 Attempt 始终派生自同一个 Public Seed，不改玩家 Seed，也不重载关卡。它们暂时保留，是因为当前楼梯的 Opening Set 每个姿态只按 Attempt 抽一个组合；今晚强行删掉会要求把楼梯、高厅和所有开口组合改成一棵联合递归，范围过大。普通格差一点、覆盖不足、路线太长、直线超过 4 格或 WFC 搜索预算耗尽都不再进入下一个整栋 Attempt；WFC 预算问题在当前楼层直接收敛。

## 6. 关键拟实现代码

以下是按当前真实接口写出的落盘预览。正式实现时可为编译调整局部名字，但不得改变算法边界。

### 6.1 删除 Version，但限制无关随机序列的变化

当前 `AlgorithmVersion=7` 对随机混合的固定贡献是 `0x5384540F`。删除字段后，将这一固定常量直接融合进混合过程：

```cpp
FRandomStream FGenerationCore::MakeRandomStream(
    const int32 PublicSeed,
    const ERandomDomain Domain,
    const int32 Salt)
{
    uint32 Mixed = static_cast<uint32>(PublicSeed);

    // 固定随机扰动，不是版本号，也不进入生成签名。
    // 保留它是为了不额外洗牌本轮未修改的 Population 随机域。
    Mixed ^= 0x5384540Fu;
    Mixed ^= static_cast<uint32>(Domain);
    Mixed ^= static_cast<uint32>(Salt) * 0x85EBCA6Bu;

    // 现有整数 avalanche 混合保持不变……
    return FRandomStream(static_cast<int32>(Mixed));
}

struct FZeroEscapeGenerationSignature
{
    int32 Seed = 0;
    EZeroEscapeDifficulty Difficulty = EZeroEscapeDifficulty::Normal;
};
```

删除：

- `GAlgorithmVersion`；
- `ProfileVersion`；
- `AlgorithmVersion`、`GenerationProfileVersion`；
- 签名 Hash 中的 Version 字段；
- 所有调用点中的版本参数。

这不是旧 Seed 兼容层，也不承诺未来算法更新后还原旧地图；它只避免本次改动顺便改变完全无关的机关和资源抽样。

### 6.3 从第一次观察就修正 Empty 倾向

不把动态全局评分回调塞进 WFC 内核，只在每棵树开始前根据该层目标计算一次有效 Empty 权重：

```cpp
static int32 ComputeEffectiveEmptyWeight(
    const FZeroEscapeWfcShapeWeights& SourceWeights,
    const int32 OptionalCellCount,
    const int32 DesiredOptionalNonEmpty)
{
    if (DesiredOptionalNonEmpty <= 0 || OptionalCellCount <= 0)
    {
        return SourceWeights.EmptyWeight;
    }

    if (DesiredOptionalNonEmpty >= OptionalCellCount)
    {
        return 1;
    }

    const int64 NonEmptyWeight = SourceWeights.GetTotalNonEmptyVariantWeight();
    const int64 TargetEmptyWeight =
        NonEmptyWeight * (OptionalCellCount - DesiredOptionalNonEmpty)
        / DesiredOptionalNonEmpty;

    return static_cast<int32>(FMath::Clamp<int64>(
        FMath::Min<int64>(SourceWeights.EmptyWeight, TargetEmptyWeight),
        1,
        MAX_int32 - NonEmptyWeight));
}
```

明确给单层输入增加“硬下限”和“软目标”两组纯值，避免继续借用旧 `Min...` 字段造成语义混乱：

```cpp
struct FZeroEscapeConstrainedFloorInput
{
    // 结构与端点字段保持……
    int32 HardMinimumOrdinaryWalkableCellCount = 1;
    int32 PreferredOrdinaryWalkableCellCount = 1;
    int32 PreferredTotalWalkableCellCount = 1;
    int32 PreferredMaxConsecutiveStraightTiles = 4;
    double PreferredRouteCoverageRatio = 0.75;
};
```

Planner 负责把整栋目标分到每层，并裁剪到该层真实容量；Grid Solver 不直接读取 `FloorOption`：

```cpp
const int32 AllocatedWholeMidpoint =
    (FloorOption.MinTotalWalkableCellCount
        + FloorOption.MaxTotalWalkableCellCount) / 2;
const int32 AllocatedFloorTotal =
    AllocatedWholeMidpoint / FloorOption.FloorCount
    + (FloorIndex < AllocatedWholeMidpoint % FloorOption.FloorCount ? 1 : 0);

const int32 HardOrdinary = FloorIndex == 0 ? 2 : 1;
const int32 FixedStructure = CountStructureWalkableCells(FloorInput);
const int32 PossibleTotal = CountNonOutsideCells(FloorInput);
const int32 PossibleOrdinary = FMath::Max(0, PossibleTotal - FixedStructure);

FloorInput.HardMinimumOrdinaryWalkableCellCount = HardOrdinary;
FloorInput.PreferredOrdinaryWalkableCellCount = FMath::Clamp(
    FMath::Max(
        FloorOption.MinOrdinaryWalkableCellCountPerFloor,
        AllocatedFloorTotal - FixedStructure),
    HardOrdinary,
    PossibleOrdinary);
FloorInput.PreferredTotalWalkableCellCount = FMath::Clamp(
    FMath::Max(
        AllocatedFloorTotal,
        FixedStructure + FloorInput.PreferredOrdinaryWalkableCellCount),
    FixedStructure + HardOrdinary,
    PossibleTotal);
```

Grid Solver 再根据这组已裁剪输入计算每棵树的有效权重：

```cpp
const int32 ForcedOrdinaryCount = CountForcedOrdinaryCells(Input);
const int32 OptionalCellCount = CountOptionalCells(Input);
const int32 DesiredOptionalNonEmpty = FMath::Clamp(
    Input.PreferredOrdinaryWalkableCellCount - ForcedOrdinaryCount,
    0,
    OptionalCellCount);

FZeroEscapeWfcShapeWeights EffectiveWeights = Weights;
EffectiveWeights.EmptyWeight = ComputeEffectiveEmptyWeight(
    Weights,
    OptionalCellCount,
    DesiredOptionalNonEmpty);
```

这样普通格目标和整栋中点目标不会互相制造“不可能同时满足”的评分项，也不会因为某层结构多就系统性压缩普通格。DeadEnd/Straight/Corner/T/Cross 的相对比例保持不变，软目标从第一次观察就开始影响结果。

### 6.4 最长直线从硬 Ban 改为上下文降权

只在整图结束后打分不够，因为它不能阻止搜索过程持续选择同一轴。本次自审后修正为：

- WFC 仍按原带权熵选 Cell；
- 仅在该 Cell 建立候选顺序时，根据相邻已强制贯通的轴线长度调整本次权重；
- 超过期望长度后逐级降权，但最低为 1，永远不删除候选；
- 空间只能直走时，长直线仍然合法。

在现有 `FZeroEscapeWfcSolveSettings` 增加一个仅供选择启发式使用的软值：

```cpp
struct FZeroEscapeWfcSolveSettings
{
    // 原硬约束值：调用方设为网格最长轴，使旧 MaxConsecutive 不再 Ban。
    int32 MaxConsecutiveStraightTiles = 1;

    // 新软目标：只调候选权重，绝不产生 Ban 或矛盾。
    int32 PreferredMaxConsecutiveStraightTiles = 4;
};
```

候选排序局部改造：

```cpp
static int32 ApplyStraightPreference(
    const int32 BaseWeight,
    const int32 PredictedRunLength,
    const int32 PreferredMaxStraight)
{
    const int32 Excess = FMath::Max(
        0,
        PredictedRunLength - PreferredMaxStraight);
    const int32 Divisor = 1 + 3 * Excess * Excess;
    return FMath::Max(1, BaseWeight / Divisor);
}

bool BuildWeightedCandidateOrder(
    const FIntPoint GridSize,
    const int32 CellIndex,
    const TArray<FWfcDomain>& Domains,
    const FZeroEscapeWfcSolveSettings& Settings,
    FWfcDomain RemainingDomain,
    const TArray<FTileVariant>& Variants,
    FRandomStream& Random,
    TArray<uint8, TInlineAllocator<16>>& OutOrder)
{
    TStaticArray<int32, 16> ContextWeights;
    for (int32 VariantIndex = 0; VariantIndex < Variants.Num(); ++VariantIndex)
    {
        const int32 PredictedRun = MeasureForcedAxisRunIfChosen(
            GridSize,
            CellIndex,
            Domains,
            Variants[VariantIndex].OpeningMask);

        ContextWeights[VariantIndex] = ApplyStraightPreference(
            Variants[VariantIndex].Weight,
            PredictedRun,
            Settings.PreferredMaxConsecutiveStraightTiles);
    }

    return BuildWeightedOrderWithoutReplacement(
        RemainingDomain,
        ContextWeights,
        Random,
        OutOrder);
}
```

`MeasureForcedAxisRunIfChosen` 只扫描当前格所在行或列，判断相邻 Domain 是否已经强制 East+West 或 North+South。20×12 网格上成本很小，不改变传播、Trail 或回溯状态机。

这里的 `MeasureForcedAxisRunIfChosen` 是拟新增的 cpp-local 函数；`BuildWeightedOrderWithoutReplacement` 是对现有 `ChooseWeightedVariantIndex` + `BuildWeightedCandidateOrder` 的局部重载/整理，不新增公开策略接口。

### 6.5 第一张合法图立即保存，最多三张择优

```cpp
struct FFloorQualityScore
{
    int32 UnmetGoalCount = 0;
    int64 NormalizedPenalty = 0;

    bool IsBetterThan(const FFloorQualityScore& Other) const
    {
        return UnmetGoalCount != Other.UnmetGoalCount
            ? UnmetGoalCount < Other.UnmetGoalCount
            : NormalizedPenalty < Other.NormalizedPenalty;
    }
};
```

评分固定四项，不建立可注册的通用评分框架：

1. 普通格低于期望值的归一化缺口；
2. 总可走格偏离期望值的归一化差；
3. 路线覆盖低于期望值的归一化缺口；
4. 最长直线超过期望值部分的平方惩罚。

比例用整数定标值，例如乘 10000，避免浮点比较误差决定候选胜负。

```cpp
// 以下是拟新增在 ZeroEscapeGridLayoutSolver.cpp 内的局部返回类型和包装函数，
// 不是当前仓库已经存在的公开 API。
enum class EHardTreeResult : uint8
{
    Success,
    RecoverableNoResult, // 仅 NoValidWfcSolution / SolverBudgetExhausted
    Fatal                // 配置、输入不变量、FatalCandidateError
};

TOptional<FZeroEscapeConstrainedFloorResult> BestCandidate;
FFloorQualityScore BestScore;

constexpr int32 MaxQualityCandidates = 3;
for (int32 CandidateIndex = 0;
     CandidateIndex < MaxQualityCandidates;
     ++CandidateIndex)
{
    FZeroEscapeConstrainedFloorResult Candidate;
    const EHardTreeResult TreeResult = SolveOneHardLegalTree(
        Input,
        CandidateIndex,
        Candidate,
        OutReport);
    if (TreeResult == EHardTreeResult::Fatal)
    {
        return false;
    }
    if (TreeResult == EHardTreeResult::RecoverableNoResult)
    {
        continue;
    }

    const FFloorQualityScore Score = ScoreCandidate(Input, Candidate);
    if (!BestCandidate.IsSet() || Score.IsBetterThan(BestScore))
    {
        BestCandidate = MoveTemp(Candidate);
        BestScore = Score;
    }

    if (BestScore.UnmetGoalCount == 0)
    {
        break;
    }
}

if (BestCandidate.IsSet())
{
    OutResult = MoveTemp(BestCandidate.GetValue());
    return true;
}

// CandidateIndex=3 是独立、稳定的 fallback Salt；
// 不能继承最后一棵失败 WFC 已经消耗过的 Random 状态。
FRandomStream FallbackRandom = FGenerationCore::MakeRandomStream(
    Input.Signature.Seed,
    ERandomDomain::WfcLayout,
    MakeFloorWfcSalt(
        Input.WholeLayoutAttemptIndex,
        Input.FloorIndex,
        MaxQualityCandidates));
const EFloorFallbackResult FallbackResult = BuildHardLegalFallback(
    Input,
    FallbackRandom,
    OutResult,
    OutReport);
return FallbackResult == EFloorFallbackResult::Success;
```

完全同分时保留更早的 CandidateIndex。第一张合法候选已经是可交付结果，后两张只在固定工作量内改善质量，不能把已有合法结果变回失败。正式 DataAsset 的 `MaxWfcSolveAttemptsPerFloor` 从 10 改为 3；这表示每层 WFC 搜索树数量，不是 `MaxWfcCandidateAttemptsPerFloor` 的分支尝试预算。

### 6.6 单层确定性收敛

上一版“把允许连通分量的全部边打开”虽然合法，但会使失败层过密，也不符合尽量少改动。本次自审后改为 Required 的 BFS 树路径并集，再做有限前沿生长：

下面的函数名都是拟新增在 `ZeroEscapeGridLayoutSolver.cpp` 匿名命名空间中的局部帮助函数，不是当前公开接口；正式实现不新增头文件、类或通用图框架。

```cpp
enum class EFloorFallbackResult : uint8
{
    Success,
    RequiredGraphDisconnected,
    InvalidInput
};

EFloorFallbackResult BuildHardLegalFallback(
    const FZeroEscapeConstrainedFloorInput& Input,
    FRandomStream& Random,
    FZeroEscapeConstrainedFloorResult& OutResult,
    FZeroEscapeGenerationReport& OutReport)
{
    FString Error;
    const int32 Root = Grid::ToIndex(Input.RequiredEnterCoordinate, Input.GridSize);
    TArray<int32> ParentByCell;
    BuildStableBfsParents(Input, Root, ParentByCell); // N/E/S/W 固定顺序

    for (const int32 RequiredCell : GatherRequiredCells(Input.Constraints))
    {
        if (RequiredCell != Root && ParentByCell[RequiredCell] == INDEX_NONE)
        {
            FailFloor(
                OutReport,
                EZeroEscapeGenerationStage::WfcLayout,
                EZeroEscapeGenerationFailure::NoValidWfcSolution,
                TEXT("Required 结构接口在潜在允许边图中不连通。"));
            return EFloorFallbackResult::RequiredGraphDisconnected;
        }

        OpenParentPathToRoot(
            ParentByCell,
            RequiredCell,
            OutResult.OpeningMaskByCell);
    }

    OpenAllRequiredEdges(Input.Constraints, OutResult.OpeningMaskByCell);

    while (CountOrdinaryCells(OutResult)
            < Input.PreferredOrdinaryWalkableCellCount
        && GrowOneSeededFrontierCell(
            Input,
            Input.PreferredMaxConsecutiveStraightTiles,
            Random,
            OutResult.OpeningMaskByCell))
    {
        // 新 Cell 通过一条父边接入，持续保持全局连通。
    }

    return BuildAndValidateHardRouteMetrics(Input, OutResult, Error)
        ? EFloorFallbackResult::Success
        : EFloorFallbackResult::InvalidInput;
}
```

潜在边只在以下条件同时成立时存在：

- 两侧都不是 Outside；
- 两侧对应方向都没有 RequiredClosed；
- RequiredOpen 双向合同已经通过输入校验。

收敛结果仍使用现有 0～15 OpeningMask，并再次走硬合法验收。它不是第二套表现系统，也不需要新资产。前沿生长对超过 4 格的直线提高代价但不禁止；空间不足时宁可交付长直线，也不能因为审美目标失败。

### 6.7 保留同 Seed 结构尝试，不重写结构搜索

最终自审不采纳“删除 `WholeAttempt` + 逐结构候选潜在图 + 楼梯/高厅联合递归”。原因是：

- 当前 `SelectLegalOpeningSet` 对一个结构姿态只按 `WholeAttempt` 抽取一个 Opening Set；删除 Attempt 后，其他合法开口组合可能永远不被尝试；
- 在必要楼梯递归尚未完成时，部分楼层还没有完整 Enter/Leave，逐候选潜在图会复制一套不完整的结构投影逻辑；
- 把楼梯、Exit、高厅和全部开口组合合成一棵新递归，已经超过今晚的最小稳定修改。

因此保留现有最多 4 个、同一 Public Seed 派生的确定性 `WholeAttempt`，但严格收窄用途：

```cpp
for (int32 WholeAttempt = 0;
     WholeAttempt < Input.Budget.MaxWholeLayoutAttempts;
     ++WholeAttempt)
{
    FPlacementState State;
    InitializePlacementState(Input, FloorOption, State);

    if (!PlaceRequiredRoute(Input, FloorOption, WholeAttempt, State, Budget, Report))
    {
        continue; // 只有必要楼梯/Exit 的硬结构无解
    }

    if (!PlaceHighCeilingRooms(Input, FloorOption, WholeAttempt, State, Budget, Report))
    {
        continue; // 两个必需高厅放不下，尝试同 Seed 的下一组结构顺序
    }

    // 可选结构在必需高厅之后；无候选或可选预算不足只 Skipped。
    const FPlacementState RequiredOnlyState = State;
    PlaceOptionalStairs(Input, FloorOption, WholeAttempt, State, Budget, Report);

    if (!SolveFloorsWithHardFallback(Input, FloorOption, WholeAttempt, State, ...))
    {
        if (Report.Failure == EZeroEscapeGenerationFailure::NoValidWfcSolution
            && State.Structures.Num() > RequiredOnlyState.Structures.Num())
        {
            // 可选结构不得拖垮整栋；恢复必需结构快照，在同一 Attempt 解一次。
            State = RequiredOnlyState;
            ResetPerFloorBudgets();
            if (SolveFloorsWithHardFallback(
                    Input, FloorOption, WholeAttempt, State, ...))
            {
                return CommitPlan(...);
            }
        }
        if (Report.Failure == EZeroEscapeGenerationFailure::NoValidWfcSolution)
        {
            continue; // 必要结构的 Required 潜在图本身不连通
        }
        return false; // 配置或代码不变量错误不得重试掩盖
    }

    return CommitPlan(...);
}
```

普通格、总量、覆盖率、端点距离、出生距离、路线长度和长直线全部不能 `continue WholeAttempt`。WFC 的候选/回溯预算耗尽也不能 `continue`，必须在当前层进入 `BuildHardLegalFallback`。

可选楼梯预算耗尽当前会返回 `Fatal`，实施时明确改为 `Skipped` 并清除本次可选放置留下的失败字段；因为此时必要楼梯和两个高厅已经成功，可选内容不能消耗掉整栋结果。若可选楼梯的占位使 Required 潜在图断开，只恢复一份约 2～4 层、每层 240 格的纯值 `FPlacementState` 快照并重解一次，不增加新的结构图实现，也不改变 Seed。

### 6.8 高厅构造保证

沿用现有精确数量递归，不新增高厅管理器：

```cpp
Difficulty.HighCeilingRooms.MinimumTotalCount = 2;

// 在三种 FloorOption 的 HighCeilingRoomTargetCounts 中，
// 把 Count=0、1 的 Weight 设为 0；Count>=2 保留目标分布。

PlaceRequiredStairs(State, Random);
```

### 6.10 现有质量拒绝点的逐处处理

为了避免只改一个入口、遗漏下游重复校验，实施时按真实函数逐处清理：

| 当前位置 | 当前行为 | 拟修改 |
|---|---|---|
| `FGridLayoutSolver::ValidateInput` | 要求软性的总量上下限与普通格下限同时可满足 | 只验证字段值本身合法；硬容量只检查固定结构 + 2/1 普通格 |
| `BuildRouteMetrics` | 总量、普通格目标不足会返回 false | 只硬验 Enter/Leave、全部非空连通和 2/1 普通格；其余写入指标 |
| `FZeroEscapeWfcSolveSettings` | Count 使用动态总量上下限，MaxConsecutive=4 | Count 只约束最低可用与潜在最大值；硬直线上限设为网格最长轴 |
| 完整候选 Validator | 覆盖率低于 0.75 时 `RejectBranch` | 删除覆盖率 Reject；候选立即成为 hard-valid incumbent |
| `PreservesOrdinaryCapacity` | 每层必须保留 26～30 普通格 | 改为一层 2、其他层 1；不复制一套部分结构潜在图 |
| `TryChooseTopExit` | 最远候选仍低于 0.65 就失败 | 保留最远优先，删除阈值失败 |
| `PlaceRequiredStairsRecursive` | 低于 0.65 后 `break` | 保留距离降序，继续遍历全部硬合法候选 |
| `TryPlaceOptionalStair` | 低于额外楼梯距离阈值时跳过；预算耗尽可 Fatal | 距离仍排序；无候选或可选预算耗尽统一 Skipped |
| `TryPlaceExactHighCeilingRoomCount` | 低于高厅距离阈值后 `break` | 保留距离降序，删除阈值 break；第一个高厅额外要求非顶层 |
| `SolveFloors` | 动态分配每层硬总量上下限并最终硬验整栋范围 | 改为稳定分配软目标；每层独立固定预算；不再验收软范围 |
| `BuildPlanFloorData` | 端点空间分离不足时失败 | 只保留 `CycleRank < 0` 这类不变量；分离比例仅记录 |
| `BuildAndValidateWholeGraph` | 整栋总格数越界时失败 | 删除总格数范围失败；整栋连通和结构 Landing 映射仍为硬检查 |
| `SelectPlayerSpawn` | 没有达到 1200 cm 的普通格时失败 | 优先达标；否则选择路线距离最远的普通格 |
| `ValidatePlayerToExitRoute` | 超过最大路线时失败 | 只保留玩家能到 Exit；最大路线字段和失败枚举删除 |
| `IsRecoverableWholeAttemptFailure` 与外层循环 | 结构、质量、WFC 预算都可能重做整栋 | 保留同 Seed 内部循环，但 Recoverable 列表只剩必要结构放置或 Required 潜在图硬冲突 |

这张表也是实施审计清单：如果其中任何质量型 `return false` 仍残留，就不能宣称软约束改造完成。

## 7. 对拟实现代码的自审

| 原拟实现想法 | 自审结论 | 本版修正 |
|---|---|---|
| 质量规则全部移到最终评分 | 不充分 | 密度在每棵树第一次观察前调 Empty；长直线在每次候选排序时上下文降权 |
| 不修改 `ZeroEscapeWfcSolver` | 过于保守 | 只改候选排序的局部权重接口；不碰传播、Trail、回溯状态机 |
| 失败时打开整个允许连通分量 | 合法但过密 | 改为 Required 的 BFS 树路径并集，再按目标密度前沿生长 |
| 继续让整栋共享预算彼此挤占 | 后层可能被前层饿死 | 每层重新建立固定预算；同一层最多三棵树 |
| 删除 4 次同 Seed 内部 `WholeAttempt` | 会丢掉其他楼梯 Opening Set，并迫使重写联合结构递归 | 保留最多 4 次，只允许必要结构硬失败触发；绝不改 Public Seed 或重载关卡 |
| 把必要楼梯、Exit、高厅合成一棵新递归 | 能更彻底回溯，但今晚改动面明显扩大 | 维持现有结构递归，高厅提前到可选楼梯之前；高厅硬失败才用下一 WholeAttempt |
| 为每个结构候选复制一套潜在图前向检查 | 部分楼层端点未完成，容易复制结构投影规则 | 不做；若已完成的可选结构导致 Required 图断开，恢复必需结构快照并只重解一次 |
| “玩家流程绝不失败”可由 PCG 覆盖所有情况 | 表述过头 | 保证正式有效 Profile 不因质量和搜索预算终局失败；Recast、碰撞、损坏配置属于独立系统故障 |
| 立即重命名所有 `Min...` 字段 | 收益小、资产迁移风险高 | 本轮保留序列化字段名，修改注释与语义，避免 Core Redirect 扩张 |
| 为软规则建立通用评分框架 | 不必要 | 评分结构只放在 `GridLayoutSolver.cpp`，固定四项，不建立注册系统 |

### 7.1 仍然存在的真实边界

本轮可以保证：

- 正式受支持 Profile 不会因为普通格数量、覆盖率、端点距离、路线长度或长直线而终局失败；
- `WholeAttempt=0..3` 只处理必要楼梯、高厅或 Required 潜在图的硬结构冲突，不处理任何质量目标或 WFC 预算；
- WFC 搜索预算耗尽时，同 Seed、同层进入确定性收敛；
- 玩家公开 Seed 不改变；
- 同输入使用固定候选数和固定工作量，结果确定；
- 两个高厅且至少一个非顶层。

本轮不能诚实承诺“引擎或配置损坏时仍绝不报错”。例如 Required 结构在潜在允许图上数学上不连通、RecastNavMesh 不存在、碰撞完全阻断导航，这些都不是继续开格或换 Seed 能正确解决的问题。正式资产校验和 Seed 扫描应在交付前阻止这类问题进入玩家版本，而不是在运行时加一张硬编码备用地图掩盖。

### 7.2 为什么暂不做每一步动态密度反馈

每棵树开始前一次性调整 Empty 权重，不会随着已生成格数每一步重新计算。这是有意的最小方案：

- 它已经从第一次观察开始朝目标密度努力；
- 不需要把整层计数状态和回溯恢复逻辑注入 WFC 候选回调；
- 最多三候选择优和最终收敛能够覆盖偏差；
- 如果 900 Seed 扫描仍显示系统性偏空，再暂停并讨论是否值得增加可回溯的动态密度上下文，不能今晚直接扩张。

## 8. 导航等待是否保留

保留。Recast 是 UE 使用的导航网格实现，运行时生成是异步过程；布局实例化完成不等于 AI 路径已经可查询。当前等待 `OnNavigationGenerationFinished` 的作用，是避免导航尚未建完就误判玩家或追猎者不可达。

但责任必须改清楚：

- 导航等待不参与地图择优；
- 导航等待超时或路径投射失败不得修改 Public Seed；
- 分开记录 `规划耗时 / 实例化耗时 / Recast 等待耗时 / 路径验证结果`；
- 本轮做代表 Seed 的 PIE/Recast 验证；若失败率高，另开导航专项处理 Bounds、碰撞、动态脏区或投射，而不是继续加地图重抽。

因此本轮承诺应准确写为：**对当前受支持的正式 Profile，规划阶段不因软质量或搜索预算向玩家报告“生成失败”，且绝不偷偷换 Seed。**

## 11. 止损线

实施中出现以下任一情况，立即暂停并向用户说明，不自行扩张：

1. 同层收敛新增超过约 260 行，或开始需要抽象成独立求解框架；
2. 为删除内部 `WholeAttempt` 而需要枚举所有 Opening Set 或重写楼梯/高厅联合递归；
3. 为保证两个高厅必须修改结构 Mesh、楼梯资产、网格尺寸或表现合同；
4. 需要新增硬编码安全地图、备用 Level 或第二套生成器；
5. 必须修改机关/资源规则才能让布局通过；
6. 发现正式 Required 结构在潜在允许图上数学上无法连通；
7. Recast 问题来自 Bounds、碰撞或项目配置，而不是布局完成时机；
8. 实际生产代码预计新增超过 480 行，或开始出现第二套评分/重试/兜底管理类。

止损线的含义是：如果代码越写越像在绕过不合理方案，就停止，而不是继续堆冗余分支。

## 12. 验证与交付标准

### 12.1 自动化

- 同一 Seed + Difficulty 连续生成两次，完整布局 Hash 一致；
- 失败诊断路径也不改变 Public Seed；
- 质量目标不满足时仍接受硬合法地图；
- 只有长直线可走的测试中，超过 4 格仍能成功；
- 有转弯选择时，长直线候选权重下降且永不为 0；
- 同层收敛遵守 RequiredOpen、RequiredClosed、Outside、全部非空连通和最低普通格；
- 质量目标和 WFC 搜索预算不会进入下一 `WholeAttempt`；内部 Attempt 只处理结构硬冲突且 Public Seed 不变；
- 两个高厅且至少一个非顶层；
- 可选楼梯没有合法候选或可选预算耗尽时只跳过；若造成 Required 硬断连，恢复必需结构快照后能够成功；
- Version 字段和版本参数全部清理，Population 随机流仍使用融合后的固定扰动。
