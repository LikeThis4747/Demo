# 磁力投掷物碰撞破碎——拟实现代码（2026-08-11 修订版）

> 状态：讨论稿。Geometry Collection 原型已经制作并由用户完成一次落地破碎测试；本修订版尚未获准写入 C++、Blueprint、Geometry Collection 或 Level0。
>
> 本版已经吸收 `claude/reviews/2026-08-10b-磁力投掷物碰撞破碎拟实现代码.md` 的有效意见，并以 2026-08-11 已落地的轻受击投掷事务为当前基线。旧稿中“破碎组件自行绑定 Hit、独立控制 CCD/碰撞快照”的方案作废，以本版为准。
>
> `Ready / BreakQueued / Consumed / BreakFailed` 是本项目拟使用的内部状态名，不是 UE 官方概念。直白含义依次是“可在下一次正式投掷中破碎”“已命中、等待安全替换”“原物体已被替换消耗”“替换失败、保留原物体且不再重试”。

## 1. 目标与本轮边界

P0 只完成这一条闭环：

```text
完整 Static Mesh 磁力物
    -> 玩家抓取、拉取、持有时绝不破碎
    -> 只有 ThrowHeldObject 正式投掷才进入破碎监听
    -> 首次达到冲量门槛的 Blocking Hit 只登记一次
    -> 同帧的轻受击请求仍先由原投掷物完成
    -> 下一帧生成 Geometry Collection 替身并继承运动
    -> 替身显式解簇
    -> Remove On Break 清理叶子碎片
    -> 6 秒 Actor LifeSpan 只作异常兜底
    -> 替身生成成功后才销毁原磁力物
```

本轮明确不做：

- Geometry Collection 不参与抓取、拉取、持有或 Physics Handle。
- 碎片不挂 `UMagneticObjectComponent`，不可再次抓取，也不提交 Light/Heavy 受击。
- 不实现“大磁力物破成一块仍可再投的小磁力物”；该资源链属于 P1。
- 不额外施加爆炸式径向冲量；先保留原碰撞的线速度和角速度。
- 不新增 Tick，全部使用碰撞事件、原生委托和一次性 Timer。
- 不让 Blueprint 再维护碰撞开关、Removal 开关或伤害开关；这些由 C++ 单点定义。

## 2. 当前真实基线

### 2.1 已存在的正式投掷事务

当前 `UMagneticObjectComponent` 已经是正式投掷碰撞事务的唯一状态 Owner：

- `ArmThrownImpact()` 保存原碰撞 Profile、Enabled、ObjectType、Responses、Hit 通知、CCD 和 `AttackProjectile` Tag。
- 正式投掷时临时切换为 `AttackProjectileBody`，Block Pawn，开启 Hit 通知和 CCD。
- 保存 `ActiveThrower`，命中投掷者本人时忽略。
- 当前轻受击窗口由 `ThrownWeaponActiveDuration = 2.5s` 控制。
- `GrabCandidate()` 已在保存抓取快照之前调用 `DisarmThrownImpact()`，可以精确恢复正式投掷前状态。

因此，破碎系统不得再次直接绑定 `OnComponentHit`，不得再次设置 Hit 通知或 CCD，也不得另存一份相同碰撞快照。否则轻受击与破碎会出现两个状态 Owner，先结束的一方会覆盖另一方。

### 2.2 已完成的碎片资产

- Geometry Collection：`/Game/ZeroEscape/Interaction/Magnetism/Destruction/GC_MagneticCrate4_P0`
- 当前层级：1 个根、18 个叶子碎片。
- 外表面继续使用原 `MI_crate4`；编辑器中的彩色块只是骨骼颜色显示，不是运行时材质。
- Remove On Break 当前实际定时：`Post Break Timer = 0~0s`，`Removal Timer = 2~3s`，因此资产最长清理时间 `T = 3s`。
- 用户已经完成一次落地破碎和消失测试。

运行时替身的 `SafetyLifetimeSeconds` 默认设为 `6s`，满足：

```text
SafetyLifetimeSeconds >= RemoveOnBreak 最大总时长 T + 3 秒异常余量
```

它只处理碎片未按预期移除、掉出世界或 Chaos 状态异常，不参与正常视觉节奏。

## 3. 修订后的职责模型

```text
UElectromagneticGrabComponent
    只决定“这次是不是正式投掷”，释放 Physics Handle，并施加速度变化冲量
                |
                v
UMagneticObjectComponent（唯一正式投掷事务 Owner）
    独占碰撞快照、AttackProjectileBody/Tag、Hit 通知、CCD、投掷者过滤与 Timer
    每次有效 Blocking Hit 广播一个原生 C++ 委托
          |                                    |
          v                                    v
现有 Light 消费者                      UMagneticThrowBreakComponent
只在前 2.5s 处理角色轻受击             只判断破碎门槛、去重并安排下一帧替换
                                               |
                                               v
                                  AMagneticFractureActor
                                  只负责 GC 表现、显式碰撞与清理
```

关键规则：

1. `UMagneticObjectComponent` 是唯一能够开启/恢复正式投掷碰撞状态的组件。
2. 通用命中委托必须在“是否为角色、是否还能提交 Light”的过滤之前广播。
3. Light 窗口到期不等于破碎监听立即结束；破碎监听有独立的硬上限，默认从出手算起 8 秒。
4. 8 秒内重新抓取且尚未进入 `BreakQueued` 时，抓取入口完整取消这次破碎资格。
5. 8 秒到期仍未达到门槛，则完整恢复碰撞状态；物体不会在很久以后随机碰一下才碎。

## 4. 状态与时序契约

### 4.1 正式投掷

`ThrowHeldObject()` 在释放前保存要投掷的 Body、磁力组件和破碎组件；释放后按以下顺序执行：

```text
读取 BreakComponent 可提供的破碎监听时长（无配置则为 0）
    -> ReleaseHeldObject(true)
    -> ArmThrownImpact(Body, Thrower, 2.5s, BreakMonitorSeconds)
    -> AddImpulse(..., bVelChange=true)
```

普通放下、安全释放、抓取中断都不调用 `ArmThrownImpact()`，因此不会获得破碎资格。

### 4.2 Light 窗口与破碎窗口

- `0~2.5s`：保留现有 Light 行为，同时广播通用 Blocking Hit 给破碎组件。
- `2.5~8s`：停止提交 Light；恢复临时 `AttackProjectileBody`、Pawn Response 和新加的 Tag，但继续保留 Hit 通知和 CCD，以等待一次破碎命中。
- `8s`：若仍未破碎，完整 `DisarmThrownImpact()`，恢复原始 Hit 通知和 CCD。
- 重新抓取：只要还没进入 `BreakQueued/Consumed`，立即完整 Disarm，下一次正式投掷可以重新获得资格。

### 4.3 什么算有效破碎命中

P0 使用 `NormalImpulse.Size()`，默认门槛为 `1000 kg·cm/s`：

- 必须是当前正式投掷 Body 的 `Blocking Hit`。
- 必须通过共享事务的投掷者过滤。
- 冲量必须为有限数且 `>= MinimumBreakNormalImpulse`。
- 低于门槛的轻擦、滚动小磕碰只忽略，不消费资格；后续更强命中仍可破碎。
- 第一次合格命中将状态改为 `BreakQueued`，同一物理步的后续 Hit 全部去重。

`1000` 与当前 `UCharacterImpactSourceProfile::MinimumPhysicalImpulse` 默认值一致，方便首轮调试；它是可调起点，不代表最终手感已经验收。

### 4.4 为什么下一帧才替换

合格 Hit 当帧只登记状态并安排 next-tick：

1. 若命中角色，原 Actor 仍可在本帧提交当前 Light 请求。
2. 避免在 Chaos Hit 回调中销毁正在参与物理求解的 Actor。
3. 下一帧读取碰撞后的 Transform、线速度和角速度，替身运动更连续。

替身生成失败时不销毁原 Actor；状态转为 `BreakFailed`，完整结束共享投掷事务，允许玩家继续抓取这个普通物体，但本实例不再重复尝试破碎。

## 6. 拟实现接口与关键代码

以下代码是授权前的接口级预览，不是已经编译的实现。

### 6.1 `UMagneticObjectComponent`：扩展共享事务，而不是新建第二套 Hit

头文件拟新增原生委托和一个破碎监听上限参数：

```cpp
DECLARE_MULTICAST_DELEGATE_FiveParams(
    FOnMagneticThrownBlockingHit,
    UPrimitiveComponent* /* HitComponent */,
    AActor* /* OtherActor */,
    UPrimitiveComponent* /* OtherComponent */,
    const FVector& /* NormalImpulse */,
    const FHitResult& /* Hit */);

bool ArmThrownImpact(
    UPrimitiveComponent* ThrownPrimitive,
    AActor* Thrower,
    float LightActiveDurationSeconds,
    float MaximumBreakMonitoringSeconds = 0.0f);

FOnMagneticThrownBlockingHit& OnThrownBlockingHit()
{
    return ThrownBlockingHit;
}
```

新增内部字段/辅助函数：

```cpp
void HandleLightWindowExpired();
void HandleDeferredLightResolved();
void HandleMaximumMonitoringExpired();
void RestoreAttackIdentityButKeepHitMonitoring();

FOnMagneticThrownBlockingHit ThrownBlockingHit;
FTimerHandle MaximumMonitoringTimerHandle;
bool bLightImpactWindowActive = false;
bool bKeepMonitoringForBreak = false;
```

Arm 的规则：

```cpp
// 先沿用当前逻辑保存唯一碰撞快照、开启 Notify/CCD、绑定一次 OnComponentHit。
bLightImpactWindowActive = true;
bKeepMonitoringForBreak =
    FMath::IsFinite(MaximumBreakMonitoringSeconds)
    && MaximumBreakMonitoringSeconds > LightActiveDurationSeconds;

SetTimer(LightWindowTimer, HandleLightWindowExpired, LightActiveDurationSeconds);
if (bKeepMonitoringForBreak)
{
    SetTimer(MaximumMonitoringTimer, HandleMaximumMonitoringExpired,
        MaximumBreakMonitoringSeconds);
}
```

Light 窗口到期时，只恢复攻击身份，不解绑 Hit：

```cpp
void UMagneticObjectComponent::HandleLightWindowExpired()
{
    bLightImpactWindowActive = false;
    if (!bKeepMonitoringForBreak)
    {
        DisarmThrownImpact();
        return;
    }

    RestoreAttackIdentityButKeepHitMonitoring();
    // Notify 和 CCD 仍由本事务临时保持；8s 硬上限或重新抓取时完整恢复。
}
```

Hit 处理顺序必须调整为：

```cpp
if (HitComponent != ArmedPrimitive.Get()
    || !Hit.bBlockingHit
    || !IsValid(OtherActor)
    || OtherActor == ActiveThrower.Get())
{
    return;
}

// 先让破碎消费者看见墙、地面、PhysicsBody 和角色命中。
ThrownBlockingHit.Broadcast(
    HitComponent, OtherActor, OtherComponent, NormalImpulse, Hit);

// 以下仍是现有 Light 的专属过滤和请求构造。
if (!bLightImpactWindowActive
    || bImpactConsumed
    || !OtherActor->GetClass()->ImplementsInterface(
        UCharacterImpactReceiver::StaticClass()))
{
    return;
}
```

Light 被角色消费后仍沿用 next-tick 收口，但不能无条件完整 Disarm：

```cpp
void UMagneticObjectComponent::HandleDeferredLightResolved()
{
    bLightImpactWindowActive = false;
    if (bKeepMonitoringForBreak)
    {
        RestoreAttackIdentityButKeepHitMonitoring();
        return;
    }

    DisarmThrownImpact();
}
```

这样即使以后把 Light 门槛调得低于破碎门槛，角色轻受击也只消费 Light，不会错误取消仍在等待更强碰撞的破碎资格。若本次角色命中已经让破碎组件登记 `BreakQueued`，替换回调会在同一 next-tick 销毁原物体；两个回调无论谁先执行都不会丢失替换资格。`DisarmThrownImpact()` 还必须清除 Light、最大监听和 deferred 三个 Timer。

### 6.2 `UMagneticThrowBreakComponent`：只做资格、门槛和替换

拟公开配置：

```cpp
UENUM()
enum class EMagneticThrowBreakState : uint8
{
    Ready,
    BreakQueued,
    Consumed,
    BreakFailed
};

UCLASS(ClassGroup=(Magnetism), meta=(BlueprintSpawnableComponent))
class DEMO_API UMagneticThrowBreakComponent final : public UActorComponent
{
    GENERATED_BODY()

public:
    UMagneticThrowBreakComponent();

    float GetFormalThrowMonitoringSeconds(
        const UPrimitiveComponent* CandidateBody) const;

    bool CanBeginGrab(const UPrimitiveComponent* CandidateBody) const;

private:
    void HandleThrownBlockingHit(
        UPrimitiveComponent* HitComponent,
        AActor* OtherActor,
        UPrimitiveComponent* OtherComponent,
        const FVector& NormalImpulse,
        const FHitResult& Hit);

    void ProcessQueuedBreak();

    UPROPERTY(EditDefaultsOnly, Category="磁力物|破碎")
    TSubclassOf<AMagneticFractureActor> FractureActorClass;

    UPROPERTY(EditDefaultsOnly, Category="磁力物|破碎",
        meta=(ClampMin="0.0", Units="kg*cm/s"))
    float MinimumBreakNormalImpulse = 1000.0f;

    UPROPERTY(EditDefaultsOnly, Category="磁力物|破碎",
        meta=(ClampMin="2.5", Units="s"))
    float MaximumMonitoringSeconds = 8.0f;

    EMagneticThrowBreakState State = EMagneticThrowBreakState::Ready;
    TWeakObjectPtr<UPrimitiveComponent> PendingBody;
    FDelegateHandle ThrownHitDelegateHandle;
    FTimerHandle DeferredBreakTimerHandle;
};
```

配置为空是合法情况：`FractureActorClass == nullptr` 时返回 `0s`，只输出 `Verbose`，该磁力物继续保留现有 Light 行为，不刷 Error。

命中登记：

```cpp
const float ImpulseMagnitude = NormalImpulse.Size();
if (State != EMagneticThrowBreakState::Ready
    || HitComponent != GetOwner()->GetRootComponent()
    || !Hit.bBlockingHit
    || !FMath::IsFinite(ImpulseMagnitude)
    || ImpulseMagnitude < MinimumBreakNormalImpulse)
{
    return;
}

State = EMagneticThrowBreakState::BreakQueued;
PendingBody = HitComponent;
DeferredBreakTimerHandle = GetWorld()->GetTimerManager().SetTimerForNextTick(
    this, &UMagneticThrowBreakComponent::ProcessQueuedBreak);
```

替换时读取碰撞后的运动，并遵守“成功后才销毁原物体”：

```cpp
UPrimitiveComponent* Body = PendingBody.Get();
AActor* OwnerActor = GetOwner();
if (!IsValid(Body) || !IsValid(OwnerActor) || !FractureActorClass)
{
    FailAndPreserveOriginal();
    return;
}

const FTransform SpawnTransform = Body->GetComponentTransform();
const FVector LinearVelocity = Body->GetPhysicsLinearVelocity();
const FVector AngularVelocityRadians = Body->GetPhysicsAngularVelocityInRadians();

AMagneticFractureActor* Fracture = GetWorld()->SpawnActorDeferred<AMagneticFractureActor>(
    FractureActorClass,
    SpawnTransform,
    nullptr,                       // 替身不挂 Owner，避免跟随原 Actor 销毁链
    OwnerActor->GetInstigator(),
    ESpawnActorCollisionHandlingMethod::AlwaysSpawn);

if (!IsValid(Fracture))
{
    FailAndPreserveOriginal();
    return;
}

Fracture->SetInheritedMotion(LinearVelocity, AngularVelocityRadians);
UGameplayStatics::FinishSpawningActor(Fracture, SpawnTransform);

State = EMagneticThrowBreakState::Consumed;
OwnerActor->Destroy();
```

`BeginPlay/EndPlay` 分别用 `AddUObject` 和保存的 `FDelegateHandle` 注册/移除共享命中委托。状态跃迁输出 `Verbose`；实际配置无效或 Spawn 失败才输出 `Warning/Error`。

### 6.3 抓取入口：先拒绝不可逆替换，再结束共享事务

`GrabCandidate()` 在任何抓取快照之前增加：

```cpp
if (UMagneticThrowBreakComponent* BreakComponent =
        CandidateComponent->GetOwner()->FindComponentByClass<UMagneticThrowBreakComponent>())
{
    if (!BreakComponent->CanBeginGrab(CandidateComponent))
    {
        UE_LOG(LogElectromagneticGrab, Verbose,
            TEXT("Rejected magnetic grab because fracture replacement is already queued."));
        return;
    }
}

// 必须仍然位于全部抓取快照之前。
MagneticObject->DisarmThrownImpact();
```

未来若新增自动吸附、传送或 AI 抢夺等抓取入口，也必须执行同一守卫，并在保存物理状态之前 Disarm；不能绕过 `GrabCandidate()` 的契约。

### 6.4 正式投掷入口：只向共享事务提供监听时长

`ThrowHeldObject()` 拟增加：

```cpp
UMagneticThrowBreakComponent* BreakComponent =
    ComponentToThrow->GetOwner()->FindComponentByClass<UMagneticThrowBreakComponent>();
const float BreakMonitoringSeconds = IsValid(BreakComponent)
    ? BreakComponent->GetFormalThrowMonitoringSeconds(ComponentToThrow)
    : 0.0f;

ReleaseHeldObject(true);

if (IsValid(MagneticObject))
{
    MagneticObject->ArmThrownImpact(
        ComponentToThrow,
        GetOwner(),
        TuningData->ThrownWeaponActiveDuration,
        BreakMonitoringSeconds);
}
```

破碎组件不再拥有 `ArmForFormalThrow()`，从根源上避免第二套武装状态。

### 6.5 `AMagneticFractureActor`：碰撞与清理由 C++ 单点定义

构造函数拟明确设置：

```cpp
PrimaryActorTick.bCanEverTick = false;

GeometryCollection = CreateDefaultSubobject<UGeometryCollectionComponent>(
    TEXT("GeometryCollection"));
SetRootComponent(GeometryCollection);
GeometryCollection->SetMobility(EComponentMobility::Movable);
GeometryCollection->SetSimulatePhysics(true);

GeometryCollection->SetCollisionEnabled(ECollisionEnabled::QueryAndPhysics);
GeometryCollection->SetCollisionObjectType(ECC_PhysicsBody);
GeometryCollection->SetCollisionResponseToAllChannels(ECR_Ignore);
GeometryCollection->SetCollisionResponseToChannel(ECC_WorldStatic, ECR_Block);
GeometryCollection->SetCollisionResponseToChannel(ECC_WorldDynamic, ECR_Block);
GeometryCollection->SetCollisionResponseToChannel(ECC_Pawn, ECR_Ignore);
GeometryCollection->SetCollisionResponseToChannel(ECC_Camera, ECR_Ignore);
GeometryCollection->SetCollisionResponseToChannel(ECC_PhysicsBody, ECR_Ignore);
GeometryCollection->SetGenerateOverlapEvents(false);
GeometryCollection->SetNotifyRigidBodyCollision(false);
GeometryCollection->SetCanEverAffectNavigation(false);

GeometryCollection->bEnableDamageFromCollision = false;
GeometryCollection->bAllowRemovalOnSleep = false;
GeometryCollection->bAllowRemovalOnBreak = true;
```

该契约的直接结果：

- 碎片与墙、地面和普通 WorldDynamic 场景保持碰撞。
- 碎片不推玩家/追猎者，不触发相机回缩。
- 碎片不与其他 PhysicsBody 二次互撞，不污染轻受击，也不撞飞玩家正在抓的磁力物。
- 即使 ObjectType 是语义正确的 `PhysicsBody`，因为没有 `UMagneticObjectComponent`，仍不会成为可抓候选。

在 deferred spawn 的 `SetInheritedMotion()` 中设置：

```cpp
GeometryCollection->InitialVelocityType =
    EInitialVelocityTypeEnum::Chaos_Initial_Velocity_User_Defined;
GeometryCollection->InitialLinearVelocity = LinearVelocity;
GeometryCollection->InitialAngularVelocity = AngularVelocityRadians;
```

`BeginPlay()` 校验 RestCollection 后调用 `CrumbleActiveClusters()`，并执行：

```cpp
SetLifeSpan(FMath::Max(SafetyLifetimeSeconds, 6.0f));
```

若 PIE 发现 BeginPlay 同帧解簇尚未准备好，再只把 `CrumbleActiveClusters()` 推到 next-tick；这是表现实验，不改变整体架构。

## 7. Blueprint 装配约束

`BP_MagneticFracture_P0` 只允许配置：

1. `RestCollection = GC_MagneticCrate4_P0`
2. `SafetyLifetimeSeconds = 6.0`

以下属性只由 C++ 决定，不在 BP 再设一遍：

- `Enable Damage From Collision = false`
- `Allow Removal On Sleep = false`
- `Allow Removal On Break = true`
- ObjectType 和各碰撞通道 Response
- Hit 通知、Overlap、导航影响

`BP_MagneticProp` 只把 `MagneticThrowBreak.FractureActorClass` 指向 `BP_MagneticFracture_P0`。未配置替身类的其他磁力物仍是合法普通磁力物。

## 8. 日志、失败与回退

### 8.1 可观测性

- `Verbose`：Ready、BreakQueued、Consumed、BreakFailed 状态跃迁，命中对象名和冲量。
- `Warning`：监听时长、门槛或 Body 装配无效，导致本次不能获得破碎资格。
- `Error`：已经进入 BreakQueued 后，World/Body/Spawn 等运行时替换失败。
- `FractureActorClass` 为空只记 `Verbose`，因为“普通但不破碎的磁力物”是合法配置。

### 8.2 失败原则

- 不能创建替身：保留原 Actor，完整 Disarm，状态转 `BreakFailed`。
- 替身成功创建：先 FinishSpawning，再销毁原 Actor。
- 原 Actor 在等待 next-tick 期间被外部销毁：清除 Timer，不生成孤立替身。
- 重复 Hit：`BreakQueued` 后全部忽略。
- EndPlay：两个组件都清 Timer、解绑委托并恢复自己拥有的状态。

### 8.3 最小回退面

如果 P0 PIE 失败，可只撤回新增破碎组件/替身 Actor 及其接线；当前 Light 投掷事务和抓取闭环仍保持原状。不得通过修改 Geometry Collection 让它直接参与抓取来绕过替换方案。

## 9. 验证矩阵

### 9.1 静态与构建

- Development Editor C++ 构建通过。
- `BP_MagneticFracture_P0` 和 `BP_MagneticProp` 编译、保存、重新打开无错误。
- 官方 UE5.8 MCP 回读父类、RestCollection、FractureActorClass、SafetyLifetime 和关键 C++ 暴露字段。
- 输出日志无 GC 配置 Error、Spawn Error、重复 Delegate 或访问失效对象。
- 无新增 Tick；10 个箱子破碎后 Actor/组件数量能回落。

### 9.2 不应破碎

- 静态摆放后被环境轻碰：不碎。
- 拉取途中碰墙：不碎。
- 持有时贴墙/贴追猎者：不碎。
- 普通放下、安全释放、重受击中断抓取：不碎。
- 正式投掷后冲量 `<1000` 的轻擦：不碎，后续强命中仍可碎。
- 正式投掷后 8 秒始终无合格命中：恢复普通物体，不会长期潜伏随机破碎。

### 9.3 应破碎

- 正式投掷命中墙、地面、WorldDynamic 场景或可动物理目标：首次合格命中只替换一次。
- 正式投掷命中角色：Light 请求照常提交，下一帧再替换原投掷物。
- 当 Light 门槛低于破碎门槛时：较轻的角色命中只消费 Light，破碎监听继续等待后续更强命中。
- 2.5 秒以后、8 秒以前命中：会破碎，但不再提交 Light。
- 贴近墙面高速投掷、斜射薄墙/栏杆、朝地面近距离投掷：CCD 下不得穿过而不触发。
- 投掷者本人接触：不因自碰撞消耗；命中脚下地面仍按真实地面冲量判断。

### 9.4 交互与竞态

- 2.5 秒后、合格命中前重新抓取：完整取消旧资格；持有路上不碎。
- `BreakQueued` 到 next-tick 的一帧内尝试抓取：被明确拒绝，不建立 Physics Handle。
- 两个已武装投掷物空中互撞：各自最多生成一个替身。
- 投掷物命中另一个正被玩家持有的磁力物：只有投掷物碎；被持有物和 Physics Handle 不受碎片干扰。
- 破碎瞬间玩家正在拉取第三个物体：拉取曲线、输入锁和 Held 状态不受影响。
- 同一物理步多次 Hit：无重复替身、无重复 Destroy。

### 9.5 碎片与清理

- 外表面保持 `MI_crate4`，内部切面没有骨骼调试色。
- 碎片 Block WorldStatic/WorldDynamic；Ignore Pawn/Camera/PhysicsBody。
- 玩家和相机不被碎片推挤；碎片不触发 Light/Heavy，不可抓取，不影响导航。
- 正常情况下叶子在 2~3 秒 Remove On Break 窗口内清理。
- 人为破坏 Removal 数据时，Actor 最迟约 6 秒由 LifeSpan 兜底销毁。
- 线速度和角速度继承合理；若碎片抱团，只记录为后续“有限微弱分离冲量”实验，不在首轮直接加爆炸力。

## 10. P1 扩展：保留一块可再次投掷的小磁力物

P0 验收后再设计资源次数链：

```text
大磁力物（可用 1 次）
    -> 碰撞破碎
    -> 视觉碎片全部清理
    -> 另生成一个完整 Static Mesh 小磁力物（剩余 1 次）
    -> 再次正式投掷后只生成视觉碎片并彻底消失
```

可再次使用的那一块仍必须是独立 Static Mesh Actor，而不是从 18 个 Geometry Collection 叶子里挑一块直接抓取。这样抓取稳定性、碰撞轮廓、质量、剩余次数和 PCG 生成规则都可控。
