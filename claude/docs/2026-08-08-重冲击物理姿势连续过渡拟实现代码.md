## 1. 先说最终要看到什么

摆锤把角色撞飞以后：

1. 飞行、翻滚、撞墙和落点仍然由真实物理决定，不播放一条“自己飞出去”的受击动画。
2. 高速阶段身体不是完全软掉，仍保留受击前动作的大致轮廓，但重物仍能真正改变身体运动。
3. 第一次落地并开始减速后，肩、脊柱、髋和腿在碰撞允许的范围内逐渐收拢到“马上可以起身”的姿势。
4. 身体接近起身动画的开头后，才关闭全身物理并播放起身 Montage。
5. 物理阶段最后一帧和 Montage 第一帧已经很接近，因此切换时不再出现“先僵住，再闪一下换姿势”。
6. 墙挡住手臂时，手臂可以暂时整理不到位；系统不能为了对齐动画把身体拉穿墙，也不能把角色搬回受击前位置。

这里把第 3 步暂称为**物理姿势准备阶段**。这是本项目的描述，不是 UE 官方功能名。UE 提供的是 Pose Snapshot、Animation Blueprint、Physics Control 和 Montage；本项目把它们按下面的时序组合起来。

## 2. 对“受击过程做插值”的准确解释

用户的理解基本正确：

```text
受击前动画姿势
    ↓
真实物理受击姿势
    ↓
起身动画的开头姿势
```

但不能直接把屏幕上的骨骼位置从 A 插到 B。那样会覆盖物理结果，身体可能无视墙壁、地面和摆锤。

本方案实际插值的是**物理身体想要靠近的目标姿势**：

- 角色骨骼仍是刚体，碰撞、重力、位移和翻滚一直有效；
- AnimBP 在后台产生一个逐渐变化的目标姿势；
- Physics Control 用有限强度的弹簧/阻尼扭矩，让各骨骼尝试追随这个目标；
- 环境碰撞和重冲击仍然可以把骨骼推离目标；
- 骨盆的世界位移不由动画目标驱动，因此不会出现“动画自己把人吸到某个位置”。

换句话说，它不是“动画替代物理”，而是“物理身体从一个逐渐变化的姿势目标中得到有限引导”。

## 3. 为什么不是从被撞中的第一帧就朝起身姿势靠

被撞后立刻把目标改成倒地起身姿势，会让角色在空中提前蜷成地面动作，削弱被重物撞飞的力量感，也可能妨碍翻滚和二次碰撞。

所以首版分成三段：

| 阶段 | 屏幕上的身体由谁决定 | 后台目标 | 目的 |
|---|---|---|---|
| `Prepared` / 刚受击 | Chaos 为主，Physics Control 辅助 | 受击前冻结姿势 | 避免接触瞬间全身像断线木偶 |
| `Simulating` / 高速飞行翻滚 | Chaos 为主，低到中等控制 | 仍偏向受击前姿势 | 保留人形轮廓，但不抵消真实冲量 |
| `Settling` / 已接触地面且明显减速 | Chaos 仍保持 100% 模拟 | 从当前物理姿势渐变到起身动画开头 | 在物理中完成可见的身体收拢 |

因此，“从击飞到倒地时就开始”可以做，但准确起点不是命中瞬间，而是现有代码已经能识别的 `Simulating → Settling` 时刻：身体有地面支撑，骨盆线速度和角速度已经降到阈值以下。这样既比“完全躺稳后才整理”更早，也不会把空中飞行变成起身预备动作。

## 4. 状态流程

公开的 `EHeavyImpactState` 不增加新状态，继续保持：

```text
Prepared → Simulating → Settling → Downed → Recovering → Inactive
```

只给组件内部的恢复阶段增加一个 `PreparingPose`：

```cpp
enum class EHeavyImpactRecoveryPhase : uint8
{
    None,
    WaitingForSpace,
    PreparingPose,
    PlayingMontage
};
```

### 4.1 正常空间充足

```text
Simulating
  └─ 首次落地、速度下降、支撑可靠
       ↓
Settling + PreparingPose
  ├─ 选择正躺/趴倒动画
  ├─ 确认附近存在安全直立 Capsule 位置
  ├─ 保存当前物理姿势
  ├─ 约 0.40 秒内，让物理身体逐渐追向起身动画开头
  └─ 姿势准备完成且仍稳定
       ↓
Recovering + PlayingMontage
  ├─ 保存最后的物理姿势，作为极小残差的视觉混合起点
  ├─ 关闭全身物理并恢复 Character 外壳
  ├─ 从与准备阶段相同的动画采样时间开始播放 Montage
  └─ Montage 结束，回到 Inactive
```

正常路线不再先睡眠并僵躺 `RecoveryDelaySeconds`。那段 0.5 秒只保留给“当前没有安全起身空间”的重试路线。

### 4.2 空间不足或卡墙角

1. 当前姿势不能规划出安全 Capsule 时，不开始姿势准备，也不强切动画。
2. 进入现有 `Downed`，刚体睡眠，隔 `RecoveryRetrySeconds` 重试。
3. 每次仍只在骨盆附近最多 60 cm 内寻找位置；不无限挪动，不穿墙，不回受击前位置。
4. 某次重试找到安全位置后，唤醒刚体，从当前睡眠姿势进入同一个 `PreparingPose`，而不是直接闪切 Montage。
5. 如果永远没有空间，就一直躺着；仍允许真实机关再次撞击并重新进入物理受击。

### 4.3 整理过程中再次失稳

如果速度重新升高、支撑丢失、被机关再次撞到，或正躺/趴倒判断翻转：

- 立即清除本次姿势准备进度；
- 回到 `Simulating` 和现有 Flight 控制；
- 不播放 Montage，不保留旧 Timer；
- 下次重新稳定时，从新的真实物理姿势重新开始。

## 5. AnimBP 的目标姿势怎么产生

玩家和 AI 继续使用各自现有 AnimBP，不更换骨架，不新做起身 Montage 资产。

新增的隐藏分支：

```text
当前基础动画输出（玩家：ControlRig → DefaultSlot；AI：BlendSpace → DefaultSlot）
                                      │
                                      ├────────────── False ──────────────┐
                                      │                                   │
当前物理姿势 Snapshot ── Blend ── 起身 Sequence Evaluator                │
                         ↑             ↑                                  │
               PreparationAlpha   固定采样起身开头                         │
                                      │                                   │
                                      └─ True：物理姿势准备目标 ───────────┤
                                                                          ↓
                                             现有 DownedPose Snapshot 混合
                                                                          ↓
                                                                      Output Pose
```

更精确的图结构：

```text
PrepTarget = Blend(
    PoseSnapshot("HeavyImpactRecoveryPreparationPose"),
    SequenceEvaluator(
        Sequence = HeavyImpactRecoveryPreparationSequence,
        ExplicitTime = HeavyImpactRecoveryPreparationTimeSeconds),
    HeavyImpactRecoveryPreparationAlpha)

BaseOrPrep = BlendByBool(
    bUseHeavyImpactRecoveryPreparationPose,
    BasePose,
    PrepTarget,
    0 秒切换时间)

Final = 现有 BlendByBool(
    bUseHeavyImpactPoseSnapshot,
    BaseOrPrep,
    PoseSnapshot("HeavyImpactDownedPose"))
```

`BaseOrPrep` 的布尔切换本身使用 0 秒，因为真正的渐变已经由 `HeavyImpactRecoveryPreparationAlpha` 明确控制；这里再加一个隐式混合会造成双重曲线和难以调试的延迟。

`Sequence Evaluator` 只读取指定起身动画在某个时间点的姿势，不负责播放。动画资源仍由两份 HeavyImpact DataAsset 选择，AnimBP 不重复硬编码四条资源。

## 6. AnimInstance 拟扩展接口

`UHeavyImpactAnimInstance` 仍然只是表现桥，不拥有状态机和空间判断。

```cpp
class DEMO_API UHeavyImpactAnimInstance : public UAnimInstance
{
    GENERATED_BODY()

public:
    static const FName RecoveryPreparationPoseSnapshotName;
    static const FName DownedPoseSnapshotName;

    bool StoreHeavyImpactRecoveryPreparationPose(
        FPoseSnapshot&& PhysicalPose,
        UAnimSequenceBase* Sequence,
        float SequenceTimeSeconds);

    void SetHeavyImpactRecoveryPreparationAlpha(float Alpha);
    void ClearHeavyImpactRecoveryPreparation();

    // 现有最终交接 Snapshot 接口继续保留。
    bool StoreHeavyImpactDownedPose(FPoseSnapshot&& Pose);
    void ReleaseHeavyImpactDownedPose();
    void ClearHeavyImpactDownedPose();

    UPROPERTY(Transient, BlueprintReadOnly, Category = "Heavy Impact")
    bool bUseHeavyImpactRecoveryPreparationPose = false;

    UPROPERTY(Transient, BlueprintReadOnly, Category = "Heavy Impact")
    TObjectPtr<UAnimSequenceBase> HeavyImpactRecoveryPreparationSequence;

    UPROPERTY(Transient, BlueprintReadOnly, Category = "Heavy Impact")
    float HeavyImpactRecoveryPreparationTimeSeconds = 0.0f;

    UPROPERTY(Transient, BlueprintReadOnly, Category = "Heavy Impact")
    float HeavyImpactRecoveryPreparationAlpha = 0.0f;
};
```

开始时先从当前物理 Mesh 保存 `HeavyImpactRecoveryPreparationPose`，再恢复 AnimGraph 求值。由于 Mesh 仍保持全身物理混合权重 1，后台 AnimGraph 的变化不会直接把屏幕上的刚体骨骼改成动画姿势；它只成为 Physics Control 的目标。

## 7. Physics Control 怎么逐渐加力

开始 `PreparingPose` 时只应用一次现有 `LandingRecovery` Profile，之后不每帧重复切 Profile。

组件现有 PostPhysics Tick 每帧计算：

```cpp
const float RawAlpha = FMath::Clamp(
    PreparationElapsedSeconds / Tuning->RecoveryPosePreparationSeconds,
    0.0f,
    1.0f);

const float PoseAlpha = FMath::SmoothStep(0.0f, 1.0f, RawAlpha);
AnimInstance->SetHeavyImpactRecoveryPreparationAlpha(PoseAlpha);

const float ControlScale = FMath::Lerp(
    Tuning->RecoveryPoseInitialControlScale,
    1.0f,
    PoseAlpha);

ApplyParentSpaceControlMultipliers(Tuning->LandingControl, ControlScale);
```

`ControlScale` 只乘角向强度和最大扭矩；阻尼比继续使用 `LandingControl.AngularDampingRatioMultiplier`。如果连阻尼一起降到 30%，身体更容易来回摆动，反而不像在主动稳定自己。

约束：

- 只调已有 ParentSpace 关节控制；
- 不创建 WorldSpace 拉拽；
- 线性驱动继续为 0；
- 不驱动骨盆世界位置；
- 刚体模拟、碰撞、重力和物理混合权重保持开启；
- 墙或地面可以阻止骨骼到达目标；
- 不增加常驻 Tick，继续复用 HeavyImpact 事务期间才开启的组件 Tick。

推荐首版默认值：

| 参数 | 初值 | 用途 |
|---|---:|---|
| `RecoveryPosePreparationSeconds` | 0.40 s | 身体从当前物理姿势收拢到起身开头的时间 |
| `RecoveryPoseInitialControlScale` | 0.30 | 开始整理时只使用 Landing 控制的 30%，随后升到 100% |
| `FaceUpPreparationSampleTimeSeconds` | 0.0 s | 正躺动画作为物理目标的采样时间 |
| `FaceDownPreparationSampleTimeSeconds` | 0.0 s | 趴倒动画作为物理目标的采样时间 |

采样时间不一定永远是第 0 帧。如果某条动画第 0 帧本身有导入缓冲或明显滑动，允许在 DataAsset 中调到真正开始发力的早期帧；准备阶段和 Montage 必须使用同一个时间值。

## 8. 从物理切到 Montage

只有同时满足以下条件才交接：

- 姿势准备时间已完成；
- 角色仍有可靠地面支撑；
- 速度仍低于稳定阈值；
- 计划的 Capsule 位置再次 Sweep 验证通过。

交接顺序：

1. 捕获此刻已经接近起身开头的真实物理姿势到现有 `HeavyImpactDownedPose`。
2. 暂时显示该 Snapshot。
3. 把 Capsule 放到已验证的最终附近位置并恢复 Character 外壳。
4. 关闭全身刚体模拟，恢复 Mesh 装配。
5. 清除后台的准备分支。
6. 从 `AnimationStartTimeSeconds` 播放动态 Montage。
7. Slot 已经求值后释放 `HeavyImpactDownedPose`，用现有约 0.20 秒混合消化很小的剩余误差。

这仍然使用 Pose Snapshot，但它不再承担“从任意布娃娃姿势硬混到起身”的全部工作，只负责遮住交接的一两帧残差。

## 10. 首版刻意不做什么

首版不加入“全身几十根骨骼逐帧计算姿势误差，再决定何时起身”的复杂求解器。先用：

- 固定约 0.40 秒准备时间；
- 现有支撑/速度稳定条件；
- 最终小幅 Pose Snapshot 混合。

如果实际画面仍有明显跳变，第二阶段才增加少数代表骨骼（骨盆、胸、左右大腿、左右上臂）的角度误差门槛。届时应替换“固定时间到了就交接”的条件，而不是在现有逻辑旁边不断堆补丁。

同样不做：

- 新受击动画；
- Root Motion 起身；
- `AddImpulse` / `LaunchCharacter`；
- 手动改骨骼 Transform；
- WorldSpace 把角色拉向安全点；
- 新 Physics Asset 或 PCA；
- 为工具不方便而增加运行时绕过代码。

## 11. A/B 验证开关

新增开发期控制变量：

```text
demo.HeavyImpact.RecoveryPosePreparation 1  // 新方案
demo.HeavyImpact.RecoveryPosePreparation 0  // 当前 Snapshot 直接交接方案
```

这只是明确的效果对比工具，不是出错后自动走旧逻辑的隐藏回退。现有 `demo.HeavyImpact.PureRagdoll` 继续负责比较“受控物理”和“普通布娃娃”。两者的明确优先级是：`PureRagdoll=1` 时全部 Physics Control 驱动关闭，因此本事务强制跳过姿势准备；比较新旧交接时使用 `PureRagdoll=0`，只切换 `RecoveryPosePreparation`。

若相同摆锤、相同角色的并排对比中，新方案不能一眼看出以下至少两项改善，就不继续堆代码：

- 倒地后不再像雕像一样停住；
- 肩、脊柱或腿在地面碰撞中可见地收拢；
- Montage 开头不再整个人闪切；
- 起身开始位置仍是实际倒地点。

## 13. 实施顺序与止损点

### Increment 0：完整 Git 基线门禁

在首次修改功能文件前，完整纳入工作区全部已确认改动并 commit/push；核对 `origin`、远端哈希和干净工作区。任何一步失败都不开始功能实现。

### Increment 1：只证明“全物理身体能追后台动画目标”

- 增加 AnimInstance 准备分支数据；
- 玩家 AnimBP 先接入 Sequence Evaluator；
- 只选脊柱/一条手臂观察目标追随；
- 保持刚体、碰撞和重力开启。

这是最高风险检查点。若 UE 的求值时序使 Physics Control 在 PrePhysics 看不到后台 AnimGraph 的新目标，立即停止并删除这条无效增量，重新评估目标来源；不叠加延迟帧、重复 Tick 或运行时复制资产等绕过代码。

### Increment 2：接入完整 Settling 流程

- 正躺/趴倒选择；
- 准备 Alpha 与控制强度曲线；
- 失稳取消；
- 同采样时间 Montage 交接；
- 正常路线移除 0.5 秒僵躺。

### Increment 3：AI 与阻塞重试

- AI AnimBP 接相同分支；
- 两份 DataAsset 配置；
- 无空间时 Downed；
- 空间恢复后从睡眠姿势先做物理准备再起身；
- 再次真实受撞可以打断。

### Increment 4：A/B 和画面调参

- 新旧交接开关；
- 玩家/AI、正躺/趴倒、开阔地/墙边/墙角；
- 只围绕看得见的问题调整 0.40 秒和 0.30 初始强度；
- 不在首轮同时修改冲击力、摆锤速度或起身动画资源。

4. Montage 开始时没有一帧整个人换姿势的闪切。
5. 角色在真实倒地点附近起身，只允许现有最多 60 cm 的安全找位。
6. 墙角无空间时继续躺；障碍移开后能重试并正常起身。
7. 准备中再次受撞会重新进入真实物理运动。
8. 玩家恢复控制和相机，AI 恢复追逐。

自动化和 MCP 只能证明状态、数据和接线正确，不能代替第 1–8 项的画面验收。

## 15. 规模与主要风险

- 生产 C++：预计净增约 180–280 行；
- 自动化测试：预计增加约 30–60 行，首版只扩展现有配置契约，不伪造 Chaos 运行结果；
- 每个 AnimBP：约增加 8 个节点及连接；
- 两份 DataAsset：各增加 4 个参数；
- 复杂度：中等；
- 预期第一版实施和工具验证：约半天，不含用户反复调手感的时间。

最高风险不是 Montage，而是 UE 的动画求值和 Physics Control 更新顺序。如果后台目标不能在下一次物理步稳定生效，方案的核心假设就不成立，应在 Increment 1 停止，而不是让修 Bug 代码无限增长。

第二风险是四条动画的真正合适开头不一定是 0 秒。该问题只通过 DataAsset 的采样时间微调解决，不修改或复制动画资源。

## 17. 当前代码的精确替换点

本增量不平行增加第二套恢复逻辑，而是在现有函数中替换以下路径：

| 当前函数 | 当前行为 | 拟修改行为 |
|---|---|---|
| `UpdateStability()` | `Simulating → Settling` 后只累计 0.35 秒，然后直接 `EnterDowned()` | 进入 `Settling` 时尝试开始物理姿势准备；准备完成、稳定条件仍成立且经过一次最终 PrePhysics 后直接交接 Montage |
| `EnterDowned()` | 切 FreeFallback，下一帧睡眠 | 仍作为无空间、准备失败、硬超时和 A/B 旧路径的安全落点；进入前统一清理未完成的姿势准备 |
| `FinishPendingDownedSleep()` | 睡眠后等待 0.5 秒 | 保留，仅供真正进入 `Downed` 的阻塞/旧路径使用；正常新路径不经过这里 |
| `TryBeginRecovery()` | 找到位置后立即 `BeginPhysicalToAnimationHandoff()` | 新方案开启时先唤醒并进入 `PreparingPose`；A/B 关闭时保留当前直接交接 |
| `BeginPhysicalToAnimationHandoff()` | 只允许 `Downed`，从任意倒地 Snapshot 关物理 | 同时允许 `Settling/PreparingPose` 和 `Downed/PreparingPose`；先保存已经整理过的最终物理姿势，再关物理 |
| `StartRecoveryMontage()` | 永远从 `0.0f` 播放 | 从准备阶段使用的 `AnimationStartTimeSeconds` 播放 |
| `ClearRecoveryAnimationState()` | 只清理最终 Downed Snapshot 和 Montage | 同时清理准备 Snapshot、动态 Sequence 引用、Alpha、计时和最终目标帧标记 |

不会修改以下权威：

- `HandleMeshHit()` 的真实 Chaos 冲量来源；
- `UpdatePhysicalFollow()` 的落点跟随；
- 现有 Capsule Sweep 搜索算法和 60 cm 硬上限；
- `UHeavyImpactResponseComponent` 作为唯一状态写入者。

bool UHeavyImpactResponseComponent::ApplyParentSpaceControlMultipliers(
    const FHeavyImpactControlStageTuning& StageTuning,
    const float StrengthAndTorqueScale)
{
    const float SafeScale = FMath::Clamp(StrengthAndTorqueScale, 0.0f, 1.0f);

    FPhysicsControlMultiplier Multipliers;
    Multipliers.AngularStrengthMultiplier =
        StageTuning.AngularStrengthMultiplier * SafeScale;
    Multipliers.AngularDampingRatioMultiplier =
        StageTuning.AngularDampingRatioMultiplier;
    Multipliers.MaxTorqueMultiplier =
        StageTuning.MaxTorqueMultiplier * SafeScale;

    return PhysicsControl->SetControlMultipliersInSet(
        TEXT("ParentSpace"), Multipliers, true);
}

### 21.4 开始物理姿势准备

```cpp
bool UHeavyImpactResponseComponent::BeginRecoveryPosePreparation(
    const FHeavyImpactRecoveryPlan& Plan,
    FString& OutReason)
{
    if ((State != EHeavyImpactState::Settling
            && State != EHeavyImpactState::Downed)
        || !IsValid(Plan.Animation)
        || bPureRagdollComparisonActive)
    {
        OutReason = TEXT("Recovery pose preparation prerequisites are invalid.");
        return false;
    }

    UHeavyImpactAnimInstance* AnimInstance =
        Cast<UHeavyImpactAnimInstance>(Mesh->GetAnimInstance());
    if (!IsValid(AnimInstance))
    {
        OutReason = TEXT("Runtime AnimInstance is not UHeavyImpactAnimInstance.");
        return false;
    }

    FPoseSnapshot PhysicalPose;
    Mesh->SnapshotPose(PhysicalPose);
    if (!AnimInstance->StoreHeavyImpactRecoveryPreparationPose(
        MoveTemp(PhysicalPose),
        Plan.Animation,
        Plan.AnimationStartTimeSeconds))
    {
        OutReason = TEXT("AnimInstance rejected the physical preparation pose.");
        return false;
    }

    HeavyImpactAnimInstance = AnimInstance;
    ActiveRecoverySequence = Plan.Animation;
    ActiveRecoveryAnimationStartTimeSeconds = Plan.AnimationStartTimeSeconds;
    RecoveryPosePreparationElapsedSeconds = 0.0f;
    RecoveryPoseFinalTargetFrame = 0;
    bRecoveryPoseFinalTargetSubmitted = false;
    RecoveryPhase = EHeavyImpactRecoveryPhase::PreparingPose;

    // 恢复后台 AnimGraph 求值；屏幕仍由 PhysicsBlendWeight=1 的刚体结果决定。
    Mesh->bPauseAnims = false;
    if (!ApplyParentSpaceControlMultipliers(
        Tuning->LandingControl,
        Tuning->RecoveryPoseInitialControlScale))
    {
        CancelRecoveryAsync(false);
        OutReason = TEXT("Failed to apply initial preparation control scale.");
        return false;
    }

    SetComponentTickEnabled(true);
    OutReason.Reset();
    return true;
}
```

如果从 `Downed` 重试进入该函数，调用者先开启 Physics Control Tick、应用 `LandingRecovery` Profile，再唤醒刚体。任何一步失败都恢复 FreeFallback 睡眠并继续现有 Timer 重试，不直接切 Montage。

### 21.5 每帧更新与“至少一个最终物理步”

```cpp
void UHeavyImpactResponseComponent::UpdateRecoveryPosePreparation(
    const float DeltaTime,
    const bool bSlowEnough,
    const bool bSupported)
{
    if (!IsRecoveryPosePreparationActive())
    {
        return;
    }

    if (!bSlowEnough || !bSupported)
    {
        CancelRecoveryPosePreparation(
            TEXT("Physical body became unstable during recovery pose preparation."));
        return;
    }

    if (Mesh->GetAnimInstance() != HeavyImpactAnimInstance)
    {
        Mesh->bPauseAnims = true;
        CancelRecoveryAsync(false);
        EnterDowned(TEXT("AnimInstance changed during pose preparation."));
        return;
    }

    RecoveryPosePreparationElapsedSeconds += DeltaTime;
    const float RawAlpha = FMath::Clamp(
        RecoveryPosePreparationElapsedSeconds
            / Tuning->RecoveryPosePreparationSeconds,
        0.0f,
        1.0f);
    const float PoseAlpha = FMath::SmoothStep(0.0f, 1.0f, RawAlpha);
    const float ControlScale = FMath::Lerp(
        Tuning->RecoveryPoseInitialControlScale,
        1.0f,
        PoseAlpha);

    HeavyImpactAnimInstance->SetHeavyImpactRecoveryPreparationAlpha(PoseAlpha);
    if (!ApplyParentSpaceControlMultipliers(Tuning->LandingControl, ControlScale))
    {
        Mesh->bPauseAnims = true;
        CancelRecoveryAsync(false);
        EnterFreeFallback(TEXT("Recovery pose multiplier update failed."));
        return;
    }

    if (RawAlpha < 1.0f || StableElapsedSeconds < Tuning->RequiredStableSeconds)
    {
        return;
    }

    // 当前函数运行在 PostPhysics。第一次提交 Alpha=1 时，下一帧 PrePhysics
    // 才会让 Physics Control 真正求解最终目标，因此此帧禁止关物理。
    if (!bRecoveryPoseFinalTargetSubmitted)
    {
        bRecoveryPoseFinalTargetSubmitted = true;
        RecoveryPoseFinalTargetFrame = GFrameCounter;
        return;
    }
    if (GFrameCounter <= RecoveryPoseFinalTargetFrame)
    {
        return;
    }

    FHeavyImpactRecoveryPlan FinalPlan;
    FString Reason;
    if (!BuildRecoveryPlan(FinalPlan, Reason)
        || FinalPlan.Animation != ActiveRecoverySequence
        || !FMath::IsNearlyEqual(
            FinalPlan.AnimationStartTimeSeconds,
            ActiveRecoveryAnimationStartTimeSeconds))
    {
        Mesh->bPauseAnims = true;
        CancelRecoveryAsync(false);
        EnterDowned(TEXT("Recovery plan changed or became blocked after preparation."));
        return;
    }

    if (!BeginPhysicalToAnimationHandoff(FinalPlan, Reason))
    {
        Mesh->bPauseAnims = true;
        CancelRecoveryAsync(false);
        EnterDowned(TEXT("Prepared physical-to-animation handoff failed."));
    }
}
```

这里的额外一帧不是视觉延迟补丁，而是明确的 Tick 顺序契约：PostPhysics 写目标，下一次 PrePhysics 才由 Physics Control 消费。

### 21.6 失稳取消

```cpp
void UHeavyImpactResponseComponent::CancelRecoveryPosePreparation(
    const TCHAR* Reason)
{
    check(IsRecoveryPosePreparationActive());

    // 先暂停，使 Physics Control 暂时保留刚才已经求值的目标，不跳回 Idle。
    Mesh->bPauseAnims = true;
    ClearRecoveryAnimationState(false);
    RecoveryPhase = EHeavyImpactRecoveryPhase::None;
    RecoveryPosePreparationElapsedSeconds = 0.0f;
    bRecoveryPoseFinalTargetSubmitted = false;
    RecoveryPoseFinalTargetFrame = 0;

    StableElapsedSeconds = 0.0f;
    if (ApplyPhysicalStage(Demo::HeavyImpact::ProfileFlight, Tuning->FlightControl))
    {
        SetState(EHeavyImpactState::Simulating);
    }
    else
    {
        EnterFreeFallback(TEXT("Flight profile failed after cancelling pose preparation."));
    }

    UE_LOG(LogHeavyImpact, Verbose,
        TEXT("HeavyImpact recovery pose preparation cancelled on %s: %s"),
        *GetNameSafe(GetOwner()), Reason);
}
```

若取消原因是“最终位置被堵”或 AnimInstance 重建，而身体仍应停下，则调用点先清理准备数据，再走 `EnterDowned()`，不调用上述回飞行版本。正式代码会通过两个含义明确的调用路径区分“物理失稳”和“安全起身失败”，不会用一个布尔参数隐藏语义。

### 21.9 清理完整性

以下入口全部必须清空准备分支：

- `ResumeFromDownedHit()`；
- `EnterDowned()`；
- `CompleteRecovery()`；
- `CancelRecoveryAsync()`；
- `RestoreSnapshotAfterFalsePositive()`；
- `EndPlay()`；
- AnimInstance 重建回调。

每次清理准备阶段都重置：AnimBP 四个准备变量、准备 Snapshot、`ActiveRecoverySequence`、动画起始时间、Elapsed 和最终目标帧。`bUseRecoveryPosePreparationForTransaction` 在同一次真实冲击的失稳、Downed 和重试之间保留，只在正常完成、Prepared 误判回滚、EndPlay 或下一次 `EnterPrepared()` 时重置/重新锁存。清理必须幂等，不新增“如果失败就悄悄站起来”的路径。

## 22. 两套 AnimBP 的精确增量

官方 MCP 当前回读事实：

- 玩家和 AI 父类均为 `/Script/Demo.HeavyImpactAnimInstance`；
- 玩家现有主链为 `Main States → ControlRig → DefaultSlot → 现有 Downed Snapshot Bool Blend → Output`；
- AI 现有主链为 `BlendSpace → DefaultSlot → 现有 Downed Snapshot Bool Blend → Output`；
- 两者现有最终 Bool Blend 时间均为 0.20 秒；
- 当前玩家 HeavyImpact AnimBP 在编辑器内为 Dirty，AI AnimBP 与两份 DataAsset 为 Clean。本轮不保存、不覆盖该 Dirty 状态，进入实现前必须先确认归属并形成完整 Git 基线。

每个 AnimBP 在 `DefaultSlot` 与现有最终 Bool Blend 之间插入：

1. `Pose Snapshot`：名称固定 `HeavyImpactRecoveryPreparationPose`；
2. `Sequence Evaluator`：
   - `Sequence` 接 `HeavyImpactRecoveryPreparationSequence`；
   - `Explicit Time` 接 `HeavyImpactRecoveryPreparationTimeSeconds`；
3. `Blend/Two Way Blend`：
   - A 为准备 Snapshot；
   - B 为 Sequence Evaluator；
   - Alpha 接 `HeavyImpactRecoveryPreparationAlpha`；
4. `Blend Poses by Bool`：
   - False 为当前 `DefaultSlot` 输出；
   - True 为上述目标 Blend；
   - Active Value 接 `bUseHeavyImpactRecoveryPreparationPose`；
   - True/False Blend Time 均为 0；
5. 上述 Bool Blend 输出接回现有 Downed Snapshot Bool Blend 的正常动画输入。

Sequence Evaluator 的 `Sequence` 属性在 UE 中默认隐藏为节点属性，实施时应直接在节点上 `Expose As Pin` 后连接父类变量。若官方 MCP 无法设置该 AnimGraph 专用属性，停止资产写入并请用户在编辑器中手动勾选；不为此增加 C++ 动画资源副本、硬编码路径或第二套 ABP。
