# 轻受击动画与局部物理融合拟实现代码

> 状态：已阅读 Review 并完成 Owner 取舍；仍是代码预览，尚未写入 `Source/`、`Content/` 或 `Config/`。
> 目标：保留现有 `None / Slow / Stop`、移动效果和 Stop 受击动画，再增加一层短暂、封顶、来源无关的上半身局部物理表现。
> 核心边界：本版不重做来源碰撞。追猎者 Mesh 当前是 `QueryOnly`，所以这是“命中事件驱动、Chaos 解算局部骨骼”的表现层，不冒充来源物体与 Physics Asset 首次接触的完整双向动量交换。

## 1. 最终选择

本版采用 Epic 官方常见的 hit-reaction 组合：

1. 来源继续提交现有 `FStandingImpactRequest`；
2. 来源 Profile 决定玩家、追猎者分别是 `None / Slow / Stop`，以及该结果是否允许局部物理表现；
3. `Stop` 可以播放 Front / Left / Right 受击动画；
4. 角色把动画姿势作为目标，用 `UPhysicalAnimationComponent` 驱动 `spine_01` 以下、但不包含 pelvis 和腿的上半身刚体；
5. 根据请求的命中点、方向和归一化强度，向躯干或左右上臂施加一次封顶表现冲量；
6. 保持很短时间，再把 Physics Blend Weight 平滑降回 0，关闭上半身模拟；
7. Heavy 请求通过自身校验、准备捕获身体前，Light 同步交还上半身。

这不是全身常驻物理，也不是新的 Light/Heavy 共用身体框架：

- 平时上半身 Body 仍不模拟，Physics Blend Weight 为 0；
- Physical Animation drive 会预先建立并持续更新动画目标，但 Strength 为 0，不产生驱动力；
- Light 命中时才临时模拟上半身；
- Heavy 仍由现有 `UHeavyImpactResponseComponent + UPhysicsControlComponent` 独占全身物理、倒地和起身。

## 2. 职责

```text
FStandingImpactRequest
  ├─ SourceProfile
  │    ├─ Player: None / Slow / Stop / 是否允许局部物理
  │    └─ Pursuer: None / Slow / Stop / 是否允许局部物理
  │
  └─ UCharacterImpactResponseComponent
       ├─ 玩法：Slow / Stop / 速度恢复 / AI 攻击抑制
       ├─ 动画：Stop 可播放方向 Dynamic Montage
       └─ 表现：预建 Physical Animation drive
                + 上半身短时模拟
                + 躯干或左右上臂承受一次封顶冲量
                + Hold / Blend Out / 关闭模拟

UHeavyImpactResponseComponent
  └─ 原状态机不变；只新增“校验通过、即将捕获”通知
```

来源不调用角色骨骼 API，也不识别“箱子类”“地刺类”。是否使用物理表现由来源 DataAsset 的角色结果栏声明。

## 4. 来源结果增加物理许可

把“方向和命中点是否足以驱动物理表现”放进既有来源结果栏，而不是用来源类名特判：

```cpp

{
    GENERATED_BODY()

    // 现有 Result / DurationSeconds / SpeedMultiplier / bPlayReactionAnimation 保持。

    /**
     * 该来源对该类接收者是否允许短暂局部物理表现。
     * false 仍可正常产生 Slow / Stop / Montage。
     */
    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category="Standing Impact")
    bool bApplyPhysicalReaction = false;

    bool IsConfigured(FString& OutError) const;
};
```

配置约定：

- `DA_MagneticThrownImpact.Pursuer`：`Stop + 动画 + bApplyPhysicalReaction=true`；
- `DA_MagneticThrownImpact.Player`：首轮仍为 `None`；
- `DA_SpikeStandingImpact`：玩家 Stop、追猎者 Slow 维持，但两栏首轮 `bApplyPhysicalReaction=false`。当前地刺只给“向上 + 角色中心”的 authored 请求，适合玩法/动画方向，不适合作为上半身冲量；
- 将来气罐只有在能给出明确受力方向和作用点时才开启，不需要新增接口。

`None` 结果必须关闭 `bApplyPhysicalReaction`，避免一个被策划声明为无反应的来源仍偷偷驱动物理。

校验合同：

```cpp
bool UCharacterImpactTuningData::IsPhysicalReactionConfigured(
    const USkeletalMeshComponent* Mesh,
    FString& OutError) const
{
    if (!bEnablePhysicalReaction)
    {
        return true;
    }

    const UPhysicsAsset* PhysicsAsset = IsValid(Mesh) ? Mesh->GetPhysicsAsset() : nullptr;
    if (!IsValid(PhysicsAsset))
    {
        OutError = TEXT("Physical presentation requires a valid PhysicsAsset.");
        return false;
    }

    const FName RequiredBodies[] = {
        UpperBodyRootBone,
        TorsoImpulseBone,
        LeftArmImpulseBone,
        RightArmImpulseBone
    };
    for (const FName BodyName : RequiredBodies)
    {
        if (BodyName.IsNone() || PhysicsAsset->FindBodyIndex(BodyName) == INDEX_NONE)
        {
            OutError = FString::Printf(
                TEXT("Physical presentation body '%s' is missing."), *BodyName.ToString());
            return false;
        }
    }

    const auto IsRootOrChild = [Mesh, this](const FName Bone)
    {
        return Bone == UpperBodyRootBone || Mesh->BoneIsChildOf(Bone, UpperBodyRootBone);
    };
    if (!IsRootOrChild(TorsoImpulseBone)
        || !IsRootOrChild(LeftArmImpulseBone)
        || !IsRootOrChild(RightArmImpulseBone))
    {
        OutError = TEXT("All impulse bodies must belong to UpperBodyRootBone.");
        return false;
    }

    if (!PhysicalAnimationSettings.bIsLocalSimulation
        || !FMath::IsFinite(PhysicalAnimationSettings.OrientationStrength)
        || PhysicalAnimationSettings.OrientationStrength <= 0.0f
        || !FMath::IsFinite(PhysicalAnimationSettings.AngularVelocityStrength)
        || PhysicalAnimationSettings.AngularVelocityStrength < 0.0f
        || !FMath::IsFinite(PhysicalAnimationSettings.MaxAngularForce)
        || PhysicalAnimationSettings.MaxAngularForce <= 0.0f
        || !FMath::IsFinite(PhysicalImpulseAtFullStrength)
        || PhysicalImpulseAtFullStrength <= 0.0f
        || !FMath::IsFinite(PhysicalHoldSeconds)
        || PhysicalHoldSeconds < MontageBlendInSeconds
        || !FMath::IsFinite(PhysicalBlendOutSeconds)
        || PhysicalBlendOutSeconds <= 0.0f
        || !FMath::IsFinite(MaxContinuousPhysicalSeconds)
        || MaxContinuousPhysicalSeconds < PhysicalHoldSeconds + PhysicalBlendOutSeconds)
    {
        OutError = TEXT("Physical presentation settings or timing are invalid.");
        return false;
    }

    return true;
}
```

必须在字段注释里写清：

- Chaos 中 `MaxAngularForce == 0` 的含义是“不限制最大角力”，不是“没有角力”；
- 本项目故意要求有限正值，避免动画马达用无限制角力把上半身焊成刚体墙；这是项目安全约束，不是 UE 通用规则；
- `bIsLocalSimulation=true` 时，PositionStrength / VelocityStrength / MaxLinearForce 不参与这条局部角向驱动，不把它们当有效调参；
- `PhysicalHoldSeconds >= MontageBlendInSeconds`，保证 Montage 目标姿势开始混入前，物理不会先退出。

## 7. Configure 时预建 drive

首次命中时才调用 `ApplyPhysicalAnimationSettingsBelow()` 会把约束创建推迟到下一次 Physical Animation PrePhysics Tick；当帧冲量会先打在没有 drive 的自由上半身上。因而预建是本版的硬要求。

```cpp
void UCharacterImpactResponseComponent::Configure(
    ACharacter* InCharacter,
    USkeletalMeshComponent* InMesh,
    UCharacterMovementComponent* InMovement,
    UPhysicalAnimationComponent* InPhysicalAnimation,
    EImpactReceiverCategory InReceiverCategory,
    UCharacterImpactTuningData* InTuning,
    UHeavyImpactResponseComponent* InHeavyImpact)
{
    StopPhysicalReaction();
    ClearActiveImpact(true, true);
    UnbindDelegates();

    Character = InCharacter;
    Mesh = InMesh;
    Movement = InMovement;
    PhysicalAnimation = InPhysicalAnimation;
    ReceiverCategory = InReceiverCategory;
    Tuning = InTuning;
    HeavyImpact = InHeavyImpact;

    // 现有玩法配置校验保持原样。

    bPhysicalReactionReady = false;
    if (Tuning->bEnablePhysicalReaction)
    {
        FString PhysicalError;
        if (IsValid(PhysicalAnimation)
            && Tuning->IsPhysicalReactionConfigured(Mesh, PhysicalError))
        {
            PhysicalAnimation->SetSkeletalMeshComponent(Mesh);
            PhysicalAnimation->ApplyPhysicalAnimationSettingsBelow(
                Tuning->UpperBodyRootBone,
                Tuning->PhysicalAnimationSettings,
                true);
            PhysicalAnimation->SetStrengthMultiplyer(0.0f);
            PhysicalAnimation->Activate(true);
            PhysicalAnimation->SetComponentTickEnabled(true);

            // Body 仍非模拟、Blend 仍为 0；这里只预建 drive 并持续更新动画目标。
            PhysicalConfigurationFrame = GFrameCounter;
            bPhysicalReactionReady = true;
        }
        else
        {
            UE_LOG(LogCharacterImpact, Warning,
                TEXT("%s Light physical presentation disabled: %s"),
                *GetNameSafe(GetOwner()), *PhysicalError);
        }
    }

    HeavyImpact->OnPreContactCaptureRequested.AddUObject(
        this, &UCharacterImpactResponseComponent::HandleHeavyPreContactCaptureRequested);
    HeavyImpact->OnStateChanged.AddUObject(
        this, &UCharacterImpactResponseComponent::HandleHeavyImpactStateChanged);
    bConfigurationReady = true;
}
```

如果命中发生在 `PhysicalConfigurationFrame` 同一帧，局部物理直接跳过一次并记录诊断，不新增 Pending/NextTick 状态。正常关卡中 Configure 发生在角色初始化，正式命中远晚于该帧。

Physical Animation 的 PrePhysics Tick 在启用角色上保持运行；Stop 后只把 Strength 归零，不停掉它。需要用追猎者并发数量做 CPU Profile，不能凭感觉宣称免费。

## 8. SubmitImpact 插入点

物理表现可以对同一玩法窗口里的另一个合法新命中再次响应，因此调用点位于：结构校验、ImpactId 去重、HeavyBusy、`None` 过滤之后，玩法强弱替换判断之前。

```cpp
const FStandingImpactReactionSpec& Spec =
    Request.SourceProfile->GetReaction(ReceiverCategory);
if (Spec.Result == EStandingImpactResult::None)
{
    RecordRecentImpactId(Request.ImpactId);
    return EStandingImpactSubmitResult::Ignored;
}

if (Spec.bApplyPhysicalReaction)
{
    TryApplyPhysicalReaction(Request);
}

// 下面现有 Stop > Slow、强度比较、速度写入、Timer 与 Montage 逻辑保持。
```

因此：

- `Invalid / Duplicate / HeavyBusy / None`：不触发局部物理；
- 新 ImpactId 即使没有升级当前 Stop/Slow，也可给一次新的局部物理反馈；
- 玩法返回值仍由现有 Stop/Slow 仲裁决定，物理表现不延长 gameplay Timer；
- `bPlayReactionAnimation=true` 时，Montage 与物理同次启动；Hold 至少覆盖 Montage BlendIn。

## 9. 命中区域映射与冲量

不把相同冲量直接施加给 `hand_l/r` 或 `head` 等小质量末端 Body。最接近命中骨骼只用于判断区域，最终只向三种受力 Body 之一施力。

```cpp
bool UCharacterImpactResponseComponent::ResolvePhysicalHit(
    const FStandingImpactRequest& Request,
    FName& OutImpulseBody,
    FVector& OutWorldPoint) const
{
    const FName ClosestBone = Mesh->FindClosestBone(
        Request.ImpactPoint, nullptr, 0.0f, true);
    if (ClosestBone.IsNone())
    {
        return false;
    }

    // 先判左右臂，再判上半身其他区域，避免 upperarm 同时被 torso 根覆盖。
    if (ClosestBone == Tuning->LeftArmImpulseBone
        || Mesh->BoneIsChildOf(ClosestBone, Tuning->LeftArmImpulseBone))
    {
        OutImpulseBody = Tuning->LeftArmImpulseBone;
    }
    else if (ClosestBone == Tuning->RightArmImpulseBone
        || Mesh->BoneIsChildOf(ClosestBone, Tuning->RightArmImpulseBone))
    {
        OutImpulseBody = Tuning->RightArmImpulseBone;
    }
    else if (ClosestBone == Tuning->UpperBodyRootBone
        || Mesh->BoneIsChildOf(ClosestBone, Tuning->UpperBodyRootBone))
    {
        OutImpulseBody = Tuning->TorsoImpulseBone;
    }
    else
    {
        return false;
    }

    OutWorldPoint = Mesh->GetBoneLocation(OutImpulseBody);
    return true;
}
```

```cpp
void UCharacterImpactResponseComponent::TryApplyPhysicalReaction(
    const FStandingImpactRequest& Request)
{
    if (!bPhysicalReactionReady
        || GFrameCounter <= PhysicalConfigurationFrame
        || !IsValid(HeavyImpact)
        || HeavyImpact->IsBusy()
        || (!Movement->IsMovingOnGround() && !Movement->IsFalling()))
    {
        return;
    }

    const float Now = GetWorld()->GetTimeSeconds();
    if (bPhysicalReactionActive
        && Now - PhysicalSessionStartTimeSeconds >= Tuning->MaxContinuousPhysicalSeconds)
    {
        return; // 当前会话只允许退出，不再被新命中无限刷新。
    }

    FName ImpulseBody;
    FVector AppliedPoint;
    if (!ResolvePhysicalHit(Request, ImpulseBody, AppliedPoint))
    {
        return;
    }

    if (!bPhysicalReactionActive)
    {
        PhysicalSessionStartTimeSeconds = Now;
        Mesh->SetAllBodiesBelowSimulatePhysics(
            Tuning->UpperBodyRootBone, true, true);
        Mesh->SetAllBodiesBelowPhysicsBlendWeight(
            Tuning->UpperBodyRootBone, 1.0f, false, true);
        PhysicalAnimation->SetStrengthMultiplyer(1.0f);
        bPhysicalReactionActive = true;
        SetComponentTickEnabled(true);
    }
    else
    {
        Mesh->SetAllBodiesBelowPhysicsBlendWeight(
            Tuning->UpperBodyRootBone, 1.0f, false, true);
    }

    LastPhysicalImpactTimeSeconds = Now;

    const FVector Direction = Request.WorldDirection.GetSafeNormal();
    const float Magnitude = Tuning->PhysicalImpulseAtFullStrength
        * FMath::Clamp(Request.NormalizedStrength, 0.0f, 1.0f);
    if (!Direction.IsNearlyZero() && Magnitude > 0.0f)
    {
        Mesh->AddImpulseAtLocation(
            Direction * Magnitude,
            AppliedPoint,
            ImpulseBody);
    }
}
```

这里使用来源已归一化的 `NormalizedStrength`，不直接重放 `RawNormalImpulse`：磁力刚体、Overlap 地刺和未来气罐的原始输入量纲不同。`RawNormalImpulse` 只保留为诊断与来源 Profile 标定证据。

不调用 `WakeAllRigidBodies()`：Physical Animation 更新本身会唤醒相关刚体，额外全身 Wake 会无意义地波及下半身。

## 10. Hold、Blend Out 与幂等清理

```cpp
void UCharacterImpactResponseComponent::TickComponent(
    float DeltaTime,
    ELevelTick TickType,
    FActorComponentTickFunction* ThisTickFunction)
{
    Super::TickComponent(DeltaTime, TickType, ThisTickFunction);
    if (!bPhysicalReactionActive || !IsValid(Mesh) || !IsValid(Tuning))
    {
        StopPhysicalReaction();
        return;
    }

    const float Now = GetWorld()->GetTimeSeconds();
    const float NormalBlendStart =
        LastPhysicalImpactTimeSeconds + Tuning->PhysicalHoldSeconds;
    const float ForcedBlendStart =
        PhysicalSessionStartTimeSeconds + Tuning->MaxContinuousPhysicalSeconds;
    const float BlendStart = FMath::Min(NormalBlendStart, ForcedBlendStart);
    if (Now < BlendStart)
    {
        return;
    }

    const float Alpha = 1.0f - FMath::Clamp(
        (Now - BlendStart) / Tuning->PhysicalBlendOutSeconds,
        0.0f,
        1.0f);
    Mesh->SetAllBodiesBelowPhysicsBlendWeight(
        Tuning->UpperBodyRootBone, Alpha, false, true);

    if (Alpha <= UE_KINDA_SMALL_NUMBER)
    {
        StopPhysicalReaction();
    }
}
```

```cpp
void UCharacterImpactResponseComponent::StopPhysicalReaction()
{
    if (IsValid(Mesh) && IsValid(Tuning) && !Tuning->UpperBodyRootBone.IsNone())
    {
        Mesh->SetAllBodiesBelowPhysicsBlendWeight(
            Tuning->UpperBodyRootBone, 0.0f, false, true);
        Mesh->SetAllBodiesBelowSimulatePhysics(
            Tuning->UpperBodyRootBone, false, true);
    }
    if (IsValid(PhysicalAnimation))
    {
        PhysicalAnimation->SetStrengthMultiplyer(0.0f);
        // 配置有效时继续 PrePhysics Tick，保持 drive 目标新鲜；不 Deactivate。
    }

    PhysicalSessionStartTimeSeconds = 0.0f;
    LastPhysicalImpactTimeSeconds = 0.0f;
    bPhysicalReactionActive = false;
    SetComponentTickEnabled(false);
}
```

`StopPhysicalReaction()` 必须显式出现在：

- `Configure` 重入开头；
- `EndPlay`；
- Heavy PreContactCapture Delegate；
- Heavy 真正进入 `Prepared` 的现有回调（幂等保险）；
- Physical Animation 配置运行时失效的兜底。

普通 `FinishActiveImpact()` / `ClearActiveImpact()` 不自动调用它：玩法 Timer、Montage 和更短的物理 Blend 是三条相关但不相同的生命周期。

`EndPlay` 或配置关闭时，在 Stop 后解除 Heavy delegates、`SetStrengthMultiplyer(0)`、`SetSkeletalMeshComponent(nullptr)`，再停用 Physical Animation Tick；只有销毁/禁用才释放这份常驻 drive。

## 11. Heavy 最小改动

### 11.1 自主判断

不在角色的 `PrepareForHeavyImpact_Implementation()` 转发前清 Light。那样会让 `Duplicate / Busy / Invalid` 的 Heavy 请求也提前截断局部物理，语义错误。

允许修改 Heavy 的最小且正确做法，是在它自己的校验成功后、捕获身体前广播一个 native delegate：

```cpp
// HeavyImpactResponseComponent.h
DECLARE_MULTICAST_DELEGATE_OneParam(
    FOnHeavyImpactPreContactCaptureRequested,
    const FHeavyImpactPreparationRequest&);

FOnHeavyImpactPreContactCaptureRequested OnPreContactCaptureRequested;
```

```cpp
// HeavyImpactResponseComponent.cpp
EHeavyImpactPrepareResult UHeavyImpactResponseComponent::PrepareForImpact(
    const FHeavyImpactPreparationRequest& Request)
{
    // 下列现有顺序、拒绝日志和返回值逐行保留：
    // HasSeenImpactId -> State -> SameSourceProtection -> ValidatePreparationRequest

    if (!ValidatePreparationRequest(Request, FailureReason, AllowedMaximumSeconds))
    {
        // 现有 ShouldLogRejectedImpact / Log / Invalid 原样保留。
        return EHeavyImpactPrepareResult::Invalid;
    }

    // 唯一新增插入点。
    OnPreContactCaptureRequested.Broadcast(Request);

    // 现有 Capture / EnterPrepared / rollback / record 原样保留。
    if (!CapturePreContactState(FailureReason)
        || !EnterPrepared(Request, AllowedMaximumSeconds, FailureReason))
    {
        RestoreSnapshotAfterFalsePositive();
        return EHeavyImpactPrepareResult::Invalid;
    }
    RecordRecentImpactId(Request.ImpactId);
    return EHeavyImpactPrepareResult::Accepted;
}
```

Light 订阅者同步执行：

```cpp
void UCharacterImpactResponseComponent::HandleHeavyPreContactCaptureRequested(
    const FHeavyImpactPreparationRequest& /*Request*/)
{
    StopPhysicalReaction();
}

void UCharacterImpactResponseComponent::HandleHeavyImpactStateChanged(
    EHeavyImpactState /*Previous*/,
    EHeavyImpactState Current)
{
    if (Current == EHeavyImpactState::Prepared)
    {
        StopPhysicalReaction(); // 幂等保险
        ClearActiveImpact(true, true);
    }
}
```

影响边界：

- 不增加 Heavy 状态；
- 不修改 Heavy PCA/Profile/Tuning；
- 不修改 Heavy 的 Capture、Prepared、Flight、Landing、Downed、Recovering 与误预测回滚；
- Busy、Duplicate、同来源保护和非法请求不会广播；
- 若校验后 Capture/Enter 仍失败，Light 的短物理余势会提前结束，但玩法状态和 Montage 不会在 PreCapture 通知里清除，也不为这条极少数错误路径增加 Light 恢复栈。

这是必要的单一职责插点，不是 Heavy/Light 大重构。

## 12. 当前资产事实与诚实边界

官方 UE5.8 MCP 已回读：

- 追猎者 Mesh：`SK_Sci_Fi_Character_08_Full_01`；
- AnimClass：`ABP_Pursuer_Locomotion`；
- Mesh CDO：`CharacterMesh / ECC_Pawn / QueryOnly / bSimulatePhysics=false / PhysicsBlendWeight=0 / bNotifyRigidBodyCollision=false`；

由 `QueryOnly` 可推出：

- 上半身 Body 能因脚本施加的冲量进入 Chaos 模拟并由 Physical Animation 回拉；
- 它们不会作为物理阻挡体反向改变箱子轨迹，也不会主动撞墙；
- 箱子仍通过现有 Capsule/磁力事务完成命中，局部骨骼反应是角色表现层；
- 本版不承诺箱子因手臂碰撞而失速或偏转。

如果用户验收标准仍要求“来源物体与身体刚体第一次接触时真实双向交换动量”，本版应判不满足并停止，而不是偷偷修改 Mesh 碰撞或重新引入 Source Lease。

## 13. 验证

### 13.1 自动化只测数据合同

扩展现有 `CharacterImpactResponseTests.cpp`：

- `PhysicalHoldSeconds < MontageBlendInSeconds` 被拒绝；
- `MaxAngularForce=0` 因项目安全约束被拒绝，并在字段注释明确 UE 本身把 0 解释为“不限制”。

不在这份纯数据测试里伪造以下结论：真实 Body 是否模拟、首次 Tick 是否有 drive、Heavy 抢占是否清干净、画面是否自然。这些必须由真实 Mesh + PhysicsAsset 的 PIE/MCP 证据验证。

### 13.2 构建和资产

- 正常关闭 UE Editor；
- 只构建 Demo 模块：`-Module=Demo -NoEngineChanges`；
- 重启后用官方 MCP 回读两个角色的 Physical Animation 组件、两份角色 Tuning、两个来源 Profile；
- 不编译或修改 UE5.8 引擎。

### 13.3 PIE 首轮

1. 关闭局部物理：磁力物砸追猎者胸、左、右，记录纯 Stop + Montage 基线；
2. 开启局部物理：同质量、速度、位置重复，三方向必须肉眼可区分，且不能全身软掉；
3. Stop 动画仍清楚；物理提供短促区域偏转与余势，不得只剩动画，也不得把动画打散；
4. Slow 继续低速寻路；Stop 停移动；二者继续打断攻击；空中 Stop 只清水平速度；
5. 连续不同箱子命中，到 `MaxContinuousPhysicalSeconds` 后必须开始退出；
6. Light 反应中触发摆锤/冲锤：Heavy Prepare、击飞、倒地、起身和误预测不得退化；
7. 摆锤击飞并起身，起身后 1 秒内再用磁力物砸胸口，局部物理应恢复可用；
8. Heavy 全身物理期间，Physical Animation drive 虽存在但 Strength=0，不得产生可见扭矩；
9. Light 退出后 `spine_01` 以下上半身 Body 全部非模拟，Light 临时 Tick 关闭；
10. 用 1 / 5 / 10 个追猎者 Profile Physical Animation PrePhysics 开销；无命中时 Body 均非模拟。

## 14. 止损

出现任一项就停止，不继续堆兼容代码：

- 为了让画面可见，必须修改磁力事务、碰撞路由或 Mesh 为 QueryAndPhysics；
- 必须使用极端冲量或无限角力才有反应；
- Stop Montage 与局部物理两轮 A/B 后仍明显互相打架；
- 上半身出现尸体感、撕裂、手臂抽飞或恢复闪切；
- Strength=0 的预建 drive 仍改变 Heavy 画面；
- Heavy 任一已验收的击飞、倒地、起身或误预测行为退化；
- 修复开始扩散到 Source Lease、预测、测试关卡、共享身体组件或 Heavy 状态重构。
