# UE 5.7.4 → 5.8 升级兼容性预检清单

> 日期：2026-07-24　作者：Claw（只读分析，未修改任何项目代码/资产）
> 范围：磁力功能 C++、UEEditorMCP 插件、自写 PCG 运行时生成器
> 结论速览：**磁力 ≈ 零风险；PCG（自写纯 C++）编译风险极低；UEEditorMCP 插件是唯一的高风险大工作量区。**

- **运行时验证项**：`SetInterpolationSpeed` / 线性刚度阻尼驱动的 Chaos 目标插值，手感在 5.8 若有内核微调可能有细微差异。→ 升级后在 PIE 用同一 `MagneticGrabTuningData` 实测抓取/吸取/投掷手感，与 5.7.4 对比。

## B. UEEditorMCP 插件 —— 风险等级：★★★★☆（最大工作量）

### 依赖的编辑器模块（`UEEditorMCP.Build.cs`）
`UnrealEd, EditorSubsystem, BlueprintGraph, Kismet, KismetCompiler, GraphEditor, UMG, UMGEditor, EnhancedInput, InputBlueprintNodes, EditorScriptingUtilities, AssetTools, SourceControl, MaterialEditor, RenderCore, RHI, ModelViewViewModel, ModelViewViewModelBlueprint, FieldNotification`

这些模块 5.8 都在，但**内部 API 是 5.7→5.8 变动的重灾区**（尤其 K2Node / Kismet / MVVM）。

### 按风险排序的排查目标（依据危险 API 出现次数）

| 文件 | K2Node/Kismet 等命中数 | 风险 |
|---|---:|---|
| `Private/Actions/NodeActions.cpp` | 176 | ★★★★★ 最高，蓝图逐节点建图/连线全在这 |
| `Private/Actions/GraphActions.cpp` | 50 | ★★★★ |
| `Private/MCPCommonUtils.cpp` | 44 | ★★★★ 类型转换/pin 处理 helper，被大量复用 |
| `Private/Actions/UMGActions.cpp` | 23 | ★★★ UMG/UMGEditor API |
| `Private/Actions/EditorActions.cpp` | 22 | ★★★ |
| `Public/MCPCommonUtils.h` / `BlueprintActions.cpp` / `LayoutActions.cpp` | 11 / 7 / 7 | ★★ |

### 高风险 API 类别（重点核对）
1. **K2Node 家族**：`UK2Node_*`（CallFunction / Event / CustomEvent / VariableGet/Set / DynamicCast / MacroInstance / ExecutionSequence / ComponentBoundEvent / CreateDelegate 等）的构造与 `AllocateDefaultPins` 流程。
2. **`UEdGraphSchema_K2`**：pin 连接/断开、类型比较、`TryCreateConnection`、pin 默认值 API。
3. **`FBlueprintEditorUtils` / `FKismetEditorUtilities`**：变量增删、图编译、节点添加的静态方法签名。
4. **MVVM（`ModelViewViewModelBlueprint`）**：`UMVVMBlueprintView` 等——MVVM 是活跃演进模块，5.8 API 变动概率高。
5. **`UMaterialEditingLibrary`（MaterialEditor）**：材质表达式操作。
6. **AssetTools / IAssetRegistry**：资产枚举/重命名/缩略图接口。

### 排查方法（升级时执行）
- 用 5.8 编译，**从 `NodeActions.cpp` 开始按上表顺序修**；每修一批重编。
- 报错优先看：函数改名、参数增减、返回类型从裸指针改 `TObjectPtr`、枚举值改名。
- **无法静态 100% 预判**——这些是编辑器私有 API，必须以实际 5.8 编译错误为准。预算上按"最大工作量项"安排。

### 备选（若适配成本过高）
UE5.8 官方自带 MCP（`ModelContextProtocol` 插件 + Toolsets），可先启用官方 MCP 顶住基本需求，再慢慢修 UEEditorMCP。二者端口不冲突（55558 vs 8000）。

## C. 自写 PCG 运行时生成器 —— 风险等级：★★☆☆☆（编译低危；"效果不对"是独立问题）

### 关键事实（来自 `DOC/DailyPlan/2026-07-23-PCG整关场景方案冻结.md`）
- 代码在 `Source/Demo/Public/PCG` + `Private/PCG`（10 个文件，`ZeroEscape*`）。
- **纯 C++ 值类型算法**：Progression / Spatial Graph / 整数 A* / Simple-Tiled WFC / Socket 回溯 / 全局验证。
- **明确不依赖** `UnrealEd`、Editor Subsystem、UE 官方 `PCG` 模块、Experimental `WaveFunctionCollapse` 插件。
- 运行时实例化用 **HISM**；配置用 DataAsset（`DA_LevelGenerationProfile` / `DA_LevelModuleCatalog` / `DA_Presentation_SFCorridors`）。
- 素材来自第三方 `/Game/Assets/SFCorridors`，并已改了 3 个根材质的 `Used with Instanced Static Meshes`（对应 git 里 M_Master / M_Glass_Panels_NM / M_MasterTransp 的改动）。

### 升级编译风险 → 低
因为不碰任何 Experimental/Editor PCG 模块，官方 PCG/WFC 在 5.8 怎么变都不影响它。用到的都是稳定 Runtime API：
- **HISM**（`UHierarchicalInstancedStaticMeshComponent`：AddInstances 等）——5.8 稳定，需回归实例化数量/Transform。
- **DataAsset / StaticMesh / SoftObjectPath**——稳定。
- 若后续接 **`UNavigationSystemV1`**（文档提到追猎者前才接）——注意 5.8 导航 API，届时再看。

### 需要在 5.8 重新验证的点
1. **之前的 NullRHI 崩溃**：13.17 记录，5.7.4 下 `-NullRHI` Spawn 首个 Actor 触发 `FSceneViewport::EnqueueBeginRenderFrame` 整数除零。→ 5.8 可能已修或行为不同，升级后重测"命令行/自动化实例化"路径。
2. **SFCorridors 第三方素材包**：在 5.8 打开是否有资产版本警告；3 个根材质的 Instanced 用法 Flag 在 5.8 是否保持。
3. **`Demo.PCG` 自动化测试**：升级后重跑（当前 5.7.4 下 13/13）。测试是纯数据 + 少量地图型，5.8 应可直接跑。

### 关于"效果不对，要大改"
- 这是**玩法/PIE 成图层面**的问题（文档 13.16/13.21 显示：还没真正跑通 PIE-A，没有 WFC 有效选择/碰撞/导航/玩家 Start→Exit 走通的验收），**与引擎升级正交**。
- 建议顺序：**先升级并让现状在 5.8 编译+自动化通过（保证基线不倒），再在 5.8 上做 PCG 大改**。不要把"升级"和"重做 PCG"两件事搅在一起，否则出问题难定位是升级引入还是重做引入。
- 升级本身还能顺带给 PCG 大改带来的好处：5.8 官方 MCP 的 `AutomationTestToolset` 可辅助批量跑你的 `Demo.PCG` 回归。

## D. 总体升级顺序建议

1. 冻结副本（Git tag `v5.7.4-final` + 物理副本 `Demo_UE5.7.4_backup`）。
2. 切引擎 5.8，Generate 工程文件。
3. 编译：磁力/PCG 预计顺畅；**主力时间花在 UEEditorMCP 插件（B 区）**。
4. 打开编辑器，验证资产（SFCorridors、DataAsset、关卡）无损坏。
5. 回归：磁力 PIE 手感对比 + `Demo.PCG` 自动化重跑 + PCG 的 NullRHI 实例化路径重测。
6. （可选）启用官方 MCP，双 MCP 并存。
7. 基线在 5.8 稳定后，再开 PCG "大改"分支。
