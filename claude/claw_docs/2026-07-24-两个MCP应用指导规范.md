# 两个 MCP 应用指导规范（供后续 AI 使用）

> 日期：2026-07-24　适用：Demo 项目（已升级 UE5.8）同时挂载两个 MCP 的场景
> 依据：对 `ue-editor-mcp`（151 actions）与 UE5.8 官方 MCP（23 toolset）的实测
> 实测证据：`claude/claw_docs/mcp_capability_overview.md`、`mcp_describe_blueprint.md`

---

## 0. 一句话定位

| MCP | 通道 | 规模 | 最擅长 |
|---|---|---|---|
| **ue-editor-mcp** | 本地 socket **55558**（Python server + C++ 桥） | 151 个细粒度 action | 蓝图图表**微操与重构**、PIE 精细控制、日志断言、depot diff / 资产历史 |
| **UE5.8 官方 MCP** | HTTP **8000** `/mcp`（Streamable HTTP + SSE） | 23 toolset / ~180+ 工具 | 引擎**子系统广度**：物理资产、语义搜索、自动化测试、各类资产 CRUD、属性/类发现、AgentSkill、Python 编排 |

**两者端口/协议独立，可同时使用，互不干扰。**

---

## 1. 官方 MCP 的调用范式（关键：tool-search 模式）

官方 server 开了 `bEnableToolSearch=true`，`tools/list` 只暴露 **3 个入口**，具体能力靠按需发现：

1. `list_toolsets()` — 列出全部 23 个 toolset 及职责
2. `describe_toolset(toolset_name)` — 看某 toolset 的所有工具+签名+schema
3. `call_tool(toolset_name, tool_name, arguments)` — 实际调用

**调用三步走**：先 `list_toolsets` 找方向 → `describe_toolset` 看具体工具和参数 → `call_tool` 执行。

- 连接：CodeBuddy 全局 `mcp.json` 已配 `ue58-official-mcp` → `http://localhost:8000/mcp`（需重载会话后原生可用）。
- 启动：项目已设 `bAutoStartServer=True`，**开编辑器即自动起 server**，无需手动命令。
- 手动兜底：编辑器控制台 `ModelContextProtocol.StartServer`。

## 2. 能力矩阵（谁强 / 谁独有）

| 领域 | ue-editor-mcp | 官方 MCP | 首选 |
|---|---|---|---|
| 蓝图创建/变量/函数/组件/接口/编译 | ✅ blueprint.* | ✅ BlueprintTools | 两者皆可 |
| 蓝图**逐节点建图+连线** | ✅ node.add_*/graph.connect_nodes | ✅ add_node/connect_pins/set_node_pin_default | 两者皆可 |
| 蓝图**专门节点**(Event/CustomEvent/Dispatcher/Macro:ForEach·Gate·DoOnce/Cast/EnhancedInput) | ✅ 细分且便捷 | ⚠ 靠通用 add_node(node_type) | **ue-editor-mcp** |
| 蓝图**图重构**(collapse→function/macro、自动排版、批量选中操作) | ✅ graph.collapse_*/layout.auto_*/batch_select_and_act | ❌ 未见 | **ue-editor-mcp** |
| EnhancedInput 节点/映射 | ✅ input.* | ❌ | **ue-editor-mcp** |
| PIE 精细控制 + 日志断言 + depot diff + 资产历史 | ✅ editor.assert_log/diff_against_depot/get_asset_history | ⚠ EditorApp 有基础 PIE/Logs | **ue-editor-mcp** |
| UMG 控件树/属性/事件绑定 | ✅ widget.* | ✅ UMGToolSet(配合 ObjectTools) | 两者皆可 |
| 材质图编辑 | ✅ material.* | ✅ MaterialTools/MaterialInstanceTools | 两者皆可 |
| **通用属性 get/set/list + 类/子类发现** | ⚠ 分散 | ✅ ObjectTools（统一入口） | **官方** |
| **语义搜索**(向量+BM25 搜资产/源码) | ❌ | ✅ SemanticSearch/AgentSkill.search_* | **官方** |
| **自动化测试**(发现/运行/取结果) | ❌ | ✅ AutomationTest(discover/list/run/get_results) | **官方** |
| **物理资产**创建/管理 | ❌ | ✅ PhysicsAssetToolset(8) | **官方** |
| **各类资产 CRUD**(DataTable/CurveTable/StringTable/Texture/Static·SkeletalMesh) | ⚠ 部分 | ✅ 专门 toolset | **官方** |
| Actor/场景/Outliner/相机 | ✅ editor.* | ✅ ActorTools/SceneTools | 两者皆可 |
| **AgentSkill**(把多工具打包成技能，可 list/read/create/update/delete) | ❌ | ✅ AgentSkillToolset(25) | **官方** |

## 3. 决策规则（后续 AI 按此选择）

按优先级从上到下匹配：

1. **语义搜资产/源码** → 官方 `SemanticSearchToolset` / `AgentSkillToolset.search_*`
2. **跑/查自动化测试**（如 `Demo.PCG` 回归）→ 官方 `AutomationTestToolset`
3. **物理资产（PhysicsAsset）创建/编辑** → 官方 `PhysicsAssetToolset`
4. **通用对象属性 get/set/list、类/子类发现** → 官方 `ObjectTools`
5. **DataTable/CurveTable/StringTable/Texture/Mesh/MaterialInstance 等资产 CRUD** → 官方对应 toolset
6. **批量、需自定义逻辑串联多个工具** → 官方 `ProgrammaticToolset`（Python 编排）
7. **蓝图图表微操**：加专门节点(事件/分发器/宏/Cast/EnhancedInput)、collapse 重构、自动排版、批量选中操作 → **ue-editor-mcp**
8. **PIE 精细控制 / 日志断言 / depot diff / 资产历史** → **ue-editor-mcp**
9. **蓝图基础 CRUD、UMG、材质、Actor/场景** → 两者皆可，**优先当前已连通、上下文已在用的那个**，减少切换成本
10. 拿不准官方有没有某能力 → 先 `list_toolsets` + `describe_toolset` 查，别臆断"不支持"

## 4. 使用注意与已知坑

**官方 MCP（HTTP/SSE）**
- 响应是 **SSE 格式**（`event: message` / `data: {json}`），解析要拼接同一 message 的多个 `data:` 行再 `json.loads`；`text` 字段里的换行是 JSON 转义 `\n`。
- **同一 session 连续发多个请求可能中途中断**（尤其首次触及 Python toolset）；批量枚举时**每个请求用独立 session**（重新 `initialize`）最稳。
- `editor_toolset.toolsets.*` 是 **Python 实现**的 toolset，首次调用可能有初始化延迟。
- Server 随编辑器进程存在；编辑器关了 server 就没了。

**ue-editor-mcp**
- 通过 `ue_actions_run` 执行 action；先 `ue_actions_search` 换多个关键词、再 `ue_actions_schema` 看参数，避免臆断"做不到"。
- 操作前先 `graph.describe` / `widget.get_tree` / `editor.list_assets` 读现状，只改缺的。

**共存**
- 端口 55558（socket）vs 8000（http）不冲突，可同时挂。
- 官方走 `mcp.json` 的 `ue58-official-mcp`；ue-editor-mcp 是原生工具。
