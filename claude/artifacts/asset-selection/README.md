## 1. 为什么使用独立测试工程

旧素材第一次打开时可能触发资产升级、Shader 重编译、蓝图重编译或插件依赖变化。独立测试工程用于隔离这些变化，避免把大量未知资产、重定向器和依赖直接带入 `Demo/Content`。

测试工程应位于 Demo 工程之外，例如 `D:\UE5projects\ZeroEscapeAssetSandbox`。在用户明确确认前，不创建该工程。

## 3. 兼容性风险分级

| 风险 | 常见类型 | 首轮检查 |
|---|---|---|
| 低 | 静态网格、纹理、普通材质、音频 | 能否加载；比例、枢轴、材质和碰撞是否正常 |
| 中 | 骨骼网格、动画、蓝图、粒子、复杂主材质 | 骨架/重定向、蓝图编译、废弃节点、渲染表现 |
| 高 | C++ 插件、Editor 插件、依赖旧第三方库的系统 | 是否提供 5.7 构建；模块能否编译；是否值得迁移 |

风险等级只表示排查成本，不等于一定不兼容。

## 4. 每个候选包的测试顺序

1. 记录包名、作者、来源、许可证、购买时间和原始支持版本。
2. 在独立 UE 5.7.4 测试工程中添加一个包，不同时混入多个包。
3. 等待 Shader 完成，保存日志；检查是否有缺失插件、失败加载或蓝图编译错误。
4. 打开包的 Overview/Demo Map；检查材质、灯光以及关闭高级渲染功能后的表现。
5. 对模块化环境检查尺寸、网格、枢轴、门洞、内外转角和简单碰撞。
6. 用当前角色尺寸和代表性铁板测试通行、遮挡、物理碰撞和快速移动。
7. 只把结论为“可用”的最小资产集合列入 Demo 迁移候选；迁移前再次征得用户授权。

## 5. PCG 环境包最低要求

- 同一套视觉风格，优先科幻工业或废料设施。
- 至少包含地面、直墙、内外转角、门洞和走廊模块。
- 模块尺寸与连接口能够归一化，关键通路能容纳玩家持有铁板通过。
- 静态环境具有可靠的简单碰撞，不依赖 Lumen、硬件光追或特殊运行时插件才能成立。
- 原始第三方素材保持独立；PCG 以后引用项目自有的模块包装层，避免算法直接绑定商店素材路径。

## 6. 当前需要用户提供的信息

最省事的方式是提供 Epic/Fab 资产库截图，或者先列出最可能相关的 5～10 个包名。优先提供环境包，其次是敌人角色/动画和物理道具。

## 7. 已确认的视觉与空间方向

### 一句话定位

**废弃科幻工业设施中的地牢式追逐。**

- 科幻：电磁能力、供电设施、隔离门、管线和设备舱提供世界观依据。
- 工业/废料：金属板、货箱、机械件、维修通道和废弃设备自然成为可抓取、投掷和阻挡的物理资源。
- 恐怖氛围：依靠追猎压力、局部黑暗、远处声响、警示灯和不完整视线营造，不依赖大量血腥或昂贵怪物美术。
- 地牢感：来自房间—走廊结构、锁闭区域、环路、捷径和逐步深入，而不是传统石墙美术。

### 推荐的 PCG 空间模型

不采用只有细走廊和随机死胡同的纯迷宫。首版更适合生成“房间图”：

1. 房间承担遭遇、观察、绕行和物理操作。
2. 走廊连接房间、制造压迫和转场，但不承担主要战斗。
3. 关键追逐区至少有两个出口，并尽量形成一个可验证的回环。
4. 通过机器、立柱、货架、废料堆和半高墙切断视线，但为玩家和追猎者保留足够通行宽度。
5. 死胡同只作为短风险支路或资源点，不连续出现，也不封死主路线。
6. 捷径、单向门或可绕行通道可以帮助玩家暂时拉开距离，但不得让追猎者永久失效。

### 首版房间类型

| 类型 | 追逐作用 | 主要素材需求 |
|---|---|---|
| 起始安全舱 | 教学、观察首批路线 | 小房间、控制台、隔离门 |
| 狭窄维修通道 | 压迫、短暂转场 | 管线、格栅、门框、警示灯 |
| 追逐房间 | 绕柱、折返、投掷和重新选路 | 立柱、机器、货架、2～3 个出口 |
| 废料处理区 | 提供轻重不同的磁性物体 | 铁板、箱体、机械零件、废料堆 |
| 环路枢纽 | 允许甩开追猎者并改变方向 | 多门房、中央遮挡、支路标识 |
| 目标/供电室 | 迫使玩家短暂停留并承担压力 | 控制台、发电设备、明确交互点 |
| 撤离区 | 最终冲刺和出口辨识 | 大门、信标、强方向性灯光 |

### 追逐空间的筛选硬条件

- 主追逐房不能只有一个入口和一个出口。
- 门、走廊和转角要能容纳玩家持有铁板移动，避免核心能力与关卡冲突。
- 每个关键区都要有至少一个视线阻断物和一个重新选择方向的节点。
- 不能连续生成多个长直走廊，否则追猎者速度会取代路线决策。
- 不能依靠大量狭窄杂物制造复杂度，否则容易造成导航、物理物体和追猎者卡死。
- 恐怖感不能牺牲可读性：出口、可抓取物、危险和目标仍需通过色彩、灯光或轮廓清楚区分。
