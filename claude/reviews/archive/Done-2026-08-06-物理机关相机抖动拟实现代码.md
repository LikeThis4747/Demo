## 2. 需要校准预期（高回报，不阻塞）

### 2.1 `bClampToMaxPhysicsDeltaTime` 的真实行为与作用面

引擎源码 `SpringArmComponent.cpp` 第 98-102 行：

```cpp
if (bClampToMaxPhysicsDeltaTime)
{
    DeltaTime = FMath::Min(DeltaTime, UPhysicsSettings::Get()->MaxPhysicsDeltaTime);
}
```

两个与方案叙述不同的事实：

1. **无条件生效**：实现里并没有头文件注释所说的"AND the view target is simulating using physics"判断——只要属性为 true 就 clamp。所以任务卡/计划里对"Capsule 是否算 simulating physics"的顾虑其实不成立，开了就会作用于 camera lag 的 DeltaTime。这是好消息。
2. **但作用面很窄**：`MaxPhysicsDeltaTime` 默认 1/30 s（0.0333）。`FMath::Min` 只在 `DeltaTime > 1/30`（即帧率低于 ~30 fps）时才真正截断。正常 30–60 fps 下这行几乎不改变 DeltaTime。**它是低帧率保险，不是常态抖动的主力解**。

建议：把它理解成「低帧率/卡顿时的防过冲兜底」，主抖动应由 §2.2 的 camera lag 本身 + 更新顺序修复承担。方案把四项改动并列，实际权重应说清 `bClampToMaxPhysicsDeltaTime` 最弱，避免调参时误判它没起作用（正常帧率下它本就几乎不动）。

### 2.2 全局 camera lag 会平滑「一切」位置变化，被击飞大位移的手感靠 `CameraLagMaxDistance` 定

源码第 129-166 行确认：camera lag 平滑的是弹簧臂 origin（挂在角色根节点），`CameraLagSpeed`（指数逼近）+ `CameraLagMaxDistance`（最大滞后钳制）。

- 受击时 HeavyImpact 让根节点跟随飞行骨盆 = 大幅快速位移。`CameraLagSpeed=12` 会让相机明显滞后再追上，`CameraLagMaxDistance=60cm` 限制最大落后。这**既消抖也带来"拖拽感"**。
- 同一组参数也作用于正常跑动（方案 §6、风险节已承认 12 是起调值、可能改手感、必要时才状态化）。

建议 PIE 必须同时确认两件事，不能只看抖动消失：① 房间中央受击不再逐帧跳；② 击飞跟随不拖沓、正常跑动不粘滞。`CameraLagMaxDistance` 是这两者之间最关键的旋钮，建议对 40/60/100 cm 做一次对照。

## 3. 经引擎源码核对为正确的部分（明确肯定）

- **更新顺序修复对症**：`CameraBoom`（构造第 49 行）比 `HeavyImpactResponse`（第 66 行）先创建，二者同为 `TG_PostPhysics`（SpringArm 默认 tickgroup，源码第 22 行确认），无显式依赖时 CameraBoom 很可能先 tick、读到本帧尚未被 HeavyImpact 更新的旧根节点位置 → 一帧错位抖动。`AddTickPrerequisiteComponent` 让 CameraBoom 等 HeavyImpact，正是对症修复。且 prerequisite 仅在 HeavyImpact 实际 tick（受击期间）时约束，平时其 tick 关闭、CameraBoom 正常运行——零常驻开销。
- **camera lag 在碰撞检测之前、只平滑 origin 不平滑命中点**：源码第 133-179 行先 lag 出 `DesiredLoc`，第 197 行 sweep（起点仍是未平滑的 `ArmOrigin`），`BlendLocations`（第 227-230 行）命中即返回命中点。因此方案 §5 的结论准确——无墙时受击抖动被平滑，贴墙时命中点不被平滑、瞬时回缩仍在。方案如实把后者划入第二阶段，不夸大第一版效果。
- **保持不变的项确实是默认值**：`TG_PostPhysics`、`ProbeChannel=ECC_Camera`、`ProbeSize=12`、`bUseCameraLagSubstepping=true`、`CameraLagMaxTimeStep=1/60` 均与 SpringArm 构造默认一致（源码第 22/34/35/39/42 行），不改是对的（`CameraLagMaxTimeStep` 另受 `OnRegister` 第 244 行强制 ≥1/200，1/60 合法）。
- **不采用的方向判断正确**（方案 §6）：关碰撞/缩探头会增加穿墙、开旋转 lag 会软化视角输入、开 Character Tick 会引入第二套状态——都应排除。判断专业。
- 不新增类/头文件/Tick/Timer/Delegate；蓝图为手感参数唯一权威、不在 C++ 重复硬写——符合项目「避免双权威」原则。

## 4. 可延后 / 信息项
