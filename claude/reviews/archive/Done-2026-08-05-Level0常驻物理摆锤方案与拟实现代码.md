## 0. 总体结论

**方向成立，可以进入实现，但先看第 2 节的核心设计风险。**

- 核心物理机制正确：约束 `Component1=nullptr` 锚定世界、`Component2=BobBody` 且约束帧在质心正上方 `PendulumLength` 处，构成真正的钟摆；主摆绕 Twist(本地 X)、`FRotator` 的 Roll 分量映射到 Twist，坐标约定自洽。
- 工程风格与现有 `SpikeTrapHazard` / `PhysicsControlHitTuningData` 高度一致（`final AActor`、`SceneRoot` Movable、`bCanEverTick=false`、`UDataAsset` 基类、中文 Category、Timer 生命周期、失效即停用、无碰撞二次加力），符合 AGENTS.md 硬规则。
- **最大风险不是 bug，而是设计张力**：用「位置伺服追正弦」实现摆动，与「外物可持续扰动摆锤」这个核心卖点在物理上互相打架。当前起调参数明显偏向「抹掉扰动」那一端，首轮 PIE 很可能看不到设计想要的可读扰动。这是本轮最该在实现前想清楚的点。

没有发现会导致编译失败或崩溃的硬阻塞。下面按优先级列出。

## 2. 高回报（强烈建议实现前处理或至少预案）

### 2.1【核心】「位置伺服追正弦」与「外物可扰动」在物理上冲突，且起调值偏向压制扰动

问题本质：
- `SetOrientationDriveTwistAndSwing(true,true)` + 移动的 `AngularOrientationTarget` 是一个**刚性角度伺服**。它的天职就是消除任何偏离目标的角位移。外物撞击带来的相位/摆幅变化，正是伺服要主动纠正掉的量。
- `SetAngularDriveAccelerationMode(true)` 下，`DrivePositionStrength`/`VelocityStrength` 是「加速度增益」（已按等效惯量归一），`DriveForceLimit` 才是真正的力矩钳制上限。当前起调 `DriveForceLimit = 6e7`，对 300 kg、L≈5.2 m 的摆几乎等于「不限制」，伺服会在一两帧内把 20 kg@2000 cm/s 的冲击纠正回正弦轨迹 → 玩家基本看不到「可扰动」。
- 也就是说，方案 §5.2 注释「Force Limit 必须有限，使外部碰撞可以暂时压过驱动」的意图是对的，但给出的**起调值方向恰好相反**：6e7 不是「有限」，是「近乎无限」。

同一逻辑也作用在次轴：`OrientationDrive` 的 swing 目标恒为 0，`SecondaryAxisLimit=±8°` 允许瞬时侧摆，但同强度伺服会立刻把侧摆拉回 0，偏心撞击产生的侧摆几乎留不住。

建议（按推荐度排序）：
1. **换驱动策略更根本**：真实钟摆靠重力自恢复，本不需要位置伺服。改为「接近无损自由摆（把 `LinearDamping`/`AngularDamping` 调到很低）+ 仅补充阻尼损耗的能量」，例如用角速度驱动或「仅当摆幅低于阈值时补一点力矩」。这样外物注入/削减的能量能保留多个周期，「可扰动」才真正可见。位置伺服本质是「假摆」，外物扰动会被即时吃掉。
2. 若坚持位置伺服，则 `DriveForceLimit` 起调值必须**主动往小调**（先从「刚好能对抗重力维持振幅」的量级开始向上试），并在报告里把它当作首要待调项，而不是从 6e7 往下摸。
3. 无论哪种，验证矩阵里「20 kg 箱撞击后出现可见但不失控的轨迹变化」应作为**首轮 gate**，看不到就先停下来改策略，不要靠继续堆 14 个参数硬凑。

方案已在 §11 与风险节承认「力矩过大抹扰动、过小卡停需 PIE 调」——认知正确，但起调值与驱动范式的选择会直接决定首轮能否观察到卖点，值得在动手前定调。

### 2.2 驱动周期(3.6 s)明显快于自然摆周期(≈4.57 s)，进一步挤压扰动余量

- L=5.2 m 的自然周期 T=2π√(L/g)≈4.57 s；强制 3.6 s 比自然快约 27%。
- 后果：伺服要持续对抗重力/惯性做正功维持更快节奏 → 需要更大 strength/力矩 → 和 2.1 叠加，留给「外物扰动」的力矩窗口更窄。
- 建议：`SwingPeriodSeconds` 起调值改到接近自然周期（4.5 s 附近），让驱动更省力，同样力矩上限下扰动更明显；节奏可读性再靠摆幅和几何补。这条与 2.1 是协同的。

### 2.3 静止不穿地校验依赖「Actor 原点贴地」这一放置约定，代码不保证

- `IsConfigured` 里 `PivotHeight > PendulumLength + BobRadius` 只保证「相对 SceneRoot 原点」锤底不低于 0；一旦关卡放置时 Actor 被抬高/压低或父级有偏移，锤底离地就变了。
- 建议：在 §8 实施步骤和 BP 放置说明里，把「SceneRoot 原点必须贴 Level0 地面」列为显式放置检查项；或在 PIE 首帧加一条一次性的「锤最低点离地 < 0 则 Error 日志」自检（不常驻 Tick）。属低成本高保险。

## 3. 可延后（实现时顺手处理，不阻塞）

### 3.1 约束参数配置顺序建议调整
`BeginPlay` 现为 `ConfigureConstraint`(设 limit/drive/target) → `SetSimulatePhysics(true)` → `SetConstrainedComponents(...)`。`ConstraintInstance` 通常会缓存 profile 并在绑定时应用，多数情况没问题，但更稳妥、更少版本坑的顺序是：先 `SetConstrainedComponents` 绑定，再设 limit/drive/target。列为 PIE 首次验证时重点确认项（若限位/驱动没生效，先查这里）。

### 3.2 `ApplyTuning` 把「几何」和「物理属性」混在一起，被构造函数/OnConstruction 反复调用
- 构造函数与 `OnConstruction` 都调 `ApplyTuning`，其中包含 `SetMassOverrideInKg`/`SetLinearDamping`/`SetUseCCD` 等纯物理属性。编辑器态 BodyInstance 未模拟，这些调用意义不大，个别引擎版本对未初始化 body 设质量会有 ensure/warning。
- 建议：拆成 `ApplyVisualGeometry`(悬点、静止位、球半径、视觉根缩放，供预览) 与 `ApplyPhysicsProperties`(质量/阻尼/CCD，仅 `BeginPlay` 调)。既避免潜在警告，也让「编辑器只预览几何、运行时才配物理」的边界更干净。

### 3.3 正弦从 sin(0)=0 起摆 = 开局在中线以最大角速度突然启动
`BeginPlay` 记 `DriveStartTimeSeconds=now`，首个目标为 0°，随即以最大角速度往一侧冲。开局会有一次「突然加速」的观感。可接受；若想更自然，可用 `(1-cos)` 缓入或从相位偏移起。低优先。

### 3.4 Pawn=Overlap + 高速摆锤存在 overlap 漏检（tunneling）风险
CCD 只对 Block 生效，对 Overlap 不生效。高速摆锤扫过角色时 overlap 可能漏报。本 Actor 只留事件、判定在另一受击会话，但建议在跨会话接口备注里点明「摆锤命中依赖 overlap，需容忍高速漏检或由受击层做扫掠/速度补偿」，免得下游默认 overlap 可靠。属跨会话提醒。

### 3.5 与现有 `SpikeTrapHazard` 的视觉装配风格差异（信息项，非问题）
- `SpikeTrapHazard` 直接用 `UStaticMeshComponent` 供蓝图指定 mesh；摆锤用 `USceneComponent` 三个 VisualRoot 让蓝图往下挂并靠父级缩放匹配半径/杆长。摆锤这样做是为了「碰撞体与视觉解耦 + 按参数缩放」，方向合理，无需与地刺强行统一。
- `RodVisualRoot` 挂在 `BobBody` 下、从质心指向悬点、随刚体旋转，视觉上杆始终连悬点与锤——这个设计是对的，予以肯定。

### 3.6 14 个参数偏多，部分可先固化为 C++ 常量
`DriveUpdateIntervalSeconds`（几乎恒为 1/60）、`LinearDamping`/`AngularDamping`（若采纳 2.1 的自由摆策略会变成关键项，否则可先固化）在首轮调试中大概率不动。可先把确实不需要逐实例调的项收进 C++，DataAsset 只暴露真正要现场试的几何/质量/周期/驱动力矩。减少 Blueprint 侧误配面。非必须。

## 4. 明确肯定的部分（避免只挑刺）

- 约束到世界 + 约束帧在质心上方的钟摆建模**正确**，不是 `RotatingMovement` 假旋转（对比第三方 `BP_SwingingBlades` 是进步）。
- 主轴/次轴/Twist/Roll 坐标约定、`Yaw=90°` 使本地 X 沿房间长轴、锤在房间宽度方向横扫的几何推导自洽；50 cm 净空推导支持「无法永久贴墙绕过」的玩法目标。
- 不绑 `OnComponentHit` 二次加力、让 Chaos 自己完成动量交换，符合项目「物理与表现分离、不伪造冲量」的原则。
- 失效路径干净：配置缺失/非法 → Error 日志(含 Actor 名与具体属性) → 关物理关碰撞不启 Timer，不静默兜底；CDO 仅用于编辑器预览且其默认值能通过 `IsConfigured`。
- `EndPlay` 清 Timer、`DisableHazard` 对无效 handle `ClearTimer` 安全、`UpdateDriveTarget` 对 `TuningData/Constraint/World` 做 `IsValid` 防护，生命周期处理到位。
- `UE_TWO_PI`(double) 用法正确；`BobVisualScale = BobRadius/50`（引擎 100 cm 直径球）换算正确。
- 文件 Public/Private 镜像、职责注释头、单位 meta、`AllowPrivateAccess` 私有组件暴露方式均符合规范。

## 5. 实现后必须靠 PIE/构建确认、静态审计无法定论的清单

1. `AngularOrientationTarget` 的 Roll→Twist 方向与正负号是否与预期摆动方向一致（可能需翻正负）。
2. 加速度模式下 `DriveForceLimit` 的实际力矩钳制效果，以及能否在「维持周期」与「外物可见扰动」之间找到窗口（对应 2.1）。
3. 约束参数配置顺序是否导致 limit/drive 未生效（对应 3.1）。
4. 3 分钟无外力不发散、不偏轴（能量注入是否失控）。
5. 20 kg@2000 cm/s 磁性箱撞击的可读性（首轮 gate）；被夹住时不爆抖。
6. 30/60/120 FPS 下周期/限位/碰撞结果无影响玩法的差异（方案已列，保留）。
7. 高速磁性物是否穿透锤体；若穿透，按方案先请用户决定是否在真实 `BP_MagneticProp` 上开 CCD，不新增补偿框架。
