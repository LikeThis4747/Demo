# PCG 玩法内容分层放置方案（修订讨论稿）

- 日期：2026-08-11
- 状态：分层架构已获用户认可；本实现级规划待确认，仍不是实现授权
- 范围：摆锤、地刺、冲锤、制导发射器与磁力资源物的 PCG 选位、数量和冲突处理
- 算法：在有限候选位置和通行图上执行泊松盘式最小间距拒绝采样
- 核心修订：机关与资源分层放置，但仍由一套 Population 总控完成，不拆成两套框架
- 本轮不修改：机关行为、伤害、触发、初始状态、WFC 布局、Level0 或正式 UE 资产

## 1. 先固定项目架构，而不是围绕单个参数摆动

本方案把生成职责固定为三层。这里的“层”是本项目的架构划分，不是 Unreal Engine 官方术语。

| 层级 | 唯一职责 | 当前 Owner | 是否参与本方案改造 |
|---|---|---|---|
| 空间生成层 | WFC、房间/走廊、楼层连接、最终 Plan 与通行拓扑 | RuntimeLevelGenerator | 只增加只读查询，不改变生成算法 |
| 流程对象层 | 玩家、追猎者、出口等局内流程对象 | 现有 GameMode/流程代码 | 不改 |
| 玩法填充层 | 在已经生成的空间里规划并生成机关与物理资源 | `AZeroEscapeGameplayPopulator` | 本方案唯一改造主体 |

玩法填充层内部固定执行两个阶段：

1. **机关阶段**：摆锤、地刺、冲锤、制导发射器。
2. **物理资源阶段**：当前只有磁力物，以后新增真正的资源类型时仍归这一阶段。

这不是两个 Manager、两个 Actor 或两套策略系统。仍然只有一个 `AZeroEscapeGameplayPopulator`、一个 Profile、一个 Placement Policy 和一次原子 Spawn/回滚事务。

## 2. 为什么必须分层

这项决定来自项目玩法职责，而不是因为用户刚提出“分层”：

| 判断依据 | 对架构的影响 |
|---|---|
| 磁力物是玩家逃脱、投掷、压制和防御的核心资源，不是装饰物 | 资源必须有独立预算，不能随机替代危险 |
| 冲锤、发射器、摆锤的合法位置受墙面、射界、高厅结构约束，候选明显更稀缺 | 应先满足受限机关，再让资源使用剩余合法空间 |
| 机关密度主要控制压力；资源密度主要控制玩家可用手段 | 两者必须能独立调参，否则一个参数同时改变难度的两端 |
| 项目正式设计要求同时验证危险与物理资源是否充足 | 两类结果必须分别统计目标与实际数，不能用“总数够了”掩盖某一类缺失 |
| 资源以后可能需要主路线覆盖、支路奖励等规则，而机关更关注迎面遭遇和操作空间 | 分层后可以只演进资源策略，不扰动机关结果 |

单池方案的根本问题不是“理论上不能运行”，而是把两种不同的策划含义压成同一个总数。大量普通磁力物候选可能抢走稀缺机关位置或配额，最后日志显示总量达标，实际地图却缺少威胁；反过来提高机关权重，又会让玩家缺少核心物理资源。这种耦合不值得保留。

## 4. 总体执行流程

```text
读取 Ready 状态下的最终 Plan
  -> 一次性建立只读 PlacementContext
       - 可走格、楼层、开口、墙面、内部连接
       - 全楼通行图和最短路距离
       - 高厅结构
       - 玩家、追猎者、出口占用格
  -> 机关阶段
       - 为每类机关枚举合法候选与实际影响范围
       - 每个合法 1x2 高厅先规划一个摆锤
       - 摆锤计入机关目标数
       - 从仍有可用候选的普通机关类型中按权重抽一种
       - 再从该类型当前满足图距离的合法位置中抽一点
  -> 资源阶段
       - 排除结构/流程占用和机关实际影响范围
       - 独立计算资源目标数
       - 用独立随机流和独立最小间距执行泊松拒绝采样
  -> 合并为一份 PlacementPlan
  -> 加载类并统一 Spawn
  -> 任一配置、加载或 Spawn 失败，回滚本轮全部 Population Actor
```

PlacementContext 只构建一次，两个阶段共享只读拓扑数据，避免重复遍历 Plan；两个阶段只交换“机关实际保留范围”，不共享数量预算。

## 5. 机关阶段

### 5.1 数量定义

机关目标统计“玩法位置”，不是 Spawn Actor 数：

| 机关 | 一个玩法位置如何计数 |
|---|---:|
| 一个合法高厅内的一套摆锤 | 1 |
| 一组地刺（当前两个 Actor 组成） | 1 |
| 一个冲锤 | 1 |
| 一个制导发射器 | 1 |

```text
HazardDensityTarget = RoundToInt(
    GameplayAreaCellCount * ExpectedHazardsPer100GameplayCells / 100)

HazardTarget = Max(HazardDensityTarget, MandatoryPendulumCount)
RemainingOrdinaryHazards = HazardTarget - MandatoryPendulumCount
```

- 每个合法高厅优先放一个摆锤，并计入 `HazardTarget`。
- 高厅多于面积密度目标时不删摆锤，机关实际数允许高于密度目标。
- 普通候选或间距不足时允许 `ActualHazards < HazardTarget`，但必须单独报告欠填原因；不偷偷缩小半径、换 Seed 或拿资源补数。
- 不设每层最多几个、每类全图硬上限或“每 2~4 格强制一个”。

### 5.2 合法候选不是额外限制，而是机关能正常工作的必要条件

| 类型 | 合法位置 | 朝向 | 机关实际影响范围 |
|---|---|---|---|
| 摆锤 | 满足正式 1x2 高厅结构合同的位置 | 摆动平面沿高厅长轴 | 两个高厅格及摆动净空 |
| 地刺 | 资产尺寸、地面和平面通行关系允许正面碰上的普通格 | 相对一个实际进入方向横向铺开 | 宿主格及地刺组合占用 |
| 冲锤 | 普通平地格的封闭墙面，锤头全行程不穿结构 | 从墙面朝格内冲出 | 安装点、锤头行程与回收净空 |
| 制导发射器 | 后方可安装、正前方开放，触发和发射方向存在有效遭遇空间 | 朝开放通路 | 安装格、前方触发区和发射通道 |

地刺不继续保留一个泛化的 `bStraightCorridorOnly` 开关。实现应直接枚举“资产确实能覆盖的进入方向”：首轮必须覆盖已验证的直道；转角、T 口或十字口只有在地刺尺寸和实际迎面路线成立时才进入候选。这样既不会先验禁用大量位置，也不会为了增加数量把不合理姿态当成合法。

### 5.3 泊松拒绝采样

本项目使用的是**有限候选位置上的泊松盘式拒绝采样**，不是照搬 Bridson 连续空间 active-list 实现：

1. 地刺、冲锤和发射器分别建立合法候选；同一格的多个墙面/进入方向只算该类型的一个候选位置，方向在位置被选中后再抽，避免多墙格被重复加权。
2. 候选按楼层、坐标和方向稳定排序，并使用机关专用 `FRandomStream` 产生确定性随机选择。
3. 每轮先检查三类机关中哪些仍至少有一个候选满足与全部已接受机关的最小图距离。
4. 只在这些“当前可放”的类型中按 `Spike/Ram/LauncherWeight` 抽一种，再从该类型的可放位置中等概率抽一个位置与方向。
5. 接受后更新最近机关距离和已占用格；达到剩余目标，或所有类型都没有可放候选时停止。

这里采用“类型先、位置后”，不是增加每类保底。它解决的是候选数量偏差：否则地刺或冲锤的大量普通候选会天然压低发射器出现率，即使三者权重相同。类型权重现在才真正表示策划期望比例；某类合法位置耗尽后，其权重自然退出，不换 Seed、不缩半径，也不要求固定出现个数。

这里采用通行图距离而不是纯世界直线距离，避免上下楼或隔墙位置在空间上很近、实际遭遇却很远时被错误互斥。

## 6. 物理资源阶段

### 6.1 独立控制

当前资源层只放磁力物，拥有独立的：

| 参数 | 策划含义 |
|---|---|
| `ExpectedResourcesPer100GameplayCells` | 地图面积对应的资源期望密度 |
| `MinimumResourceRouteSpacingTiles` | 资源之间不要挤成一堆 |
| 磁力物 Class 与必要装配参数 | 保留当前类引用、Z 落点和用于格内安全取点的占地半径 |

```text
ResourceDensityTarget = RoundToInt(
    GameplayAreaCellCount * ExpectedResourcesPer100GameplayCells / 100)
```

资源候选远多于受墙面、朝向和结构限制的机关候选，因此不再增加第二个 `MinimumResourcesPerMap` 数量控制，也不让资源欠填成为运行时硬失败。资源目标、实际数和欠填原因仍与机关完全分开统计；修改资源密度或间距不能改变已经选出的机关。正式 Profile 应通过 Seed Sweep 证明资源可以稳定达到密度目标，异常欠填作为配置/算法回归告警，而不是为理论极端情况再建一套保底规则。

资源采用“整栋图上选分布格、格子内部再随机落点”的两级放置：

1. 先在普通可走格上按 `MinimumResourceRouteSpacingTiles` 做图距离泊松拒绝采样，决定资源在整栋地图中的疏密。
2. 全部锚点格确定后，再使用资源独立随机流，在每格的可用地板矩形内均匀采样 X/Y；本轮不额外改变磁力物朝向。
3. 可用矩形由格子边界减去资源占地半径得到，避免旋转后的碰撞伸进墙体；不增加“偏移强度”参数，默认使用整个安全区域。
4. 机关操作格和玩家、追猎者、Exit 的直接占用格仍不进入资源锚点池；除此之外不按房间、直道、转角或距机关统一半径继续删候选。

格内随机在锚点选择完成后执行，因此修改资源外观位置不会反向改变机关，也不会因为格内重抽次数改变已经确定的资源整体分布。

### 6.2 与机关的关系

- 机关先选，资源后选；资源永远不会替代机关或减少机关目标。
- 资源不得进入机关的**实际操作范围**，例如冲锤行程、导弹触发/发射通道、摆锤净空和地刺组合占用。
- 不增加统一的“机关到资源最小距离”。只要不妨碍机关工作，资源可以靠近危险，这正好支持铁板挡弹、覆盖地刺或临场投掷等玩法关系。
- 资源仍需避开玩家、追猎者和出口的直接占用位置；其他安全约束只在碰撞或导航验证证明必要时添加。

### 6.3 主路线覆盖如何控制复杂度

正式设计要求关键追逐路段有可用资源，但当前生成 Plan 没有稳定的“追逐区”语义。首轮不伪造一套分区框架，也不立即增加支路比例、房间标签、每段配额等参数。

首轮做法：

1. 独立资源密度和机关优先占位，保证资源数量不会反向挤掉稀缺机关；资源自身有充足的剩余普通格候选。
2. Seed Sweep 额外记录 Start 到 Exit 主路径上的最大无资源间隔、主路线资源数和支路资源数。
3. 若数据或实际体验证明主路线出现不可接受的资源空窗，只在资源阶段增加“主路径覆盖修复”；不修改机关算法和公共架构。

这是有意延后一个尚无输入语义和验收阈值的策略，不是兼容旧代码。它保留了扩展位置，又避免现在就建立一套没有证据的追逐分区系统。

## 7. 跨层确定性与冲突规则

| 规则 | 结果 |
|---|---|
| `HazardPopulationPlacement` 独立随机流 | 同一 Seed/Plan/机关配置生成相同机关 |
| `ResourcePopulationPlacement` 独立随机流 | 资源调参不会导致机关整体洗牌 |
| 机关只向资源层输出实际影响范围 | 机关变化只通过合法候选集合影响资源，且绝不会反向改变机关；资源层会基于新的候选集合确定性重采样 |
| 两层各自执行最小间距 | 机关压力与资源可用性可以独立调节 |
| 一个统一 PlacementPlan 和 Spawn 事务 | 保留当前统一 Owner 与原子回滚，不制造生命周期技术债 |

随机流仍从同一个局内 Seed 确定性派生，但不再为每格创建子流，也不维持旧规则循环的随机调用顺序兼容。

## 8. 数据与代码边界

### 8.1 Profile

`UZeroEscapePopulationProfile` 保留为唯一 DataAsset，内部不复制三套资产装配，而是拆成“一份共享装配 + 三档纯策划数值”：

- `FZeroEscapeHazardPopulationAssembly`：摆锤、地刺、冲锤、发射器 Class；地刺组合装配；冲锤与发射器的墙面偏移和安装高度。
- `FZeroEscapeResourcePopulationAssembly`：磁力物 Class、Z 偏移与 `PlacementFootprintRadiusCm`。
- `TArray<FZeroEscapePopulationDifficultySettings>`：必须恰好包含 Easy、Normal、Hard 各一条；每条只含机关/资源密度、各自最小通路间距，以及地刺、冲锤、发射器三个非负权重。

三档初值允许先相同，Seed Sweep 和实际体验后再拉开。难度只改变单位面积压力与构成，不改变某类内容怎样安装、怎样判合法，也不会把同一组 Actor Class 和尺寸数据复制三遍。

只把策划需要调整、或由资产装配决定的数据暴露给 DataAsset。候选合法性、图搜索、拒绝采样、确定性和回滚属于 C++ 不变量，不做成大量布尔开关。

### 8.2 Policy 与结果

现有 `FZeroEscapePopulationPlacementPolicy` 重写为一份纯 C++ 规划器，内部有两个清晰阶段，不新增 Hazard/Resource Manager、Component、UObject 策略层或注册表。

它返回一份内部 PlacementPlan，至少分开保存：

- `HazardPlacements`
- `ResourcePlacements`
- 两层各自的 `Target/Actual/Rejected/Underfilled` 统计

`AZeroEscapeGameplayPopulator` 仍只负责读取配置、调用规划器、加载 Class、Spawn、登记与失败回滚，不承担候选算法。

## 9. 旧代码取舍：哪些删、哪些迁移、哪些保留

### 9.1 直接替代，不保留双轨兼容

| 旧内容 | 处理 | 理由 |
|---|---|---|
| `FZeroEscapePlacementRule` 与 `Rules` 数组 | 由两个配置块替代 | 旧模型把每类内容当独立顺序规则，无法表达分层预算 |
| `OneEveryNCells`、`MaxCount` | 删除 | 被面积密度和实际候选耗尽语义替代 |
| 逐规则 Shuffle/Spawn 循环 | 删除 | 改为一次建上下文、两阶段规划、一次 Spawn |
| `EPopulationPlacementBudgetResult`、旧 `Evaluate` | 重写/删除 | 旧预算只服务旧规则链 |
| `bStraightCorridorOnly` | 删除 | 改为地刺自身的实际候选枚举，不保留泛化开关 |
| 旧随机调用序列兼容 | 不保留 | 两个命名随机流提供新的确定性合同 |

### 9.2 迁移，不丢失有效装配信息

- 地刺每处两个 Actor、当前中心间距与 Z。
- 磁力物当前 Class 和 Z 落点。
- 冲锤、发射器经验证的墙面装配偏移。
- 现有 `DA_Population_Default` 资产路径。

### 9.3 保留并复用

- `AZeroEscapeGameplayPopulator` 的唯一 Owner 职责、`SpawnedActors` 和原子回滚。
- `UZeroEscapePopulationProfile` 作为唯一人口配置资产。
- 现有 Placement Policy 文件职责和自动化测试文件；重写内容，不为每层新建一套文件。
- RuntimeLevelGenerator 对最终 Plan 的权威所有权。

### 9.4 删除前必须审计

`GetGeneratedOrdinaryGameplayCellWorldTransforms` 必须先通过官方 MCP 检查 Blueprint/资产调用：

- 无调用：删除。
- 有调用：先迁移调用到新的只读 Plan 查询，再删除。
- 不保留永久兼容包装器。

## 12. 验证合同

### 自动化

- 每个合法 1x2 高厅恰好规划一个摆锤，且计入机关目标。
- 资源密度、资源间距和资源 Class 变化不改变机关结果。
- 机关目标与资源目标分别计算，资源不能补足机关欠填。
- 每个类型只出现在其合法结构和朝向。
- 同层结果满足各自的最小通路距离。
- 资源不进入机关操作范围，但允许出现在机关附近的非冲突位置。
- 同一 Seed/Plan/Profile 完全复现。
- Profile 的 Easy、Normal、Hard 必须各有且仅有一条；数组排序变化不改变结果，缺失或重复属于配置失败。
- 候选不足时只让对应层欠填并产生明确统计。
- 非法配置、Class 加载或 Spawn 失败时保持原子回滚。
- 权重相同但候选数量悬殊时，类型抽取不按候选数量暗中偏向候选多的一类。
- 资源格内落点保持在占地半径缩进后的安全矩形内，同一 Seed 可复现且不是固定格心；本轮保持磁力物现有朝向合同。
- 当前正式 Profile 的 Sweep 应稳定达到资源密度目标；若出现欠填，测试与汇总日志必须暴露 Seed 和拒绝原因，但运行时不为此整轮失败。

### Seed Sweep 统计

- `HazardTarget/Actual/MandatoryPendulums/Underfilled`
- 地刺、冲锤、发射器各自候选数、实际数与无合法类型拒绝数
- `ResourceTarget/Actual/Underfilled`
- 两层的间距拒绝数和候选耗尽数
- 每层数量分布
- 主路线资源数、支路资源数、主路线最大无资源间隔（先作为观测值，不先设硬约束）
- 使用真实 `DA_LevelGenerationProfile` 与 `DA_Population_Default` 执行独立的 3 难度 × 96 Seed 诊断 Sweep；分布统计先用于定默认值，不在数据形成前写类型比例硬断言。
- 三档尚未拉开时允许统计相同；拉开后验证 Hard 的单位面积机关压力高于 Normal/Easy，而不是只比较不同地图的 Actor 总数。

### PIE/实际体验

- 摆锤在正式 1x2 高厅中的完整摆幅和净空。
- 地刺在不同路口形状中是否确实形成正面遭遇。
- 冲锤全行程、导弹触发区/枪口/飞行通道无结构或资源干扰。
- 机关总体不挤成团，资源也不堆成团。
- 地图既有稳定威胁密度，也有足够可利用资源；资源靠近机关时能形成有意义的对抗而非阻塞。

## 13. 当前仍需后续数据决定的数值

架构可以先确定，但以下数值不应凭空固定：

- `ExpectedHazardsPer100GameplayCells`
- `MinimumHazardRouteSpacingTiles`
- 地刺、冲锤、制导发射器的初始权重
- `ExpectedResourcesPer100GameplayCells`
- `MinimumResourceRouteSpacingTiles`
- `PlacementFootprintRadiusCm`（按当前磁力物真实碰撞占地确定，不作为难度参数）

先用现有地图规模和多 Seed 候选统计形成第一组默认值，再由用户体验调整。这样不会把未经验证的 `8/100` 或任意上下限包装成设计结论。

## 14. 本次取舍结论

- **采用**：一个总控下的机关/资源两阶段分层；各自预算、间距、随机流和统计。
- **采用**：一份共享资产装配 + Easy/Normal/Hard 三档纯数值配置；首轮可同值，不建立三份重复 Class/偏移数据。
- **采用**：合法高厅必放摆锤并计入机关目标。
- **采用**：有限候选位置上的泊松盘式图距离拒绝采样。
- **采用**：机关先占用其实际操作范围，资源只避让真实冲突，不做全局跨层间距。
- **采用**：资源在图上用泊松间距选锚点格，再在格内安全区域均匀随机位置；不固定格心，不顺手增加朝向随机化。
- **删除**：资源全图最低数和对应硬失败语义；正式密度是否可满足由真实 Profile Sweep 保证。
- **替代**：旧逐规则密度/上限链和单一混合池。
- **保留**：现有 Populator、Profile、Policy、回滚和测试文件边界。
- **暂缓**：动态 Director、追逐区框架、房间标签库、资源分段保底、每类硬配额和自适应缩半径；除非 Seed Sweep 或玩法验收给出明确需求。

这套边界能让机关压力与玩家资源各自可控，同时没有为“分层”付出两套生命周期、两套管理器或一套通用框架的复杂度。

## 15. 代码级实施设计（2026-08-12）

### 15.1 生成器只新增一个只读快照入口

删除旧的“按两个布尔值直接吐普通格 Transform”查询后，Generator 不再替 Population 做候选筛选。新增一个仅供 C++ 使用的只读入口：

```cpp
bool GetGeneratedPopulationSnapshot(
    FZeroEscapeGeneratedLevelPlan& OutPlan,
    FTransform& OutGeneratedRootWorldTransform,
    double& OutFloorTopZCm) const;
```

- 只在 `Ready` 返回成功；复制最终 Plan，不返回可变引用或悬空指针。
- 同时快照生成根世界变换和表现地面高度，Population 可以纯值计算本地 Transform，最后统一组合为世界 Transform。
- 不把机关/资源字段写进空间 Plan，也不让 WFC 知道 Population。
- 官方 MCP 已确认 `/Game/ZeroEscape/Generation/BP_ZeroEscapeRuntimeLevelGenerator` 与 `/Game/ZeroEscape/Generation/Population/BP_GameplayPopulator` 的图中没有调用旧查询；二进制字符串检索也只命中三处 C++ 定义/调用。实施时再做一次删除前复核即可直接移除，不留包装层。

### 15.2 Policy 的纯值输入与输出

内部类型只放在 `Private/PCG/Population`，不做 USTRUCT、UObject、Component 或可扩展注册表：

```cpp
enum class EPopulationPlacementKind : uint8
{
    Pendulum,
    SpikeTrap,
    BatteringRam,
    GuidedLauncher,
    MagneticResource
};

struct FPopulationPlannedPlacement
{
    EPopulationPlacementKind Kind;
    FIntVector AnchorAddress;
    TArray<FTransform> LocalSpawnTransforms;
    TArray<FIntVector> ResourceBlockedAddresses;
};

struct FPopulationLayerStats
{
    int32 TargetCount;
    int32 ActualCount;
    int32 CandidateCount;
    int32 SpacingRejectedCount;
    int32 ExhaustedCount;
};

struct FPopulationPlacementPlan
{
    TArray<FPopulationPlannedPlacement> HazardPlacements;
    TArray<FPopulationPlannedPlacement> ResourcePlacements;
    FPopulationLayerStats HazardStats;
    FPopulationLayerStats ResourceStats;
};
```

真实实现会补齐失败枚举与每类统计，但不把纯诊断字段暴露给蓝图。Policy 的唯一入口接收 Plan、地面高度、两个配置块和主 Seed，原子返回完整 PlacementPlan；失败时输出保持空。

### 15.3 一次建立通行图

1. 把普通格和全部结构 `WalkableCells` 建为唯一节点。
2. 普通格按互相匹配的 `OpeningMask` 连边。
3. 结构按 `InternalConnections` 连边，并用 `Openings` 接回普通格。
4. 节点和邻接表稳定排序、去重；非法重复地址、单向开口或断开的结构连接直接返回明确失败。
5. 每接受一个位置，只做一次多源 BFS 更新“离最近已接受位置的距离”；不会预建全点对距离矩阵，也不会每个候选都重新 BFS。

当前正式地图总可走格约 72～160；这个实现的运行成本远小于 WFC 和 Actor Spawn，不需要缓存对象、Subsystem 或异步任务。

### 15.4 面积、间距与占用使用不同语义

- `GameplayAreaCellCount`：普通格 + 高厅可走格；楼梯只承担连接，不计入内容密度面积。
- `SpacingAddresses`：描述一次危险遭遇在整栋通行图上的位置，只用于同一内容层内部的泊松距离。
- `ResourceBlockedAddresses`：描述资源不能占用的实际操作格，只用于跨层冲突。

这三者不能混成一个 `ClaimedCells`：例如发射器会阻止资源出现在宿主格和正前触发格，但不应因为触发盒很长就额外扩大机关之间的泊松半径。

### 15.5 各类型的确定候选合同

| 类型 | 实现合同 |
|---|---|
| 摆锤 | `Kind == HighCeilingRoom` 且具有正式 1×2 两格与内部连接；根位于两格中心，局部 X 为摆轴、摆动沿房间长轴；所有合法高厅必放，两个高厅格阻止资源进入 |
| 地刺 | 任意非流程占用普通格；每个真实开口都是一个可迎面进入的方向，选中格后再抽方向；当前两个 HurtZone 半宽 112 cm、中心间距 300 cm，组合保持在 600 cm 格内；只阻止资源占宿主格 |
| 冲锤 | 普通格的任意封闭边均可作为墙面，局部 +X 从墙指向格内；不要求直道、不要求每段唯一；当前 450 cm 行程留在 600 cm 宿主格内，资源只避开宿主格 |
| 发射器 | 后方封闭、正前开放，且正前连接到普通格；局部 +X 指向正前路线；宿主格与正前格阻止资源，以覆盖当前 Anchor +600 cm、半长 500 cm 的触发盒和初始发射净空 |
| 磁力物 | 先在普通格上使用资源层独立图距离选择锚点；全部锚点确定后，在扣除 `PlacementFootprintRadiusCm` 的格内安全矩形均匀随机 X/Y，并保持现有朝向；避开流程占用和机关 `ResourceBlockedAddresses`，不避开机关周边非冲突格 |

玩家、追猎者和 Exit 的实际占用格从所有普通候选中排除；不再默认向外扩大一圈安全区。出生安全通过“实际操作格不得覆盖流程坐标”保证，而不是保留旧的泛化邻格布尔开关。

### 15.6 Spawn 与失败语义

1. Policy 成功后按实际用到的 Kind 加载 Class；权重为 0 且未使用的类型不产生同步加载。
2. 先验证全部 Local/World Transform、Class、计划 Actor 总数和 `MaxGridCells × MaxFloorCount` 安全预算，再 Spawn 第一个 Actor。
3. 继续使用 `AlwaysSpawn`，避免碰撞处理擅自移动已经验证的机关；任一 Spawn 失败则清空本轮全部对象。
4. 机关或资源密度目标欠填均是对应层的告警，彼此不补数；资源欠填不触发整轮回滚。
5. 必放摆锤缺 Class、配置非法、Class 加载失败或 Spawn 失败仍使 `Populate` 返回 false，由现有 GameMode 走 `PopulationFailed`，不自动换 Seed 掩盖真正错误。

### 15.7 日志只保留一条汇总和失败诊断

成功日志使用新的稳定 schema，包含 Seed、LayoutHash、两层 target/actual、四类机关数、资源数、候选耗尽和间距拒绝；不逐格刷日志。欠填另外输出一条 Warning，失败输出结构化 reason。这样 Seed Sweep 能直接聚合，而正常 PIE 不被候选细节淹没。

### 15.8 实施检查点

1. **纯值层**：配置结构、随机域、Policy、合成 Plan 单元测试；先构建通过。
2. **只读空间桥接**：新增快照、移除旧查询，再构建并复核 Blueprint。
3. **运行时接入**：重写 Populator、迁移 `DA_Population_Default`、编译并保存 `BP_GameplayPopulator`。
4. **真实数据诊断**：运行 `Demo.PCG.Population` 自动化及 288 组真实 Profile Sweep，依据候选/欠填分布提出首轮密度、间距和权重，不在代码里临时写死。
5. **代表 Seed PIE**：至少覆盖无高厅、一个高厅、多高厅、发射器候选稀缺、较高资源密度和格内随机边界；用户最终判断地图是否过空、过密、资源是否显得刻意或失去反制空间。

进入第 1 步前仍需：用户确认本实现级规划、对话中展示实际头文件/Policy 函数代码预览、用户明确授权、处理当前其他任务改动与 Level0 Dirty 分叉，并完成内部工蜂完整基线门禁。
