## 当前权威结论

1. 保留现有统一 `StandingImpact` 请求、来源 Profile、`None / Slow / Stop`、速度效果、AI 攻击打断与可选受击 Montage。
2. `Stop` 使用“方向受击动画 + 上半身短时局部物理”；`Slow` 默认使用“减速 + 局部物理”，不播全身 Montage。
3. 局部物理使用 UE 官方 `UPhysicalAnimationComponent`；Heavy 继续使用现有 `UPhysicsControlComponent`。二者是不同 API，不抽新的 Light/Heavy 大一体化组件。
4. 当前追猎者 Mesh 已由官方 MCP 回读为 `CharacterMesh / QueryOnly / ECC_Pawn`。因此本版是：来源先与现有 Capsule/机关逻辑碰撞，角色再按请求位置、方向和归一化强度给上半身刚体施加封顶表现冲量。骨骼会参与 Chaos 模拟，但不会反向阻挡来源物体；不得再称为第一次接触中的完整双向动量交换。
5. 这项取舍是有意的：它对应 Epic 官方 hit-reaction 工作流，能保留动画并避免重写磁力、破碎和碰撞路由。若现场效果仍像纯动画或假物理，立即止损，不重新堆 Source Lease、预测或测试关卡。
6. Heavy 状态机、PCA、击飞、倒地、起身和误预测回滚保持不变；只在 Heavy 请求通过自身校验、即将捕获身体前新增一个清场 Delegate，让 Light 交还上半身。

### 采纳

- B1：在 `Configure` 预先创建 Physical Animation drive；Strength 为 0、Body 仍非模拟。命中时只开局部模拟、把 Strength 设为 1 并加一次冲量，避免首帧自由布娃娃。
- P1-1：用户允许最小修改 Heavy。新增 `OnPreContactCaptureRequested`，只在 Heavy `ValidatePreparationRequest` 成功后、`CapturePreContactState` 前广播；拒绝把清场放在角色接口转发层。
- P1-2：`Configure / EndPlay / Heavy PreCapture / Heavy Prepared` 显式调用幂等物理清理；普通玩法 Timer 结束不强制截断更短的物理 Blend。
- P1-3：要求 `PhysicalHoldSeconds >= MontageBlendInSeconds`，避免物理先退、Montage 后混入造成二段抽动。
- P1-4：给每个 `FStandingImpactReactionSpec` 增加 `bApplyPhysicalReaction`。磁力追猎者开启；地刺第一版关闭。由来源资产声明物理方向是否有表现意义，不写机关类特判。
- P1-5：不把同一冲量直接施加到手/头小刚体。角色 Tuning 配置 Torso/LeftArm/RightArm 三个受力 Body，末端命中上溯到对应区域 Body。
- P1-6：依据官方 MCP 真实回读，把方案降级为“局部模拟表现”，不承诺 Mesh 阻挡物体；不为此修改 Mesh 碰撞。
- P1-7：增加 `MaxContinuousPhysicalSeconds`，连续不同 ImpactId 也不能无限保持上半身模拟。
- P1-8：构造期只设置 `PrimaryComponentTick.bStartWithTickEnabled=false`；Tuning 开启后由 Configure 明确启用 Physical Animation 的 PrePhysics Tick。
- 测试修正：自动化只测数据合同；真实 Body、Tick、Heavy 抢占与画面全部放 PIE/MCP 回读，不造 Chaos Mock。

### 部分采纳 / 自主修正

- B2：Review 正确指出 UE 中 `MaxAngularForce=0` 表示不限制，不是“无力”。但本项目为避免上半身被无限制马达焊死，仍要求 `MaxAngularForce > 0`；DataAsset 注释必须明确这是项目安全约束，而非 UE 语义。
- Physical Animation drive 在 Light 开启的角色上常驻建立并更新动画目标，但 Strength=0、Body 非模拟；这不是常驻受控物理。需要在追猎者数量下测 CPU 成本。
- 不把 `StopPhysicalReaction()` 塞进所有 `ClearActiveImpact()`：玩法 Timer 与物理 Blend 生命周期分开。只在配置重入、销毁和 Heavy 抢占路径强制清理。

### 不采纳 / 延后

- 不延后一帧再处理每个 Light 请求：drive 已预建，直接施加冲量即可；若实测仍有 tick 时序问题再回评，不预建 Pending 状态。
- 不删除旧 `UPhysicsControlHitResponseComponent`、旧动画字段或旧回退代码；等新效果用户验收后单独做删除审计。
- 不改 Mesh 为 QueryAndPhysics，不让 Light 动态 Body 撞墙或反向阻挡来源；这会把本轮重新扩大为碰撞路由项目。

## 最小运行闭环

```text
来源命中 / Overlap
  -> 现有 FStandingImpactRequest
  -> 来源 ReactionSpec 决定 None / Slow / Stop / 是否允许物理表现
  -> UCharacterImpactResponseComponent
       ├─ 玩法：Slow / Stop / 速度恢复
       ├─ 动画：Stop 可播 Front / Left / Right
       └─ 表现：预建 Physical Animation drive
                + 上半身短时模拟
                + 三个区域 Body 之一承受封顶冲量
                + Hold / Blend Out / 关闭模拟
```

## 验证门槛

1. 磁力物砸追猎者胸口、左侧、右侧；物理开/关 A/B 必须肉眼可分。
2. Stop 动画仍清楚，局部物理带来命中区域偏转与短余势，不能只有动画或全身尸体感。
3. Slow 保持低速寻路；Stop 停移动；二者继续打断攻击；空中 Stop 只清水平速度。
4. 连续不同物体命中可重新触发局部物理，但到达 `MaxContinuousPhysicalSeconds` 后必须开始退出。
5. 摆锤击飞追猎者并起身，起身后一秒内再用磁力物砸胸口，局部物理仍须生效；验证清场 Delegate 没有被 Heavy Busy/保护期误触发。
6. Light 反应中触发摆锤/冲锤：Heavy Prepare 必须成功，击飞、倒地、起身与误预测不得退化。
7. Heavy 全身物理期间 Physical Animation drive 虽存在但 Strength=0；不得产生可见扭矩或姿势差异。
8. 退出后上半身 Body 全部非模拟；CharacterImpact 临时 Tick 关闭。
9. 构建只允许 `-Module=Demo -NoEngineChanges`；最终效果由用户 PIE 验收。
