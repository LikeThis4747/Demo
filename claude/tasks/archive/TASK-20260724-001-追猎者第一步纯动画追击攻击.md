## 目标与验收

- 目标：用官方 Manny 骨架，在 Level0 灰盒里做出一个**追猎者**：能感知玩家、持续追击、进入攻击距离后播放攻击蒙太奇并冷却回追。**全程纯动画，不涉及任何物理受击**（物理受击属第二步）。
- 验收：
  - 追猎者能感知玩家并在 NavMesh 上持续寻路追击。
  - 进入攻击距离播放攻击蒙太奇，冷却结束后继续追。
  - 玩家跑远/绕柱时追猎者重新寻路，不卡死。
  - 全部参数走 DataAsset，默认关 Tick，无硬编码资源路径。
- 非目标：不做物理受击/失衡/倒地（第二步）；不做真实伤害判定（攻击 Notify 只发事件，先不结算后果）；不做 EnemyBase 父类；不接 PCG 运行时 NavMesh 重建；不找/导入敌人美术资产。

## 架构原则（承接讨论结论）

- **抽象能力（组件/数据）趁早，抽象继承树延后**：第一步只做 `APursuerCharacter` 一个具体类，不做 EnemyBase；能力用组件、参数用 DataAsset。
- **AI 用 C++ 状态机**，不用行为树：逻辑简单（察觉→追→到距离→攻击→冷却→回追），C++ 更省更可控，符合项目"能 C++ 尽量 C++"，也绕开 MCP 行为树短板。
- **默认关 Tick**：AI 状态机用 Timer 驱动。
- **攻击表现与后果分离**：动画 Notify 只发"攻击生效"事件，不把伤害/击退写死在 Notify（为第二步和多种追猎者复用留口）。

### 2026-07-25 保存失败事故与修复（重要）

- **现象**：用户无法保存 BP_Pursuer；磁盘上 `BP_Pursuer.uasset` 根本不存在。
- **根因**：上一轮 AI（上下文爆掉那次）创建的 BP_Pursuer 带损坏的父类 import `A/Script/Demo.PursuerCharacter`（多了前缀 `A`）。本会话 `blueprint.create` "成功"实为复用了内存里这个损坏幽灵——CDO 属性能设对（get_properties 验证通过），但存盘时 UE 解析不了坏 import，`SaveDirtyPackages - Failed to save`，永远落不了盘。同类父类 `set_parent_class` 被拒（no-op），无法借此重建 import。
- **修复**：官方 `AssetTools.delete` 删掉损坏幽灵 → `blueprint.create` 干净重建 → 先空 BP `save_assets` 验证能落盘（磁盘出现 .uasset）→ 再设 Config/Mesh/AnimClass/偏移 → 编译 → `save_assets` → `is_dirty=false` 且磁盘文件在，确认修复。
- **遗留清理（2026-07-25 完成）**：上一轮 AI 建的重复件 `Content/ZeroEscape/Enemies/Data/DA_Pursuer.uasset` 已删除（AssetTools.delete 需先退出 PIE 才生效；删后磁盘 `Data/` 文件夹消失、资产注册表仅剩 `Enemies/BP_Pursuer` + `Enemies/DA_Pursuer` 两个正式件）。BP 的 Config 指向正式件 `Enemies/DA_Pursuer`。
- **PIE 初测（2026-07-25）**：追击闭环已跑通——日志反复出现 `LogPursuer: BP_Pursuer_1 触发攻击（暂无攻击蒙太奇，仅记录时机）`，证明感知→追击→进攻击距离→触发攻击时机全链工作。伴随 `LogCrowdFollowing: Unable to find RecastNavMesh instance while trying to create UCrowdManager instance` 警告（Crowd/RVO 避障子系统初始化找不到 navmesh），但 MoveToActor 寻路正常（能追上并攻击），暂列为非阻断项，后续接 PCG 运行时 NavMesh 重建时一并复核。
