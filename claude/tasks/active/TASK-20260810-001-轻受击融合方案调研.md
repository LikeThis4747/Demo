## 目标

- 为玩家与追猎者设计不会击飞、不会击倒的轻受击：实际接触方向和强度应清楚可见，并可让角色短暂减速或停顿。
- 当前 HeavyImpact 继续作为已验收的重受击权威；轻受击不得为了复用而进入完整全身物理、倒地和起身流程。
- 抛开旧 `PhysicsControlHitResponseComponent` 的既有实现选择，先按最终画面、稳定性和项目工期重新评估；旧代码只作为问题证据和可回退材料。

## 本轮范围

- 只读检查当前 HeavyImpact、旧局部 Physics Control 受击、玩家/追猎者移动与动画接入。
- 调研 UE 官方 Physics Control、物理动画、动画分层/惯性混合，以及有开发者分享的成熟游戏受击方案。
- 对比纯动画、纯 Physics Control、程序化姿势与混合方案，给出推荐效果、复杂度、失败风险和原型止损点。
- 不修改 Source、Config、AnimBP、DataAsset、角色资产、HeavyImpact 或机关；不恢复旧局部受击运行装配。

## 必须回答

1. 轻受击第一眼应看到什么，如何同时表达受击方向、受击位置和短暂停顿。
2. 哪部分真正由物理接触数据驱动，哪部分需要受控表现，避免“只是播动画”或“只是松骨头”。
3. 玩家与 AI 如何共享核心，同时允许停顿时长、移动减速和连续命中抗抖不同。
4. 轻受击与 HeavyImpact 的状态优先级、打断和同帧升级规则。
5. 第一版必须通过什么 A/B 画面门槛，失败时如何及时停损。

## 当前硬边界

- 用户明确把“合理、可用的效果”置于复用旧代码和技术形式之上。
- 轻受击不造成离地、全身倒地或起身流程；达到这些表现时必须升级为 HeavyImpact。
- 当前允许编写 `claude/` 下的拟实现方案；在用户明确授权前不修改 Source、Config、Blueprint、AnimBP、DataAsset 或机关资产。
- 当前另有“磁力投掷物碰撞破碎”任务与本方案重叠 `ElectromagneticGrabComponent.cpp` 和 `BP_MagneticProp`；两项实现必须串行。开始本任务实现前需先确认该任务写入窗口已释放，并按项目门禁完成全工作区基线提交、推送和远端核验。

## 2026-08-10 早期调研候选（已被下方“方案复审后的修正”覆盖）

- 推荐第一版采用“短暂移动受阻 + 程序化身体偏移”的组合：Capsule/CharacterMovement 始终保持角色移动权威；真实接触只提供冲量方向、接触点、强度和来源，不让骨骼进入全身或单肢完全模拟。
- 画面核心是快速吃力、短暂停顿、顺滑恢复：腿和脚继续支撑，骨盆只做很小偏移；脊柱、肩、头及命中侧手臂按实际冲量产生有上限的旋转与跟随。玩家保留镜头和转向，追猎者可暂停寻路/攻击稍长时间。
- 第一版不依赖新受击动画；AnimBP 只负责在基础 locomotion 上叠加由 C++ 计算的骨骼偏移。若后续确有合适动画，可作为较强轻受击的可选层，而不是系统成立的前提。
- Physics Control 只作为第二轮 A/B 的可选细节层：仅允许很小的命中链条滞后并持续追随动画目标，不允许单肢 Physics Blend Weight 直接到 1，也不允许改变骨盆、Capsule 或角色落地状态。若正常游戏镜头下提升不明显或出现橡皮感，应删除该层。
- 旧 `PhysicsControlHitResponseComponent` 不直接复活：它要求 Mesh 常驻 QueryAndPhysics、只接受 `AttackProjectile`、单次只激活一个区域、首次切区补施冲量并把该区 Physics Blend Weight 设为 1；这些选择会与 HeavyImpact 的碰撞/Physics Control 所有权冲突，也无法直接覆盖玩家。
- 轻重只共享受击输入，不共享表现求解：现有 HeavyImpact 忙碌时忽略轻受击；重冲击请求可以立即打断轻受击；同一物理批次先合并接触，再由来源意图与归一化强度决定是否仍是轻受击，避免一个碰撞触发多次抖动。
- 原型止损顺序：A 仅移动受阻；B=A+程序化方向/部位姿势；C=B+小幅 Physics Control 细节。只有 B 在正常镜头、移动中和连续命中下都明显优于 A，才进入 C；C 不明显就不保留。

## 外部依据

- Epic UE5.8 Skeletal Controls：AnimGraph 可直接、动态修改骨骼并用 Alpha 控制影响；适合以少量节点叠加程序化命中姿势。
- Epic UE5.8 Layered Animation / Blend Mask / Blend Profile：可让上半身反应叠加在 locomotion 上，并让下半身更快回归以维持脚底稳定。
- Epic UE5.8 Physics-Based Animation：官方命中示例会把命中骨骼以下切到模拟并把物理混合权重升至 1；这可作为对照样例，但其“limp/ragdolling arm”行为不适合作为本项目写实轻受击的核心。
- Volition《Animating an Agent of Mayhem》：开发者展示了可在站立、移动、蹲伏、翻越等状态叠加且不打断玩家控制的 additive hit reactions，支持将轻受击与完整动作打断分层。
- Respawn《Physical Animation in Star Wars Jedi: Fallen Order》与 Naughty Dog《Physics Animation in Uncharted 4》：均强调物理模拟应由动画目标约束并与动画混合，以获得可预测、可控的结果；支持把 Physics Control 降为细节层，而非轻受击唯一表现层。

## 2026-08-10 用户补充边界

- 用户已有三套轻受击动画，但不要求系统依赖动画成立；需要先检查动画方向、骨架、Root/腿部位移和是否适合叠加，再决定只供 AI、也供玩家，或完全不用。
- 玩家与 AI 共享轻受击输入、强度归一化和状态优先级；移动结果由来源 Profile 的玩家/追猎者对应栏选择，动画资产由各自 Tuning DataAsset 配置，不在机关或角色类中写目标类型分支。
- 追猎者主要来源：磁力物体真实碰撞、未来高压气罐；目标表现倾向原地短暂停住并维持站立。
- 玩家主要来源：未来高压气罐、可能的地刺轻受击版本；目标表现倾向减速但保留转向和镜头控制。
- 摆锤与冲锤当前保持 HeavyOnly，不为慢速或擦边额外实现轻受击分支；若后续需要，必须由接触前预测决定是否准备 HeavyImpact，真实接触再决定轻受击强弱。
- 第一版来源 Profile 只决定 `None / Slow / Stop`，真实接触数据只决定站立结果内部的方向、减速深度与持续时间；现有 Heavy 使用独立的接触前准备契约，不由轻受击 Profile 自动升级。
- 来源触发时机与接收端表现解耦：磁力物在真实碰撞提交一次脉冲；地刺由伤害/触发确认提交；高压气罐的持续推力留到其玩法确定后单独设计，不在第一版预建刷新接口。

## 2026-08-10 方案复审后的修正（覆盖上面的早期候选）

- 第一版不实现通用“冲量自动判轻重”，也不让 `Light/Heavy` 同时代表玩法后果、身体控制权和视觉强弱。成熟项目更常见的是：来源先限定玩法结果，物理数据再决定方向与表现幅度。
- 所谓玩家/AI“映射”只是一张直观对应表：同一来源分别填写 `PlayerReaction` 与 `PursuerReaction`。第一版不引入 GameplayTag 规则树、任意 Map 或全局“角色硬度”公式。
- 第一版对应表只支持站立结果 `None / Slow / Stop`。现有 HeavyImpact 保持独立的接触前准备契约，不作为所有来源都能选择的普通下拉项。
- 地刺当前是 `Overlap + ApplyDamage`，刺网格还忽略 Pawn；因此未来若要把地刺改成真实击飞，必须同时把它改造成可预测的真实运动刚体，或另外明确授权一套脚本击退执行器。不能承诺只改 DataAsset 即可进入当前 HeavyImpact。
- 用户已确认本轮不把地刺改造成真实物理机关，也不为它实现脚本击飞；地刺只验证站立 `Slow / Stop`。
- 新增一个角色侧总协调 Component；轻受击状态由它拥有，Heavy 的 PCA、倒地和起身仍由现有 `UHeavyImpactResponseComponent` 独占。现有 Heavy 接口先保留为兼容入口，但玩家与追猎者都先转发到总协调 Component；只有 Heavy 真实进入 `Prepared` 后才原子清除轻受击，被拒绝的准备请求不得产生副作用。
- 第一版不新增平级 `LightImpactComponent`，不恢复旧 `UPhysicsControlHitResponseComponent`，也不修改 HeavyImpact 内部。轻受击用短时速度影响和可选动画 A/B；动画为空时玩法状态仍必须正确。
- 官方 MCP 已确认两个运行时 AnimBP 都继承 `UHeavyImpactAnimInstance` 且已有 `DefaultSlot`，第一版可播放 Montage/Dynamic Montage，无需修改两个 AnimBP。玩家与追猎者骨架不同，只共享逻辑和数据结构，不共享同一动画资产。
- 追猎者现有三条 `standing_react_large_*` 是 1.0～1.77 秒的非 Additive 全身动画，适合停顿 A/B，但可能过重或脚滑；玩家现有 `MM_HitReact_Front_Lgt_01..04` 是 0.7～1.23 秒的 Local-space Additive 动画，可作低成本 A/B，但目前只有正面候选。
- 高压气流以后应拆成“一次进入反应 + 持续移动影响”，第一版不预建每帧刷新或 Begin/Update/End 接口。
- 已确认验收顺序：先用磁力投掷物验证真实接触、方向、强度、去重与动画，再用地刺补充验证同一 Profile 对玩家/AI的不同站立结果，最后验证轻受击中被摆锤命中时 Heavy 立即接管。
- Heavy 真实进入 `Prepared` 时必须同时清理当前 Light、轻动画、同帧暂存请求与下一帧 Timer；Heavy 结束后不得补交旧轻受击。
- 若后续磁力破碎与轻受击共存，`UMagneticObjectComponent` 必须成为根刚体 Hit Delegate/通知的唯一 Owner 并分发同一次 Hit；破碎组件只拥有破碎资格与下一帧替换，不得另行切换 Hit 通知。Light 与 Break 都释放后才恢复原始通知状态。
