## 当前目标与验收

- 当前目标：用 HydroLab 原始 `BP_HydroLab_LampA` 为运行时 PCG 场景补充稳定室内照明，缓解封闭场景过暗与天花板接缝漏光闪烁。
- 当前验收：48～72 个有效逻辑格约生成 24～37 盏灯；直路上大致隔一格一盏；Start 所在格必有灯；重新生成或失败时没有旧灯残留。
- 后续目标：光源通过用户 PIE 验收后，再单独确认小地图最小方案。
- 非目标：本步不做小地图、不改 WFC/Seed/Layout Hash、不增加灯光覆盖搜索算法、不随机选灯、不复制灯具参数、不修改第三方灯蓝图或 Level0。

## 当前实施方案

- Presentation Profile 新增灯开关、灯 Actor 类和相对逻辑格中心的修正 Transform；颜色、强度、半径与 RectLight 细节继续由原始灯 Blueprint 持有。
- 生成器统计有效格的两组棋盘奇偶性，选择数量较少的一组；数量相同则选择 Start 所在组。若较少组不含 Start，只额外补 Start 一盏。
- 这是当前四方向方格的直接抽样规则，不是新的路径算法：相邻格必属不同组，因此直路自然呈现隔一格一盏，灯数接近有效格的一半。
- 灯在 HISM 成功后生成；每个 Actor 创建后立即登记，统一 Clear、重生成、失败与 EndPlay 路径销毁。
- DataAsset 绑定 `BP_HydroLab_LampA`，灯位为逻辑格中心、天花板 Pivot 高度、`Roll=180°`。

## 风险、回退与下一步

- 性能风险：最多约 37 个独立灯 Actor；真实 GPU 成本仍取决于素材 Blueprint 的 RectLight 半径、阴影和重叠范围，需在 PIE 中观察并按需使用 `Stat GPU`/`ProfileGPU`。
- 已知边界：MCP 尚未读出 RectLight 组件全部默认值；直接复用原 Blueprint 可以避免在 PCG 中复制一套可能失真的灯参数。
- 回退：关闭 DataAsset 的 `bSpawnCeilingLights` 即停止生成；源码失败则现有事务回滚全部 HISM 与灯 Actor。
- 下一步：源码与资产装配完成后，由用户做主视口 PIE；通过后再讨论小地图。
