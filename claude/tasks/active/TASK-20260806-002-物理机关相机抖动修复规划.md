## 目标与验收

- 目标：降低玩家靠近摆锤/冲锤以及被物理机关击中时的相机快速跳动，同时保留地牢墙体防穿透能力和现有第三人称旋转手感。
- 第一版验收重点：角色在房间中央受击时，相机不再因 HeavyImpact 更新与弹簧臂更新顺序不稳定而出现逐帧错位；正常跑动和旋转不能出现明显拖沓；墙后相机仍不能穿墙。
- 第一版不是“所有近距离遮挡问题一次解决”：UE5.8 原生 `USpringArmComponent` 的位置延迟发生在碰撞检测之前，墙体命中后的回缩仍是即时的。若只靠近墙体、完全未受击时仍反复伸缩，将以实测证据决定是否进入第二阶段。

## 已核对事实

- `/Game/ZeroEscape/Characters/BP_ZeroEscapeCharacter` 的实际 `CameraBoom` 为：臂长 `220 cm`、探头半径 `12 cm`、`ECC_Camera`、碰撞检测开启、位置/旋转延迟均关闭、位置延迟子步已开启、Tick 为 `TG_PostPhysics`。
- `UHeavyImpactResponseComponent` 同样在 `TG_PostPhysics` 更新，并在物理事务期间用骨盆位置驱动玩家 Actor/Capsule 根节点。
- `CameraBoom` 直接挂在玩家根节点上。当前没有显式更新依赖，因此两个同组组件的同帧先后关系没有由项目代码声明。
- 摆锤和冲锤的主要碰撞体对 `ECC_Camera` 为 Ignore；测试房间墙体会阻挡 `ECC_Camera`。靠近机关但未受击时的相机回缩更可能来自机关所在的狭窄墙体，而不是锤体推动相机。
- UE5.8 原生 `BlendLocations` 在墙体命中时直接返回命中位置。内置 Camera Lag 会平滑弹簧臂起点，但不会平滑碰撞命中位置。

## 第一版方案

1. 在玩家构造函数完成 `CameraBoom` 与 `HeavyImpactResponse` 装配后，调用 UE 原生 `AddTickPrerequisiteComponent`。
   - 这里的“更新依赖”是 UE `FTickFunction` 的原生调度能力，不是项目自创术语。
   - 含义是：HeavyImpact 当帧需要 Tick 时，先完成骨盆到 Actor 根节点的跟随，再允许弹簧臂读取根节点。
   - HeavyImpact 未启用 Tick 时不会产生额外常驻逻辑。
2. 在现有玩家 Blueprint 的 `CameraBoom` 上启用轻量全局位置延迟：
   - `bEnableCameraLag = true`
   - `CameraLagSpeed = 12.0`
   - `CameraLagMaxDistance = 60.0 cm`
   - `bClampToMaxPhysicsDeltaTime = true`
   - 其中 `60 cm` 只是首测值；PIE 以同一受击场景对照 `40/60/100 cm`，以“消抖但不拖拽”为选择依据。
   - `bClampToMaxPhysicsDeltaTime` 只在帧时间超过物理最大时间步时发挥明显作用，按当前常见默认值主要是低于约 `30 FPS` 时的保险，不作为正常帧率消抖主力。
3. 保持以下行为不变：
   - `bEnableCameraRotationLag = false`，不让视角输入变软。
   - `bUseCameraLagSubstepping = true`、`CameraLagMaxTimeStep ≈ 1/60 s`。
   - `bDoCollisionTest = true`、`ProbeChannel = ECC_Camera`、`ProbeSize = 12 cm`。
4. 位置延迟先采用全局配置，而不是接入 HeavyImpact 状态委托。原因是第一版要验证最小闭环，避免为了开关一个现成的 SpringArm 属性增加状态缓存、恢复路径和受击系统耦合。

## 规模与风险

- 第一版 C++：现有 `.cpp` 增加约 `2` 行（`1` 行说明注释 + `1` 行调用），不新增头文件、类、Tick、Timer 或运行时状态。
- Blueprint：修改 `4` 个 SpringArm 配置值；保留 `4` 项关键碰撞/旋转配置。
- 主要风险：全局位置延迟会轻微改变正常跑动手感；`12` 是起调值，不是最终策划参数。
- 主要调参旋钮是 `CameraLagMaxDistance`；数值越大越能过滤大位移，但击飞时的相机拖拽感也越明显。第一轮必须比较 `40/60/100 cm`，不能只验证“抖动是否消失”。
- 已知边界：第一版不能平滑原生 SpringArm 的墙体命中位置，也不处理锤头可视模型进入近裁剪面。
- 若第一版后仍确认存在“无受击、纯贴墙”的反复缩臂，再单独提第二阶段：项目自定义 SpringArm 只让离墙伸回平滑、遇墙缩进仍立即生效，预计新增 `2` 个镜像 C++ 文件、约 `80~140` 行。该阶段不在本次拟实现代码中。
- 若只是锤头突然铺满屏幕而相机位置稳定，后续应做机关可视组件近距离淡出；不能把它误判为弹簧臂抖动。
