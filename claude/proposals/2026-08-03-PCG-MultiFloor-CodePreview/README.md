# PCG 多层关卡完整拟实现代码（Code Review 包）

> 状态：仅供代码审查，**没有应用到 `Source/Demo`、`Content` 或 `Config`**。
> 基线：2026-08-03 当前工作树；其中 `ZeroEscapeGameMode.h/.cpp` 已包含用户正在进行的结算界面改动，本审查包必须保留并在其上合并。

## 目的

本目录把已批准的多层 PCG 方案展开成可逐文件审查的 C++ 补丁。它不是已构建、已运行或已验收的实现；在用户明确授权前，不得把这些补丁应用到正式源码或资产。

## 补丁顺序

1. `01-data-contract-core.patch`：生成结果、DataAsset 配置、配置校验、确定性随机与规范 Hash。
2. `02-multifloor-layout.patch`：完整楼梯/高天花板房间放置、逐层二维 WFC、整栋通行图验收与纯数据测试。
3. `03-presentation-runtime-flow.patch`：HydroLab 表现装配、隐藏坡面、Generator 生命周期、RecastNavMesh 等待、GameMode 与 Population 正式开局流程及相关测试。

每个补丁旁的 `*-review-notes.md` 记录该片的前提、跨片接口与尚需 UE 资产装配验证的部分。`INTEGRATION_REVIEW.md` 汇总整套代码的审查重点、资产迁移清单和落盘后验证顺序。

## 已冻结的游戏规则

- 每局使用 DataAsset 的实际 `GridSize`；不固定为 `20×12` 或 `24×16`。
- 首版生成 2、3 或 4 层；三档难度分别保存楼层数权重。
- 玩家与追猎者出生在一楼，Exit 在本局最高层。
- 每对相邻楼层至少一座双层楼梯；贯通三层的楼梯间最多一座且只能作为额外捷径。
- 必需楼梯优先让每层进入点与离开点覆盖尽可能大的地图范围，靠近边缘只作为次级偏好；额外楼梯尽量远离所有现有端点。
- 高天花板房间的整栋最低数量、目标数量权重、每层上限和间距均可按难度配置；允许某层为零，也允许位于顶层。只有真实上层存在时才写上层净空。
- 保留现有二维 `FWfcSolver` 接口；完整跨层结构先放置，再分别投影为各层固定格、禁用格和固定开闭边，最后合并为整栋通行图做一次遍历验收。
- 旧 `RoomCount/RoomSizeTiles/GeneratedRoom` 整链删除；`RegionKind` 的两个真实消费者先迁移后再删除。
- 不生成一次性导航实验代码。正式 HISM 生成后等待本轮目标 `RecastNavMesh` 更新，再进行最多 20 个代表点的有界路径存在性检查；不使用 Tick。

- 不修改第三方 HydroLab 素材。
- 不实现摆锤、钥匙、机关、加载界面、三维 WFC 或 5 层以上地图。
- 不声称代码已经通过编译、自动化、PIE、真实玩家或追猎者验收。
