# 整体审查说明

## 审查结论边界

本目录是“准备实施的代码设计稿”，不是已经落入正式模块的代码。Code Review 应先判断数据合同、职责边界、确定性、预算与失败原子性；通过后才进入按步骤落盘、编译和 UE 资产装配。

## 推荐审查顺序

1. 先审 `01` 的公共类型和 DataAsset 交叉字段校验，确认没有把旧 Room 换成另一个没有消费者的标签系统。
2. 再审 `02` 的确定性候选顺序、共享计数预算、必需楼梯不能被三层楼梯间替代、逐层 WFC 约束和最终整栋遍历。
3. 最后审 `03` 的表现所有权、隐藏坡面碰撞职责、导航事件时序、异步开局回调和失败清理。
4. 跨片检查同名类型、函数签名、补丁应用顺序和 `GameMode` 现有结算界面改动是否完整保留。

## 需要 Code Review 特别验证的安全不变量

- 相同 Seed、难度、Profile/Presentation 版本和结构定义，必须得到相同 Plan 与规范 Hash。
- 候选集合遍历、Hash 和稳定 ID 不得依赖 `TMap`/`TSet` 的迭代顺序，也不得使用进程内 `FName` 比较索引。
- 每对相邻楼层的 `RequiredTwoFloorStairStableIdByLowerFloor` 必须指向一座真实双层楼梯；贯通三层的楼梯间永远不能写入该数组。
- 所有楼层和最多四次完整布局重试共享同一组 WFC 候选、回溯、求解树与结构候选计数；重试不得刷新预算。
- 额外双层楼梯和三层楼梯间放不下时可以跳过；必需楼梯、顶层 Exit、最低高天花板房间数量或全楼层连通失败时必须丢弃整轮。
- `Walkable`、`Solid`、`Clearance` 三种结构占用不可混为一类；只有 `Walkable` 进入通行图，后两者都投影为该层 WFC 的禁用格，但最终 Plan 仍要保留差异。
- 高天花板房间位于顶层时合法；只能裁掉超出真实最高层的净空地址，不能裁实体或可走格，也不能让其他结构越界获得同样豁免。
- Generator 在纯数据、场景实例、目标 `RecastNavMesh` 更新和代表点路径存在性全部通过前不得进入 `Ready`，不得广播成功，也不得让 GameMode/Population 启动半局。
- 导航等待不使用 Tick，不自动更换 Seed，不在失败后保留场景或玩法 Actor，不通过放宽 Recast 全局参数掩盖楼梯装配问题。
- `ZeroEscapeGameMode.h/.cpp` 当前已有未提交的 ResultMenu 功能；落盘时必须进行三方合并，不能用审查稿整文件覆盖。

## 第一轮技术安全值（待批量 Seed 校准，不属于难度玩法）

- 完整布局重试：最多 4 次。
- 完整结构候选检查：整栋共享 250000 次。
- WFC：每层基线候选 100000、回溯 25000、求解树 10；按实际楼层数线性形成整栋共享上限，所有重试共同消费。
- 导航等待：10 秒。
- 导航代表点：最多 20 个，最多 19 次 `TestPathSync`。
- 单 Seed 批测观测线：15 秒；墙钟时间只用于停止批处理和报告长尾，不参与 Seed 的算法选择，因此不会破坏确定性。

`250000` 是首轮防止结构组合搜索失控的工程安全值：四层最大网格、三种首版结构和四个旋转的一次全枚举约为五万级；该值给必需楼梯的有界回溯、额外楼梯和高天花板房间留出数轮空间，又不会形成无界搜索。它需要由 2/3/4 层批量 Seed 的 P95/P99 数据校准，而不是随 Hard 难度放宽。

## 资产迁移（代码审查通过后才执行）

- `/Game/ZeroEscape/Generation/Data/DA_LevelGenerationProfile`
  - 删除旧 Room 数量/尺寸。
  - 录入双层楼梯、贯通三层的楼梯间和高天花板房间的局部可走格、实体格、净空格、内部连接、每层落脚平台、连接口和合法连接口组合。
  - 为 Easy/Normal/Hard 分别录入 2/3/4 层权重、额外双层楼梯数量权重、三层楼梯间概率、空间与路线覆盖比例、高天花板房间数量规则。
- `/Game/ZeroEscape/Generation/Presentation/DA_Presentation_SciFiHydroLab`
  - 录入三个完整结构的可见构件配方、连接口封闭/开放收边、护栏、楼层高度和每跑隐藏坡面。
  - 隐藏坡面继续使用 Level0 已验证的约 `393.23×205×8cm` 配方；可见踏步忽略 Pawn 且不影响导航，坡面阻挡 Pawn、忽略 Visibility/Camera 并影响导航。
- `/Game/ZeroEscape/Generation/Population/DA_Population_Default`
  - 删除 `TargetRegionKind`；默认只从普通 WFC 可走格候选中放置，继续支持避开出生点/Exit 邻格和只选直走廊。
- 编译并保存 Generator、Population、GameMode 蓝图，再只修改 `L_Game` 的正式装配；`Level0` 只读作为配方证据。

## 落盘后最低验证顺序

1. C++ 完整构建和 UHT。
2. 纯数据自动化：结构四向旋转、越界/重叠/错口、预算不刷新、同 Seed Hash、2/3/4 层必需楼梯与全楼层可达。
3. 用正式 DataAsset 生成第一座双层楼梯，检查 HISM、碰撞、栏杆和隐藏坡面，再验证目标 RecastNavMesh 完成事件及真实上下层路径。
4. 扩到三层楼梯间、高天花板房间和四层最坏组合。
5. 三档难度各 300 个纯数据 Seed，再挑代表 Seed 运行 PIE、玩家胶囊和真实追猎者双向实走。
6. 从 `L_MainMenu` 进入 `L_Game` 连续游玩；用户实际行走验收前只能标记为“待用户验收”。
