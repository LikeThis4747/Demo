## 重点问题

- 补丁按 README 顺序是否能够机械应用；是否还有旧 Room/RegionKind 引用、缺失声明、UHT 不合法字段、错误 include、私有/公开边界或明显 UE5.8 API 签名错误。
- 数据合同是否真正支持：2/3/4 层、玩家和追猎者在一楼、Exit 在顶层、每对相邻层必需双层楼梯、最多一座只能作为额外捷径的三层楼梯间、额外楼梯按难度配置、高天花板房间顶层合法。
- 必需楼梯 StableId 映射是否可能被额外楼梯或三层楼梯间冒充；结构旋转、连接口、内部边、实体、净空和共享边是否有越界、重叠、单向开口或重复所有权漏洞。
- 必需端点排序是否先最大化空间跨度、再偏向边缘；额外楼梯是否逐座最大化到所有既有端点的最近距离；所有比值是否使用当局实际 `GridSize`。
- WFC 是否仍是逐层二维接口；固定结构格是否正确映射为 Required/Outside/固定开闭边；结构可走格是否不会吃掉普通内容下限。
- 多层预算是否在所有楼层和最多四次完整布局重试之间共享且不刷新；墙钟超时是否只用于批测监控而没有进入确定性算法。
- 同 Seed 确定性是否可能受 `TMap/TSet` 迭代、数组资产顺序、`FName` 进程索引、浮点近似 Hash 或共享随机流消费次序影响。
- 最终整栋图是否一次覆盖玩家、Exit、所有楼层、必需/额外楼梯落脚点；每层路线覆盖检查与整栋检查是否职责不同，而不是相互矛盾的重复门禁。
- 表现 Builder 是否只有一个结构边所有者；普通格、完整楼梯和高厅是否可能生成双地板、双墙、封死开放口或补回高厅标准天花板。
- 隐藏坡面是否严格延续 Level0 配方：可见踏步 Pawn Ignore 且不影响导航，隐藏坡面 Pawn Block、Visibility/Camera Ignore、影响导航；是否有一次性探针、临时 Actor 或全局 Recast 参数改动混入。
- Generator 是否在绑定目标导航完成事件后才实例化；能否区分本轮操作、目标导航数据和构建静止状态；超时、EndPlay、重入、旧回调和失败回滚是否安全。
- 最多 20 个代表点/19 次 `ProjectPointToNavigation + TestPathSync` 是否真正有硬上限、核对投影楼层并从追猎者点验证到玩家、Exit 和每个楼梯落脚平台。
- GameMode 是否在请求前绑定、等待最终完成事件、锁定移动与视角，并且只在最终成功后放置玩家/追猎者/Exit、启动 Population、绑定死亡；直接运行 `L_Game` 是否同样走等待流程；失败是否保留 Seed、清理半局并明确返回主菜单。
- 自动化是否覆盖成功和失败合同，但没有把纯单元测试冒充实际 Recast、玩家胶囊或真实追猎者验收。

## 报告格式

按严重度列出可操作问题，先写会导致编译失败、错误地图、非确定性、预算失效、半局提交或导航假成功的问题。每条给出补丁文件、目标源码路径和精确行号/片段，并解释为什么会违反已确认规则。最后单独列出：

1. 可直接采纳的修改；
2. 需要用户决定的玩法取舍；
3. 只能在正式落盘后通过构建、UE 自动化或 PIE 证明的事项。

不要因为这是拟实现稿就降低标准，也不要要求它在代码审查阶段提供尚未授权的资产修改或玩家验收证据。
